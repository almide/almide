# v0.70.0 — dialect epoch 17 (byte bodies, a failing process.run is an error), and an incomplete wasm certificate is refused

v0.70.0 follows v0.69.1 as the stable release. It opens dialect epoch 17, which removes the spellings deprecated at epoch 15, makes `process.run` fail on a failed command and makes an HTTP `Body` hand over its bytes. A wasm module whose certificate is INCOMPLETE is now refused unless you opt out. `fan` behaves the same on every native route, native `build`, `run` and `test` use the verified render, and every stdlib function was inspected on both targets. Dependencies are fetched in process and locked by a tree hash. These notes cover everything since v0.69.1, including the three release candidates.

## Upgrading from v0.69.1: breaking changes

The public stdlib interface is **breaking** against v0.69.1: five signatures are removed or changed and one is added. Each change has a row under epoch 17 in `proofs/dialect-epochs.toml`.

- **An HTTP `Body` type requires `to_bytes`, not `to_text`** (#4311, ADR-0032 amendment A1, C-275). A response now keeps a Bytes body exactly. Before, every Bytes body was decoded as lossy UTF-8, so `http.body_bytes` of a response built from non-UTF-8 bytes returned the lossy decoding, and `http.serve` sent it. **Fix:** replace `fn T.to_text(self) -> String` with `fn T.to_bytes(self) -> Bytes`. To keep a text body, return `bytes.from_string(text)`.
- **`regex.full_match` is removed** (#3942, R-regex-01). It was deprecated (E052) at epoch 15 in v0.69.0. **Fix:** write `regex.is_full_match(re, s)`. It gives the same answer under the `is_*` spelling that every Bool question in the stdlib uses.
- **`int.pop_count`, `int.bit_width` and `float.sign` are removed** (#3985). They were deprecated at epoch 15. **Fix:** use `int.count_ones`, `int.bit_length` and `float.signum`. The answers are the same, and `float.signum` still gives 1.0 for 0.0 and -1.0 for -0.0.
- **`process.run(c)` returns `Result[Unit, String]` and fails when the command fails** (#4148, C-374). It returns `ok` on exit 0. Any other exit fails with `process.run(<cmd>): exited with status <code>`, and a signal fails with `process.run(<cmd>): ended by a signal`. Before, it returned `ok(code)` for every exit. **Fix:** to read the exit code, call `process.output(c)!` and read `.code` (the output is then captured instead of shown). Otherwise, drop the read and let `!` stop on a failure.
- **`almide.toml` refuses an unknown key or table** (#3382, #4851). This applies to an unknown top-level table such as `[targets]`, and to an unknown key in `[package]`, `[permissions]`, `[trust]`, a `[dependencies]` entry or a `[target.<platform>]` table. Every command refuses it (`check`, `build`, `run`, `test`, `bench`, `emit`), and the editor shows it as an error. The message lists the keys that section declares and suggests the nearest one. Before, such a key was ignored. **Fix:** delete the key or correct its spelling. A `[targets]` table never had an effect, so delete it.
- **`[package].name` must be a plain name on every route.** A plain name uses letters, digits and `_` and does not start with a digit. Names with a hyphen were already refused. Every route now refuses any other non-plain name too, and `build -o` no longer lets one through. `almide add` refuses a dependency name that is not an identifier before it probes or writes anything (#4867). **Fix:** rename the package, for example `my-app` to `my_app`. The package name is the import name.
- **A stdlib call that reaches a file needs its `FS` leaf in `[permissions].allow`** (C-460, #4825). `unix.connect` is now `Net.fetch` and `FS.read`. `unix.listen` is `Net.listen` and `FS.write`. `unix.shm_create` is `FS.write`. **Fix:** add `FS.read` or `FS.write` (or `FS`). `fs.temp_dir` opens no file and is now `Env.read`, so add `Env.read` where only `FS` was granted.
- **Host Rust code sees a `List` field of a record or variant as `AlmideList<T>`, not `Vec<T>`** (ADR-0037). This affects a package's `native/*.rs`, or a host that calls an Almide package. **Fix:** build such a field with `vec![..].into()`. Function parameters and return values are still `&[T]` / `Vec<T>`, copied at the boundary.
- **An `http.serve` handler can no longer replace `X-Content-Type-Options`** (C-407). The server drops the handler's value and writes `X-Content-Type-Options: nosniff` on every response.
- **`http.typed` accepts only the stdlib's closed table of media types that cannot run script** (C-465, E117). Any other type needs a grant to the application itself, `[trust] media "self"`. A script-capable type needs that grant under its exact name.
- **A `[trust].media` grant names the dependency by host and full path** (#4868). The old `owner/repo` key is refused, and the message shows the new form. **Fix:** write `"github.com/owner/repo"`.
- **A `[permissions].native` grant names a dependency by its origin** (#4834). A bare name now covers only the root's own `[dependencies]` entry of that name. To grant a transitive package, name its git source or directory.
- **A private https dependency cannot be fetched.** The in-process fetch sends no credentials, and the 401/403 refusal tells you to use the ssh form, for example `git = "git@github.com:owner/repo"`. A git source that git could read as an option, one with `?`, `#` or credentials in it, or one whose scheme is not https or ssh is refused on its manifest line (#4810, #4811). So is a tag or branch shaped like a path (#4838).
- **`almide run` refuses `--profile` and `--allow`** (#4885). Use them with `almide check`.

## Verification by default

- **wasm modules with an INCOMPLETE certificate are refused by default** (C-462). This applies to `almide build --target wasm` (and the core module of `build --component`), `run --target wasm`, `test --target wasm` and `bench --target wasm`. Before writing or running the module, each one judges its certificate with the `almide-verify` library linked into the compiler. A build therefore can't ship unjudged because no verifier binary is installed (#4836). An INCOMPLETE module is refused exactly as a REJECTED one is: exit code 1, nothing written or run, and every uncertified function is named with the producer's reason. `--allow-incomplete-verification` lets it pass with a `warning[verification-incomplete]`. A REJECTED certificate is refused even with the flag.
- **The default `almide test` lane runs a file whose wasm certificate is INCOMPLETE on native, with a note** (#4959). The note says the wasm module was not run and gives the `--target wasm` command that runs it on wasm. An explicit `--target wasm` still refuses.
- **The native build route refuses a reachable `@extern` fn that has no native binding and no body, with E081 before anything is rendered** (C-461). Before, the binary aborted when it reached the call. The native route also refuses an `@extern(rust)` fn that returns a Region (E090), and a Set whose element holds a Float two runtime containers deep (E081) (C-464).
- **Native routes that no certificate covers print a warning on every use** (C-463). They are `--target rust` source output, `build --repr-c`, `build --cdylib`, the rustc route `build --target wasi`, and the REPL. `check --profile critical --target wasi` is refused.
- **The verified native render's certificates are judged by the linked verifier before rustc runs, and a rejection stops the build** (#4828, #4932).
- **Every pass/refuse decision site is listed in `proofs/decision-sites.toml`.** There are 161 sites, and 81 carry an inspection stamp. All but one refuse on an input they do not recognise. The one site that still passes it is described under Known limitations.

## Language and checker

- **A failing `guard let` returns from the fn in every expression position** (issue #4678, C-266). Before, it returned only from a `let`/`var`/assignment value, a statement or a tail `if` arm. In other positions the `else` value became the block's value and the fn carried on. A lambda body still returns from the lambda.
- **E121 refuses an import whose first segment names both a local module and a dependency** (C-458, #4865). This covers `import pkg` and `import pkg.sub`.
- **E122 refuses a spread of a type parameter that has no record-shape bound** (#4285).
- **Sets and Maps treat every NaN as one key and -0.0 as the key 0.0** (ADR-0039, C-466). This holds through every nested component and on native, wasm and the interpreter. `==`, `list.contains`, `list.unique` and the other list operations still use IEEE equality.
- **A generic body orders a type by its protocol's `compare` in every natural-order operation** (C-456, #4788). For example, `list.sort` and `set.sort` over `BigInt` now sort numerically on every leg.
- **`almide check` refuses an unordered element type wherever a stdlib function orders it** (#4758, E030). Equality wrappers such as `deque.unique`, `dedup` and `group_by` declare `[A: Eq]` (#4796, E016). Both kinds of program used to pass check and then fail to build.
- **A generic stdlib function passed by name as a callback is typed from the call site** (#4745, #4747). `list.map(rows, list.len)` was refused on native, and on wasm it was refused or printed a wrong length.
- **Purity is decided from declarations instead of lists of names.** A `@pure` fn that calls a testing assertion is E092 (#4951). A function passed to a `@pure` fn is refused when it reaches an effect (#4928). An `@inline_rust` fn outside the stdlib counts as foreign (#4824).
- **More checks, now enforced on every route:**
  - a closure that writes a mutable binding declared outside every closure is refused (#4859);
  - a slotted fn used as a value is refused with E008, and the message shows the call to write instead (#4903);
  - pattern depth counts against the nesting budget (#4818);
  - the permissions gate runs on `check --json` and `check --effects` too (#4815).
- **Parse errors are clearer.** After a missing `=`, the parser keeps reading the fn body, so the body's other errors arrive in the same run. A `let … in` block, a stray `in`, a bar-led match arm and `match … with` each get their own message instead of a generic parse error.

## Correctness: `fan`

- **Arms that directly call user fns run `@ordered` fs work in arm order on native** (issue #4615, C-004). A fan arm whose callee the ordered walk cannot see now runs serially (#4856, #4893).
- **`io.eprint` and `io.write(io.stderr(), …)` inside an arm follow the arm's output order** (issue #4616).
- **A fan arm, a line-fold worker and a parallel `fan.map` worker get the main thread's stack size, up to 1 GiB** (issue #4617, C-196). Before, a recursion depth that the sequential run reached overflowed under `fan` on two or more CPUs.
- **`unix.shm_write` and `unix.shm_resize` are `@ordered`** (#4618), so a fan that reaches them runs its arms in order.
- **Output lines never interleave** (C-457). A `println` / `eprintln` of an interpolated string writes each line whole, even when `fan.map` arms print concurrently, and allocates nothing per line on native.

## Correctness: native

- **A list built by `list.flat_map` keeps its elements when wrapped in `ok(…)` or `some(…)`** (issue #4764). This affected rc1 and rc2, which returned `[]` without an error.
- **Native `almide test` accepts the shapes v0.69.1 tested** (issue #4749). These include a record `var` rebuilt in a loop and then in nested branches, and a closure that wraps a module-level String in `some`, both of which were still refused at rc3. When the verified render can't render a test program, the test lane builds it through the standard codegen, as `build` and `run` do (#4956).
- **Fixed programs that passed check but failed in rustc or ran wrong:**
  - an `effect fn` whose whole body is `process.exit(c)` (#4619, C-219);
  - a guard whose `else` is `err` of a non-String payload (#4654);
  - a guard inside a bound `match` arm (#4722);
  - a `!` inside a branch-statement arm (#4651);
  - ordering a captured `var` String against a literal (#4780);
  - a fallible `list.map` whose callback bangs a rebuilt Result (#4784);
  - a handler passed through `Result[Secret[HttpHandler]]` (#4768);
  - `Set[Bool]`, `Set[Float]` and `Set[Option[Int]]` (#4795, #4797);
  - a spread record moved into a fallible fn's tail tuple, which was released twice (#4958).
- **Native `almide test` builds packages that carry native code again** (issue #4640). The test report also keeps a nested abort's `at:` line (#4798).
- **`http.set_body_bytes` on a request sends its bytes unchanged** (issue #4744). A call handle's response body is now the exact bytes the server sent.
- **`fs.read_text` works on a WASI host that enforces rights.** The read now requests the right to stat the file.
- **A process command name runs the program found on the `PATH` the program was launched with** (C-459, #4844). `env.set("PATH", …)` no longer changes which program a name runs.
- **A refused thread spawn is an error, not an abort** (#4918).

## Correctness: wasm

- **Six leaks are closed:**
  - a `!` in a later operand of a call or map literal (#4639);
  - a failing `fan { }` nested inside a constructor or literal (#4642);
  - `(fan { … }).0`;
  - a heap `Ok` payload bound in a loop of a Result fn (#4648);
  - `json.parse` over a 4-byte character followed by a `\u` escape (#4607);
  - `filter_map |> map.from_list` over string tuples (#4630).
- **An effect fn that answers `ok(x)` with a borrowed `x` no longer hands its caller a released block** (#4936). The program trapped on wasm.
- **`env.get` and `env.vars` see the same environment on native and wasm under `almide run`** (#4774). wasm `http.serve` frees everything it holds after a SIGTERM (#4769).
- **Fetched response header names are lowercase on both targets** (#4766, C-455), and the fields the transport manages are left out.

## Stdlib inspection

- **Every stdlib function but one carries an inspection stamp.** Each one is checked for the same result on native and wasm, for a measured complexity that fits its declared class, for leaks and for diamond-free imports. The fixes below came from that inspection. The exception, `http.with_body`, is listed under Known limitations.
- **Linear where they were quadratic, or O(1) per call where that applies:**
  - `string.pop`, `bytes.pop` and `drop_end` (#4756, #4761);
  - `min_by` / `max_by` on bytes and strings (#4755);
  - `int.parse_radix` (#4765);
  - `heap.push` and `heap.filter` (#4777);
  - deque `drop` / `take` (#4773) and wasm `deque.pop` (#4778);
  - `matrix.concat_rows`, `zip_with` and `to_bytes_f16_le` (#4770, #4775, #4786);
  - wasm `regex.replace` (#4779) and `list.join` over `List[Bytes]` (#4785);
  - bigint division by a one-limb divisor (#4783);
  - native `bytes.fold` over a String accumulator (#4762).
- **wasm `value.get` and the `value.get_*` readers are O(1) on objects of 16 or more pairs** (#4757).
- **`matrix.split_cols_even` is held to the shared matrix size ceiling on every leg** (#4914).

## Packages and security

- **Dependencies are fetched in process** (ADR-0035). A git source is read once into a typed value that trust, the fetch, the cache key and the lock are all built from. An https source is fetched by an in-process git client, and the only process the fetch path can start is one typed `ssh` launcher. A fetched package must be a tree of regular files within fixed size, count and depth budgets. `almide.lock` records a tree hash (`sum`), which is checked on every use, including cache hits. An older lock without `sum` still reads and gets the sum on the next resolve. `--locked` refuses a lock entry without one. `almide clean` removes the old cache layouts.
- **Fixes from the pre-release security audit:**
  - git option injection and host confusion (#4810, #4811);
  - a lock commit read as a path (#4812);
  - dependency symlinks (#4813);
  - two sources declaring one package name (#4834);
  - a native-grant scan that walked different files from the resolver (#4809);
  - an unparsable manifest read as no manifest (#4829);
  - `--locked` now applies on `check`, `bench` and `emit` too (#4852);
  - each program's fs scope now comes from its own project (#4816, #4831, #4833, #4843);
  - `unix.listen` / `unix.connect` socket paths are bounded by `[permissions] fs` (#4832);
  - shared-memory regions are backed by storage that no path names (#4850);
  - hidden characters are escaped in diagnostics, test names, `--json` and the editor and MCP output (#4819, #4820).
- **`[permissions] proc` covers every stdlib fn that can spawn a process**, read from declarations (#4817).

## Performance

- **`fs.fold_lines_chunked` folds its chunks in parallel on native** (#4741). On a 16-vCPU host, a 50-million-line aggregation with 12 workers takes 0.54 s, against 0.63 s on v0.69.0.
- **Native `List` is a shared block with a count, copied only when it is written while shared** (ADR-0037). A loop that only appends to a list renders through an appender.
- **String churn (split, trim, join) runs at 0.88× of the equivalent Rust program on native and 1.06× on wasm** (#4612).
- **On native, a closure no longer copies captures it only reads** (#4700), and a self tail call no longer copies a `@consume` accumulator each step (#4789). `@consume` http operations move their value instead of copying it (#4771), and `io.read_to_end` and `io.read_exact` are linear (#4782).
- **Sets and Maps whose keys are records, variants or tuples are indexed instead of scanned**, on native (#4787) and wasm (#4887).
- **On native, a tuple-literal `match` no longer copies the code of the next row into every leaf** (#4954). On the reported task, the generated code fell from 111,504 ops to 270.
- **`almide check` runs its front end once** (#4187).
- **On a wasm build, a module-level table of records costs time linear in its row count** (#4614). A 1,600-row table builds in 0.08 s instead of 4.4 s.

## Known limitations (to be addressed in v0.71)

- **One decision site still passes an input it does not recognise:** `witness.native-verified-fallback`. When the verified native render can't render a program, the native build falls back to the standard codegen, which has no certificate. The C-463 warnings cover the declared unverified routes, but not this fallback.
- **In the compiler's own CLI test suite, 56 programs still can't be rendered by the verified native render and use that fallback.** The native test lane does the same, which restores the v0.69.1 behaviour (#4956).
- **80 of the 161 decision sites have no inspection stamp yet.**
- **`http.with_body` has not been re-inspected since its body moved to Bytes** (#4311). Its results match and nothing leaks, but its native instruction count varies by about 0.3% between runs, so its complexity class can't be confirmed within the 3% bound.
- **Five test files of the compiler's own suite have an INCOMPLETE wasm certificate.** They are listed in `proofs/incomplete-verification.toml`, which has one row per file with the number of uncertified functions and the producer's reasons. They run with `--allow-incomplete-verification` or, on the default test lane, on native.

## Gates and evidence

- The native verified floor is 1,066 of 1,067 `spec/wasm_cross` programs (507 at v0.69.1). The corpus list of native walls (`proofs/native-walls.txt`) is empty.
- The Rocq spine has 744 theorems and lemmas (648 at v0.69.1). Three new kernel rules read the shipped wasm bytes directly: guarded windows, fresh blocks and loop reads (#4952, #4953). A second decoder re-derives every byte string they judge. The kernel also checks that each judged module's shipped runtime routines decode to the proven trees.
- Contracts C-455 to C-466 are new. C-004, C-196, C-219, C-266, C-275, C-374 and C-407 are amended, each in the judge repository first.
- Each fix carries a test with a negative control. All 133 decision-site controls turn red when their check is removed.
