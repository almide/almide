# v0.70.0 — `fan` behaves the same on every native route, and every cross-target fixture renders on the certified native path

v0.70.0 fixes the cross-target divergences found in `fan`, and moves native `almide build`, `run` and `test` onto the certified render for every program in the cross-target corpus. It soaked as v0.70.0-rc1. No language surface changes: the public stdlib interface is identical to v0.69.1.

## Since v0.70.0-rc1

- **`fs.fold_lines_chunked` folds its chunks in parallel on native again** (issue #4741). rc1 ran every chunk on one thread: the certified render judged a step that calls a stdlib function or hands a closure to `map.upsert` as unsafe to share between threads, and chose the sequential twin. The judgement now follows each closure to where it is built and reads a bodiless stdlib call from its declaration. A step that prints, or that calls a closure from outside the walk, still folds sequentially. On a 16-vCPU host, a 50-million-line aggregation with 12 workers takes 0.54 s (v0.69.0: 0.63 s; rc1: 5.49 s), and the same aggregation on one thread takes 4.23 s (v0.69.0: 4.79 s). A step that only reads its line now borrows it instead of copying it, and `map.upsert` keeps its String key borrowed. The parallel chunked fold is now in the native render perf corpus.
- **The certified render no longer copies a closure's captures that it only reads** (issue #4700). `fallible_hof_recursive_callee` went from 1.108× to 0.943× of the earlier render; it was the last program in the render comparison that was slower.
- **String churn is faster on both targets** (issue #4612). Split, trim and join stream through borrowed views, `string.trim` and `string.to_upper` are rewritten. On the string-churn benchmark, native runs at 0.88× of the equivalent Rust program (1.54× at rc1). On wasm it runs at 1.06× of the equivalent Rust program, measured on an n2-standard-16 host. `string.trim`, `trim_start` and `trim_end` were re-inspected on the new code and stamped again.
- **A deep chain of heap-result `if` arms renders faster on native**: a 28-level chain renders in 1.37 s, down from 3.3 s at rc1. The move-parameter solver keeps each verdict instead of judging the same takeover once per round.
- **An Option fallback join rewrite the render no longer reaches is removed.** All 1,420 rendering programs of a 3,526-program survey produce byte-identical Rust without it.

## Correctness: `fan`

- **Arms that are direct calls of user fns run `@ordered` fs work in arm order on native** (issue #4615). The certified native render lifted such arms onto threads and let their fs writes interleave. Contract C-004 now names this route, with `spec/wasm_cross/fan_ordered_direct_call_arms.almd`.
- **`io.eprint` and `io.write(io.stderr(), …)` inside an arm follow the arm's output order** (issue #4616), as `eprintln` and the stdout writes already did (`spec/wasm_cross/fan_arm_stderr_timeline.almd`).
- **A fan arm, a line-fold worker and a parallel `fan.map` worker get the main thread's stack size**, at most 1 GiB (issue #4617). They had Rust's 2 MiB spawned-thread default, so a recursion depth the sequential run reached overflowed under `fan` on two or more CPUs, and the exit code depended on the core count. Contract C-196 is amended.
- **A fan gate helper no longer holds a protected borrow across the caller's free** (issue #4452). This was undefined behaviour under Miri; no wrong output was observed.

## Correctness: native

- **An `effect fn` declared to return a Result whose whole body is `process.exit(c)` builds on native** (issue #4619). It was refused with a Rust type error while wasm ran it. Contract C-219 is amended (`spec/wasm_cross/never_tail_of_result_effect_fn.almd`).
- **`list.flat_map` over a Float list with a list-literal callback builds** (for example `list.flat_map([1.5, 2.5], (f) => [f, f * 2.0])`). The certified render emitted Rust that did not type-check.
- **Native `almide test` builds packages that carry native code again** (issue #4640). The test lane uses the certified render only, and it refused a dependency's `@extern(rust)` fn, did not emit the module fns that `native/*.rs` links against, and refused a `todo(…)` body and an unreached `@extern(wasm, …)` declaration. A linked native callback with String, List, Option, Result, tuple, record, variant or `mut` parameters is adapted to the signature the earlier render emits for it. Still refused by the test lane: a callback with a function-typed parameter. Across a 45-file corpus of real package and test code, the certified native render refuses no file and no function.
- **A `!` inside a branch-statement arm or a bare block statement propagates on the certified render** (issue #4651). On the development branch after v0.69.1 the certified render accepted these functions and the program ran on past the failing call with exit 0; no tagged release carried it. A generated sweep of 2,100 programs agrees with wasm on every program the certified render accepts (`tests/v1_branch_arm_propagation_test.rs`).
- **A guard inside a bound `match` arm returns its `else` value on the certified render** (issue #4722). It bound the value as the arm's result instead of leaving the function.
- **A guard whose `else` is `err` of a non-String payload in an `effect fn` builds** (issue #4654). It passed `almide check`, then failed in rustc and panicked the wasm emitter.
- **A Float-returning lambda that returns a literal builds through the typed closure dispatch** (issue #4606).
- **A record literal inside a tuple builds on native** when a declared record type has the same shape. The certified render emitted two Rust types for one value.
- **Scalar `@export(c)` signatures build on the certified render**; every other row is still built by the earlier render.
- **More shapes render on the certified path instead of falling back**: `fan.map` outside the scalar matrix and with a propagating callback, a function that recurses in both tail and non-tail position over heap values, a propagation inside a loop under a branch statement, a destructuring unwrap in a loop body, an unwrap in a record field or a `for` head, a fold whose callback is one constructor, and a variant field holding a list of tuples or records.
- **`list.get(xs, i) ?? "literal"` reads through a borrow on native** when the element is only inspected, and shares the element's handle when it escapes.
- **`almide build` holds the shared build directory's lock from the cache check through the copy-out** (issue #4269). The reported race did not reproduce, so the issue stays open for the reporter to confirm.

## Correctness: wasm

Six leaks on the wasm leg are closed. Output and exit code were already identical to native; the blocks were left live at exit.

- **A `!` in a later operand of a call or map literal releases the operands before it** (issue #4639). Present since v0.69.0.
- **A failing `fan { }` block inside `ok(…)`, `some(…)` or a list, tuple, record or map literal leaves no block behind** (issue #4642). A fan block nested as another fan's arm is this shape.
- **A position read of a fan block, `(fan { a(), b() }).0`, releases the tuple.**
- **A heap `Ok` payload bound by `let` in a loop of a Result fn is released when a later iteration propagates** (issue #4648).
- **`json.parse` no longer leaks one block per 4-byte character followed by a `\u` escape** (issue #4607).
- **`filter_map |> map.from_list` over string tuples releases its strings** (issue #4630).

## Performance

- **A wasm build of a module-level table of records is linear in its row count** (issue #4614): a 1,600-row table builds in 0.08 s, down from 4.4 s. The witness bundles are byte-identical on every corpus program.
- **Reading the head of a list does not copy the element on native.** `list.get(xs, 0) ?? d`, `list.first` and `match list.first(xs)` on a list parameter read through a borrow; at 160,000 elements the head-read probe went from 1.20 s to under 0.01 s.
- **`acc = step(acc)!` in a loop does not clone the accumulator each round on native.** A path that ends the process no longer keeps the value live.
- **A recursive rebuild of a variant moves the untouched subtree on native** instead of copying it: the tree-insert probe makes 3,467 allocations, down from 40,403.
- **`m[k] = (map.get(m, k) ?? d) + 1` is one probe on native**, and `list.group_by(xs, f) |> map.map((g) => list.len(g))` counts in one pass without building the groups.
- **8-byte-wide copies on wasm** for list and string buffers (#4612).

## Known in this release

- The certified render does not yet carry foreign record, variant, RawPtr and Region representations. Those five documented rows build through the earlier render (#4641).
- Two gaps in what the ownership certificate covers are open as #4631 and #4632. No program was found that passes the checker and misbehaves.
- 1,387 render branches are not exercised by any perf benchmark (#4624). The gate's list was re-baselined to that set at this release and only shrinks from here. The remaining branches are untaken cases inside functions the corpus does run, not unreachable code.

## Gates and evidence

- The native verified floor is at 1058 of 1058 `spec/wasm_cross` programs (507 of 1034 at v0.69.1).
- The extracted checker accepts every witness on the fixtures and stdlib-test legs of the trust-spine job.
- Each fix above carries a test with a negative control. The fan probes ran 200 times each on 1 and 2 CPUs with no divergence.
- Size baselines: 13 extended fixtures' rows follow their new text (the compiler's output for the old text is byte-identical to the old pins); `fs_glob_segments` rises 22 B and `fan_deterministic` 12 B for the two leak fixes; `effect_unwrap_in_loop` +228 B, `licm_mut_param_named_call` +8 B and `guard_value_exit_in_loop` +4 B for the loop-body releases of #4648. The string-churn work raises 58 wasm rows by 27,471 B emitted in total (31 to 1,233 B each), with allocation counts and bytes equal or lower on every row.
- Contracts C-004, C-196 and C-219 were amended in the judge repository first; the pin is at its `7a193ac`.
- Five commits that mixed implementation with a verification artifact are closed by reviewed records in `proofs/ratchet-dispositions.txt`.
- The map and set remove scaling gates time the n and 4n collections in alternating chunks of one run, so a loaded runner slows both alike (#4644).

## Dependencies

Two new crates in the lockfile: `blake3` (cached artifact digests are recorded as BLAKE3) and its dependency `constant_time_eq`. The compiler also depends on `ring` 0.17 directly; it was already present through the native HTTPS client. The wasm-tools crates move to 0.263 (`wasm-encoder`, `wasmparser`, `wit-component`, `wat`), with `toml` 1.2.0, `unicode-script` 0.5.9 and `unicode-security` 0.1.3.
