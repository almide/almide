# v0.70.0-rc1 — `fan` behaves the same on every native route, and every cross-target fixture renders on the certified native path

**Release candidate 1** (#1484): published as a prerelease for the soak window and excluded from "latest". v0.69.1 stays the current stable until the v0.70.0 final, which is tagged once the soak is clean and the open `regression` issue #4640 is settled.

v0.70.0 fixes the cross-target divergences found in `fan`, and moves native `almide build`, `run` and `test` onto the certified render for every program in the cross-target corpus. No language surface changes: the public stdlib interface is identical to v0.69.1.

## Correctness: `fan`

- **Arms that are direct calls of user fns run `@ordered` fs work in arm order on native** (issue #4615). The certified native render lifted such arms onto threads and let their fs writes interleave. Contract C-004 now names this route, with `spec/wasm_cross/fan_ordered_direct_call_arms.almd`.
- **`io.eprint` and `io.write(io.stderr(), …)` inside an arm follow the arm's output order** (issue #4616), as `eprintln` and the stdout writes already did (`spec/wasm_cross/fan_arm_stderr_timeline.almd`).
- **A fan arm, a line-fold worker and a parallel `fan.map` worker get the main thread's stack size**, at most 1 GiB (issue #4617). They had Rust's 2 MiB spawned-thread default, so a recursion depth the sequential run reached overflowed under `fan` on two or more CPUs, and the exit code depended on the core count. Contract C-196 is amended.
- **A fan gate helper no longer holds a protected borrow across the caller's free** (issue #4452). This was undefined behaviour under Miri; no wrong output was observed.

## Correctness: native

- **An `effect fn` declared to return a Result whose whole body is `process.exit(c)` builds on native** (issue #4619). It was refused with a Rust type error while wasm ran it. Contract C-219 is amended (`spec/wasm_cross/never_tail_of_result_effect_fn.almd`).
- **`list.flat_map` over a Float list with a list-literal callback builds** (for example `list.flat_map([1.5, 2.5], (f) => [f, f * 2.0])`). The certified render emitted Rust that did not type-check.
- **Native `almide test` builds packages that carry native code again** (issue #4640). The test lane now uses the certified render only, and it refused a dependency's `@extern(rust)` fn, did not emit the module fns that `native/*.rs` links against, and refused a `todo(…)` body and an unreached `@extern(wasm, …)` declaration. A linked native callback with String, List, Option, Result, tuple, record, variant or `mut` parameters is adapted to the signature the earlier render emits for it. Still refused by the test lane: a callback with a function-typed parameter.
- **A `!` inside a branch-statement arm or a bare block statement propagates on the certified render** (issue #4651). On the development branch after v0.69.1 the certified render accepted these functions and the program ran on past the failing call with exit 0; no tagged release carried it. A generated sweep of 2,100 programs now agrees with wasm on every program the certified render accepts (`tests/v1_branch_arm_propagation_test.rs`).
- **A record literal inside a tuple builds on native** when a declared record type has the same shape. The certified render emitted two Rust types for one value.
- **Scalar `@export(c)` signatures build on the certified render**; every other row is still built by the earlier render.
- **More shapes render on the certified path instead of falling back**: `fan.map` outside the scalar matrix and with a propagating callback, a function that recurses in both tail and non-tail position over heap values, a propagation inside a loop under a branch statement, a destructuring unwrap in a loop body, an unwrap in a record field or a `for` head, a fold whose callback is one constructor, and a variant field holding a list of tuples or records.
- **`list.get(xs, i) ?? "literal"` reads through a borrow on native** when the element is only inspected, and shares the element's handle when it escapes.
- **`almide build` holds the shared build directory's lock from the cache check through the copy-out** (issue #4269). The reported race did not reproduce, so the issue stays open for the reporter to confirm.

## Correctness: wasm

Three leaks on the wasm leg are closed. Output and exit code were already identical to native; the blocks were left live at exit.

- **A `!` in a later operand of a call or map literal releases the operands before it** (issue #4639). Present since v0.69.0.
- **A failing `fan { }` block inside `ok(…)`, `some(…)` or a list, tuple, record or map literal leaves no block behind** (issue #4642). A fan block nested as another fan's arm is this shape.
- **A position read of a fan block, `(fan { a(), b() }).0`, releases the tuple.**

## Performance

- **A wasm build of a module-level table of records is linear in its row count** (issue #4614): a 1,600-row table builds in 0.08 s, down from 4.4 s. The witness bundles are byte-identical on every corpus program.
- **Reading the head of a list does not copy the element on native.** `list.get(xs, 0) ?? d`, `list.first` and `match list.first(xs)` on a list parameter read through a borrow; at 160,000 elements the head-read probe went from 1.20 s to under 0.01 s.
- **`acc = step(acc)!` in a loop does not clone the accumulator each round on native.** A path that ends the process no longer keeps the value live.
- **A recursive rebuild of a variant moves the untouched subtree on native** instead of copying it: the tree-insert probe makes 3,467 allocations, down from 40,403.
- **`m[k] = (map.get(m, k) ?? d) + 1` is one probe on native**, and `list.group_by(xs, f) |> map.map((g) => list.len(g))` counts in one pass without building the groups. Both hold on the certified render as they did on the earlier one.
- **8-byte-wide copies on wasm** for list and string buffers (#4612).

## Known in this candidate

- The nightly comparison of the certified native render against the earlier one is red: nine whole-program rows are slower, the worst 1.32×, tracked in #4633–#4637, and the count of render branches no benchmark exercises is above its baseline (#4624). No baseline was raised for either.
- The certified render does not yet carry foreign record, variant, RawPtr and Region representations. Those five documented rows build through the earlier render (#4641).
- Three gaps in what the ownership certificate covers are filed as #4630, #4631 and #4632. No program was found that passes the checker and misbehaves.

## Gates and evidence

- The native verified floor is at 1055 of 1055 `spec/wasm_cross` programs (507 of 1034 at v0.69.1).
- The extracted checker accepts every witness on the fixtures and stdlib-test legs of the trust-spine job.
- Each fix above carries a test with a negative control. The fan probes ran 200 times each on 1 and 2 CPUs with no divergence.
- Size baselines: 13 extended fixtures' rows follow their new text (the compiler's output for the old text is byte-identical to the old pins); `fs_glob_segments` rises 22 B and `fan_deterministic` 12 B for the two leak fixes. No other row rose.
- Contracts C-004, C-196 and C-219 were amended in the judge repository first; the pin is at its `7a193ac`.
- Five commits that mixed implementation with a verification artifact are closed by reviewed records in `proofs/ratchet-dispositions.txt`.
- Two wall-clock scaling tests can fail on a loaded runner and pass on re-run (#4644).

## Dependencies

No new crate in the lockfile. The compiler now depends on `ring` 0.17 directly for native artifact SHA-256; it was already present through the native HTTPS client.
