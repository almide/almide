# v0.68.0-rc2 — the soak fixes: argument rebinding, fan String capture, and a linear check on self-referencing variants

**Release candidate 2** (#1484): published as a prerelease for the soak window, excluded from "latest". rc1's notes still describe the epoch-14 surface this release ships; everything below landed after rc1 was cut. It is mostly soak fixes: argument rebinding on both targets, a `fan` arm capturing a String parameter, a check that went exponential on self-referencing variants, and the fixes from the stdlib inspection's final re-run. Release blockers are 0. The public stdlib interface diff against v0.67.1 is unchanged from rc1: breaking, with 34 removed and 2 added, and every removal is declared in epoch 14 of `proofs/dialect-epochs.toml`.

## Correctness

- **An argument that rebinds a variable an earlier argument reads is ordered correctly on both targets** (#3823, #3844; #3815, #3835, C-258). `st |> set.fold({ st = set.from_list([0]); 0 }, f)` failed with rustc E0506 on native, as did `list.contains`, `set.contains`, `map.get`, `string.contains`, `fs.fold_lines` and user fns with a borrowed param in the same shape. On wasm, the earlier read was a view that the later argument freed. Earlier arguments are now bound in source order before the rebinding one.
- **A `fan` arm capturing a String parameter compiles on native** (#3844; #3819, C-004). It used to emit a std `String` into an `AlmideString` binding (rustc E0308). A fixture covers String, List, Map, record, variant, Option, Bytes and `let` captures.
- **Calls are resolved by definition rather than spelling** (#3844; #3825, #3831, #3832, new contract C-388). The interpreter resolves named calls, tail calls and the fuel meter's user fns by identity, and wasm's small-scalar-fn inliner resolves each call in its own module first, so two functions with the same name in different modules are no longer confused.
- **A list still borrowed by an `if` selection is no longer moved into an owned-twin call** (#3872; #3870), a native build failure (rustc E0505) that the inspection re-run turned up. A test covers every list op that has an owned twin.
- **Every stdlib function that manufactures a NaN returns the fixed +qNaN on every leg** (#3872; #3846), so `list.min` / `list.max` over Float agree between native and wasm.
- **The http client and server retry a read that a signal interrupted** (#3872; #3857).
- **`fan.bounded`, `fan.timeout` and `fan.min` meter the arguments of a single-call body** (#3822, C-204, C-205). In `fan.bounded(…) { id(heavy(1000)) }` the argument `heavy(1000)` ran before the budget was entered and was charged nothing; a non-atomic argument is now evaluated inside the metered region, identically on every leg.

## Performance

- **Checking no longer goes exponential on a self-referencing variant** (#3821; #3818). The expected-effect search followed every named type eight levels deep without remembering where it had been. `almide build --release` of a 15-grammar parser ran for more than 30 minutes before it was killed; it now takes 26.7 s, against 32 s on v0.67.1.
- **Native `Value` programs no longer run slower than their wasm build** (#3826; #2157). `value.array`, `value.object` and `value.as_array` move a dying source instead of deep-copying it (declared `@reuse`), `value.stringify` writes into one buffer, and `json.parse` builds escape-free strings straight from the input. A 50,000-record JSON round trip went from 1.26× the wasm time to 0.69×, and a new gate holds `jsonround`, `wordfreq` and `wordfreq-group` at native ≤ wasm.
- **Release builds keep in-order float reductions scalar** (#3824). On aarch64 the loop vectorizer vectorized strict `Float` sums badly, so `--release` ran slower than the default profile on spectralnorm; it now passes `-force-ordered-reductions=false` (a no-op on x86). A range literal heading a fold (`list.fold(0..<n, …)`) is no longer built as a list on either leg (#3810).
- **The cold native build is 17% faster**: the runtime rlib compiles with 4 codegen units and no local ThinLTO pass, and a same-runner A/B against the latest release now gates the cold build (#3844; #3829).
- **The canonical allocator releases a block above its ceiling in O(1)** (#3872; #3849), and **`zlib.crc32` is table-driven**, so its wasm leg is no longer 3–10× slower than native (#3872; #3848).

## Docs

- **The README is rewritten and slimmed** (#3813, #3820). It names programs written in Almide, claims only what the compiler can back, is brought up to the 0.68.0 surface, and gains Japanese and Simplified Chinese translations. It went from 312 lines to 114; the measured sections move to new pages (`docs/benchmarks/`, `docs/how-it-works.md`, `docs/status.md`, `docs/written-in-almide.md`), with every generated block still gated on its new page.

## Gates and evidence

- The stdlib inspection folds each function's wasm emitter arm into its fingerprint, and the counted judge bounds k by its longest run; every changed row was re-inspected, and the ledger stands at 0 uninspected (#3872; #3796, #3859).
- The wasm-runtime and build-speed ledgers are re-stamped on a re-creatable cloud machine class, and their verdicts check that class before judging (#3828).
- A corpus fixture cut by the per-fixture limit now stops its interpreter run instead of leaving the thread running (#3817; #3809), and the test for it no longer flakes on a loaded runner (#3844).
- Both `wordfreq` perf rows move from 4M to 8M words, so the now-faster native Map path stays above the timing floor (#3844), and the ratchet-separation negative controls no longer fail on their own cleanup (#3833).
