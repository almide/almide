# v0.70.0-rc3 — every stdlib function is inspected, and a failing guard let returns from the fn in every position

**Release candidate 3** (#1484): published as a prerelease for the soak window, excluded from "latest". v0.69.1 stays the current stable. After rc2, every stdlib function was inspected on native and wasm, and this candidate ships the fixes that inspection found. The public stdlib interface is identical to v0.69.1.

## Language

- **A failing `guard let` returns from the fn in every expression position** (issue #4678, contract C-266). Before, it returned only when its block was a `let`/`var`/assignment value, a statement or a tail `if` arm. In an arm of a bound value, an `if` condition, a call argument, an operand or a list element, the `else` value became the block's value and the fn carried on. Native, `--target rust`, wasm and the reference interpreter now all leave the fn; a lambda body still returns from the lambda.

## Stdlib inspection

- **Every stdlib function carries an inspection stamp.** The 93 rows held at rc2 are now 0. Each row is checked for the same result on native and wasm, a measured complexity that fits its declared class within 3%, no leak, and diamond-free imports. The fixes below come from that inspection (#4800).
- **Linear where they were quadratic.** These were quadratic before, on one leg or both, and are now linear, or O(1) per call where that applies:
  - `string.pop`, `bytes.pop` and `bytes.drop_end`/`string.drop_end` on a sole owner (issues #4756, #4761);
  - `bytes`/`string` `min_by` and `max_by` (#4755);
  - `int.parse_radix` (#4765);
  - `heap.push`/`heap.filter` (#4777);
  - deque `drop`/`take` and their `_end` forms (#4773), and wasm `deque.pop` (#4778);
  - `matrix.concat_rows`, `zip_with` and `to_bytes_f16_le` (#4770, #4775, #4786);
  - wasm `regex.replace` (#4779);
  - wasm `list.join` over `List[Bytes]` (#4785);
  - bigint division by a one-limb divisor (#4783);
  - native `bytes.fold` over a String accumulator (#4762).
- **wasm `value.get` and the `value.get_*` readers are O(1)** on objects of 16 or more pairs, through a key index (issue #4757).
- **Fetched response header names are lowercase on both native and wasm** (issue #4766, contract C-455), and the transport-managed fields are left out on both.
- **`env.get` and `env.vars` see the same environment on native and wasm** under `almide run` (issue #4774).
- **wasm `http.serve` frees everything it holds after a SIGTERM** (issue #4769).
- **`deque.unique`, `dedup`, `group_by` and the other equality wrappers declare `[A: Eq]`** (issue #4796). Check now refuses an element type with no equality (E016) instead of letting both legs fail to build.

## Correctness: native

- **A self tail call no longer copies a `@consume` accumulator on every step** (issue #4789). This was a regression in rc1 and rc2.
- **`Set[Bool]` and `Set[Float]` work on the certified native render**, including in `set.any`/`set.all` callbacks (issues #4795, #4797).
- **Fixed rustc errors in programs that pass check:**
  - ordering a captured `var` String against a literal (#4780);
  - a fallible `list.map` whose callback bangs a rebuilt Result (#4784);
  - a handler lambda passed through `Result[Secret[HttpHandler]]` (#4768).
- **The native test report keeps a nested abort's `at:` line** (issue #4798).

## Known in this candidate

- **Native `almide test` still refuses two shapes that v0.69.1 accepted** (issue #4749). They are a record `var` rebuilt in a loop and then in nested branches, and a closure that wraps a module-level String in `some`. Both run on wasm. They are fixed before the final.
- **Further correctness issues are being fixed before the final.** They include #4788 (`set.sort` over `Set[BigInt]` on native), #4751, #4598, #4285 and the Miri finding #4452.

## Gates and evidence

- Stdlib inspection: the uninspected ceiling is 0. The wasm size, size ladder and alloc ledger rows moved only where each fix needed it.
- The als pin advances to cover C-455 and C-266. Trust Spine passed on the merged tree.
