# v0.69.1 — `??` joins one precedence order, guard let names the error, and v0.69.0's regressions are fixed

v0.69.1 opens dialect epoch 16: `??` takes its place in one precedence order for every binary operator, and a program written for the old grouping is refused with E120 until `almide fix` migrates it. It also adds three guard let forms, reorganizes the `almide` commands (a breaking change for scripts, see the CLI section), and fixes the regressions found after v0.69.0 shipped. Each regression was found by the release-gate differential fuzz on the v0.69.0 tag or by downstream projects, and was checked against the released v0.67.1 and v0.69.0 binaries on CI. The stdlib interface is identical to v0.69.0.

## Language surface: one precedence order (dialect epoch 16)

- **`??` is an infix operator with its own precedence level** (#4549, issue #4531). It was a postfix that bound tighter than the arithmetic. It is now right-associative, below `|>`, the ranges and the arithmetic, and above the comparisons, `and` and `or`. Every other binary operator keeps its place, the right side of `|>` is still one stage, and `>>` is still the top binary level. What reads differently:
  - `x ?? 0 - 1` is `x ?? (0 - 1)`; it was `(x ?? 0) - 1`. The same holds for `*`, `/`, `%`, `^`, `**`, `>>` and the ranges.
  - `-x ?? 0` is `(-x) ?? 0` and `not p ?? false` is `(not p) ?? false`.
  - `xs |> f ?? d |> g` is `(xs |> f) ?? (d |> g)`. `xs |> f(a) ?? d` keeps its meaning.
- **E120: a program written for the old grouping is refused, not reinterpreted.** A file that is not stamped `@dialect(16)` or later and has a `??` whose operands group differently under the two orders gets E120 at each such site. The program never compiles silently with a new meaning.
- **`almide fix` migrates the file.** It adds the parentheses that keep each site's old meaning (`x ?? 0 - 1` → `(x ?? 0) - 1`), splices them into the source so the rest of the layout stays, and keeps the result only when the new grammar reads it as the same program the old grammar did. A site it cannot prove is reported and left alone, with E120 still standing. Run `almide fix <file>` once per file before moving to v0.69.1.
- **The two deprecation windows opened at epoch 15 now close at epoch 17.** `regex.full_match` and the second numeric rename wave (`int.pop_count`, `int.bit_width`, `float.sign`) stay accepted with E052 through epoch 16.

## Language surface: guard let

- **The failure arm names the error** (#4546, issue #4543). `guard let x = r else err(e) => E` binds `e` with the Result's error type, in scope only in `E`. On an Option the arm is `else none => E`, the same as `else E`. A guard has one failure arm; to split errors into cases, write a `match`. `else err("…")` without `=>` is still the else value.
- **`guard let x else E` is short for `guard let x = x else E`.** `x` is a local or parameter that holds an Option or a Result, and it is rebound to the payload.
- **`guard var` makes the binding a `var`** for the rest of the block. The three forms combine.
- No existing program changes meaning, so these forms need no epoch. The refused shapes (a nested failure pattern, a second arm, a field-path shorthand, the wrong arm for the type) each have a diagnostic that says what to write instead.

## CLI: one verb per job (breaking)

The `almide` command set is reorganized (#4592, issue #4590): daily work is flat, rare work sits under a group noun, and internal tools are hidden. **This is a breaking change for scripts and agents.** There are no aliases: each old spelling exits 2 with `error: `<old>` was removed (#4590); use `<new>``, so a script fails loudly instead of doing something else.

| Was | Now |
|---|---|
| `almide check --explain <code>` | `almide explain <code>` |
| `almide dep-path <name>` | `almide deps --path <name>` |
| `almide survive <file> --with …` | `almide apply <file> --with … --dry-run` (same report, same exit codes 0/1/2) |
| `almide ide outline` / `ide doc` / `ide stdlib-snapshot` | `almide query outline` / `query doc` / `query stdlib` |
| `almide compile [mod] --json` / `--dry-run` | `almide query interface [mod] [--json]` |
| `almide self-update` | `almide upgrade` |
| `almide install <repo>` | `almide tool install <repo>` |
| bare `almide` (started the REPL) | prints the grouped help and exits 0; never reads stdin. The REPL is `almide repl` |

- **New commands.** `almide remove <name>` is the twin of `almide add`: it removes the dependency from the manifest and the lock. `almide repl` is the REPL; with no terminal on stdin it prints no banner and no prompt.
- **One `--json` envelope.** Every command that prints a report takes `--json` and prints one line, `{"schema_version":1,"ok":<bool>,"diagnostics":[…],"result":…}`. `ok` is true exactly when the exit code is 0, and exit codes are unchanged. `diagnostics` rows have the shape of `check --json`'s rows; a failure without a structured diagnostic, and a usage error, carry their text as one row. `result` keeps each command's old `--json` fields.
- `--help` is grouped into Daily, Dependencies, Agents and Toolchain. `emit`, `switches`, `docs-gen`, `budgets` and `compile` (the `.almdi` writer) still work but are hidden from it.

## Native builds

- **A program that declares a `Map`, `Set` or `Value` it never operates on builds natively again.** v0.69.0's certified native render wrote the runtime type's alias into the program but left the type's definition out of the runtime crate, so rustc failed with "cannot find type `AlmideMap`" (or `AlmideValue`). `option.unwrap_or` over a `List[Float]` hit the same error through a second fault: the render read the signatures of every function in a linked stdlib source, used or not. v0.67.1 built these programs (#4516, issue #4514).
- **`map.merge(m, m)`, the same map passed twice, builds natively again.** The render moved the map into the owned-merge routine at the first argument and borrowed it at the second, which rustc rejects. A value the same call reads more than once is now borrowed at every position. The other two-operand calls (set operations, list and string `+`, `bytes.xor`) were already right and are now pinned by tests (#4526, issue #4517).
- **A dependency package's `[native-deps]` reach the generated `Cargo.toml` again.** The manifest was written after the dependency crates had been added to it on disk, so they were dropped, and every app depending on a package with native code failed with E0433. The manifest now has one writer (#4523, issue #4521).

## Correctness

- **wasm no longer returns an empty list for a range whose element count overflows `Int`.** `list.len(0...9223372036854775807)` printed `0` on wasm while native failed with out of memory. A range whose count can't be represented now fails with out of memory on every target and render. A fold that only counts walks the exact count, so `list.range(MIN, 2^31) |> list.fold(0, (a, _) => a + 1)` gives Int's wrapping answer again on native, where v0.69.0 printed `0` (#4540, issue #4538).

## Packages

- **Deleting `almide.lock` resolves a branch dependency against the remote again.** Before, the cached checkout was reused, and the old commit was locked again until `almide update` ran. Offline, the cached commit is used with a warning that names it, and it is not locked (#4544, issue #4527).
- **Parallel fetches of the same dependency no longer fail.** One clone runs under a per-entry lock, and the other callers wait for it (#4544, issue #4529).
- **A dependency pointing at a tag that doesn't exist** now names the dependency, the chain that requires it, and the newest tags that do exist. `almide add` checks the tag before writing anything (#4544, issue #4528).
- **A file that imports only `self.<submodule>` of its own package no longer hangs.** The package root wasn't loaded, so the submodule's `import self` named the submodule itself, and its forwarders compiled to infinite loops. A bare `import self` now loads the root, or reports that it is missing (#4552, issue #4551).

## Checker

- **E109 no longer blames a stdlib function for an unrelated effectful closure.** With `heap` anywhere in the program, an effectful closure stored in a record made `almide check` report that `heap.__before` runs an effect function. The value-flow analysis matched untracked function values by argument count; it now matches them by type. Programs that really run an effectful closure from a pure function still get E109 (#4524, issue #4522).

## Tooling

- **A bare `almide test` inside a project runs the tests in every directory, `src/` included.** Before, a project with `spec/` or `exercises/` ran only those, and its `src/` tests were skipped without a word. The walk skips dot directories, `target/`, `node_modules/` and any directory holding an `.almideignore` file. Every leg (`--target rust`, `--target wasm`, `--json`) now finds the same files. Tests that never ran before may now fail; those failures were already there (#4532, issue #4530).

## More fixes

- **wasm wraps a pure function value in `ok` on every route into an effect slot** (#4576, issue #4545). A pure `fn` passed where an effect function is expected, through a parameter, a `let`-bound lambda, a named function or a block whose tail is `Unit`, was handed over without the `ok` wrap on some routes, so the wasm build failed where native ran. Every route now wraps it.
- **`almide fix` applies an epoch rename only when the new function keeps the old one's type** (#4572, issue #4525). A rename whose target takes or returns a different type is reported for a hand edit instead of rewritten, so the fix never turns a compiling program into one that doesn't.
- **wasm no longer copies a `mut` Bytes parameter on every helper call** (#4581, issue #4580). A helper whose last write was a tail call into a stdlib `mut` routine shared its buffer into that call, so the callee's copy-on-write copied the whole buffer once per call. The dying parameter now moves into the tail call. The perf ratchet's MUT PARAM relation holds it on both legs.

## Certificates

- **More programs build on the certified native render** (#4006, C1). A module-level `var` or eager `let` holding a heap value now lives in a thread-local cell on that render, read in place where nothing in between can see the slot, and a borrow-only read of it takes an `Rc` snapshot instead of a copy, matching the standard codegen's fix for a module-level map read on every call (#4564, issue #4562). A combinator call whose linked self-hosted body the render refuses is served by the runtime body its declaration names. The certified render also keeps a key built before a loop alive until the loop ends; it had released it after the first read inside the loop.
- **wasm heap accesses in the self-hosted stdlib carry linear bounds certificates** (#4005, A4). The `prim` loads and stores of 303 self-hosted bodies are certified in bounds by checked contracts plus linear facts, judged by the extracted checker, the Rocq kernel and almide-verify. The UTF-8 producer ledger names every function that hands out a `String` and the evidence that it stays valid UTF-8, with its own gate.

## Performance and size (#4550)

- A small predicate over a read-only `Bytes` parameter is inlined on the wasm leg, so the typed byte IO wrappers no longer call `bytes.fits` with a reference-count round trip on every write.
- A recursive type's deep-drop queue push and drain are shared module helpers, and a shallow drop skips the drain call.
- A `mut` Map or Set parameter rebound by a reuse op moves into the op's owned twin on the standard native codegen (MUT SET and MUT MAP relations).
- A `Bytes` global's `Rc` moves into a stdlib `mut`-parameter call, so the take allocates nothing (#4563).

## Gates and evidence

- Every fix carries a negative control on CI: with the fix reverted and its tests kept, the new tests fail.
- The native verified floor is at 507 of 1034 spec/wasm_cross programs (484 of 1017 at v0.69.0).
- The edit-loop scale gate is anchored per runner CPU class. One baseline for every class made it fail on the faster runners (#4537).
- The stdlib purity gate no longer misreads a classified module when `echo | grep -q` takes SIGPIPE under `pipefail` (#4512).
- `tests/precedence_regroup_corpus_test.rs` keeps every tracked `.almd` free of E120 sites, and pins that the old-meaning program is E120 while its migrated text prints the old answers on native and on wasm.
- The guard-let forms run byte-identically on native and wasm under C-266 (`spec/wasm_cross/guard_let_forms.almd`, `guard_let_forms_typed_err.almd`).
- `proofs/dialect-epochs.toml` has epoch 16, `one-precedence-order`, with four `breaks` rows.
