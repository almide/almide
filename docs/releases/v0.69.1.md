# v0.69.1 — native builds that v0.69.0 broke work again, and a bare almide test runs every test in the project

A patch release for v0.69.0. It fixes the regressions found after v0.69.0 shipped. Each one was found by the release-gate differential fuzz on the v0.69.0 tag or by downstream projects, and was checked against the released v0.67.1 and v0.69.0 binaries on CI. There are no language-surface changes. The stdlib interface is identical to v0.69.0.

## Native builds

- **A program that declares a `Map`, `Set` or `Value` it never operates on builds natively again.** v0.69.0's certified native render wrote the runtime type's alias into the program but left the type's definition out of the runtime crate, so rustc failed with "cannot find type `AlmideMap`" (or `AlmideValue`). `option.unwrap_or` over a `List[Float]` hit the same error through a second fault: the render read the signatures of every function in a linked stdlib source, used or not. v0.67.1 built these programs (#4516, issue #4514).
- **`map.merge(m, m)`, the same map passed twice, builds natively again.** The render moved the map into the owned-merge routine at the first argument and borrowed it at the second, which rustc rejects. A value the same call reads more than once is now borrowed at every position. The other two-operand calls (set operations, list and string `+`, `bytes.xor`) were already right and are now pinned by tests (#4526, issue #4517).
- **A dependency package's `[native-deps]` reach the generated `Cargo.toml` again.** The manifest was written after the dependency crates had been added to it on disk, so they were dropped, and every app depending on a package with native code failed with E0433. The manifest now has one writer (#4523, issue #4521).

## Correctness

- **wasm no longer returns an empty list for a range whose element count overflows `Int`.** `list.len(0...9223372036854775807)` printed `0` on wasm while native failed with out of memory. A range whose count can't be represented now fails with out of memory on every target and render. A fold that only counts walks the exact count, so `list.range(MIN, 2^31) |> list.fold(0, (a, _) => a + 1)` gives Int's wrapping answer again on native, where v0.69.0 printed `0` (#4540, issue #4538).

## Packages

- **Deleting `almide.lock` resolves a branch dependency against the remote again.** Before, the cached checkout was reused, and the old commit was locked again until `almide update` ran. Offline, the cached commit is used with a warning that names it, and it is not locked (#4544, issue #4527).
- **Parallel fetches of the same dependency no longer fail.** One clone runs under a per-entry lock, and the other callers wait for it (#4544, issue #4529).
- **A dependency pointing at a tag that doesn't exist** now names the dependency, the chain that requires it, and the newest tags that do exist. `almide add` checks the tag before writing anything (#4544, issue #4528).
- **A file that imports only `self.<submodule>` of its own package no longer hangs.** The package root wasn't loaded, so the submodule's `import self` named the submodule itself, and its forwarders compiled to infinite loops. A bare `import self` now loads the root, or reports that it is missing (#4552, issue #4551).

## Checker

- **E109 no longer blames a stdlib function for an unrelated effectful closure.** With `heap` anywhere in the program, an effectful closure stored in a record made `almide check` report that `heap.__before` runs an effect function. The value-flow analysis matched untracked function values by argument count; it now matches them by type. Programs that really run an effectful closure from a pure function still get E109 (#4524, issue #4522).

## Tooling

- **A bare `almide test` inside a project runs the tests in every directory, `src/` included.** Before, a project with `spec/` or `exercises/` ran only those, and its `src/` tests were skipped without a word. The walk skips dot directories, `target/`, `node_modules/` and any directory holding an `.almideignore` file. Every leg (`--target rust`, `--target wasm`, `--json`) now finds the same files. Tests that never ran before may now fail; those failures were already there (#4532, issue #4530).

## Gates and evidence

- Every fix carries a negative control on CI: with the fix reverted and its tests kept, the new tests fail.
- Native renders of the existing spec/wasm_cross corpus are byte-identical, except for six matrix renders that each lose one dead type alias. The native verified floor is at 494 of 1027 (484 of 1017 at v0.69.0).
- The edit-loop scale gate is anchored per runner CPU class. One baseline for every class made it fail on the faster runners (#4537).
- The stdlib purity gate no longer misreads a classified module when `echo | grep -q` takes SIGPIPE under `pipefail` (#4512).
