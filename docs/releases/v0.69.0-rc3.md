# v0.69.0-rc3 — C exports pass Int as int64_t, and http programs on wasm build as a WASI 0.3 component

**Release candidate 3** (#1484): published as a prerelease for the soak window and excluded from "latest". It follows [v0.69.0-rc2](./v0.69.0-rc2.md). Everything below landed after rc2. It adds one epoch-15 entry, for the C export ABI; the [v0.69.0-rc1](./v0.69.0-rc1.md) notes still describe the rest of the epoch-14 and epoch-15 surface. The final v0.69.0 is tagged once the soak is clean.

## Behaviour changes

- **`@export(c)` passes `Int` as `int64_t`** (#4447, C-452, dialect epoch 15). It used to cross as a 32-bit integer, so `5000000000` came back truncated. Every parameter and return now follows one C ABI table, so a `Float`, `Int64`, `UInt64`, `Float32` or `Float64` return keeps its type. Re-declare the C side with `int64_t` where it said `int32_t`.
- **E090: an `@export(c)` type with no C form is refused at check time** (#4448). A `String` parameter used to become a Rust `String` in an `extern "C"` function, and an effect fn that returned `Unit` or `String` failed in rustc. The hint points at a `Region` for text. An effect err writes its message and exits 1.
- **A wasm `@export` effect fn that returns `Int`, `Float`, `Bool` or `Unit` returns the value itself** (#4376, C-451). It used to return the address of a Result block. An err writes the message and traps, and the `--host js` glue reads the result as a plain value.
- **http client programs on `--target wasm` build as a WASI 0.3 component.** Run them with `wasmtime run -S http`; the build says so. The http call handle (`http.start`, `poll`, `read_new`, `wait` and `cancel`) now runs on that component, where it was E081. The guest enforces `total_ms` and `idle_ms`, and `cancel` or dropping the last handle abandons the exchange (C-004, C-366).
- **Host text that is not UTF-8 is decoded lossily** (#4391, C-449, C-450). Each bad byte becomes U+FFFD:
  - `env.args` decodes such an argument lossily, where the native binary used to panic.
  - `env.get` answers `none` for a value that is not UTF-8, and `env.vars` leaves it out.
  - `fs.list_dir`, `walk` and `glob` list such a name as its lossy decode.
  - The same holds on native, `almide run`, `almide run --target wasm` and a stock preview-1 host.

## Security

- **wasm size arithmetic never wraps** (#4396). An allocation length near 4 GiB, a capacity doubling past 2^31 and a length sum past 2^32 used to wrap to a small block that the caller then overran. They are now the defined out-of-memory abort (C-197).
- **CI:** the repository requires every GitHub Action to be pinned to a full commit SHA, and a probe with a tag pin is refused (security row 16).

## Correctness

- **A `guard … else continue` inside an `if` arm in a loop ends that iteration on native** (#4386). The statements after the `if` used to run anyway, so v0.68.0-rc2 and v0.69.0-rc2 printed a wrong answer natively; wasm was right.
- **A self-recursive call whose argument is the same call builds on native** (#4443). `put(put(b, k), v)` failed rustc with E0716 because the tail-call lowering borrowed the inner call's temporary.
- **`==` on a stdlib type built with a module-qualified constructor checks** (#4383). `net.V4(..)` and `url.Url { .. }` are typed by the name `net.parse_ip` and the annotations use, so the comparison is no longer E037 and native, wasm and the interpreter agree.
- **`regex` accepts `\r` inside a character class**, as it already did outside one (#4420).
- **Every `matrix` producer builds uniform rows**, now pinned by a cross-target fixture (#4397, C-353).

## Performance

- **wasm `regex` calls are cheaper than in v0.68.0-rc2** (#4399). A `find_all` over a 64-byte line costs about 5,000 fuel where rc2 spent 92,000, a regex-heavy program runs in about a third of its rc2 time, and every regex module ships smaller.
- **wasm `regex.captures_all` and `replace_with` are linear in memory** (#4419). They ran out of memory on a few hundred KB of input; they now run at the sizes native handles (C-032).
- **wasm substring search keeps linear time without its per-call cost** (#4430). `string.contains`, `index_of` and `split_once` allocate their search table only when a partial match of two or more bytes fails, so a string/list loop runs at v0.67.1's cost again.

## Tooling

- **A native `almide test` run compiles its test files as one program** (#4441). Every module is checked, lowered and emitted once, the compiled program is cached by its inputs, and an edit rebuilds only the modules it reached. Each file still runs in its own process, with the same output, counts and exit codes.

## Gates and evidence

- The wasm `regex` per-call cost and the string/list loop cost are gated by wasmtime fuel against their v0.68.0-rc2 and v0.67.1 levels.
- The interpreter oracle runs the `regex` surface, so most regex fixtures vote three ways.
- The linearity tests for `bigint` text and the `value` JSON combinators time the child's own CPU time, so a busy runner no longer fails them (#4331, #4428).
- New contracts C-449 to C-452. C-004, C-328, C-330 and C-366 are amended.

## Dependencies

getrandom 0.4.3, rustix 1.1.6 and libc 0.2.191.
