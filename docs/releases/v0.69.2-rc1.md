# v0.69.2-rc1 — one precedence order for every binary operator, and guard let names the error

**Release candidate 1** (#1484): published as a prerelease for the soak window and excluded from "latest". It follows [v0.69.1](https://github.com/almide/almide/blob/develop/docs/releases/v0.69.1.md) and opens dialect epoch 16. The final v0.69.2 is tagged once the soak is clean.

## Language surface: one precedence order (dialect epoch 16)

- **`??` is an infix operator with its own precedence level** (#4549, issue #4531). It was a postfix that bound tighter than the arithmetic. It is now right-associative, below `|>`, the ranges and the arithmetic, and above the comparisons, `and` and `or`. Every other binary operator keeps its place, the right side of `|>` is still one stage, and `>>` is still the top binary level. What reads differently:
  - `x ?? 0 - 1` is `x ?? (0 - 1)`; it was `(x ?? 0) - 1`. The same holds for `*`, `/`, `%`, `^`, `**`, `>>` and the ranges.
  - `-x ?? 0` is `(-x) ?? 0` and `not p ?? false` is `(not p) ?? false`.
  - `xs |> f ?? d |> g` is `(xs |> f) ?? (d |> g)`. `xs |> f(a) ?? d` keeps its meaning.
- **E120: a program written for the old grouping is refused, not reinterpreted.** A file that is not stamped `@dialect(16)` or later and has a `??` whose operands group differently under the two orders gets E120 at each such site. The program never compiles silently with a new meaning.
- **`almide fix` migrates the file.** It adds the parentheses that keep each site's old meaning (`x ?? 0 - 1` → `(x ?? 0) - 1`), splices them into the source so the rest of the layout stays, and keeps the result only when the new grammar reads it as the same program the old grammar did. A site it cannot prove is reported and left alone, with E120 still standing. Run `almide fix <file>` once per file before moving to v0.69.2.
- **The two deprecation windows opened at epoch 15 now close at epoch 17.** `regex.full_match` and the second numeric rename wave (`int.pop_count`, `int.bit_width`, `float.sign`) stay accepted with E052 through epoch 16.

## Language surface: guard let

- **The failure arm names the error** (#4546, issue #4543). `guard let x = r else err(e) => E` binds `e` with the Result's error type, in scope only in `E`. On an Option the arm is `else none => E`, the same as `else E`. A guard has one failure arm; to split errors into cases, write a `match`. `else err("…")` without `=>` is still the else value.
- **`guard let x else E` is short for `guard let x = x else E`.** `x` is a local or parameter that holds an Option or a Result, and it is rebound to the payload.
- **`guard var` makes the binding a `var`** for the rest of the block. The three forms combine.
- No existing program changes meaning, so these forms need no epoch. The refused shapes (a nested failure pattern, a second arm, a field-path shorthand, the wrong arm for the type) each have a diagnostic that says what to write instead.
