# E100 — メモリ安全性の保証の外側

[English](../../../diagnostics/E100.md) | [日本語](./E100.md) | [简体中文](../../zh-CN/diagnostics/E100.md)

> 原文: [E100.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E100.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

Almide の値の外側のメモリを読み書きできる構文を、2つの場面で拒否します。

## `import ffi` がない場合（#4043）

生のメモリは Rust の `unsafe` のように明示的なオプトインです。外部コードも到達できるメモリに触れる標準ライブラリ関数は、`.almd` ソースで `@memory_unsafe` と宣言されています。すべての `ffi.*` 関数（`ffi.region`、`ffi.alloc`、`ffi.len`、`ffi.is_writable`、`ffi.read`、`ffi.write`、`ffi.to_bytes`）が該当します。標準ライブラリ外から呼び出すには、呼び出し側ファイルに `import ffi` が必要です。オプトインはファイル単位です。生メモリに触れるモジュールは、自分をインポートするファイルの記述によらず、自身で明示します。したがって、各ファイルに `import ffi` も `@extern` もないプログラムは、どのターゲットでもその値の外側のメモリに到達できません。`@memory_unsafe` 関数を持つのは `ffi` だけで、自動インポートもされないため、import のないファイルでは名前を書くことすらできません。呼び出しは E003（`undefined variable 'ffi'`）となり、ヒントは import です。E100 は、別の方法で `@memory_unsafe` 関数に到達した場合の拒否です。

すべての `ffi` アクセスは `Region` の長さに対して境界検査されます（[ADR-0031](../../../adr/0031-raw-pointers-carry-provenance.md)）。範囲外の `ffi.read` または `ffi.write` は `err` を返します。それでも import が必要なのは、`Region` が外部コードからも到達できるメモリを参照できるためです（`@extern(c)` fn に渡したバッファー、または `@region(len = …)` を付けた `@extern` が返したもの）。

```almide
effect fn main() -> Unit = {
  let small = bytes.from_list([1, 2, 3, 4])
  let copied = ffi.read(ffi.region(small), 0, 4)!   // ← E003: no `import ffi`
  println(int.to_string(bytes.len(copied)))
}
```

```
error[E003]: undefined variable 'ffi'
  hint: Add `import ffi` (stdlib: bounds-checked memory regions shared with foreign functions)
```

修正は、ファイル先頭の1行です。

```almide check
import ffi

effect fn main() -> Unit = {
  let small = bytes.from_list([1, 2, 3, 4])
  let copied = ffi.read(ffi.region(small), 0, 4)!
  println(int.to_string(bytes.len(copied)))
}
```

この規則が以前対象としていたアドレスをポインターとして扱う表記（`ffi.address`、`ffi.to_int`、`bytes.as_ptr`、`bytes.as_mut_ptr`、`bytes.data_ptr`、`bytes.from_raw_ptr`、`bytes.copy_to_ptr`）は廃止済みです（ADR-0031 D4、dialect epoch 15）。`Bytes` の読み取り専用ビューは `ffi.region(b)`、書き込み可能なバッファーは `ffi.alloc(n)!` です。読み書きは領域内のオフセット（`ffi.read(r, off, n)`、`ffi.write(r, off, b)`）を指定し、アドレスは指定しません。

## `--profile critical` の場合（#4008）

`almide check --profile critical` は Almide のメモリ安全性の保証内のコードだけを受け入れます。2つのものは範囲外であり、`import ffi` があってもそれぞれ E100 です。

- 任意の `ffi.*` 関数の呼び出し。`Region` は外部コードも到達するメモリを参照でき、外部領域の長さは束縛の申告（`@region(len = …)`）なので、境界検査付きの `ffi.read` でも拒否します。
- `@extern` fn の宣言。本体が外部コードだからです。

ケイパビリティ（E076）と異なり、どの `--allow` 許可でもこれらは受け入れません。プロファイルなしなら同じプログラム（`import ffi` を伴う）は以前どおり検査に通ります。critical は言語の部分集合であり、dialect ではありません。

```almide
import ffi

effect fn main() -> Unit = {
  let b = bytes.from_string("abc")
  let c = ffi.read(ffi.region(b), 0, 3)!   // ← E100 under --profile critical
  println(int.to_string(bytes.len(c)))
}
```

```
error[E100]: `ffi.region` is outside the memory-safety guarantee and is not admissible under `--profile critical`
  hint: the critical profile admits only code inside the memory-safety guarantee — keep raw-address and foreign code in a module that is not checked with `--profile critical`
```

## 修正

1. 領域で代用していた安全な操作を使います。`bytes.slice`、`bytes.copy_from`、`bytes.get`、型付き読み取り関数は、すべてのアクセスをバッファー長で制限し、import を必要としません。
2. 本当に外部コードとやり取りするプログラムなら、そのファイルに `import ffi` を書き、そのファイルを独立したモジュールにし、残りのプログラムを `--profile critical` で検査します。

## 理由

ADR-0031 以前、検査しない長さでの生メモリ読み取りは、通常の Almide コードがメモリを破損できる唯一の方法でした。3バイトのバッファーのアドレスから100万バイト読むと、その後ろにあるものを何でもコピーしていました。現在の `Region` は長さを保持するため、`ffi` 自体は代わりに `err` を返します。保証外に残るのは、`Region` が外部コードと共有するメモリです。`import ffi` 行は、それに触れるファイルを読み手、レビュー担当者、モデルが最初に見る場所に示します。critical プロファイルは、プログラムが一切それに触れないという約束なので、触れられるすべての構文を拒否します。

## Fix-it 判定

**not-fixable**：代わりの操作は、その生アクセスの目的によります。診断は構文と不足する import またはプロファイルを示し、コードを書き換えません。

拒否される標準ライブラリ関数は `.almd` ソース（stdlib/ffi.almd）で `@memory_unsafe` と宣言されたものです。検査器は名前一覧ではなくその宣言を読みます。標準ライブラリ自身のソースは E085 と同じく import 規則の対象外です。

これは ALS §B（`@bounded`）の規則ではありません。`ffi` を呼ぶ `@bounded` fn は、宣言したケイパビリティの外のモジュールと同じく E076 です。フィクスチャ：`tests/diagnostics/e100-critical-*`（各 `meta.toml` が `check_profile = "critical"` を指定）、`tests/diagnostics/e003-no-import-ffi-region-*`（#4043 のプローブ）。行列検査：`tests/critical_profile_test.rs`（`memory_unsafe_surface_is_refused_under_critical`）、`tests/memory_unsafe_import_gate_test.rs`、`tests/raw_ptr_surface_test.rs`。
