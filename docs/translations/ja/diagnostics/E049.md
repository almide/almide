# E049 — `let ... in <expr>` は OCaml/Haskell の構文

[English](../../../diagnostics/E049.md) | [日本語](../../ja/diagnostics/E049.md) | [简体中文](../../zh-CN/diagnostics/E049.md)

> 原文：[`docs/diagnostics/E049.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E049.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

Almide に `in` キーワードはない。束縛はブロック内で改行によって連なり、ブロック末尾の式がその値となる。そのため OCaml、Haskell、F# が束縛と本体の間に置く `in` は、ここでは何も区切らない。

```almide
fn sum_digits(n: Int) -> Int =
  let abs_n = int.abs(n)
  in if abs_n == 0 then 0            // ← E049: `let ... in <expr>` is OCaml/Haskell syntax
     else (abs_n % 10) + sum_digits(abs_n / 10)
```

## 修正

`in` を削除する。その後に続くものは既に改行で連なる続きである。

```almide
fn sum_digits(n: Int) -> Int =
  let abs_n = int.abs(n)
  if abs_n == 0 then 0
  else (abs_n % 10) + sum_digits(abs_n / 10)
```

複数の束縛も同様に、一行に一つ、区切り記号なしで連なる。

```almide
fn area(w: Int, h: Int) -> Int = {
  let width = int.abs(w)
  let height = int.abs(h)
  width * height
}
```

## 診断の形

```
error[E049]: `let ... in <expr>` is OCaml/Haskell syntax
  in let ... in
  here: in if abs_n == 0 then 0
  hint: In Almide, multiple lets chain by newlines inside a block — no `in` keyword.
  try: delete the highlighted text (machine-applicable — `almide fix` applies it)
```

fix-it は **machine-applicable** で、`in` キーワードとその後の空白に位置を固定する。`almide fix <file>` はそれらをすべて機械的に削除し、他には触れない。この削除は純粋な記法変更であり、生成するプログラムは `in` 形式が表していたプログラムと同じである。

## Fix-it 判定

**mechanical** — `let x = e in b` → `{ let x = e; b }` は正確である。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
