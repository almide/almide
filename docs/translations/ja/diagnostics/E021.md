# E021 — 無効なレコードの構築またはパターン

[English](../../../diagnostics/E021.md) | [日本語](./E021.md) | [简体中文](../../zh-CN/diagnostics/E021.md)

> 原文: [E021.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E021.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

レコード（またはレコードをペイロードに持つバリアントケース）が、誤った**形状**で構築または照合されました。レコードは**名前付きフィールド**から、タプルケースは**位置引数**から構築します。両者を混同したり、存在しないフィールドを指定したりすると、この検査が導入される以前は値が暗黙に破損していました（引数が捨てられ、その後の動作もターゲット間で一致しませんでした）。

`Cfg { name: "x" }`（波括弧）が正準の書き方です。`Cfg(name: "x")`（丸括弧の名前付き引数呼び出し構文）は**別名**として受け入れられ、まったく同じ構築へ正規化されます。ただし、構築時かつ通常のレコード型の場合だけです。バリアントのレコードペイロードケース（`type Shape = Circle { radius: Float } | ...` の1つの arm である `Circle { radius: Float }`）の照合には波括弧パターンだけを使え、`Circle(radius)` は使えません。最後の例を参照してください。

## よくある例

レコードに位置引数を指定する場合：

```almide
type Cfg = { name: String }
let c = Cfg("x")          // E021: 'Cfg' takes named fields, not positional arguments
let ok1 = Cfg(name: "x")  // ✓ normalized to the brace form
let ok2 = Cfg { name: "x" } // ✓
```

未知・重複・不足フィールド（どちらの書き方も検査対象）：

```almide
type User = { name: String, age: Int = 0 }
let a = User { nmae: "x" }            // E021: 'User' has no field 'nmae'
let b = User { name: "x", name: "y" } // E021: field 'name' given more than once
let c = User { }                      // E021: missing field 'name' ('age' has a default — fine)
```

タプルケースに名前付き引数を渡す場合と、波括弧でタプルケースを構築する場合：

```almide
type W = Wrap(Int) | E
let w = Wrap(value: 1)   // E021: constructor 'Wrap' takes positional arguments
let v = Wrap { x: 1 }    // E021: case 'Wrap' does not take named fields
```

レコードペイロードケースに丸括弧パターンを使う場合：

```almide
type Tag = | SetEmotion { name: String } | Other
fn f(t: Tag) -> String = match t {
  SetEmotion(_) => "s",       // E021: use a record pattern
  _ => "o",
}
// ✓ write: SetEmotion { .. }  (or bind fields: SetEmotion { name })
```

## エラーになる理由

名前付きフィールドに位置で束縛すると、フィールドの追加や並べ替えのたびに意味が暗黙に変わります。それは、レコード型が耐えるために存在する変更そのものです。名前付きフィールドによる構築は順序に依存せず、宣言と照合して検証されるため、タイプミスや必須フィールドの不足をここで検出できます。生成された Rust のエラー（`E0560`/`E0063`）や wasm のトラップにまで漏れることを防ぎます。

## Fix-it 判定

**not-fixable** — このエラーは、自動書き換えでは判断できない意味上／設計上の問題を示します。（`mechanical` = 無人の修正ツールが書き換えを適用可能、`conditional` = 提案された修正にレビューが必要、`not-fixable` = 自動書き換えは存在しません。#1486 の適用可能性の原則。）
