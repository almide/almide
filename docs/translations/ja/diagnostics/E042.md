# E042 — この文は Result を捨てている（must-use）

[English](../../../diagnostics/E042.md) | [日本語](../../ja/diagnostics/E042.md) | [简体中文](../../zh-CN/diagnostics/E042.md)

> 原文：[`docs/diagnostics/E042.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E042.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

型が `Result` の式を文位置に置くと、値と、それに伴うエラーを捨ててしまう。暗黙の伝搬が廃止された今（ADR-0008、[E041](E041.md)）、黙って捨てられた Result は、失敗が跡形もなく消える場所になってしまう。そのため、すべての fn の種類（effect、fallible、pure、test）で検査エラーとなる。

## よくある例

```almide
effect fn main() -> Unit = {
  cleanup(tmp)            // E042 — the err is silently dropped
  fs.write_text(p, s)          // E042
}
```

## 診断

```
error[E042]: this statement discards a Result — the error would be silently dropped
  try: !          ← a suggestion, not a machine-applicable edit
```

## 修正

意図に応じた2つの表記：

```almide
cleanup(tmp)!             // propagate the err
let _ = cleanup(tmp)      // discard ON PURPOSE (the explicit-discard spelling)
```

互換性のある Result チャネルを通じて返される末尾の Result は、捨てられた文ではない。一方、Unit を返す effect の末尾では明示的な伝搬が必要な場合がある。ok/err に対する match も Result を消費する。`let _ =` は、`map_err` の `(_)` と同じ、意図的な破棄の系譜にある（ADR-0004 D3）。

## 理由

Rust の Result は `#[must_use]` を警告として持ち、エコシステムの lint はそれを拒否に引き上げる。Swift は例外を投げるすべての呼び出しの前に `try` を要求する。ADR-0008 D2 が選んだのは、より厳しい既定でのエラーである。黙ってエラーを失うことは silent-loss の種類に属し、流れて見過ごされる警告では、そのまま出荷されてしまう。
