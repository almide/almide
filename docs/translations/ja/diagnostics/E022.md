# E022 — エラー伝搬可能な文脈の外にある `!` 演算子

[English](../../../diagnostics/E022.md) | [日本語](./E022.md) | [简体中文](../../zh-CN/diagnostics/E022.md)

> 原文: [E022.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E022.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

後置 `!` は `Option[T]` または `Result[T, E]` を取り出し、失敗時には最も内側の互換性のある失敗チャネルを通して脱出します。そのチャネルは effect fn、Result/Option を返す純粋な fn、または失敗可能と推論された lambda に属します。テストブロックでは代わりに test-unwrap の意味論を使います。

通常の失敗しない fn には失敗チャネルがありません。

```almide
fn parse_number(s: String) -> Int = int.parse(s)!   // E022
```

## 修正

伝搬する意図があるなら、失敗可能な戻り型を宣言します。

```almide
fn parse_number(s: String) -> Int! = int.parse(s)!
```

または、失敗をその場で処理します。

```almide
fn parse_or_zero(s: String) -> Int = int.parse(s) ?? 0
```

lambda の `!` は周囲の fn ではなく、その lambda 自身のチャネルに属します。エラー型は文脈から与えられる型、または `!` の各オペランドの型の結合から決まります（ADR-0021）。失敗可能なコールバックを受け取る呼び出し自体が Result を返すこともあります。`effect` の追加が必要なのは実際のエフェクトがある場合であり、失敗し得る純粋な計算というだけでは必要ありません。

## エラー型の不一致（#2635）

`!` が伝搬できる場所でも、運ぶエラーは最初から fn と互換性のあるエラー型でなければなりません。ユーザー定義のエラー型への変換を勝手に作りません。エラー型がユーザー型の fn（`-> Result[T, Failure]`、`-> T!Failure`）では、次の3種のオペランドは代わりに `String` で失敗するため E022 になります。

- 戻り型が `Result` ではないエフェクト呼び出し（`-> Bool`、`-> Unit`、`-> Int`、レコードなど）：エフェクトのチャネルは `String` です。
- `Result[_, String]`。
- `Option`（その `none` は `String` エラーになります）。

```almide
type Failure = | Slow | Broken(String)

effect fn ready() -> Bool = ...
effect fn tidy() -> Unit = ...

effect fn step() -> Result[Int, Failure] = {
  tidy()!                                   // E022: fails with String
  if ready()! then ok(1) else err(Slow)     // E022: fails with String
}
```

```
error[E022]: operator '!' cannot propagate this error: the fn's error type is `Failure`, but this effect call fails with `String`
```

エラーをその場で処理します。結果を `match` して `Failure` のケースで `err(...)` を返す、`?? default`（`ready() ?? false`）を使う、または `let _ = tidy()` で Unit 呼び出しのエラーを捨てます。エラー型が `String` の fn 内でバリアントのエラーに `!` を適用することは引き続き許されます。そのテキストに変換されます。

## 理由

失敗可能性とエフェクトは別の軸です。E022 が拒否するのは失敗チャネルの不足または非互換性であり、純粋なコード全般ではありません。バリアントエラーから String チャネルへの変換には repr テキストを使います。厳密な変換設計との不一致は ADR-0021 D5 に記録されています。
