# E030 — 型に順序がない

[English](../../../diagnostics/E030.md) | [日本語](./E030.md) | [简体中文](../../zh-CN/diagnostics/E030.md)

> 原文: [E030.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E030.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

`list.sort`、`list.min`、`list.max` と `list.sort_by` のキーには、順序付け可能な要素が必要です。これはネイティブランタイムの `T: Ord` 制約です。単独の `Float` 要素は問題ありません（IEEE-754 totalOrder の `_float` 対応版に振り分けられます）。一方、`Map`、`Set`、関数の要素、または複合要素にネストした `Float` には順序がありません。以前は `check` が受理しても、ネイティブ rustc が単相化結果を拒否していました（`AlmideMap: Ord is not satisfied` — check と build の受理の隔たり。差分ファジング seed 20260718、index 629）。

```almide
fn main() -> Unit = {
  let xs: List[Map[String, Int]] = [["a": 1]]
  let s = list.sort(xs)                       // ← E030: Map has no ordering
  println("${list.len(s)}")
}
```

## 修正

代わりに、順序付け可能なキーを明示してソートします。

```almide
fn main() -> Unit = {
  let xs: List[Map[String, Int]] = [["a": 1], ["b": 2]]
  let s = list.sort_by(xs, (m) => map.len(m))   // Int key — orderable
  println("${list.len(s)}")
}
```

順序付け可能なもの：`Int`（全ビット幅）、`Bool`、`String`、単独の `Float`、およびそれらだけで作られたタプル／リスト／`Option`。

ユーザー定義のレコードやバリアントも順序付け可能です。レコードはフィールド宣言順の辞書式順序、バリアントはケースの順序、次にペイロードの順序で、ネイティブの derive が与えるものと同じです。ただし、**型が導出を宣言している場合に限ります**。

```almide
type Score: Ord = { points: Int, name: String }   // orders
type Level: Ord = | Low | Mid | High              // Low < Mid < High
```

`: Ord` がなければ型は順序付け可能ではなく、これは意図的です（#1521）。フィールドの構造的な順序付け可能性だけでは不十分です。ネイティブの単相化結果が `T: Ord` を満たす必要があり、それを与えるのは宣言された導出だけだからです。

順序付けできないもの：`Map`、`Set`、関数、複合要素内の `Float`（明示的なキーで比較してください）。
