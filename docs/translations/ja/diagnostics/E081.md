# E081 — 選択した wasm ターゲットでは関数を利用できない

[English](../../../diagnostics/E081.md) | [日本語](../../ja/diagnostics/E081.md) | [简体中文](../../zh-CN/diagnostics/E081.md)

> 原文：[`docs/diagnostics/E081.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E081.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

選択した wasm 経路が、指定された関数または出力されたホスト操作を提供できない。利用可能性は経路ごとに異なり、標準 preview1、直接の component、組み込みホストは同じサービスを公開していない。現在のマトリクスは `proofs/target-availability.toml`。CI は宣言された壁を renderer と照合する。wasm の実行経路が一切ないと決めつけず、選択した経路の理由を読むこと。

例えば標準 preview1 の HTTP クライアントの壁は、組み込みホストや WASI 0.3 HTTP component 経路がないことを意味しない。component ビルドも、選択した shim が提供する操作を検証する。

移植可能な代替がある場合、診断はそれを示す（`try:` 行。例：`testing.assert_gt` → `assert(a > b)`）。利用可能性マトリクスの行にその代替を記載する。各行は、利用不能がどう解消されるかを示す `class` も持つ。`pending-self-host` は自ホスト本体で解消、`pending-port` はホストへの移植で解消（行の `issue` が対象を示す）、`native-only-forever` は仕様上 wasm ターゲットに存在できない関数（行の `justification` が理由を示す）。`host-capability` 行は標準成果物に必要な private import を示す。サブプロセス対応は組み込みホスト上の `almide:process/spawn`（ADR-0025）を使うのであり、wasm 全般の禁止ではない。二つの pending 件数は CI で増加を許さないラチェットとなっている。

直接の `--component` ビルドも、出力ファイルを書き込む前に、出力されたホスト操作を選択した p2 または p3 shim と照合する。失敗時は操作と component バージョンを示す。例えば現在の直接 p2/p3 には argv import がなく、`args.option` 経由の呼び出しは `env.args`、`args.option`、host op 29 を報告する。通常の preview1 ビルドは argv を提供し、この component 固有の検査では拒否されない。`almide check --target wasm` は標準ビルド経路を検査し、component profile は選択しない。

native または組み込み実行なら、必要なホスト操作を提供できる場合がある。

## Fix-it 判定

**not-fixable** — 修正はプラットフォームの判断（native で実行する、示された代替を使う、移植を待つ）であり、無人の修正ツールが適用する書き換えではない。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
