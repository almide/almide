# E051 — このコンパイラが扱えない dialect の印があるファイル

[English](../../../diagnostics/E051.md) | [日本語](../../ja/diagnostics/E051.md) | [简体中文](../../zh-CN/diagnostics/E051.md)

> 原文：[`docs/diagnostics/E051.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E051.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

ファイルの `@dialect(N)` の印が、このコンパイラが実装する dialect より大きい epoch を持つ。

```almide
@dialect(2147483647)           // ← E051: deliberately beyond this compiler's epoch

fn main() -> Unit = println("hi")
```

## 印の意味

`@dialect(N)` は、そのファイルが最後に**検証された**言語 dialect を記録する。リリース番号ではない。Almide は頻繁にリリースするが、書き手が観測できるものが変わるリリースはごく少ないため、epoch は既存コードを壊し得る言語の公開仕様の変更時だけ進む。epoch と各破壊的変更の規範的な一覧は [`proofs/dialect-epochs.toml`](../../../../proofs/dialect-epochs.toml) にある。

Almide の利用者の多くはコード生成器なので、この印が存在する。モデルは学習した dialect に従って書く。その dialect をファイルに記録すると、コンパイラが「このプログラムは誤っている」と「このプログラムは古い言語向けに書かれた」を区別でき、modification survival を一つの混在した数値ではなく dialect ごとに計測できる。

## コンパイラより先の印がエラーになる理由

四つの状態のうち三つは何も報告しない。

| 印 | 意味 | 挙動 |
|---|---|---|
| なし | 印が導入される前に書かれた、または意図的に未記入 | 何も報告しない |
| コンパイラと同じ | この dialect で検証済み | 何も報告しない |
| コンパイラより**小さい** | 古い dialect で検証済み | **何も報告しない** — 変わったものを実際に使うまでコンパイルできる |
| コンパイラより**大きい** | このバイナリが一度も扱ったことのない言語で検証済み | **E051** |

成功が誤解を招くのは最後の行だけ。より大きい印は、より新しい Almide がファイルを検査したことを示すが、ここにあるコンパイラは検査していない。たまたまコンパイルできても証拠ではなく偶然である。生成器の出力が問題なさそうに見えて実際にはそうでない、まさにそのケースである。

## 修正

- **コンパイラを更新する** — 通常は `PATH` 上のものより新しい Almide 向けにファイルが書かれたことが原因。
- **または印を下げる** — ファイルが本当にこの dialect を対象にする場合。問題なく検査を通ると `almide check <file> --stamp` が正しい epoch を書き込む。ただし印を動かすのは前方のみ。新しいコンパイラの印はそのまま残す。戻すことは、このバイナリが実施できない検証を偽造することになるためである。
