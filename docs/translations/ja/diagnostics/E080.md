# E080 — or パターンの選択肢が変数を束縛する

[English](../../../diagnostics/E080.md) | [日本語](../../ja/diagnostics/E080.md) | [简体中文](../../zh-CN/diagnostics/E080.md)

> 原文：[`docs/diagnostics/E080.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E080.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

or パターンの arm `a | b | c => body` は、**いずれか**の選択肢が一致したときに選ばれる。そのため、本体はどの選択肢が一致したかに依存できない。選択肢内に変数束縛があると、その変数が現れない選択肢では単一の値を持てない（または経路ごとに異なる中身を束縛することになる）。したがって、選択肢には**束縛を含めない**。

```almide
fn class(x: Option[Int]) -> String = match x {
  some(n) | none => "?",   // ← E080: `n` binds in one alternative only
}
```

ワイルドカードは何も束縛しないので使用できる。

```almide
fn class(x: Option[Int]) -> String = match x {
  some(_) | none => "either",
}
```

本体が中身を必要とする場合は、arm を分けて書く。

```almide
fn class(x: Option[Int]) -> String = match x {
  some(n) => "got ${n}",
  none => "nothing",
}
```

この規則は、コンストラクター引数、タプル、リスト、レコードパターンのフィールド内など、どの深さの束縛にも適用する。

## Fix-it 判定

**conditional** — 束縛を `_` に置き換える操作は機械的だが、本体が中身を必要としていたか（その場合は arm を分けるべきか）は意図による。
（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
