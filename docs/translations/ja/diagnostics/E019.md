# E019 — 曖昧なコンストラクター

[English](../../../diagnostics/E019.md) | [日本語](../../ja/diagnostics/E019.md) | [简体中文](../../zh-CN/diagnostics/E019.md)

> 原文：[`docs/diagnostics/E019.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E019.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

単独のバリアントコンストラクター名が**複数**のバリアント型で宣言されているため、その名前だけでは曖昧で、チェッカーはどの型を意図したか判断できない。この例は同一モジュール内のコンストラクター重複を扱う。異なるモジュールが所有するコンストラクターはモジュールの所有関係で解決され、綴りが共通なだけではパッケージ間の衝突にはならない。

Almide は検査を続けるため最初に宣言された候補へ名前を解決するが、誤った型を黙って構築せず、競合を報告する。黙って構築すると、後になって不可解な生成 Rust のエラー（`E0769`/`E0308`）として現れてしまう。

## よくある例

```almide
type Cmd   = | Stop | Send(Int)
type Event = | Tick | Send(Int)   // `Send` now lives in two types

fn main() -> Unit = {
  let x = Send(5)   // E019: ambiguous constructor 'Send': declared in Cmd and Event
  println("${x}")
}
```

## 修正

一方の型のコンストラクターを改名して名前を一意にする。修飾された `Type.Ctor` 形式はまだ未対応であるため、曖昧さの解消には改名を使う。

```almide
type Cmd   = | Stop | Send(Int)
type Event = | Tick | Emit(Int)   // renamed `Send` → `Emit`

fn main() -> Unit = {
  let x = Send(5)   // unambiguous: only Cmd declares `Send`
  println("${x}")
}
```

## Fix-it 判定

**not-fixable** — 自動書き換えでは判断できない意味・設計上の問題を報告している。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
