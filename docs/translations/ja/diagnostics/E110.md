# E110 — 信頼できない入力は入力型にのみデコードできる

[English](../../../diagnostics/E110.md) | [日本語](../../ja/diagnostics/E110.md) | [简体中文](../../zh-CN/diagnostics/E110.md)

> 原文：[`docs/diagnostics/E110.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E110.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

`@input_sink` を付けた fn（`http.decode_json`）は、信頼できない入力を `Decode` 制約付きの型パラメーターへデコードする。このパラメーターには**入力型**を束縛する必要がある。入力型とは `: Decode` と宣言し、同時に `Encode` ではないレコードまたはバリアントである（row 22、C-436）。入力型のすべてのフィールドは入力なので、この型がクライアントの設定できるものの許可リストとなる。

```almide
type User: Codec = { name: String, email: String, is_admin: Bool = false }

match http.decode_json[User](req) {   // ← E110
```

```
error[E110]: `http.decode_json` decodes untrusted input only into an input type, and `User` is also sent out (it is `Codec`)
  hint: Declare what the client may set as its own type, then build `User` in code:
          type UserInput: Decode = { name: String, email: String }
          match http.decode_json[UserInput](req) {
            ok(i) => … User { name: i.name, email: i.email, … } …
            err(bad) => bad,     // unknown key → 400
          }
        Every field of a `: Decode` type is input. A field the client must not set stays out of it.
```

同じコードが、さらに2つの形を対象とする。

- 入力型の**内部に入れ子になった**、出力にも使うレコード。フィールド（`Address: Codec` に対する `type SignupInput: Decode = { address: Address }`）やバリアントの中身（`Role: Codec` に対する `| Grant(Role)`）が該当する。共有する `Address` に `verified: Bool = false` を追加すると、それをリクエストから設定できてしまう。
- 自身が `@input_sink` ではない fn の**型パラメーター**（`fn body_as[T: Decode](req) = http.decode_json[T](req)`）。転送する fn を `@input_sink` とすれば、その呼び出し元の型が判定される。

入力型の内部にある、標準ライブラリモジュールで宣言された型（`Url`、`Uuid`）は葉の値として扱い、判定対象としない。

### リクエストを手動でデコードする場合 (#4232)

sink を使わなくても規則は回避できない。リクエストデータ、つまり `@input_sink` が宣言するパラメーター型 `HttpRequest` から計算された任意の値は、束縛、コンテナー、コールバック、ユーザー定義の補助関数を通じてデコード位置まで追跡される。出力にも使う型、そのような型を保持する入力型、または `@input_sink` ではない fn の型パラメーターの `T.decode` / `T.decode_strict` に到達すると、デコード位置（またはデコードする補助関数へデータを渡す呼び出し位置）で同じ E110 となる。

```almide
let u = User.decode(json.parse(http.body(req))!)!   // ← E110
```

```
error[E110]: `User.decode` decodes request data into `User`, and `User` is also sent out (it is `Codec`)
  note: path: HttpRequest → User.decode
```

代わりに入力型へデコードし（`UserInput.decode_strict(..)` または `http.decode_json[UserInput](req)`）、コードで `User` を構築する。リクエスト由来ではないデータからデコードする `Codec` 型は判定対象ではない。`@input_sink` fn の本体も判定しない。その型パラメーターは各呼び出し元で判定する。

## 修正

```almide
type User: Codec = { name: String, email: String, is_admin: Bool = false }

type UserInput: Decode = { name: String, email: String }

match http.decode_json[UserInput](req) {
  ok(i) => http.response(201, "${User { name: i.name, email: i.email, is_admin: false }.name}"),
  err(bad) => bad,
}
```

## 理由

mass assignment には、信頼できない入力元**と**、その入力元が設定してよい範囲より広いフィールド集合を持つ対象型が必要である。計測したすべての導出型 codec（Go、serde、pydantic、zod、Swift、kotlinx、Jackson、aeson）では、`is_admin` のような既知フィールドは、何らかの印を付けない限り入力から設定される。`is_admin` は既知のキーなので、未知キーの厳格な処理では防げない。この穴を塞ぐエコシステムは、ドメイン型とは別の許可リスト型を使う（FastAPI の `UserCreate`、zod の `pick`、Elm の decoder 値、Rails の strong parameters）。ドメイン型の `@skip_decode` は拒否リストであり、次に `User` へ追加するフィールドには印がない。

`: Decode` のみの型が、一度宣言すればよい許可リストとなり、`User` の編集では広がらない。sink は `T.decode_strict` でもデコードするため、入力型の外にあるキーは、どの深さでも（`is_admin`、誤記、探索的入力、入れ子の入力レコードやバリアントの中身のキー）、経路を伴う `400 Bad Request: unknown key '<k>'` となる。他の場所での `T.decode` は寛容なままである。
