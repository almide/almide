# E116 — レスポンスの Content-Type は本体の型から設定される

[English](../../../diagnostics/E116.md) | [日本語](../../ja/diagnostics/E116.md) | [简体中文](../../zh-CN/diagnostics/E116.md)

> 原文：[`docs/diagnostics/E116.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E116.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

レスポンスの `Content-Type` は、その本体の型である（ADR-0032、row 11e）。String は `text/plain; charset=utf-8`、`html.*` は `text/html` を構築し、許可されたパッケージの安全な型はその固有の型、`Value` は `application/json`、その他のメディア型は `http.typed("text/csv", bytes)` である。ヘッダーを名前で書くと本体のラベルを付け替えてしまう。String を `text/html` として配信すると攻撃者の文字列がスクリプトとして実行されるため、レスポンスへの `http.set_header` と `http.with_headers` はこれを拒否する。名前がリテラルならここで拒否し、計算された名前なら呼び出し実行時に中断する。リクエストはレスポンス本体ではないため、任意の Content-Type を持てる。

```almide
import http

fn report(rows: String) -> HttpResponse =
  http.with_headers(200, rows, [("Content-Type", "text/csv")])   // ← E116
```

```
error[E116]: `http.with_headers` writes `Content-Type` by name, and a response's `Content-Type` is written from its body's type
```

## 修正

```almide
import http

fn report(rows: String) -> HttpResponse =
  http.with_headers(200, http.typed("text/csv", bytes.from_string(rows)), [])
```

呼び出しが1行、本体が String、型が `http.typed` の受理するものであれば、`almide fix` がこの書き換えを行う（`r` が名前である `set_header(r, "Content-Type",
t)` は `http.with_body(r, http.typed(t,
http.body_bytes(r)))` になる）。

## 理由

本体が所有するヘッダーは、書き込み関数上で一度宣言する（`stdlib/http.almd` の `@header_write(…, owned = "__http_response_body_headers")`）。この検査と実行時の拒否は、両方ともその宣言を読む。

## Fix-it 判定

上記の1行リテラル形式では **mechanical**（無人の修正ツールが適用可能）。それ以外では、診断は修正を伴わない。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
