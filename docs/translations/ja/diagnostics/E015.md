# E015 — 標準ライブラリの再実装の可能性

[English](../../../diagnostics/E015.md) | [日本語](../../ja/diagnostics/E015.md) | [简体中文](../../zh-CN/diagnostics/E015.md)

> 原文：[`docs/diagnostics/E015.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E015.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

トップレベルの `fn` が、計算系標準ライブラリモジュールの純粋関数と同じ名前・互換性のあるシグネチャを持つ。これは参考情報としての警告であり、比較するのは名前と型のみ。本体は異なる操作を実装している可能性がある。E015 は置換編集や委譲 shim を提供しない。

`args` を含むホスト／環境モジュールは、関数のシグネチャが純粋に見えても対象外となる。空文字列を `none` に変える補助関数を、コマンドラインオプション検索で置き換えてはならない。

## よくある例

```almide
// ~30 lines of algorithm:
fn binary_search(xs: List[Int], target: Int) -> Option[Int] = {
    let lo = 0
    let hi = list.len(xs) - 1
    // ... loop implementation ...
}
// warning[E015]: has the same signature as stdlib `list.binary_search`
```

## 修正

標準ライブラリ関数が意図した意味を持つと確認した上で、委譲してもよい。

```almide
fn binary_search(xs: List[Int], target: Int) -> Option[Int] =
    list.binary_search(xs, target)
```

アルゴリズムが意図的に異なるなら、自分の fn を改名する。

```almide
fn my_search_descending(xs: List[Int], target: Int) -> Option[Int] = ...
```

## E015 が出ない場合

- **名前が異なる** — `optional` と `option` のような似た名前は一致しない。
- **ホスト／環境モジュールまたは effect 関数** — 候補から除外する。
- **パラメーター型、戻り値の形、引数の数が異なる** — 候補から除外する。

標準ライブラリ側がジェネリック（`binary_search[T: Ord]`）、ユーザー側が単相（`List[Int]`）でも一致と見なす。非対称な `TypeVar` ワイルドカードは意図した仕様である。

## エラーではなく警告にする理由

正しさの問題はなく、その fn は動作する。計測上の仮説（`docs/roadmap/done/reimpl-lint.md`）は、同名の標準ライブラリ関数の存在を知ることで LLM の再試行ループが改善するというものである。エラーにすると正当な特殊化を壊してしまう。
