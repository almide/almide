# E103 — 定時間で比較できない Secret に対する `==`

[English](../../../diagnostics/E103.md) | [日本語](./E103.md) | [简体中文](../../zh-CN/diagnostics/E103.md)

> 原文: [E103.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E103.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

`secret.Secret[A]`（#4107）が `==` / `!=`（および `assert_eq` / `assert_ne`）で比較できるのは、`A` が `String` または `Bytes` の場合だけです。その場合は定時間で比較します（`string.is_equal_constant_time` / `bytes.is_equal_constant_time`）。比較対象のレコード、タプル、リスト、option、result の中に Secret がある場合も同様です。それ以外で Secret を読むことになる比較はすべて E103 です。

- その他の型の `Secret`（`Secret[Int]`、`Secret[MyRecord]`）。
- いずれかのペイロードに Secret を含むバリアント。
- Secret を含む map または set。

```almide
import secret

fn main() -> Unit = {
  let a = secret.new(1234)
  println(if a == secret.new(1234) then "same" else "different")   // ← E103
}
```

```
error[E103]: operator '==' cannot compare 'Secret[Int]': a Secret compares only when it holds a String or Bytes (in constant time)
  hint: Compare what the secrets hold, explicitly: `secret.reveal(a) == secret.reveal(b)`. `==` on Secret[String] / Secret[Bytes] is constant time; a variant or map holding a Secret compares by `match` / per key.
```

## 修正

1. 明示的に取り出した値を比較します：`secret.reveal(a) == secret.reveal(b)`。取り出しが呼び出し箇所に見えることが要点です。
2. Secret を含むバリアントでは、ペアを `match` し、Secret ペイロードを `==` で比較します（String / Bytes は定時間）。

## 理由

導出した `==` は最初に異なるバイトで止まるため、所要時間は推測した秘密がどこまで正しかったかを示します。String と Bytes の Secret は代わりに定時間で比較します。それ以外のペイロードには提供できる定時間比較がないため、暗黙に時間差を生むのではなく比較を拒否します。

## Fix-it 判定

**not-fixable**：取り出した後の比較が許容できるかは、秘密の内容によります。診断は型と明示的な書き方を示します。
