# E109 — 純粋な fn が関数値を通じて effect fn を実行する

[English](../../../diagnostics/E109.md) | [日本語](../../ja/diagnostics/E109.md) | [简体中文](../../zh-CN/diagnostics/E109.md)

> 原文：[`docs/diagnostics/E109.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E109.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

通常の `fn` が、値として到達した `effect fn` を実行した。渡されたコールバック、レコードフィールド、リスト要素、option の中身、別の関数が作ったクロージャーなどが該当する。E006 は、呼び出し時に見える形（直接呼び出し、effect fn を保持する名前（#3274）、引数として名前を指定した effect fn）を拒否する。しかし関数値は呼び出し位置より先まで運ばれ、最終的にそれを呼ぶ純粋な fn が、拒否されずにエフェクトを実行していた（#4151）。

```almide
import fs

type Reader = { read: (String) -> Result[String, String] }

fn pure_looking(r: Reader) -> Result[String, String] = (r.read)("s.txt")   // ← E109

effect fn main() -> Unit = {
  let r = Reader { read: fs.read_text }
  println(pure_looking(r) ?? "none")
}
```

```
error[E109]: pure function `pure_looking` runs an effect function it does not call by name
  --> main.almd:5:56
  = path: pure_looking → field `read` → closure (line 8:26 in main) → fs.read_text (line 8:26)
  hint: A plain `fn` cannot run an `effect fn`, even one it receives as a value — a callback, a record field, a list element (ADR-0009 D2). Mark `pure_looking` as `effect fn` if it is meant to do I/O, or pass it a function that does none
```

## 判定方法

エフェクトのビットは、エフェクトのカテゴリーと同様に関数値に付随する（ADR-0026 D1、`crates/almide-codegen/src/effect_flow`）。`effect fn` はそのビットを持ち、それを呼ぶクロージャーも持つ。フィールド、リスト、option に格納しても保持される。単なる関数型のパラメーターは透過的である（ADR-0009 D2）。通常の fn はそれを呼べるが、effect fn を渡す呼び出し位置でエフェクトとして扱う。そのため `fn apply(f: (A) -> B, x: A) = f(x)` は問題なく、`apply(fs.read_text, p)` はエフェクト呼び出しとなる（純粋な fn からなら E006）。E109 は残るケース、つまり自身のパラメーター経由ではなく、自分の本体でそのビットを持つ値を実行する純粋な fn を対象とする。

解析はプログラム全体を対象とする保守的なもの。追跡位置を離れた値（リスト、バリアントの中身、未知の呼び出し先へ渡した値）は、同じシグネチャを持つ他の追跡外の値すべてとプールされる。そのような位置から読み戻した値の呼び出しには、そのプールのエフェクトを計上する。したがって、リストから読み出した関数を呼ぶ純粋な fn は、同じシグネチャで I/O を行う関数がプログラムのどこかでリストに入れられていれば拒否される。

`process.exit`（結果が `Never` の `effect fn`）はこのビットを持たない。プログラムの終了は ADR-0022 の abort であり、通常の fn でも実行できる。

## 修正

1. I/O を行う関数なら、`effect fn` と明示する（呼び出し元には `Result` が見え、`!` で伝搬する）。
2. 純粋であるべきなら、I/O を行わない関数を渡す。値を構築する effect fn 内で I/O を行い、純粋な fn にはデータを渡す。

## Fix-it 判定

**not-fixable**：関数を `effect fn` にすべきか、別の値を渡すべきかは設計判断である。診断は、純粋な fn から到達した effect fn までの経路（`= path:`）を示す。

フィクスチャ：`tests/diagnostics/e109-*`。両ターゲット：`tests/effect_value_laundering_test.rs`。
