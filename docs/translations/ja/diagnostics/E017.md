# E017 — enum 型名によるレコード構築

[English](../../../diagnostics/E017.md) | [日本語](../../ja/diagnostics/E017.md) | [简体中文](../../zh-CN/diagnostics/E017.md)

> 原文：[`docs/diagnostics/E017.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E017.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

レコードリテラル `{ field: value, ... }` の前に、レコード型またはレコードを持つ具体的なケースではなく、**enum 型**（`type T = A | B { ... }` 宣言）の名前が付いている。enum 型自体にフィールドはなく、個々のケースだけがフィールドを持つため、この構築に意味はない。

これは**両方**のターゲットで必ずエラーとなる。以前は挙動が分かれ、Rust は `rustc` の `error[E0574]: expected struct, variant or union
type, found enum` を「Almide bug」として漏出させた。一方 WASM はコンパイルされ、黙って値を誤構築した（名前付きフィールドをゴミ値として読む）。型検査時に拒否することで両ターゲットを一致させ、対処可能なメッセージを出す。

## よくある例

```almide
type V = Tag(Float) | Named { who: String }

let v = V { who: "x" }
// error[E017]: cannot construct enum type 'V' with record syntax
```

## 修正

enum 型ではなく、レコードを持つ具体的なケースを構築する。

```almide
let v = Named { who: "x" }   // the case, not the enum
```

enum にレコードを持つケースがなければ、意図したケースを選び、ペイロードを直接渡す（`Tag(1.0)`）。
