# E048 — 対象の型が持たないバリアントパターン

[English](../../../diagnostics/E048.md) | [日本語](../../ja/diagnostics/E048.md) | [简体中文](../../zh-CN/diagnostics/E048.md)

> 原文：[`docs/diagnostics/E048.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E048.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

コンストラクターパターンは、**対象**が実際に持つケースを指定しなければならない。E048 はそれに失敗する三つの形を扱う。

| パターン | 対象 | |
|---|---|---|
| `ok(..)` / `err(..)` | `Option` | ファミリー違い |
| `some(..)` / `none` | `Result` | ファミリー違い |
| `some`/`none`/`ok`/`err` | ユーザーバリアント | ユーザー ADT に対する組み込み carrier |
| ユーザー ctor `C(..)` | `C` を持たないバリアント、または Option / Result | 別のケース |
| ユーザー newtype の `Value(..)` / レコードの `Value { .. }` | 標準ライブラリの `Value`（`FileStat`、…） | 標準ライブラリ型とそれを隠すユーザー型 |

`some(..)` / `none` は **Option** を、`ok(..)` / `err(..)` は **Result** を分解する。Almide では二つのファミリーは別の型であり、一方のパターンが他方の対象に一致することはない。独自のケースを持つユーザーバリアントにも、どちらも一致しない。

```almide
fn first_plus_one(xs: List[Int]) -> Int = match list.get(xs, 0) {
  ok(a) => a + 1,   // ← E048: `list.get` returns `Int?`, an Option
  _ => 0,
}
```

典型的な原因は、生成元の戻り型の誤推測である。`list.get`、`map.get`、`string.find` はいずれも `T?`（Option）を返すが、`int.parse`、`fs.read_text`、`json.parse` は Result を返す。arm の記法を確実に選ぶには、生成元のシグネチャを読む。

## 黙って束縛せずエラーにする理由

#1341 までは、チェッカーが拒否していたのは単純なスカラーを対象とするコンストラクターパターンだけだった。異なるファミリーのパターンは通過し、ペイロードを `Ty::Unknown` として束縛していた。それが後続の全 pass を通過し、codegen で失敗した。

```
error: [COMPILER BUG] internal type resolution failed before codegen
    [fn f:3:12] unresolved Var ty=Unknown var_id=1 name=a stored_ty=Unknown
  hint: please report this at https://github.com/almide/almide/issues
```

native では上記、wasm では「outside the executable subset」の壁となった。どちらも単なるプログラムの型エラーをコンパイラのせいにし、一語の修正を示さなかった。#1266 の誤帰属分類である。E048 は同じ拒否処理を、パターンと対象の型を両方見られる唯一の場所へ移したものとなる。

**別のケース**の場合はさらに悪かった。別のバリアントのユーザー ctor（`match shape { Red(r) => .. }`）はペイロードを Unknown に束縛して codegen に到達し、native では**不正な Rust**（`codegen produced invalid Rust — this
is an Almide bug`）を出力し、wasm では壁に当たった。

対象として主張するのは構造が既知のものだけ。推論途中の型や、opaque alias である `Named` 型（その `SafeHtml(s)` 分解は正当）は黙って通し、エラー回復には影響しない。

さらに一つ、**標準ライブラリ型と、それを隠すユーザー型**のケースがある（#1828、#1835）。プログラム独自の `Value`（レコードまたは opaque newtype `mod type
Value = String`）は `self.Value`（モジュール `m` では `m.Value`）として所有される一方、`json.parse` は依然として標準ライブラリの `Value` を返す。ユーザー型のパターンを json 値に適用すると E048 となり、E013 と同じヒントで両型を示す。

```
error[E048]: pattern `Value(..)` is not a case of `Value`
  in match pattern
  hint: `Value` is the `value` module's type and has no constructor to destructure.
        Here `Value` is the `value` module's type, not your `type Value` (which is
        `self.Value`): a same-name declaration never rebinds a stdlib type, so read
        this value through `value.*` — or rename your type to keep the two apart.
```

このケースの検査がなかった頃は、パターンがペイロードを `Ty::Unknown` に束縛して codegen へ進み、native では rustc E0308、structural wasm 経路では json 値のペイロードをユーザーの `String` として読み取っていた。

## 診断の形

```
error[E048]: pattern `ok(..)` destructures a Result, but the subject is `Option[Int]`
  in match pattern
  hint: Option and Result are separate types: an Option is matched with `some(..)`
        / `none`, a Result with `ok(..)` / `err(..)`. Write `some(..)` here.
  try:
      some(..)
```

`try:` 断片は常に、対象のファミリーの**同じ arm の位置**を示す。成功 arm ↔ 成功 arm、失敗 arm ↔ 失敗 arm である。非対称なのは `err(e)` ↔ `none` の組だけ。Option の失敗 arm はエラー値を持たないため束縛名がなくなる（逆に `none` ↔ `err(..)` では追加される）。

## 修正

対象が実際に属するファミリーの記法を使う。

```almide
fn first_plus_one(xs: List[Int]) -> Int = match list.get(xs, 0) {
  some(a) => a + 1,
  _ => 0,
}
```

値を Result にしたかったなら、パターンではなく生成元で変換する。例えば代替値なら `list.get(xs, 0) ?? 0`、または `some`/`none` で match し、各 arm で必要な `ok(..)` / `err(..)` を作る。

ユーザーバリアントには独自のケースを使う。ヒントに一覧を示す。

```
error[E048]: pattern `Red(..)` is not a case of `Shape`
  hint: the subject's cases are: Circle / Square.
```
