# E037 — 異なる2つの型の間で比較している

[English](../../../diagnostics/E037.md) | [日本語](../../ja/diagnostics/E037.md) | [简体中文](../../zh-CN/diagnostics/E037.md)

> 原文：[`docs/diagnostics/E037.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E037.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

`==`、`!=`、`<`、`<=`、`>`、`>=` のいずれかを、異なる2つの型のオペランドに適用した。比較は1つの型の2つの値を関係付けるもので、片側を暗黙に変換することはない。該当例は、`Int` と `String`（`1 == "1"`）、`Int` と `Float`（`1 == 1.0`）、リストと要素、要素数の異なるタプル、2つのレコード型、2つの型パラメーター（`a: A == b: B`）、型パラメーターと具体型、ちょうど片側だけの `Result`、または型パラメーターの異なる同じコンテナー（`Option[Int]` と `Option[String]`）である。サイズ付きの幅の型が標準型と合うのはリテラルを通じた場合だけ（`x8 == 1`）。標準型の*値*には `<type>.from(x)` が必要となる。

この検査は推論後、解決されたオペランド型に対して実行するため、ジェネリクスを通じても成り立つ。ジェネリック本体内では、型パラメーターは自分自身とのみ一致し、1つのパラメーターを2つの型に束縛する呼び出しは、呼び出し位置で拒否される。

このコードが存在する前は、同じコンテナーの形が `check` を通過し、「codegen produced invalid Rust」という壁の向こうで rustc E0308 として失敗していた。

## よくある例

```almide
helper() == ok(0)          // E037: Result on one side only
a == b                     // E037 when a: Option[Int], b: Option[String]
1 == "1"                   // E037: Int with String
n == 1.0                   // E037: Int with Float — `float.from(n) == 1.0`
fn same[A, B](a: A, b: B) -> Bool = a == b   // E037: A with B
```

## 診断

```
error[E037]: operator '==' compares Option[Int] with Option[String]
  hint: == requires both operands to have the same type
```

（推論後の検査のヒント：「比較は同じ型の2つの値を関係付けるもので、片側を暗黙に変換することはない — …」。）

## 修正

- 先に Result 側を unwrap する（effect fn 内の `!`、`?? fallback`、または ok/err に対する `match`）。または同じ型の2つの Result を比較する。
- パラメーターが一致しない場合は、片側を変換するか、unwrap 後の中身を比較する。

## 理由

`==` は1つの型に対する深い構造的等価性である。決して真にならない比較（または rustc が拒否する比較）を検査時に表面化させることで、「読んだものが実行される」という契約を保つ。
