# E024 — 整数リテラルが範囲外

[English](../../../diagnostics/E024.md) | [日本語](./E024.md) | [简体中文](../../zh-CN/diagnostics/E024.md)

> 原文: [E024.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E024.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

整数リテラルが、使われる型に収まりません。低水準化と両コード生成器は `.unwrap_or(0)` でリテラルを解析するため、範囲外のリテラルは、この検査がなければ両ターゲットで診断なしに**暗黙に 0 に変わります**。検査は型を認識し、型推論後に実行されるので、範囲は常に `i64` ではなく、リテラルの*実際の*型に基づきます。

範囲外になる原因は2種類あり、それぞれにヒントがあります。

| | 原因 | 修正 |
|---|---|---|
| **大きさ** | 値がビット幅に対して大きすぎる | より小さいリテラル、またはより幅の広い型 |
| **符号** | 符号なし型で負のリテラルを使用 | `-` を外すか、同じ幅の符号付き型を使用 |

## よくある例

### 大きさ

```almide
fn main() -> Unit = println(int.to_string(9223372036854775808))  // E024: > i64::MAX in an Int context
```

`9223372036854775808` は `i64::MAX + 1` です。既定の `Int`（i64）の文脈では表現できないため、0 に変わってしまいます。

```
error[E024]: integer literal '9223372036854775808' is out of range for Int
  hint: Int would silently fold to 0 here; its range is -9223372036854775808..=9223372036854775807, so use a literal within it, or model larger magnitudes as Float (lossy) or a parsed string
```

### 符号

```almide
fn main() -> Unit = {
  let k: UInt64 = -5   // E024: UInt64 has no negative values at all
  println(uint64.to_string(k))
}
```

符号なし型に負の値はないため、これは `5` の大きさの問題ではありません。`5` は完全に範囲内ですが、`-5` はその大きさにかかわらず表現できません。ネイティブの `rustc` は出力された `-5u64` を即座に拒否します（`error[E0600]: cannot apply unary
operator '-' to type 'u64'`）。したがって、E024 がない場合、これは暗黙の 0 化ではなく、check は通るが build は失敗するという隔たりになります。

```
error[E024]: integer literal '-5' is out of range for UInt64
  hint: UInt64 is unsigned — it has no negative values at all; drop the '-', or use the signed Int64 if the value can go below zero
```

`-0` は例外です。すべての符号なし型で表現できる `0` だからです。

## 修正

- 値の大きさが正当なら、より幅の広い型／符号なし型を使います。`UInt64` は宣言された全範囲に到達します（スロットは上半分をビットパターンとして保持し、符号なし経路が読み戻します — #872）。
  ```almide
  let big: UInt64 = 18446744073709551615  // u64::MAX — division, ordering and
                                          // printing are all unsigned
  ```
- `i64::MIN` の大きさに負号を付けた値は、符号付き値として有効です（`-` によって表現可能になります）。
  ```almide
  let lo: Int = -9223372036854775808      // i64::MIN — fine
  ```
- 非常に大きい値は `Float`（情報が失われ得る）で表すか、文字列として保持します。
- 符号エラーの場合、同じ幅の符号付き型へ変更します。`UInt8` → `Int8`、`UInt16` → `Int16`、`UInt32` → `Int32`、`UInt64` → `Int64`。
  ```almide
  let delta: Int32 = -5                   // was UInt32
  ```

## 型を認識する理由

範囲は、型解決後に決まるリテラルの文脈に依存します。

- `Int` / `Int64` → i64（`-9223372036854775808 .. 9223372036854775807`）。正の `9223372036854775808` はオーバーフローしますが、`-9223372036854775808` は `i64::MIN` に達し、有効です。
- `UInt64` → `0 .. 18446744073709551615`、宣言された全範囲（#872）。`Int8`/`UInt8`/… はそれぞれの幅を使います。下限は `0` なので、ゼロ以外のリテラルに負号を付けると、幅を問わず範囲外になります。

単純な `i64` だけの検査では、有効な `UInt64` リテラルや `i64::MIN` の大きさに負号を付けた値まで誤って拒否するため、検査は解決済み／注釈付きの型が決まるまで待ちます。
