# E045 — 非タプルへのタプル添字、または範囲外の添字

[English](../../../diagnostics/E045.md) | [日本語](../../ja/diagnostics/E045.md) | [简体中文](../../zh-CN/diagnostics/E045.md)

> 原文：[`docs/diagnostics/E045.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E045.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

`.k` による位置アクセスはタプル値だけに定義され、添字はタプルの要素数未満に限られる。以前はどちらの誤用も、式の型が `Unknown` のまま `almide check` を通過していた（「No errors found」）。その後ビルド時に ConcretizeTypes の表示の下で失敗し、ユーザー自身の型エラーをコンパイラのバグとして upstream への報告を求めていた（#1266）。現在はチェッカーが両方を早期に拒否し、検出内容を示す。

```almide
let n = 5
let a = n.0        // ← E045: tuple index .0 on non-tuple type Int

let t = (1, 2)
let b = t.5        // ← E045: tuple index .5 is out of range for (Int, Int)
                   //         (valid: .0 through .1)
```

型がまだ未確定の推論変数（呼び出し位置を待つ lambda パラメーター）のオブジェクトは、ここでは拒否しない。添字を保留し、union-find がタプル型を束縛した時点で解決するため、`xs |> list.map((p) => p.1)` のような連鎖は引き続き動作する。

## 修正

タプルに対して要素数の範囲内で添字を使うか、添字の代わりに分解する。

```almide
let t = (1, 2)
let b = t.1

let (x, y) = t
```

## Fix-it 判定

**not-fixable** — 自動書き換えでは判断できない意味・設計上の問題を報告している。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
