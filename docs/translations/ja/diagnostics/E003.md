# E003 — 未定義の変数

[English](../../../diagnostics/E003.md) | [日本語](../../ja/diagnostics/E003.md) | [简体中文](../../zh-CN/diagnostics/E003.md)

> 原文：[`docs/diagnostics/E003.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E003.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

値として使われた名前が現在のスコープ内で束縛されていない。

## よくある例

```almide
fn f() -> Int = x                      // x is not declared
match v { ok(value) => valeu }         // typo: 'valeu' instead of 'value'
let x = y                              // y is not bound at this point
json.stringify(v)                      // forgot `import json`
```

## 特定のパターン（`try:` 断片付き）

### `import json` / `import fs` などの書き忘れ

明示的 import が必要な Tier 2 標準ライブラリモジュールでは、`<module>.<fn>` の最初の使用で次を出力する。

```
error[E003]: undefined variable 'json'
  hint: Add `import json` (stdlib: JSON parsing and querying)
  try:
      import json
```

`almide fix` がこれを自動適用する（フォーマッターの `auto_imports` を呼ぶ）。ユーザー操作は不要で、ハーネスが再試行前に `almide fix` を実行するだけでよい。

### スコープ内の名前のタイプミス

曖昧一致が見つかると：

```
error[E003]: undefined variable 'lenth'
  hint: Did you mean `length`?
  try:
      // lenth  →  length
      length
```

## 修正（一般）

- 使用前に `let` または `var` で宣言する。
- パターンで束縛された名前と綴りを照合する（`match v { ok(value) => ... }` が束縛するのは `value` であり、`val` や `valeu` ではない）。
- 式の中の let 束縛は、その使用箇所を含む `Block { ... }` 内に置く。トップレベルの単独の `let x = 1` は `TopLet` 宣言である。fn 本体内では `{ let x = 1; x }` などが必要。
- Tier 2 標準ライブラリでは、先頭に `import <module>` を追加する（または `almide fix` を実行して自動で行う）。

## 関連

- E002 — 未定義の関数（モジュール全体が欠けていると一緒に発生しやすい：`json.stringify(v)` → `json` が未定義（E003）となり、連鎖した呼び出しも別途失敗する）
- E010 / E011 — 変数のスコープ／初期化の問題
- `llms.txt` —「Fast facts」に自動 import される標準ライブラリモジュールを列挙

## Fix-it 判定

**conditional** — 不足する import は導出できるが、その名前を export するモジュールがちょうど一つの場合に限る。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
