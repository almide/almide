# E098 — `testing.assert_aborts` に渡したクロージャがローカル変数をキャプチャする

[English](../../../diagnostics/E098.md) | [日本語](./E098.md) | [简体中文](../../zh-CN/diagnostics/E098.md)

> 原文: [E098.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E098.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

`testing.assert_aborts(expected, f)` は `f` だけを子側で実行します。ネイティブのテストバイナリはその1つのクロージャのために自分自身を再実行し、wasm 経路は同じモジュールの新しいインスタンスを起動します（ADR-0029）。子はプログラムを最初から始めるため、テストのローカル変数 — `let`、`var`、`where` 束縛、外側の lambda の引数 — は存在しません。

したがってクロージャは呼び出し箇所に直接書いた lambda でなければならず、自分で束縛せずに読み取る名前はすべてトップレベル項目である必要があります。fn、トップレベルの `let` または `var`（初期値として見える）、インポートしたモジュール、標準ライブラリが該当します。

```almide
import testing

test "reading past the end aborts" {
  let xs = [1, 2, 3]
  testing.assert_aborts("index out of bounds", () => xs[5])   // ← E098: captures `xs`
}
```

ローカル変数に保持した fn 値も拒否されます。渡した場所では何をキャプチャするか見えないためです。

```almide
import testing

test "a panic aborts" {
  let boom = () => panic("boom")
  testing.assert_aborts("boom", boom)                          // ← E098: `boom` is a fn value
}
```

## 診断

```
error[E098]: the closure passed to testing.assert_aborts captures `xs`, a local of the test
  in a call of testing.assert_aborts
  hint: the closure runs in a separate process (native) or instance (wasm), where the test's locals do not exist. Inline the value into the closure, or make it a top-level `let`.
```

エラーは各キャプチャ済みローカル変数の最初の読み取りを指します。

## 修正

クロージャの中で値を計算します。

```almide check
import testing

test "reading past the end aborts" {
  testing.assert_aborts("index out of bounds", () => {
    let xs = [1, 2, 3]
    xs[5]
  })
}
```

またはトップレベルの `let` にし、子自身に計算させます。

## Fix-it 判定

**conditional** — 値がプログラム自身のものであれば、束縛をクロージャ内へ移すのが修正です。ただし、テストが実行から計算した値はクロージャ内で再計算するかトップレベルの `let` にする必要があり、作者の選択になります。（`mechanical` = 無人の書き換え、`conditional` = 修正案にレビューが必要、`not-fixable` = 自動書き換えは存在しません。#1486 の適用可能性の原則。）
