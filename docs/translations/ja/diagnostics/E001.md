# E001 — 型の不一致

[English](../../../diagnostics/E001.md) | [日本語](../../ja/diagnostics/E001.md) | [简体中文](../../zh-CN/diagnostics/E001.md)

> 原文：[`docs/diagnostics/E001.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E001.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

式の型が、その周囲の文脈で期待される型と一致しない。

## よくある例

```almide
let x: Int = "hello"             // expected Int, got String
fn f() -> Int = "abc"            // body type doesn't match return type
list.map(xs, (x) => x + "!")     // closure return type conflicts with list element
```

## 特定のパターン（`try:` 断片付き）

### Unit の混入：fn 本体が `let` 束縛で終わる

```almide
fn sum_digits(n: Int) -> Int = {
    let abs_n = int.abs(n)           // ← `let` returns Unit, not Int
}
```

診断：

```
error[E001]: type mismatch in fn 'sum_digits': expected Int but got Unit
  try:
      // fn body ends with `let abs_n = ...` (a statement, returns Unit).
      // Add `abs_n` as the trailing expression so the fn returns Int:
      //
      //   let abs_n = <computation>
      //   abs_n                         // <-- add this line
```

コンパイラは AST から実際の束縛名を取り出し、断片内で示す。修正：末尾の式としてその名前を追加する。

### Unit の混入：if の分岐が代入である

```almide
fn clamp(x: Int, lo: Int) -> Int = {
    var val = x
    if val < lo then { val = lo } else val    // ← then-arm is Unit
}
```

診断：

```
error[E001]: type mismatch in if branches: expected Int but got Unit — Int is the declared return type, and the branch at line 3 produces it
  try:
      // the then-arm is `val = ...` (assignment, returns Unit).
      // Rewrite as a rebinding of `val`:
      //
      //   let new_val = if cond then <new-value-for-val> else val
```

実際の変数名（`val`）を示す。修正：`let new_x = if cond ... else ...` を使う。

### `!` なしの effect 呼び出しを型注釈付き `let` に束縛する

```almide
effect fn count() -> Int = 3

effect fn main() -> Unit = {
  let n: Int = count()             // ← the call is Result[Int, String]
  println(int.to_string(n))
}
```

診断：

```
error[E001]: type mismatch in let n: expected Int but got Result[Int, String]
  hint: the value is a Result[Int, String] — unwrap it first: `!` propagates the error (effect fn body), `?? fallback` supplies a default, or `match` handles ok/err
  try: (machine-applicable — `almide fix` applies it)
      !
```

ユーザー定義の `effect fn f() -> T` は呼び出し位置で `T!` になる（ADR-0002 §D6）。したがって、注釈が成功時の型を指定しており、欠けているのは `!` である。E005 が `g(count())` に、E041 が `let m = count()` に与えるものと同じ案内である。effect fn 本体内（lambda の外）では、呼び出し先が非 Result の `-> T` を宣言した `effect fn` である場合、`count()` → `count()!` の修正は **machine-applicable** となる。`!` は両端で宣言された型を表す唯一の記法だからである。`-> Result[T, E]` を宣言した呼び出し先は意図して Result を返すため、同じ `!` は提案にとどまる（作者の意図は `??` や `match` かもしれない）。pure fn 内、lambda 内、または呼び出しが複数行にまたがる場合は、編集を伴わないヒントを示す。

### 最初の arm が誤っている場合（#2927）

```almide
effect fn level() -> Level? = some({ label: "v", n: 1 })

effect fn apply(c: Cmd) -> Result[Level?, String] = match c {
  A => ok(level()),        // ← the mistake: level() without `!`
  B(_) => ok(none),
}
```

診断：

```
error[E001]: type mismatch in match arm: expected Result[Option[Level], String] but got Result[Result[Option[Level], String], String] — Result[Option[Level], String] is the declared return type, and the arm at line 5 produces it
  --> app.almd:4:8
  hint: add `!` to `level()`: without it the call's own Result is wrapped a second time. …
  try: (machine-applicable — `almide fix` applies it)
      !
```

末尾位置の match / if は fn の宣言戻り型に照らして検査するため、それに一致しない arm（または分岐）を報告する。その後に続く正しい arm を報告するわけではない。基準となる宣言型がなければ、最初の arm が型を決め、その旨をメッセージに示す（`the first arm at line N fixed
the type to T`）。宣言型では入れ子になっていない Result を呼び出しが返す `ok(f())` / `some(f())` の arm では、不足する `!` を示す。

### Option を返す effect fn に `!` なしで `??` を使う（#3522）

```almide
import args

effect fn main() -> Unit = {
  let ledger = args.option("ledger") ?? "ledger.toml"   // ← missing `!`
  println(ledger)
}
```

診断：

```
error[E001]: type mismatch in ?? fallback: expected Option[String] but got String
  --> app.almd:4:37
  hint: `args.option` is an effect fn (its call is `Result[Option[String], String]`): propagate its error with `!` before `??` — `args.option("ledger")! ?? "ledger.toml"`
  try: (machine-applicable — `almide fix` applies it)
      !
```

`-> Option[T]` を宣言した effect fn（`args.option`、または自作のもの）は `Result[Option[T], String]` として呼び出される。そのため、`??` だけでは `Err` に既定値を与えることになり、`Option[T]` 型の代替値が必要となる。代替値が `T` の場合、修正は `!` の後に `??` を置くこと。`!` がエラーを伝搬し、`??` が none に既定値を与える。束縛は `T` 型になるため、後の使用箇所で重複報告しない。代替値が `Option[T]` でも `T` でもない場合や、純粋な `Option[T]` 呼び出しに対する `??` は、通常の型不一致のままとなる。

## 修正（一般）

- 期待される型に合うようリテラル／値を調整する。
- 実際の式に合うよう明示的な型注釈を変更する。
- 標準ライブラリの補助関数で変換する：`int.to_string`、`int.parse(s)!`（対応する失敗チャネル内）または `int.parse(s) ?? 0`、`float.from(n)`、`int.from_saturating(x)`（小数部切り捨て）など。
- **型不一致の「got Unit」側が不自然な場合**は、値を返すはずの位置に、末尾の `let x = ...` や `x = y` 代入が置かれていないか確認する。

## Fix-it 判定

**mechanical** となるのは限定された形のみ（#2653）。`let x: T = f()` で `f` が `-> T` を宣言した `effect fn`、かつ束縛が effect fn 本体内にある場合、呼び出しに `!` を追加する修正は正確である（上記）。同じ呼び出し先の規則の下で、宣言された `Result` を一段深く入れ子にする `ok(f())` / `some(f())` の match arm または if 分岐にも同じ `!` が該当する（#2927）。また、左辺が `-> Option[T]` を宣言した `effect fn` の一行呼び出しで、代替値がその `T`、かつ `??` が lambda の外の effect fn 本体にある場合の `??` の前の `!` も該当する（#3522）。その他の E001 はすべて **not-fixable**。自動書き換えでは判断できない意味・設計上の問題を報告している。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
