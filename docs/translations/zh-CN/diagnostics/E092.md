# E092 — `@pure` fn 并不纯

[English](../../../diagnostics/E092.md) | [日本語](../../ja/diagnostics/E092.md) | [简体中文](../../zh-CN/diagnostics/E092.md)

> 原文：[`docs/diagnostics/E092.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E092.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

`@pure` 承诺空 effect 集合：该 fn 及其调用的一切没有 effect category、不写输出、不声明 abort。该属性过去被接受却忽略，因此作者以为不会发生时，标记 `@pure` 的 fn 仍可能打印、abort 或调用宿主（#3250）。现在会检查它。

`@pure` fn 在以下情况产生 E092：

- 它是 `effect fn`；
- 它是 `@extern` fn——无法检查外部函数体；
- 它能到达的任何调用使用 `println`、`eprintln`、`panic`、`assert`、`assert_eq` 或 `assert_ne`（ADR-0022 在普通 `fn` 中接纳的输出和 abort，在那里允许，在这里不允许）；
- 它能到达的任何调用使用带 effect category 的标准库函数（`io.write`、`process.pid`、`args.has_flag`、…；表为 `crates/almide-ir/src/effect.rs` 中的 `STDLIB_MODULE_EFFECTS`）；
- 它能到达的任何调用使用 `@extern` fn。

```almide
fn checked(n: Int) -> Int = {
  assert(n >= 0)
  n
}

@pure
fn double(n: Int) -> Int = checked(n) * 2   // ← E092
```

```
error[E092]: `@pure` fn `double` reaches `assert` via `checked`, and `assert` aborts the program when it fails
  --> main.almd:7:28
```

错误定位于 `@pure` fn 中通向不纯调用的调用，并指出路径。如果不纯调用位于比 `@pure` fn 文件更晚推断的模块中，就在该模块路径的首个调用处报告，并指出 `@pure` fn 及其文件和行号。

## 哪些不计入

- 通过函数类型参数或局部值调用。`@pure fn apply(f: (Int) -> Int,
  x: Int) -> Int = f(x)` 是纯的；传入函数在其编写位置判断（ADR-0026 D1）。
- 语言定义的 trap：除零、索引越界。它们仍可能终止运行，但不是声明的 abort。

## 修复

将不纯调用移到非 `@pure` 的调用者，或移除 `@pure`。保护输入的断言通常可变为全域表达式（`if n >= 0 then n else 0`），或由调用者处理的 `Result`。

## Fix-it 判定

**not-fixable**：将不纯调用移到调用者、改成全域表达式，还是移除属性，属于编译器无法作出的设计选择。错误指出调用与路径，不改写 fn。
