# E037 — 比较两个不同的类型

[English](../../../diagnostics/E037.md) | [日本語](../../ja/diagnostics/E037.md) | [简体中文](../../zh-CN/diagnostics/E037.md)

> 原文：[`docs/diagnostics/E037.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E037.md)，固定提交 `9a95b285`。这是供读者参考的非规范性译文，CLI 诊断输出仍为英文。

`==`、`!=`、`<`、`<=`、`>` 或 `>=` 被应用于两个不同类型的操作数。比较关联的是同一类型的两个值，不会隐式转换任何一侧。例如：`Int` 与 `String`（`1 == "1"`）、`Int` 与 `Float`（`1 == 1.0`）、列表与元素、不同元数的元组、两个记录类型、两个类型参数（`a: A == b: B`）、类型参数与具体类型、恰好只有一侧为 `Result`，或类型参数不同的同种容器（`Option[Int]` 与 `Option[String]`）。定宽类型只有通过字面量才能与标准类型相合（`x8 == 1`）；标准类型的*值*需要 `<type>.from(x)`。

检查在推断之后对已解析的操作数类型执行，因此同样适用于泛型：泛型函数体中的类型参数只与自身一致；会把同一参数绑定到两个类型的调用，将在调用处被拒绝。

此代码出现之前，同种容器的这些形式会通过 `check`，随后在“codegen produced invalid Rust”这道墙后因 rustc E0308 失败。

## 常见情况

```almide
helper() == ok(0)          // E037: Result on one side only
a == b                     // E037 when a: Option[Int], b: Option[String]
1 == "1"                   // E037: Int with String
n == 1.0                   // E037: Int with Float — `float.from(n) == 1.0`
fn same[A, B](a: A, b: B) -> Bool = a == b   // E037: A with B
```

## 诊断

```
error[E037]: operator '==' compares Option[Int] with Option[String]
  hint: == requires both operands to have the same type
```

（推断后检查的提示：“比较关联同一类型的两个值，不会隐式转换任何一侧 — …”。）

## 修复

- 先解包 Result 一侧（effect fn 中的 `!`、`?? fallback`，或对 ok/err 使用 `match`），或者比较两个同类型的 Result。
- 参数不匹配时，转换一侧，或者在解包后比较内部值。

## 原因

`==` 是同一类型上的深层结构相等。让永远不可能为真（或会被 rustc 拒绝）的比较在检查时暴露，才能维持“读到什么就执行什么”的契约。
