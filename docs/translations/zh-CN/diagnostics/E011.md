# E011 — 在 pure fn 的闭包内修改可变 var

[English](../../../diagnostics/E011.md) | [日本語](../../ja/diagnostics/E011.md) | [简体中文](../../zh-CN/diagnostics/E011.md)

> 原文：[`docs/diagnostics/E011.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E011.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

纯函数（`fn`）中声明的 `var` 正在被该函数内嵌套的 lambda／闭包重新赋值。在 Almide 的纯语义中，闭包按值捕获；在闭包内修改捕获的 `var` 需要隐藏的共享单元，这会破坏引用透明性。

## 常见情况

```almide
fn count_evens(xs: List[Int]) -> Int = {
    var count = 0
    let _ = list.map(xs, (x) => {
        if x % 2 == 0 then count = count + 1    // E011: closure mutation
        x
    })
    count
}
```

## 诊断

```
error[E011]: mutable variable 'count' is mutated inside a closure in a pure function — use effect fn instead
  hint: Move the mutation out of the closure, or mark the enclosing function as `effect fn`
```

## 修复——pure fn 中优先采用函数式形式

计数／累积请使用 `list.fold` / `list.count`：

```almide
fn count_evens(xs: List[Int]) -> Int =
    list.count(xs, (x) => x % 2 == 0)
```

转换请使用 `list.map`：

```almide
// ✗
fn doubles(xs: List[Int]) -> List[Int] = {
    var out: List[Int] = []
    let _ = list.map(xs, (x) => {
        out = out + [x * 2]
        x
    })
    out
}

// ✓
fn doubles(xs: List[Int]) -> List[Int] = xs |> list.map((x) => x * 2)
```

## 修复——确实需要修改时标记为 `effect fn`

如果修改确实涉及副作用（例如累积 I/O 结果），外层函数应为 `effect fn`：

```almide
effect fn gather(xs: List[String]) -> Result[List[String], String] = {
    var out: List[String] = []
    for x in xs {                     // `for` is allowed; it's not a closure
        let text = fs.read_text(x)!
        out = out + [text]
    }
    ok(out)
}
```

`for` / `while` 循环不是闭包，可以修改外部 `var` 而不触发 E011。只有 `lambda`（`(x) => ...`）捕获才触发检查。

## 原因

纯函数必须具有引用透明性：调用两次 `f(x)` 必须产生相同值。如果闭包可以修改外部状态，这个不变量就被破坏。Almide 静态捕获此问题，要求作者重构为函数式基本操作（通常也更短、更适合 LLM），或升级为 `effect fn`。
