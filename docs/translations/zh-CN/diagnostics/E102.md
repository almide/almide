# E102 — `regex.new` 中的无效模式

[English](../../../diagnostics/E102.md) | [日本語](../../ja/diagnostics/E102.md) | [简体中文](./E102.md)

> 原文：[E102.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E102.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

`regex.new("…")` 从程序知道有效的模式创建 `Regex`。当模式是字符串字面量时，`almide check` 使用正则引擎自身的检查器检查，凡引擎会拒绝的都拒绝：同一模式在运行时构造，会以 `Error: invalid regex: <reason>` 中止（C-395）。原因与 `regex.compile` 在 err 中返回的相同：`unclosed group`、`unmatched )`、`unclosed character class`、`nothing to repeat`、`malformed repetition`、`repetition minimum exceeds maximum`、`invalid class range`、`trailing backslash`、`unsupported escape \X`（及 `… in a class`）、`named groups are not supported`、`lookaround is not supported`、`flags are only supported at the start of the pattern`、`unsupported group syntax`、`groups nested deeper than 250`，以及 `pattern too large: more than 20000 states`。

```almide
import regex

fn main() -> Unit = println("${regex.is_match(regex.new("(a|b"), "abc")}")   // ← E102
```

```
error[E102]: invalid regex: unclosed group
  hint: write the pattern in the syntax docs/stdlib/regex.md lists; a pattern built at run time goes through regex.compile, which answers err(reason) instead of aborting
```

## 修复

1. 按 [docs/stdlib/regex.md](../../../stdlib/regex.md) 列出的语法编写模式：闭合分组或字符类，对希望按字面理解的元字符转义（`regex.escape` 可为字符串完成此操作），给分组编号而非命名。
2. 过大的模式拥有超过20,000个 Pike VM 状态：嵌套计数相乘（`((a){200}){200}` 是40,000份 `a`）。匹配形状而不是展开计数，或在代码中检查数量。
3. 来自输入的模式应交给 `regex.compile(p)`，它返回 `err(reason)`，让程序决定如何处理。

## Fix-it 判定

**not-fixable**：被拒字符原本想按字面使用（转义它），还是作为引擎没有的语法（重写模式），由作者选择；超过状态限制的模式需要不同的模式。诊断指出原因，不会重写代码。（`mechanical` = 无人值守重写；`conditional` = 修复建议需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）

## 原因

引擎过去会宽松读取语法之外的模式：`(` 变成到处匹配的空组，`a{` 变成字面花括号，`(?P<n>a)` 变成包含 `P<n>a` 的普通组。每一种都无错误地给出了无人写过的含义（#3942）。写在程序中的模式会在运行前被拒绝。
