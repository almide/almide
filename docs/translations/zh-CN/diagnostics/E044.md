# E044 — main() 返回 Unit

[English](../../../diagnostics/E044.md) | [日本語](../../ja/diagnostics/E044.md) | [简体中文](../../zh-CN/diagnostics/E044.md)

> 原文：[`docs/diagnostics/E044.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E044.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

纯 `main` 声明 `Unit`：程序的结果是输出，而不是返回值。C/Go 风格的 `fn main() -> Int` 在结构上通过类型检查，但入口会原样生成；原生驱动曾生成 `pub fn main() -> i64`，被 Rust 拒绝（`main` 只能返回 `Termination` 类型）。这种语言从未支持的签名最终表现为归咎编译器的错误（“codegen produced invalid Rust — this is an Almide bug”）。现在 checker 提前拒绝它（由 #912 诊断分歧视角发现）。

```almide
fn add(x: Int, y: Int) -> Int = x + y
fn main() -> Int = add(1, 2)   // ← E044
```

带 EFFECT 的 `main` 不受此限制：`effect fn main() -> T` 经过 carrier 包装层，解包 Result 并丢弃 Ok 载荷，因此任何 `T` 都可以。

## 修复

打印该值，或显式设置进程退出码：

```almide
fn add(x: Int, y: Int) -> Int = x + y

fn main() -> Unit = println("${add(1, 2)}")
```

```almide
import process

effect fn main() -> Unit = {
  process.exit(3)
}
```

## Fix-it 判定

**not-fixable** — 错误报告的是自动改写无法判断的语义／设计问题。（`mechanical` = 无人值守的修复器可以应用改写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动改写。#1486 的适用性原则。）
