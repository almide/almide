# E024 — 整数字面量超出范围

[English](../../../diagnostics/E024.md) | [日本語](../../ja/diagnostics/E024.md) | [简体中文](./E024.md)

> 原文：[E024.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E024.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

整数字面量无法容纳在其使用的类型中。降级转换和两个代码生成器都使用 `.unwrap_or(0)` 解析字面量，因此没有这项检查时，越界字面量会在两个目标上都**悄然变成 0**，没有诊断。检查会识别类型，并在类型推断之后运行，因此采用的是字面量的*实际*类型范围，而不总是 `i64`。

字面量越界有两种原因，各有对应提示：

| | 原因 | 修复 |
|---|---|---|
| **大小** | 数值相对于位宽过大 | 使用更小的字面量或更宽的类型 |
| **符号** | 在无符号类型中使用负字面量 | 去掉 `-`，或使用相同位宽的有符号类型 |

## 常见情况

### 大小

```almide
fn main() -> Unit = println(int.to_string(9223372036854775808))  // E024: > i64::MAX in an Int context
```

`9223372036854775808` 是 `i64::MAX + 1`。在默认 `Int`（i64）上下文中无法表示，因此会变为 0。

```
error[E024]: integer literal '9223372036854775808' is out of range for Int
  hint: Int would silently fold to 0 here; its range is -9223372036854775808..=9223372036854775807, so use a literal within it, or model larger magnitudes as Float (lossy) or a parsed string
```

### 符号

```almide
fn main() -> Unit = {
  let k: UInt64 = -5   // E024: UInt64 has no negative values at all
  println(uint64.to_string(k))
}
```

无符号类型没有负值，所以问题不在于 `5` 有多大——`5` 完全在范围内，而 `-5` 无论大小如何都无法表示。原生 `rustc` 会直接拒绝输出的 `-5u64`（`error[E0600]: cannot apply unary
operator '-' to type 'u64'`）。因此，没有 E024 时，这是 check 通过而 build 失败的缺口，并非悄然变成 0。

```
error[E024]: integer literal '-5' is out of range for UInt64
  hint: UInt64 is unsigned — it has no negative values at all; drop the '-', or use the signed Int64 if the value can go below zero
```

`-0` 例外：它就是 `0`，所有无符号类型都能表示。

## 修复

- 如果数值大小合理，使用更宽／无符号类型。`UInt64` 可覆盖其声明的完整值域（槽位以位模式保存上半区，随后由无符号路径读回 — #872）：
  ```almide
  let big: UInt64 = 18446744073709551615  // u64::MAX — division, ordering and
                                          // printing are all unsigned
  ```
- `i64::MIN` 的绝对值加上负号后是有效的有符号值（正是 `-` 让它能够表示）：
  ```almide
  let lo: Int = -9223372036854775808      // i64::MIN — fine
  ```
- 对特别大的数值，使用 `Float`（有损）表示，或以字符串保存。
- 对于符号错误，改用相同位宽的有符号类型：`UInt8` → `Int8`、`UInt16` → `Int16`、`UInt32` → `Int32`、`UInt64` → `Int64`：
  ```almide
  let delta: Int32 = -5                   // was UInt32
  ```

## 为什么检查要识别类型

范围依赖于字面量的上下文，在类型求解后确定：

- `Int` / `Int64` → i64（`-9223372036854775808 .. 9223372036854775807`）；单独的正数 `9223372036854775808` 会溢出，但 `-9223372036854775808` 达到 `i64::MIN`，是有效的。
- `UInt64` → `0 .. 18446744073709551615`，即其完整声明值域（#872）；`Int8`/`UInt8`/… 使用各自的位宽。下界为 `0`，所以任何非零字面量取负后都会越界，与位宽无关。

仅使用 `i64` 的简单检查会错误拒绝有效的 `UInt64` 字面量或带负号的 `i64::MIN` 大小，因此检查会等待字面量的类型被解析／注解确定。
