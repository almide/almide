# E113 — match 过于复杂，无法检查穷尽性

[English](../../../diagnostics/E113.md) | [日本語](../../ja/diagnostics/E113.md) | [简体中文](../../zh-CN/diagnostics/E113.md)

> 原文：[`docs/diagnostics/E113.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E113.md)，固定提交 `9a95b285`。这是供读者参考的非规范性译文，CLI 诊断输出仍为英文。

某个 `match` 的穷尽性与可达性检查超出了 `exhaustiveness_steps` 编译成本预算（ADR-0030）。判定一组模式是否覆盖所有值，在最坏情况下是指数复杂度：若 `Bool` 元组的分支在每一列都列出 `true` 和 `false`，检查就会在每列分成两路。

```almide
fn f(a: Bool, b: Bool, c: Bool /* … 24 more */) -> Int = match (a, b, c /* … */) {   // ← E113
  (true, _, _ /* … */) => 0,
  (_, true, _ /* … */) => 1,
  // … one arm per column and constructor
}
```

## 修复

拆分 match：先匹配第一个分量，然后在各分支内匹配剩余部分；或者添加一个统一处理剩余情况的 `_ =>` 分支。

## 原因

编译器处理不可信源码，因此检查用计数预算而非超时来限制：同一 match 在每台机器上得到相同判定。无法完成检查的 match 不会被假定为穷尽。源码不能提高预算；命令行上的 `--budget exhaustiveness_steps=N` 可以（`almide budgets`）。

测试样例：`tests/diagnostics/e113-{bool,option,variant}-matrix-too-complex`；门禁是 `tests/compile_budget_test.rs`。

## Fix-it 判定

**not-fixable**：如何拆分 match 是有关程序的决策。（`mechanical` = 无人值守的修复工具可以应用改写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动改写。#1486 的适用性原则。）
