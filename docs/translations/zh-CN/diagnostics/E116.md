# E116 — 响应的 Content-Type 由其正文类型写入

[English](../../../diagnostics/E116.md) | [日本語](../../ja/diagnostics/E116.md) | [简体中文](../../zh-CN/diagnostics/E116.md)

> 原文：[`docs/diagnostics/E116.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E116.md)，固定提交 `9a95b285`。这是供读者参考的非规范性译文，CLI 诊断输出仍为英文。

响应的 `Content-Type` 就是正文的类型（ADR-0032，row 11e）：String 是 `text/plain; charset=utf-8`，`html.*` 构造 `text/html`，获授权包的安全类型使用其自己的类型，`Value` 是 `application/json`，其他媒体类型用 `http.typed("text/csv", bytes)` 表达。按名称写入头部会给正文重新贴标签；将 String 作为 `text/html` 提供，会把攻击者文本作为脚本运行，因此响应上的 `http.set_header` 和 `http.with_headers` 会拒绝它。名称写成字面量时在此拒绝；计算得到的名称在调用运行时中止。请求不是响应正文，可以携带任意 Content-Type。

```almide
import http

fn report(rows: String) -> HttpResponse =
  http.with_headers(200, rows, [("Content-Type", "text/csv")])   // ← E116
```

```
error[E116]: `http.with_headers` writes `Content-Type` by name, and a response's `Content-Type` is written from its body's type
```

## 修复

```almide
import http

fn report(rows: String) -> HttpResponse =
  http.with_headers(200, http.typed("text/csv", bytes.from_string(rows)), [])
```

当调用在一行内、正文是 String、类型是 `http.typed` 所接受的类型时，`almide fix` 会执行此改写（`r` 为名称时，`set_header(r, "Content-Type",
t)` 变为 `http.with_body(r, http.typed(t,
http.body_bytes(r)))`）。

## 原因

正文拥有哪个头部，只在写入函数上声明一次（`stdlib/http.almd` 中的 `@header_write(…, owned = "__http_response_body_headers")`）；此检查与运行时拒绝都读取该声明。

## Fix-it 判定

上述单行字面量形式为 **mechanical**（无人值守修复工具可应用改写）；其他情况下诊断不提供修复。（`mechanical` = 无人值守的修复工具可以应用改写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动改写。#1486 的适用性原则。）
