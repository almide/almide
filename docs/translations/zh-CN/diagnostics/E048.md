# E048 — 目标类型不具有的变体模式

[English](../../../diagnostics/E048.md) | [日本語](../../ja/diagnostics/E048.md) | [简体中文](../../zh-CN/diagnostics/E048.md)

> 原文：[`docs/diagnostics/E048.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E048.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

构造器模式必须指明**目标**实际具有的分支。E048 涵盖未满足这一要求的三种方式：

| 模式 | 目标 | |
|---|---|---|
| `ok(..)` / `err(..)` | `Option` | 错误的类型系列 |
| `some(..)` / `none` | `Result` | 错误的类型系列 |
| `some`/`none`/`ok`/`err` | 用户变体 | 对用户 ADT 使用内置 carrier |
| 用户 ctor `C(..)` | 不含 `C` 的变体，或 Option / Result | 外来分支 |
| 用户 newtype 的 `Value(..)` / 记录的 `Value { .. }` | 标准库的 `Value`（`FileStat`，…） | 标准库类型与遮蔽它的用户类型 |

`some(..)` / `none` 解构 **Option**；`ok(..)` / `err(..)` 解构 **Result**。在 Almide 中两者是独立类型，一个系列的模式不会匹配另一个系列的目标，也不会匹配具有自身分支的用户变体。

```almide
fn first_plus_one(xs: List[Int]) -> Int = match list.get(xs, 0) {
  ok(a) => a + 1,   // ← E048: `list.get` returns `Int?`, an Option
  _ => 0,
}
```

典型原因是猜错了生产函数的返回类型：`list.get`、`map.get`、`string.find` 都返回 `T?`（Option），而 `int.parse`、`fs.read_text`、`json.parse` 返回 Result。读取生产函数的签名是可靠选择 arm 写法的方法。

## 为什么是错误，而非静默绑定

在 #1341 之前，checker 只拒绝针对普通标量的构造器模式。跨类型系列的模式会漏过，将载荷绑定为 `Ty::Unknown`，通过所有后续 pass，最终在 codegen 爆发：

```
error: [COMPILER BUG] internal type resolution failed before codegen
    [fn f:3:12] unresolved Var ty=Unknown var_id=1 name=a stored_ty=Unknown
  hint: please report this at https://github.com/almide/almide/issues
```

native 上如上所示，wasm 上则是“outside the executable subset”壁垒。两者都将程序中普通的类型错误归咎于编译器，也都没指出只需改一个词的修复——属于 #1266 的错误归因类别。E048 将同样的拒绝移到唯一能同时看到模式与目标类型的位置。

**外来分支**情况更糟：来自其他变体的用户 ctor（`match shape { Red(r) => .. }`）将载荷绑定为 Unknown 并到达 codegen，在 native 上生成**无效 Rust**（`codegen produced invalid Rust — this
is an Almide bug`），在 wasm 上遇到壁垒。

声明的覆盖范围仅限结构已知的目标。仍在推断的类型，或属于 opaque alias 的 `Named` 类型（其 `SafeHtml(s)` 解构是合法的），保持静默，不影响错误恢复。

还有一种情况是**标准库类型与遮蔽它的用户类型**（#1828、#1835）。程序声明自己的 `Value`——记录或 opaque newtype `mod type
Value = String`——以 `self.Value`（模块 `m` 中为 `m.Value`）拥有它，而 `json.parse` 仍返回标准库的 `Value`。将用户类型的模式用于 json 值会产生 E048，并使用 E013 的提示指出两种类型：

```
error[E048]: pattern `Value(..)` is not a case of `Value`
  in match pattern
  hint: `Value` is the `value` module's type and has no constructor to destructure.
        Here `Value` is the `value` module's type, not your `type Value` (which is
        `self.Value`): a same-name declaration never rebinds a stdlib type, so read
        this value through `value.*` — or rename your type to keep the two apart.
```

在此检查出现之前，模式将载荷绑定为 `Ty::Unknown` 并进入 codegen：native 上为 rustc E0308，而 structural wasm 路径将 json 值的载荷当作用户的 `String` 读取。

## 诊断形式

```
error[E048]: pattern `ok(..)` destructures a Result, but the subject is `Option[Int]`
  in match pattern
  hint: Option and Result are separate types: an Option is matched with `some(..)`
        / `none`, a Result with `ok(..)` / `err(..)`. Write `some(..)` here.
  try:
      some(..)
```

`try:` 片段始终对应目标所属系列的**相同 arm 位置**：成功 arm ↔ 成功 arm，失败 arm ↔ 失败 arm。唯一不对称的一对是 `err(e)` ↔ `none`：Option 的失败 arm 不携带错误值，所以绑定名消失；反方向 `none` ↔ `err(..)` 则增加绑定。

## 修复

使用目标实际所属系列的写法。

```almide
fn first_plus_one(xs: List[Int]) -> Int = match list.get(xs, 0) {
  some(a) => a + 1,
  _ => 0,
}
```

如果原意是让值成为 Result，请在生产函数处转换，而不是在模式处转换。例如用 `list.get(xs, 0) ?? 0` 提供后备值，或通过 `some`/`none` match，在各 arm 中构造所需的 `ok(..)` / `err(..)`。

对用户变体，匹配其自身分支；提示会列出它们：

```
error[E048]: pattern `Red(..)` is not a case of `Shape`
  hint: the subject's cases are: Circle / Square.
```

## Fix-it 判定

**conditional** — 原本想使用哪个构造器系列取决于意图。（`mechanical` = 无人值守的修复器可以应用改写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动改写。#1486 的适用性原则。）
