# E009 — 对不可变绑定重新赋值

[English](../../../diagnostics/E009.md) | [日本語](../../ja/diagnostics/E009.md) | [简体中文](./E009.md)

> 原文：[E009.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E009.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

`let x = ...` 创建不可变绑定。可变绑定请使用 `var`。

## 常见情况

```almide
let count = 0
count = count + 1            // E009: 'count' is immutable
```

## `try:` 片段

```
error[E009]: cannot reassign immutable binding 'count'
  hint: Use 'var count = ...' instead of 'let count = ...' to declare a mutable variable
  try:
      // let count = ...  →  var count = ...
      var count = <initial value>
```

编译器从 AST 提取实际名称。当被重新赋值的绑定是**函数参数**（不可变）时，片段会变化：

```
  hint: 'count' is a function parameter (immutable). Use a local copy: var count_ = count
  try:
      // 'count' is a parameter — make a mutable copy:
      var count_ = count
      // ...then reassign count_ instead of count
```

## 修复

- 使用 `var` 实现可变性（如果修改确实是设计意图，优先使用此方法）：
  ```almide
  var count = 0
  count = count + 1          // OK
  ```
- 优先采用函数式风格：生成新值，让旧名称保持不可变：
  ```almide
  let count = 0
  let count2 = count + 1
  ```
- 特别是对于参数，创建一个局部副本：
  ```almide
  fn step(x: Int) -> Int = {
      var x_ = x
      x_ = x_ + 1
      x_
  }
  ```

## 为什么默认不可变

不可变性最大化 LLM 修改的存活率：读者可以相信 `x` 在整个作用域中代表相同的值。显式的 `var` 表明修改意图，通常与 `effect fn`（有副作用的代码）或局部累加器模式一起出现。

对于看似需要修改状态的纯函数（循环），优先采用递归：

```almide
fn count_up(n: Int) -> Int =
    if n == 0 then 0
    else 1 + count_up(n - 1)
```
