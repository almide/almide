# E084 — 字面退出码超出退出状态范围

[English](../../../diagnostics/E084.md) | [日本語](../../ja/diagnostics/E084.md) | [简体中文](../../zh-CN/diagnostics/E084.md)

> 原文：[`docs/diagnostics/E084.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E084.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

`process.exit` 接受从 `0` 到 `255` 的 POSIX 退出状态。直接调用传入范围之外的整数字面量时，checker 会指向参数并拒绝程序。

```almide
import process
effect fn main() -> Unit = process.exit(256) // E084
```

成功选择 `0`，失败选择 `1` 至 `255` 的代码：

```almide
import process
effect fn main() -> Unit = process.exit(1)
```

此检查涵盖模块别名、选择性导入、管道调用、带基数字面量、括号及一元负号。计算得到的参数在运行时检查，超出范围的值以 `Error: exit code must be in 0..=255` 中止。checker 不求值任意表达式，也不追踪存入函数值变量的别名。

所有目标的检查相同。WASI preview-1 构建（`almide build --target wasm`，在标准 runtime 上运行）只能传递 `0..=125`。它在运行时而非检查时拒绝 126..=255，显示 `Error: a WASI preview-1 build cannot exit with a code in 126..=255` 并以代码 1 退出（C-350）。

Dialect 4（0.63）以 `0..=125` 范围引入此诊断。自 #2780 起范围恢复为 `0..=255`，只会接纳更多程序，因此无需 dialect 变更。

## Fix-it 判定

**conditional** — 合适的失败代码取决于程序协议，因此编译器不自动选择替代值。
