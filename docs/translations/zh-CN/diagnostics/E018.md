# E018 — 无法推断元素类型的空集合

[English](../../../diagnostics/E018.md) | [日本語](../../ja/diagnostics/E018.md) | [简体中文](../../zh-CN/diagnostics/E018.md)

> 原文：[`docs/diagnostics/E018.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E018.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

空集合字面量（`[]`、`[:]`），或不接收含元素参数的泛型集合构造器（`set.new()`、`map.new()`、`list.with_capacity(n)`），被用于**周围上下文无法确定元素类型的位置**。空集合没有元素可供推断，因此元素类型无法确定。

Almide 遵循 **Rust 和 Swift**：无法确定类型的空集合是编译错误，要求显式类型注解，绝不静默默认成任意元素类型。与 Rust/Swift 一样，可观察性无关紧要：`for _ in []` 即使从不读取元素也会报错。

此错误由前端类型检查器在代码生成前产生，因此在**两个**目标上都是硬错误。过去两者存在分歧：Rust 在生成的 `Vec::<_>::new()` 上泄漏 `rustc` 的 `error[E0282]: type annotations needed`（包装为“Almide bug”），而不携带元素类型的 WASM 能编译运行。在类型检查时拒绝它，使两个目标保持一致，并产生可操作的消息。

## 常见情况

```almide
let n: Int = list.len([])            // element of `[]` never constrained
let c: Int = set.len(set.new())      // element of the set never constrained
for _ in [] { }                      // iterated element type undecidable
```

```text
error[E018]: cannot infer the element type of empty list `[]`
```

## 修复

标注元素类型。最可靠的形式是带类型的绑定：

```almide
let xs: List[Int] = []
let n: Int = list.len(xs)

let s: Set[Int] = set.new()
let c: Int = set.len(s)

let empty: List[Int] = []
for _ in empty { }                   // for over an explicitly-typed list
```

对于调用参数位置的单独列表字面量，也可以内联标注：

```almide
let n: Int = list.len([]: List[Int])
```

如果空集合是字段值、默认字段值或赋值，其元素类型取自声明的字段／变量类型，无需额外注解：

```almide
type Bag = { items: List[Int] }
let b = Bag { items: [] }            // element inferred as Int from the field
```

## Fix-it 判定

**conditional** — 元素类型注解只能从意图得知。（`mechanical` = 无人值守的修复器可以应用改写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动改写。#1486 的适用性原则。）
