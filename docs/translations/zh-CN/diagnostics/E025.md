# E025 — 无法推断具体类型（无约束的类型槽位）

[English](../../../diagnostics/E025.md) | [日本語](../../ja/diagnostics/E025.md) | [简体中文](./E025.md)

> 原文：[E025.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E025.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

绑定的类型包含一个没有任何上下文能够确定的槽位。典型情况是静态上始终为 `ok(...)` 的值的错误类型——它只能通过未被使用的 `err` 分支触及，因此始终没有约束。

```almide
fn main() -> Unit = {
  let r0: Result[Int, String] = ok(7)
  let r = result.or_else(r0, (e) => ok(0))   // ← error type never pinned
  println("done")
}
```

Almide 遵循 Rust/Swift 的规则（参见 Rust E0282）：无法确定的类型槽位就是编译错误，即使从未构造该类型的值；绝不会悄然赋予默认类型，否则会造成 `check` 通过而代码生成失败。

## 修复

为绑定（或 lambda 结果）注解完整类型，从而确定该槽位：

```almide
let r: Result[Int, String] = result.or_else(r0, (e) => ok(0))
```

## 没有任何信息能够确定的类型参数

同一规则也适用于泛型 fn 的调用：如果没有参数提及其类型参数，结果也无法确定它（参见 Rust E0282，“无法推断在函数 `tag` 上声明的类型参数 `T` 的类型”）：

```almide
fn tag[T](s: String) -> Int = string.len(s)

effect fn main() -> Unit = {
  println(int.to_string(tag("abc")))   // ← nothing determines `T`
}
```

在调用处指定类型实参——`tag[Int]("abc")`；或者，当签名完全不使用该参数时，将其从声明中删除：`fn tag(s: String) -> Int`。如果该参数确实出现在结果中（`fn dekode[T](s: String) -> Option[T]`），调用会改为报告无约束的结果类型，只报告一次。

## Fix-it 判定

**conditional** — 具体类型必须由作者给出。（`mechanical` = 无人值守的修复器可以应用重写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）
