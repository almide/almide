# E027 — fan 组合器的废弃记录：旧写法会指出替代写法

[English](../../../diagnostics/E027.md) | [日本語](../../ja/diagnostics/E027.md) | [简体中文](./E027.md)

> 原文：[E027.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E027.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

E027 是 fan 表层语法的迁移代码。每种已废弃写法都会在提示中给出替代写法。

## `fan.race` → `fan.min(clock)`、`fan.any` → `??` / `list.find_map`（dialect epoch 14）

在其他生态中，`race` 表示“最先完成”（JS `Promise.race`、Haskell `race`、`select`），`any` 表示“不保证顺序”（`Promise.any`、`findAny`、Rayon `find_any`）。Almide 的这两种形式都不按这些方式选择，因此 dialect epoch 14 废弃了两个名称（ADR-0028，于 2026-10-18 接受）：

| 过去 | 现在 | 选择什么 |
|---|---|---|
| `fan.race { a(), b() }`、`fan.race(budget) { … }`、`fan.race(xs, f)`、`fan.race(budget, xs, f)` | `fan.min(compute.ms(5)) { a(), b() }` / `fan.min(compute.ms(5), xs, f)` — clock 参数必需 | 预算内消耗确定性计算量最少的 Ok；相同时按源码顺序 |
| `fan.any { a(), b() }` | `a() ?? b() ?? fallback` | 源码顺序中的第一个 Ok；`??` 右侧仅在左侧失败时运行，因此后续候选不会运行 |
| `fan.any(xs, f)` | `list.find_map(xs, (x) => f(x)?) ?? fallback` | 列表顺序中的第一个 Ok；`?` 将元素的 Err 转为 `none`，从而跳过该元素 |
| `fan.first_ok`（epoch 14 草案的临时名称） | 相同的两种写法 | — |

`fan.any` 并非改名，而是删除：依次尝试候选按定义就是顺序执行，其他语言也不会将它放在并发库中（Rust `Iterator::find_map`、OCaml `List.find_map`、Elixir `Enum.find_value` 都是列表函数）。`fan.min` 的 clock 参数说明“最少”衡量什么；没有它，`fan.min { 3, 5 }` 会被理解为最小值，因此不带 clock 的形式是解析错误，而非 E027。

```almide
effect fn main() -> Unit = {
  let w = fan.race { solve_fast(), solve_slow() } ?? -1   // ← E027: write fan.min(compute.ms(5)) { … }
  let f = fan.any { fetch_a(), fetch_b() } ?? -1           // ← E027: write fetch_a() ?? fetch_b() ?? -1
}
```

实时时序选择——`fan.min(duration.ms(n)) { … }`，选取最先完成的分支、分支可执行 I/O、未胜出者在下一计量点或 I/O 边界取消并等待结束——已经确定（ADR-0028），将在后续变更（#3788）中落地；在此之前它是类型错误，不是 E027。

## 更早的移除

`fan.timeout(ms, thunk)` 被直接移除，`fan.race` / `fan.any` / `fan.settle` 的 thunk 列表形式被确定性的块头替代。调用任何旧形状都会得到 E027，并附带各函数的迁移提示（“changed signature: the thunk-list form was removed; ... is now a block head”）。

`fan.timeout` 本身在 0.29.0 中移除（契约 C-006）。基于实际时钟的超时没有可移植的跨目标含义：原生可以用真实线程和 `recv_timeout` 强制执行，但 wasm 没有时钟、调度器或线程，因此 thunk 总是运行至完成，超时从不发生。它也是标准库中唯一一个结果不由程序及其输入决定的表层 API：即使两次原生运行，是否触发截止时间也取决于机器负载。这两种性质都违背语言的核心承诺：各目标可观察输出逐字节一致。

```almide
effect fn main() -> Unit = {
  let r: Result[Int, String] = fan.timeout(5000, () => slow())   // ← E027
}
```

## 修复

在调用程序的宿主边界强制执行截止时间：

```bash
timeout 5 ./app          # POSIX
wasmtime run app.wasm    # + host-side deadline of your choice
```

在 Almide 内，直接运行工作，或者用确定性的 `fan.bounded(compute.ms(n)) { … }` 限制，或使用 oracle 层的 `fan.timeout(duration.ms(n)) { … }`（替代调用形式的块头）：

```almide
effect fn main() -> Unit = {
  let r: Result[Int, String] = fan.bounded(compute.ms(5)) { slow() }
}
```

## E027 现在涵盖三次废弃

`fan.timeout`（0.29.0）、`fan.race(thunks)`（0.42.0）和上述 epoch 14 的一对名称。前两者因同一原因被移除，只是表达方式不同：实际时钟截止时间和实际时钟竞速都会使结果取决于机器时序，而 Almide 的模型是确定性数据并行——`fan` 可以并行执行，但可观察行为定义为按列表顺序逐个求值（见[并发立场](../../../roadmap/active/concurrency-stance.md)）。oracle 层（`fan.timeout(duration…)` 以及未来的 `fan.min(duration…)`）允许时序作为已记录的宿主输入，但绝不作为隐含输入。

`fan.race(thunks)` 还存在废弃提示指出的另一个问题：它从未竞速。脱糖将 `fan.race([t0, t1, …])` 替换为 t0 的函数体，从不求值其他项，因此它实际上就是 `thunks[0]()`。

迁移：

| 已移除 | 如果你想要 | 使用 |
|---|---|---|
| `fan.timeout(...)` | 截止时间 | 调用程序的宿主边界（`timeout 5 ./app`），或 `fan.timeout(duration.ms(n)) { … }` |
| `fan.race(ts)` | thunk[0] 的结果 | `ts[0]()` — 直接调用 |
| `fan.race(ts)` / `fan.any { … }` | 第一个成功的候选 | `a() ?? b() ?? fallback` |
| `fan.race { … }` | 最少的确定性计算量 | `fan.min(compute.ms(n)) { … }` |

## Fix-it 判定

**not-fixable** — 此错误报告的是自动重写无法决定的语义／设计问题。（`mechanical` = 无人值守的修复器可以应用重写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）
