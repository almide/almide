# E062 — shebang 缺少 `-S`（警告）

[English](../../../diagnostics/E062.md) | [日本語](../../ja/diagnostics/E062.md) | [简体中文](./E062.md)

> 原文：[E062.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E062.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

`#!/usr/bin/env almide run` 在 macOS 上能运行，在 Linux 上会失败。

Darwin 内核在调用 `env` 前会按空白拆分 shebang 行。Linux 的 `binfmt_script` 不会：`env` 将余下整行作为一个参数接收，并寻找字面名称为 `almide run` 的程序。

```
$ /usr/bin/env "almide run" --version
env: almide run: No such file or directory
```

`env -S`（coreutils 8.30，2018）正是为这种拆分而存在。故障不会在编写脚本的机器上重现，而错误写法恰好是作者自然会写出的：见过的 shebang 都只有一个词（`#!/usr/bin/env python3`），所以只是再加第二个词，从未学到 `-S`。在此警告出现之前，曾连续五个脚本都遗漏它（#2159）。

```almide
#!/usr/bin/env almide run        // ← E062: this shebang does not run on Linux

fn main() -> Unit = println("hi")
```

## 修复

在 `env` 后紧接着插入 `-S`：

```almide
#!/usr/bin/env -S almide run

fn main() -> Unit = println("hi")
```

警告下的 `try:` 行就是这个精确的改写。

## 不触发的情况

判断只依据第1行文本——不查找 PATH，不探测宿主：

- 解释器不是 `env`（`#!/usr/local/bin/almide run`——两个平台的内核都会把 `run` 直接交给 almide）
- 已存在 `-S` / `--split-string`，包括位于组合标志中（`-iS`）
- `env` 后只有一个程序词（`#!/usr/bin/env almide`），不计标志和 `NAME=value` 赋值

在 `--deny-warnings` 下，它与其他警告一样会成为错误。

## Fix-it 判定

**mechanical** — 在 `env` 后插入 `-S` 是对相同命令行的纯粹表记改写：解释器、程序和参数相同，现在两个内核以相同方式拆分。`almide fix` 会无人值守应用它（发出方式为 `with_machine_fix`，替换第1行全部内容）。（`mechanical` = 无人值守的修复器可以应用重写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）
