# E022 — `!` 运算符位于可传播错误的上下文之外

[English](../../../diagnostics/E022.md) | [日本語](../../ja/diagnostics/E022.md) | [简体中文](./E022.md)

> 原文：[E022.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E022.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

后缀 `!` 解包 `Option[T]` 或 `Result[T, E]`，失败时通过最内层兼容的失败通道退出。该通道可以属于 effect fn、返回 Result/Option 的纯 fn，或推断为可失败的 lambda。测试块则使用 test-unwrap 语义。

普通的不会失败的 fn 没有失败通道：

```almide
fn parse_number(s: String) -> Int = int.parse(s)!   // E022
```

## 修复

如果希望传播失败，请声明可失败的返回类型：

```almide
fn parse_number(s: String) -> Int! = int.parse(s)!
```

或者就地处理失败：

```almide
fn parse_or_zero(s: String) -> Int = int.parse(s) ?? 0
```

lambda 的 `!` 属于它自己的通道，而不是外围 fn。错误类型来自上下文类型，或其 `!` 操作数类型的合并（ADR-0021）；接收可失败回调的调用本身也可能返回 Result。只有确实存在效应时才需要添加 `effect`，仅仅是可能失败的纯计算并不需要。

## 错误类型不匹配（#2635）

即使 `!` 可以传播，它携带的错误也必须已经与 fn 的错误类型兼容；它不会凭空生成到用户错误类型的转换。在错误类型为用户类型的 fn 中（`-> Result[T, Failure]`、`-> T!Failure`），以下三种操作数会以 `String` 失败，因此触发 E022：

- 返回类型不是 `Result` 的效应调用（`-> Bool`、`-> Unit`、`-> Int`、记录等）——其效应通道为 `String`；
- `Result[_, String]`；
- `Option`（它的 `none` 会变为 `String` 错误）。

```almide
type Failure = | Slow | Broken(String)

effect fn ready() -> Bool = ...
effect fn tidy() -> Unit = ...

effect fn step() -> Result[Int, Failure] = {
  tidy()!                                   // E022: fails with String
  if ready()! then ok(1) else err(Slow)     // E022: fails with String
}
```

```
error[E022]: operator '!' cannot propagate this error: the fn's error type is `Failure`, but this effect call fails with `String`
```

请就地处理错误：对结果进行 `match` 并用一个 `Failure` 分支返回 `err(...)`，使用 `?? default`（`ready() ?? false`），或通过 `let _ = tidy()` 丢弃 Unit 调用的错误。在错误类型为 `String` 的 fn 中，对变体错误使用 `!` 仍然被接受：它会转换为其文本。

## 原因

可失败性与效应是两个独立的维度。E022 拒绝缺失或不兼容的失败通道，而不是拒绝所有纯代码。从变体错误转换到 String 通道时使用其 repr 文本；与严格转换设计的差异记录在 ADR-0021 D5 中。
