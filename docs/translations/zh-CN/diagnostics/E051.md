# E051 — 文件标记的 dialect 超出此编译器支持范围

[English](../../../diagnostics/E051.md) | [日本語](../../ja/diagnostics/E051.md) | [简体中文](../../zh-CN/diagnostics/E051.md)

> 原文：[`docs/diagnostics/E051.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E051.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

文件带有 `@dialect(N)` 标记，其 epoch 高于此编译器实现的 dialect。

```almide
@dialect(2147483647)           // ← E051: deliberately beyond this compiler's epoch

fn main() -> Unit = println("hi")
```

## 标记的含义

`@dialect(N)` 记录文件最后一次经过**验证**的语言 dialect。它不是发布版本号：Almide 不断发布，但几乎都不改变编写者可观察的内容，所以只有语言公开规则以可能破坏已有代码的方式变化时，epoch 才会推进。epoch 及各次破坏性变化的规范清单为 [`proofs/dialect-epochs.toml`](../../../../proofs/dialect-epochs.toml)。

标记存在的原因是，Almide 的用户主要是代码生成器。模型按它学过的 dialect 编写；将该 dialect 记录在文件中，才能让编译器区分“这个程序有误”与“这个程序是为较旧语言编写的”，也让 modification survival 可以按 dialect 测量，而不是混成一个数字。

## 为什么领先编译器的标记是错误

四种状态中有三种保持静默：

| 标记 | 含义 | 行为 |
|---|---|---|
| 缺失 | 在标记出现前编写，或故意不标记 | 静默 |
| 等于编译器的值 | 针对此 dialect 验证过 | 静默 |
| **低于**编译器的值 | 针对较旧 dialect 验证过 | **静默**——直到实际使用变化过的内容前仍可编译 |
| **高于**编译器的值 | 针对此二进制程序从未见过的语言验证过 | **E051** |

只有最后一行中，成功会造成误导。高于编译器的标记说明某个更新的 Almide 检查过该文件；这里的编译器并未检查过。如果碰巧能编译，那是运气而非证据，恰是生成器输出看似没问题却并非如此的情形。

## 修复

- **升级编译器**——通常是文件面向的 Almide 比 `PATH` 上的更新。
- **或降低标记**，前提是文件确实以此 dialect 为目标。检查干净通过时，`almide check <file> --stamp` 会写入正确 epoch。它只会向前推进标记；来自更新编译器的标记保持不变，因为倒退会伪造此二进制程序无法执行的验证。
