# E004 — 参数数量错误

[English](../../../diagnostics/E004.md) | [日本語](../../ja/diagnostics/E004.md) | [简体中文](../../zh-CN/diagnostics/E004.md)

> 原文：[`docs/diagnostics/E004.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E004.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

函数调用传入的参数过少或过多。

## 常见情况

```almide
list.map(xs)                  // missing closure
list.join(xs)                 // missing separator
int.pow(2)                    // pow expects (base, exp)
fn f(a, b) = a + b ; f(1)     // missing b
```

## 带签名占位符的 `try:` 片段

```
error[E004]: list.join() expects 2 argument(s) but got 1
  hint: Check the number of arguments
  try:
      // list.join() takes 2 arg(s) — you passed 1
      list.join(<xs: List[T]>, <sep: T>)
```

片段将每个参数的名称与类型列为 `<name: Type>` 占位符。LLM 在下一轮重试中填入占位符，逐步形成有效调用。

## 修复

- 检查函数签名。快速查询：
  - `almide ide doc <module>.<fn>` — 仅签名
  - `almide ide outline @stdlib/<module>` — 完整模块列表
  - `docs/CHEATSHEET.md` — 常见情况
- 标准库中的可选参数只支持按位置传递；如果需要跳过前面的可选参数以提供后面的必需参数，请显式传入 `none`。
- 对 UFCS／方法式链式调用（`x |> f`），记住接收者（第一个参数）是管道前的值。
