# E029 — 未知类型名

[English](../../../diagnostics/E029.md) | [日本語](../../ja/diagnostics/E029.md) | [简体中文](./E029.md)

> 原文：[E029.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E029.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

注解或记录字面量中提及的每个类型名，都必须是已声明（或已导入）的类型。过去，未声明的名称会无约束地通过统一过程：即使没有 `type Inner`，`let xs: List[Inner] = []` 或 `Inner { x: 1 }` 也能通过类型检查，随后原生构建以 rustc `E0412`/`E0422`/`E0425` 失败（检查接受、构建失败的接受一致性缺口；差分模糊测试 seed 20260718、index 940 在变异删除 `type` 声明后发现此问题）。

```almide
fn main() -> Unit = {
  let xs: List[Inner] = []          // ← E029: unknown type 'Inner'
  let n = Inner { x: 1, y: 10 }     // ← E029: unknown type 'Inner'
}
```

## 修复

声明该类型（或修正拼写／补上缺失的导入）：

```almide
type Inner = { x: Int, y: Int }

fn main() -> Unit = {
  let xs: List[Inner] = [Inner { x: 1, y: 10 }]
  println("${list.len(xs)}")
}
```

泛型参数在机制上不受此问题影响：作用域内的泛型（`fn
f[T](x: T)`）在处理注解时会解析为类型变量，而不是名义类型名称。内置动态 `Value` 类型也始终在作用域内。

## Fix-it 判定

**mechanical** — 对于 dialect epoch 移除的类型写法（`RawPtr` → `Handle`、`proofs/dialect-epochs.toml`），重命名类型就是完整修改；其他所有 E029 都是 **not-fixable** — 报告自动重写无法决定的语义／设计问题。（`mechanical` = 无人值守的修复器可以应用重写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）
