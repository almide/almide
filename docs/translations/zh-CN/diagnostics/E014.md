# E014 — 不可达的 match arm

[English](../../../diagnostics/E014.md) | [日本語](../../ja/diagnostics/E014.md) | [简体中文](../../zh-CN/diagnostics/E014.md)

> 原文：[`docs/diagnostics/E014.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E014.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

一个 `match` arm 在静态上已被先前 arm 覆盖，因此运行时永远不会触发。Almide 将其标为错误，而非警告，因为不可达 arm 几乎总是生成失误：作者错误地编码了先前模式的覆盖范围，并以为后续 arm 能捕获它实际上永远看不到的情况。

## 常见情况

```almide
type Shape = | Circle | Square | Triangle

fn area(s: Shape) -> Int =
    match s {
        _ => 0,
        Circle => 1,   // E014: `_` above already matches Circle
    }
```

```almide
match n {
    5 => "five",
    5 => "again",  // E014: the preceding unguarded literal covers 5
    _ => "other",
}
```

```almide
type Tree = | Leaf | Node(Tree, Tree)

fn size(t: Tree) -> Int =
    match t {
        Leaf => 0,
        Node(_, _) => 1,
        Node(Leaf, _) => 2,   // E014: earlier `Node(_, _)` catches this
    }
```

## 修复

删除不可达 arm，或收窄先前 arm，使后续 arm 可达：

```almide
// Option A — drop the dead arm
match s {
    _ => 0,
}

// Option B — make the earlier arm more specific
match s {
    Circle => 1,
    _ => 0,
}
```

## 带守卫的 arm

带守卫的 arm（`pat if cond => ...`）既不遮蔽后续 arm，也不会被遮蔽。守卫可能在运行时失败，因此可达性分析在两个方向上都将它们视为“始终可能可达”。

```almide
match n {
    x if x > 0 => "positive",
    x if x < 0 => "negative",
    _ => "zero",     // OK: guarded arms above don't cover 0
}
```

## 为什么不是警告？

LLM 将警告视为噪声，而 dojo MSR 显示，不可达 arm 几乎无一例外都是模式编码失误的信号（作者以为 `Leaf` 的含义与其实际匹配内容不同）。以错误级别呈现，能将修复保留在第一轮反馈循环内。
