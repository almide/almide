# v0.68.0-rc1 — 领域内核移出 stdlib，fan.min 取代 fan.race

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](v0.68.0-rc1.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](v0.68.0-rc1.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](v0.68.0-rc1.zh-CN.md)

> 这是固定于 35297a612fb29e3f78f6587aba253aa91d51f466 的[正本](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/releases/v0.68.0-rc1.md)的非规范性阅读译本，不会自动同步，原本仍具权威性。下文发布状态、计划、实现、安全、检查和性能主张属于这份历史发布记录；此处未独立验证发布、命令、基准、通告或保证。发布计划的陈述不是发布已发生的证据。

**发布候选 1**（#1484）：作为预发布版本发布，用于观察期，不计入“latest”。包含 v0.67.1 以来落入 `develop` 的全部内容；观察期无问题后为最终 v0.68.0 打标签。

此候选版本开启 **dialect epoch 14**，按已有裁定在不设弃用窗口的情况下删除或重命名语言表面。两项变更影响已编写的代码：厂商与模型专用的领域内核从 stdlib 移入包，fan 选择形式重命名（`fan.race` 变为 `fan.min(clock)`，`fan.any` 被移除）。每个被移除的写法都会产生指出迁移去向的诊断。在这些变更背后，每个公开 stdlib 函数现已在两个目标上接受检查。

<a id="breaking-at-epoch-14"></a>

## epoch 14 的破坏性变更

- **33 个厂商与模型专用函数从 stdlib 移入包。** 提供商流式客户端（OpenAI、Anthropic）、Qwen3 模块、Q1_0/Q8_0 量化内核和 transformer 构建模块现位于 `almide/llm` 与 `almide-graphics/nn`（模块 `nn.kernels`），`mem` 模块被移除。调用已删除函数会得到指出新包、或要求删除调用的诊断。cheatsheet 和 `llms.txt` 说明每项的去向（#3797、#3806）。
- **`fan.race` 现为 `fan.min(clock) { … }` / `fan.min(clock, xs, f)`，且时钟必填**（ADR-0028）。时钟类型表明“最少”按什么衡量：`compute` 选择预算内确定性计算量最少的分支，平局按源码顺序。未指定时钟的 `fan.min` 是解析错误（#3808）。
- **移除 `fan.any`。** 按源码顺序取首个 `Ok`，写作 `a() ?? b() ?? fallback`；对列表则写 `list.find_map(xs, (x) => f(x)?) ?? fallback`。两者在两个目标上都已支持 effect callback。每个旧写法（`fan.race` 的全部四种形式、`fan.any { }`、`fan.any(xs, f)`）均产生 E027 并指出替代写法。`fan.bounded` 和 `fan.timeout` 保留名称（#3808）。
- **以 `testing.assert_aborts(expected, () => …)` 替换 `testing.assert_throws`**（ADR-0029）。闭包在 native 的子进程、wasm 的全新实例中运行（C-384，新增代码 E098 和 E099）。新的 Process capability 允许该操作（#3806、#3808）。
- **移除 #3338 之前的 native callback 别名**，兑现弃用时的承诺。epoch 门禁现在会在弃用过期时失败（#3806）。

<a id="language-surface"></a>

## 语言表面

- **`fan { }` 接受带具名分支的记录形式。** 按普通记录字面量定型，lower 为解构到记录的元组形式 fan。格式化为每行一个字段，分支内嵌套 fan 也能正确稳定（#3808，issue #1388）。
- **标识符可以是非 ASCII。** lexer 按 UAX #31 XID 类别分类标识符，以 NFC 存储。没有大小写之分的名称由其模块的声明方式决定属于类型侧还是值侧。模块名和 import 别名仍限 ASCII，否则在解析时拒绝（C-387、#3808，issue #1456）。
- **parser 对其他编程语言的惯用写法各报一个错误后恢复并继续解析。** 例如 `return EXPR`、`let mut`、花括号式 `if`、`===`/`!==`、`elif`、三元式 `c ? a : b`、`&&`/`||`/前缀 `!`、使用 `->`/`:`/`case` 的 match 分支、顶层 `def`/`function`/`func`/`fun`/`proc`、`const`/`val`、`println!`/`assert_eq!` 式宏、`int`/`i64`/`string` 式类型名及 Rust 闭包（#3746）。
- **接受表达式从 `${` 下一行开始的插值孔**，适用于普通字符串和 heredoc（#3746，issue #2810）。
- **不带花括号的 `then`/`else` 分支可为任意赋值语句**，包括嵌套赋值目标（#3808，issue #3757）。
- **针对 `Result` 值的 `if` 和 `match` 按 `let`/`var` 注解合流。** 当 effect fn 的分支为 `Result` 值，并绑定到带 `Result` 注解的 let 时，不再报告 E041（#3808，issue #3777）。
- **可以在类型注解中指定 `Duration` 和 `Compute`**（此前为 E029）（#3773）。

<a id="fan"></a>

## fan

- **当 `fan { }` 分支到达 `@ordered` stdlib fn 时，native 也按分支顺序运行该块。** 覆盖 `env.set`、fs 写入、stdin 读取和进程启动，使 native 与 wasm 观察到同样状态（ADR-0024 D3、C-004）（#3808）。
- **两个 meter 遵循同一 charge 表。** native 默认路径不再对无循环包装器的入口和字符串插值计费，因此 `fan.bounded` 判定和 `fan.min` 胜者跨目标一致（C-204、C-294）（#3808）。
- **`fan { list.map }` 内多个元素 trap 时，报告索引最小的 trap**，而非时间上最早的 trap。轻量 `fan.map` 现在每个元素块支付一次记账成本，而非每个元素一次（C-200）（#3808）。
- **fan 语义审计的修复：**
  - Float、List 或记录类型的胜者可以编译；
  - 空 `fan.bounded`/`fan.timeout` 本体在每个目标上都是 Unit 块；
  - wasm `fan.timeout` 遵循重放并使用单调时钟。

  审计本身、跨语言比较及验收测试也已落地（#3785、#3786）。
- **native fan 可为更多程序并行运行。**
  - `String` 和 `List`/`Set`/`Map`/`Result` 类型的值现符合条件（#3569）。
  - 在堆参数旁保留标量 `var` 的行内核也符合（#3724）。
  - effect callback 仅将已证明纯的工作向外分发的 `fan.map` 也符合（#3775）。
  - 即使整个程序脱离 v1 render，native 仍计量 `fan.race`/`bounded` 区域（#3683）。
  - 当累加器或 callback 持有 Rc 时，`fs.fold_lines_chunked` 串行运行（#3681）。
  - `fs.fold_lines_chunked` 限制线程数量（#3711）。
- **为提速重建了 native fan 运行时：**
  - 线程现常驻并按块获取元素，使用调用者也从中领取工作的同一个共享池（#3759、#3767）；
  - 将工作提案发布给轮询线程，由它们窃取块（#3774）；
  - 按执行分支重新校准成本模型（#3763、#3765）。

  fan floor 台账（`docs/benchmarks/fan-floor.md`、#3766、#3764）中，在实测的两台 GCE 机器上，每行现在均不高于 Rayon、Go、Zig 中最快者：Intel 为 0.48–0.92x，AMD 为 0.47–0.85x。此前 24 行中有 22 行为 1.06–5.05x（#3775）。
- **wasm fan worker 接受标量列表捕获，并按块接收工作。** 嵌入式主机线程在整个运行期间常驻（#3730、#3732、#3748）。

<a id="correctness"></a>

## 正确性

- **wasm `error.message` 不再释放仅借用的 payload**（use-after-free）。`error.context` 泄漏的块也被释放（#3610）。
- **通过 `check` 但 native 构建失败的程序现在可以编译。** 已修复情况：
  - `Bytes`/`Matrix` fold 累加器，以及包装运行时结果（#3581、#3582）；
  - 传给 Almide 编译 fn 的 `Bytes` `if`/`match`（#3609）；
  - effect fn 中提升的 `list.set` 值（#3594）；
  - effect fn 中 `some`/`ok`/`err` 的 `Result` payload（#3632）；
  - 两个模块声明同名顶层 `let`（#3728）；
  - 参数上的 `matrix.concat_cols`，以及调用实参绝不自动 `?`（#3675）；
  - 传给运行时 `Fn` 槽位的闭包值（#3693）；
  - 展开的 matmul、对捕获 var 的 mut-param 调用，以及不透明 stdlib 类型的排序（#3773）。
- **对 `Matrix` 或 `Value` 执行 `list.sort`/`min`/`max` 在 check 时产生 E030。** 此前 native 构建生成不合法 Rust（#3589）。wasm 现在像 native 一样为 `Bytes`、`Result` 和 `Unit` 元素排序，而非拒绝（#3593）。
- **native 尾递归对每种返回类型均以常数栈运行**，包括记录、variant、`Set` 和 `Bytes`（#3563）。
- **沙箱化 effect fuzz 活动发现的缺陷已修复：**
  - 每次 `fs.read_lines`/`list_dir`/`walk` 失败时的 wasm 泄漏；
  - 对目录执行 `fs.copy`；
  - Unit let 内的 Unit effect（#3621）。
- **wasm 泄漏得到释放：**
  - host-leaf 调用结果（#3624）；
  - `io.read_n_bytes`/`read_byte` 的 staging 块（#3629、#3631）；
  - `fs.read_bytes`/`read_bytes_if_exists`/`stat` 的 staging 块（#3680）。
- **跨目标值修复：**
  - wasm `bytes.read_string_at`/`read_string_be` 以有损方式 decode，确保 String 不含无效 UTF-8（#3566）；
  - 每个 bytes 浮点写入器在两个执行分支上均写入 canonical NaN（C-210、#3701）；
  - wasm `json.to_map` 对每个重复键保留一个条目（C-380、#3702）；
  - wasm `json.remove_path` 在根处返回带标签的 Null（#3806）；
  - rope rotation 和 multi-head attention 不再遍历没有配对或没有列的 head（#3583）；
  - 多项 native 差异：NaN 追加、空 rope、hidden-width 乘法及对目录执行 `fold_lines_range`（#3675）；
  - 转发 `mut` 参数的自身或相互尾调用在 wasm 上仍保持尾调用（#3675、#3693）。
- `almide fix` 识别导入的模块，effect 调用的 `??` fallback 内的 `!` 会在诊断中被指出（#3527）。

<a id="wasm-and-hosts"></a>

## wasm 与主机

- **`process.stdin_lines` 在每个 wasm 执行分支上运行**（#3629）。**`net.tcp_*` 在嵌入式 wasm 通道上运行**，基于一个带分类错误的 native core 构建（#3693）。**完整响应 http 客户端**在 WASI 0.3 component 上运行（#3675）。unix/shm 获得临时嵌入式 host op（C-382、C-383）（#3806）。
- **http 客户端在每个通道自行进行正文分帧**，并丢弃调用者的 `Content-Length`（C-385）。**`http.serve` 拒绝**非最终状态、不是 token 的头部名称和头部值中的控制字节，并丢弃 handler 的分帧字段。所有这些在每个主机上行为相同（C-367、C-375）（#3806）。

<a id="performance"></a>

## 性能

- **native Almide `String` 现在默认是共享引用计数缓冲区**（ADR-0013 stage 2）。推进步骤：
  - 生成代码中统一的 `AlmideString` 别名（#3716）；
  - 带 Miri 作业的 `AlmideStr` crate（#3717）；
  - 通过别名 render 字面量（#3719）；
  - 用别名表达运行时 ABI（#3746）；
  - 切换本身，同时移除 `ALMIDE_SHARED_STR`（#3806）。

  迁移计划和 GCE A/B 流程记录在 #3720 与 #3715。
- **x86_64 上的 `--release` 默认以 x86-64-v3 基线（AVX2 + FMA）为目标。** `--target-cpu portable`（或任意 rustc CPU 名称）可覆盖。其他架构保留 rustc 的 generic CPU（#3740）。此前的默认值 `native` 在写法比率门禁发现 1.25x 的 x86 回退后被撤销（#3727、#3734）。
- **原地编辑来自各 stdlib 函数的一处 `@reuse` 声明**，两个执行分支都由此导出原地路径。当源值处于最后一次使用时，以下函数现在原地写入：
  - `list.set`/`swap`/`update` 和 `bytes.set`（#3598）；
  - `set.insert`/`remove`（#3603、#3713）；
  - `map.update`（#3708）；
  - wasm 上串联的 `map.set`/`upsert`/`update`（#3729）；
  - `string.push`（#3675）；
  - `map.delete`/`remove`、`map.merge` 和 `bytes.copy_within`/`fill`/`clear`（#3675）。

  `@implements` 无需名称列表即可注册自托管本体（#3587、#3626）。fold callback 内或自身尾调用前的 push/set 循环保持线性（#3682）。
- **二次路径变为线性：**
  - wasm 前置累加器（`[e] + acc`，以及 fold callback 内同样的 push）（#3529、#3531）；
  - wasm `list.flatten`（#3536）；
  - `option.collect` 和 wasm `map.from_list`（#3553）；
  - wasm `set.from_list` 与 `list.unique`/`unique_by`，以及 native `list.unique`（#3703、#3706）；
  - `string.take_end`/`drop_end`/`ends_with`（#3612）；
  - `http.wrap` 和 `http.with_headers`（#3773）；
  - `map.delete`/`set.remove` 为摊销 O(1)（#3693）；
  - wasm 上的 `value.merge`（#3675）。
- **较小的改进：**
  - enumerate 写法在两个执行分支上均融合（#3592）；
  - native region alloc 在 x86 上为 bump（#3597）；
  - `Int % literal` 转为魔数乘法（#3771）；
  - `option.is_some`/`is_none` 借用实参（#3723）；
  - `option.collect` 一次性预留结果空间（#3725）；
  - wasm `list.intersperse` 分配一次（#3596），带字面量尾部的 wasm `flat_map` 预留结果空间（#3714）；
  - wasm 字符串比较每次处理 8 字节（#3714）；
  - wasm `option.zip`/`result.partition` 正确取得 credit（#3546）；
  - 只读 `if`/`match` 选择存活局部值时借用而非克隆，v1 native render 中 if 分支临时值移动到合流处（#3731、#3808）；
  - wasm `matrix.fma`/`fma3` 只接触操作数重叠部分（#3808）；
  - 作为 `for` 头部的拥有型列表会被移动（#3746）。

<a id="stdlib-inspection"></a>

## stdlib 检查

- **每个公开 stdlib 函数都在两个目标上接受检查。** `proofs/stdlib-inspection.toml` 的 999 行中未检查行数为 0。每行具有五项标准的 GCE stamp：native/wasm parity、复杂度、分配、200 程序的 fuzz 活动和 diamond。泛型函数在 Int 与 String 上都测量，每个探针都运行成功路径（#3797、#3806、#3772、#3773）。
- **检查如何工作：**
  - 台账和 harness（#3541）；
  - 实现 fingerprint 变化时 stamp 失效（#3547）；
  - 基于指令数和移动字节数、在五种大小上拟合的计数式复杂度判定器（#3568、#3576、#3613、#3721）；
  - effect 函数在带种子的沙箱世界中检查（ADR-0027、#3616、#3617、#3627）；
  - generator 扩展到 Bytes、定宽数值、Set、Matrix、Value、仅 import 模块和名义类型（#3551、#3562、#3580、#3602、#3606、#3614）；
  - harness 修复（#3545、#3710、#3712）。
- 加盖 stamp 的批次：#3572、#3578、#3601、#3607、#3675、#3693。
