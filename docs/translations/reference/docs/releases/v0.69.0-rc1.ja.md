- **Epoch 14**（rc1 と rc2 で出荷）：ベンダー固有の streaming client をパッケージ `almide/llm` に、モデル固有の kernel をパッケージ `almide-graphics/nn` のモジュール `nn.kernels` に移す（rc1 と rc2 では `almide/nnlib` という名称だった）。`fan.race` は `fan.min(clock)` となり、`fan.any` を削除し、`testing.assert_throws` は `testing.assert_aborts` になる。
- **Epoch 15**（rc2 以降の新規分）：標準ライブラリ再設計。再設計後の表面にない関数を削除し、残る関数は役割ごとに一つの規則で命名する。map callback は entry を一つの `(K, V)` tuple として取り、外部入力を読むすべてのモジュールはその入力に上限を設ける。

削除した各表記は、置換先を名指しする診断になった。rc1 と rc2 のノートは epoch-14 の表面、正しさの修正、性能作業を説明する。以下はすべて rc2 後に導入されたもの。

タグ時点の release blocker は 0。v0.67.1 との差分は公開 stdlib interface の破壊的変更であり、675 シグネチャを削除または変更し、964 を追加した。出荷対象の表面について `scripts/check-interface-diff.sh` で測定した（map entry callback を含み、シグネチャ索引はコンパイラから再生成）。すべての削除と非互換変更は `proofs/dialect-epochs.toml` の epoch 14 または epoch 15 に宣言されている。

<a id="breaking-changes"></a>

## 破壊的変更

- **約 600 の stdlib 表記を削除または改名**（epoch 15、R-L0-30、R-L0-40）。大半には結果が同じ直接の置換先がある。例：
  - `fs.write` → `fs.write_text`、`map.entries` → `map.to_list`、`string.chars` → `string.to_list`、`value.str` → `value.string`。
  - `math.fmax` → `float.max`、`int.to_float(n)` → `float.from(n)`、`float.to_int(x)` → `int.from_saturating(x)`、`int64.to_int8(x)` → `int8.from_wrapping(x)`。
  - `list.get_or(xs, i, d)` → `list.get(xs, i) ?? d`、`error.context(r, msg)` → `result.map_err(r, (e) => "${msg}: ${e}")`。
  - `bytes.set_u8` → `bytes.put_u8`、`bytes.cmp` → `bytes.compare`。
  - `matrix.add`、`sub`、`mul`、`div` を演算子形式に置き換え、`Bytes + Bytes` は連結する。
- **全体または一部が移動・削除されたモジュール：**
  - `error` モジュールを削除。補間と `result.map_err` を使う。
  - 型 `bytes.Endian`、`path.SafePath`、`json.JsonPath` を削除。バイト順は関数名に入れ（`bytes.get_u32_le`）、`value.root()`、`value.key`、`value.index` で `value.Path` を構築する。
  - さらに五つの `matrix` kernel を、パッケージ `almide-graphics/nn` のモジュール `nn.kernels` に移す：`linear_row`、`linear_row_no_bias`、`conv1d`、`linear_f32_row_no_bias`、`select_rows_f32`。`import nn.kernels` と書き、同じ引数で `kernels.linear_row(…)` を呼ぶ。
- **map callback は entry を一つの `(K, V)` tuple として取る**（R-map-09、#4004）。`map.filter`、`any`、`all`、`count`、`find` は callback に entry を一つの tuple として渡し、`map.fold` は accumulator とその tuple を渡す。`map.to_list` が出す要素と同じである：
  - `map.filter(m, ((k, v)) => v > 0)` と `map.fold(m, 0, (acc, (k, v)) => acc + v)`。
  - 2 引数 lambda `(k, v) => …` は引き続き check を通る。パラメーターは tuple の各要素として解釈される。
  - `map.fold(m, init, (acc, k, v) => …)` は E004。`map.fold(m, init, (acc, (k, v)) => …)` と書く。
  - これらの callback として渡す名前付き関数は、以前の key と value の代わりに tuple を取る：`fn keep(e: (String, Int)) -> Bool`。
- **`regex` はコンパイル済み `Regex` を取る。** `regex.new(pat)`、または `Result` が欲しければ `regex.compile(pat)` で作る。engine が拒否する literal pattern は check 時の E102。`regex.captures` は `List[String?]` を返す。
- **システムモジュールは型付き handle を使う：**
  - `io` は `Stdin`、`Stdout`、`Stderr` handle と汎用の `io.read`、`write`、`close` を持つ。`io.read_line` は `String?` を返す。
  - `net.TcpStream` と `net.TcpListener` は opaque 型。
  - Unix socket と共有メモリは新しい `unix` モジュールへ移る。
  - `process` は `exec_*`、`run_in`、`spawn` の形式を、`ProcessCommand` record、`output`、`run`、および `start` / `poll` / `wait` / `stop` handle に置き換える。
  - `http` の request と response は、headers が `List[(String, String)]` の一つの `HttpMessage` となり、`http.send` と `http.start(req, limits)` を使う。
- **一部の結果が変わる：**
  - `matrix.get` は `Option[Float]`、`matrix.from_bytes_f16_le`、`f32_le`、`f64_le` は `Option[Matrix]` を返す（C-282、C-341）。
  - `datetime.from_parts` は `Result` を返し、範囲外フィールドを `parse_iso` と同じ規則で拒否する。
  - `int.wrap_add`、`wrap_mul`、`rotate_left`、`rotate_right` は幅を取らず、64-bit Int に作用する（R-int-12）。`int.wrap_add(a, b, bits)` は `int.wrap(int.wrap_add(a, b), bits)` に書き換え、幅 8、16、32 の回転は、固定幅値に対する固定幅モジュールの `rotate_left` にする。3 引数呼出しは arity error。
  - `env.set` は可謬になる。
  - `zlib.inflate`、`decompress`、`gunzip` は plain function。
  - `hash.fnv1a32` と `hash.sha256_hex` は `Bytes` を取る。
  - `args.positional` と `args.positional_at` はプログラムが読む option の名前を取り、名前付き `--option` の次の引数は位置引数でなくその値となる。`--out report.txt input.txt` に対する `args.positional(["out"])` は `["input.txt"]`（#4144、C-181）。一覧を渡さない呼出しは arity error。
  - `args.flag(name)` は `-<first letter>` に反応しなくなり、`--name` だけで設定される。`--` は option 解析を終える。flag と option の reader はその後を無視し、位置引数 reader は後続を含める（#4144）。
  - `list`、`string`、`bytes`、`matrix` の負の個数または範囲境界は 0 として扱う。
  - `http.decode_json[T](req)` は入力型を型引数として取り、厳密に decode する。
- **effect と権限が厳格になる：**
  - 値として渡す effect fn も effect であり、pure fn からの `list.map(xs, fs.read_text)` は E006。
  - `[permissions] allow` は細かい分類を使う。ファイルに `FS`、プロセスに `Proc`、ネットワークに `Net.fetch` と `Net.listen`、時計に `Time`、出力と abort に `IO.stdout`、`IO.stderr`、`Abort`。
  - `allow = []` は何も許可しない。
  - `process.env`、`process.pid`、`process.sleep`、`io.write`、`net.tcp_is_open` は `effect fn` である。
- **raw memory 関数は明示 import が必要。** 新しい `ffi` モジュールへ移り、呼出しファイルに `import ffi` が必要となる（E100）。五つの `bytes` raw-pointer 関数はこれに代えて非推奨になる。

<a id="migration"></a>

## 移行

1. **`almide check` を実行する。** 削除された表記の呼出しはエラー（E002、または削除モジュールの module-not-found error）となり、hint が epoch-15 台帳から置換呼出しを示す。削除表記は自動書換えされないため、各 hint を手で適用する。大半は引数が同じで名前一つの変更。
2. 削除ではなく、まだ非推奨（E052）の表記には **`almide fix` を実行する**：
   - `regex.full_match` → `regex.is_full_match`。
   - `int.pop_count` → `int.count_ones`、`int.bit_width` → `int.bit_length`、`float.sign` → `float.signum`。
   - `bytes` raw-pointer 関数 → `ffi.*`。`almide fix` がこの書換えを提案するのは、すでに `import ffi` があるファイルだけ。
   - `almide fix` は literal regex pattern を `regex.new(…)` で包むことも行う。
   - 古いパラメーター名の名前付き引数は E004 で、hint が新しいパラメーター名を示す。位置指定呼出しは変わらない。
3. **形が変わった呼出しを修正する。** 削除表記ではなく、hint 付きの check error である：
   - `map.fold(m, init, (acc, k, v) => …)` → `(acc, (k, v)) => …`。名前付き map callback は `(K, V)` tuple を取る。
   - `matrix.get` と `matrix.from_bytes_*_le` loader は Option を返す。`?? default` を追加するか match する。
   - `datetime.from_parts` は `Result` を返し、`env.set` は可謬。effect fn 内で `!` で伝搬するか、`??` で代替値を使う。
   - regex 操作は `Regex` を取る。pattern text ではなく `regex.new(pat)` を渡す（literal pattern は `almide fix` が包む）。
   - `int.wrap_add(a, b, bits)` → `int.wrap(int.wrap_add(a, b), bits)`。`int.rotate_left(a, n, 8)` → 固定幅モジュールの `rotate_left`。
   - `args.positional()` → `args.positional(["<option>", …])`。プログラムが読むすべての option を列挙する。
   - `http.decode_json(req, decode)` → `http.decode_json[T](req)`。`T` は `: Decode` と宣言する。
   - `hash.fnv1a32` と `hash.sha256_hex` は `Bytes` を取る。`bytes.from_string(s)` を渡す。
   - effect fn を値として渡す pure fn（`list.map(xs, fs.read_text)`）は `effect fn` にする必要がある（E006）。
4. **`almide.toml` を更新する：**
   - ファイルアクセスに `IO` を使っていた manifest は `FS` を追加する。`process.*` に `Env` を使っていたなら `Proc` を追加する。
   - print または assert を行うプログラムには `IO` と `Abort` が必要。
   - native-code 依存は `[permissions] native = ["<dep>"]` に名前を列挙して許可する。
   - `github.com/almide` 以外の git 依存 owner は `[trust] owners` に列挙するか、`almide trust <owner>` を実行する。
5. **パッケージ：** ニューラルネットワーク kernel は `almide-graphics/nn` の `nn.kernels` モジュールにある。`almide add almide-graphics/nn@v0.2.0 --trust github.com/almide-graphics` を実行し、`import nn.kernels` と書いて `kernels.gelu(m)` を呼ぶ。rc1 または rc2 の `nnlib` を import していたプログラムは、このパッケージへ移る。`almide/llm` は epoch-15 の表記を使うリリースでなければならない。

表記ごとに置換先を示す完全な一覧は `proofs/dialect-epochs.toml`（epoch 14 と 15）にある。再設計記録は `docs/roadmap/stdlib-redesign/`。

## Stdlib

- **新しいモジュール：**
  - `deque`（両端で push/pop する `Deque[A]`）と `heap`（`Heap[A]`、最小優先、key 順序と comparator 順序）。
  - `parse`、`compare`、`to_string` を持つ `bool`。
  - `uuid`（v4、v7、parse、バイト変換）、`unix`、`ffi`、`secret`。
- **数値の family は八つの固定幅整数全体で揃った。** 各型に `compare`、`min`、`max`、`clamp`、`floor_div`、`modulo`、`pow`、`is_even`、`is_odd`、ビット演算とビットカウント、wrapping 算術、回転、`bit_length`、`parse` がある。
  - `float32` と `float64` は浮動小数点の要件を持つ：全順序比較、分類、丸め、`signum`、bits、定数。
  - 実行可能な matrix gate が各 family を検査する。
- **既存モジュールの新関数：**
  - `list` は sort、min、max、binary search の `_by` と `_with` の各枠、および `unzip` と `range_step` を得た。`set` と `map` には sequence algorithm を追加。
  - `string` は Text と Container の関数を得た。
  - `math` は逆三角関数、双曲線関数、`hypot`、`cbrt`、`expm1`、`log1p` を得た。
  - `hash` は `crc32`、`adler32`、`sha512`、および `Secret[Bytes]` の key と tag を使い定数時間で検証する HMAC-SHA256 と HMAC-SHA512 を得た。stdlib に MD5 や SHA-1 はない。
  - `url` は `encode_form`、`decode_form`、`parse_query`、`resolve`（RFC 3986 §5）を得た。
  - `path` は `components`、`relative_to`、`with_extension` を得た。
  - `env` は `vars`、`remove`、変数を `Option[Secret[String]]` として読む `secret` を得た。
  - ほかに `random.Rng`（seed 付き生成器）、`datetime.now_ms`、`args.has_flag`、`matrix.zip_with`、`matrix.concat_rows` を追加。
- **`fs.open_root`** は、両ターゲットで root の外へ出るすべてのパスを拒否する rooted filesystem family を開く。
- **自動 import モジュールはソースがそこに到達した時だけ読み込む**ため、モジュールを使わないプログラムはそのモジュールを check しない。

<a id="security-hardening"></a>

## セキュリティ強化

このリリースは toolchain と stdlib のセキュリティレビューを完了する。各修正には、記録済み negative control を持つ contract または gate がある。各行の状態は `docs/roadmap/active/security-by-construction.md` にある。

- **toolchain と supply chain：**
  - git 依存は信頼された owner からだけ取得する。
  - 依存内の native code と `@inline_rust` には明示的な許可が必要。
  - native build は rustc が最低バージョンを満たすか確認する。
  - ソースの Unicode 双方向制御文字は E101。
  - release build は開発用の環境スイッチを無視する。
- **installer、updater、cache：**
  - self-update はツリー内の HTTPS client を使い、暗黙の downgrade を拒否する。install script は HTTPS を要求する。
  - `almide install` は bin directory 内の単純な名前にしか書き込まず、trust check と native-code 許可を適用する。
  - build cache はユーザーごとの private directory に置き、cache binary は digest が一致するときだけ実行する。
  - `almide build` の出力名は単純な名前でなければならない。
- **editor と agent 統合：**
  - `almide mcp` tool は path 引数をプロジェクト内に制限し、flag ではなく引数として渡す。
  - read-only の `almide mcp` tool は依存を取得せず、`almide.lock` に書き込まない。
  - language server は workspace root を絶対パスとして取り、その内側に留まる。
  - directory に対する `almide fmt` は `.git`、`target`、`node_modules` をスキップし、`fmt` も `test` も symlink をたどらない。
- **manifest：**
  - `almide.toml` と `almide.lock` は、上限内のサイズの通常ファイルとしてだけ読む。
  - manifest text の制御文字と双方向文字を拒否する。
  - コンパイラのバージョン要件はすべての build で強制する。
- **effect と権限：**
  - 関数値が持つ effect と、protocol bound 経由で呼ぶ effect method を check する。
  - capability 分類が細かくなり、`[permissions] fs` は native と組込み wasm host でファイルアクセスを許可 directory に制限する。
- **信頼できない入力：**
  - `json.parse` は RFC 8259 と I-JSON に厳密に従い、入れ子上限は 1000。
  - `url.parse`、`url.resolve`、HTTP client の URL splitter はブラウザーと同じように URL を読む。
  - `base64` decode は正規形だけを受理する。
  - `datetime.parse_iso` は年に上限・下限を設ける。
  - case mapping は非 ASCII 字母を ASCII に折り畳まない。
  - 数値解析は、前後の ASCII 空白を除去した有限の十進テキストだけを受理する。
  - regex engine は線形時間（Pike VM）で、深い入れ子を拒否する。
  - hash index が衝突 key で flood された map は、両ターゲットで key 順の index に fallback し、flood ですべての lookup が悪化することを防ぐ。
- **http.serve：**
  - RFC 9112 が許可しない request head には 400 を返す。
  - router は一つの正規 path を読む。
  - 接続は 64-slot pool で処理し、head deadline は 10 秒。
  - handler error には固定の 500 body を返し、server にログを残す。
  - handler 内の runtime abort はその request だけを失敗させる。
  - response は `X-Content-Type-Options: nosniff` を持つ。
  - 型付き request decode はすべての深さで未知 key を拒否する。
- **runtime 上限：**
  - `zlib` 出力の上限は 256 MiB。より大きい上限には `_max` variant を使う。
  - whole-file `fs` reader が受理するのは 1 GiB 以下の通常ファイルだけ。
  - network read と受信 descriptor に上限を設ける。
  - native fan thread は CPU ごとに一つを上限とする。
  - 組込み wasm host は、環境のメモリ制限に従う一つの memory budget ですべての store を計量し、すべての guest pointer を check する。
  - メモリ不足は封じ込められない。
- **計算量：** substring と byte search、`value.merge`、`pick`、`omit`、`json.set_path`、`path.normalize`、`math.factorial`、`bigint` の text conversion と `pow`、`url.parse_query`、`string.from_utf16`、`list.range_step`、`math.choose`（#4212）、wasm の `map.remove` と `set.remove` には、二次時間または上限なしのケースがなくなった。
- **secret と乱数：**
  - 新しい `Secret[A]` 型は伏字で出力し、定数時間で比較する。`Secret` を含む `Codec` 型は decode だけを導出する（encode は E023）。
  - `bytes` と `string` に `is_equal_constant_time` がある。
  - Codec field は `@skip` と `@skip_decode` を受け取り、`T.decode_strict` は未知 key を拒否する。
  - `random` はすべてのターゲットで OS entropy から取り出す。
- **エラーテキスト：**
  - runtime error text は引用する path、command、host、その他の値の制御文字と双方向文字を escape する。
  - URL を引用する HTTP error は password を mask する。
  - `process.kill` は kill(2) を直接使い、pid と signal を check する。

<a id="correctness"></a>

## 正しさ

- **wasm：関数の結果となる呼出しに渡した module global は値を維持する**（#4115）。
- **整数の幅縮小：** constant folding の `MIN / -1` は C-002 guard を維持し（#4161）、`Int8`、`Int16`、`Int32` の単項 minus は幅を縮める（#4163）。
- **再束縛された block より長く生存する raw address を拒否する**（#4153、#4169）。
- **導出した `Codec.decode`** は、短すぎる tuple-variant payload で abort せず err を返し、両ターゲットで同じ error path を報告する（#4164、#4165）。
- **native と wasm が一致する：**
  - `io.read_all`、`read_line`、binary `io.write`（#4138、#4142）。
  - `http.query_params`（#4117）。
  - `env.set`（#4200）。
  - 深く入れ子の `regex.compile`（#4195）。
  - fan arm 間で共有する net handle（#4199）。
  - HTTP value と `JsonPath` の補間（#4204、C-432）。
- **native：**
  - JSON key interning に上限を設けた（#4202）。
  - `process.start` で開始し、一度も wait しなかった子は、プログラム終了時に停止する（#4214、C-437）。
- **checker：**
  - 呼出し後に型が解決される protocol bound は、solve 後に判定する。たとえば非数値要素に対する `list.sum` は、build panic でなく check error となる（#4235）。
  - `Numeric`、`Integer`、`Text` bound における container、tuple、function 型を拒否する。
  - plain fn slot の effect fn value は check 時に拒否する（#4173）。
  - 名前付き record literal は構築する型に対して check する。
  - E033 は同梱モジュール自身の opaque 型だけに適用し、同じ単純名のユーザー型には適用しない。
  - 型引数のない宣言済み generic 型は E093。
  - 異なる種類の scalar 間の `==` は E037。
  - 組込み protocol 名はどのモジュールでも再宣言できない（#4190）。
  - `Secret` など、他モジュールの opaque record に対する record update や分解 pattern は E033。
  - `-> Never` と宣言した fn で本体が値を返して完了するものを拒否する。
  - 対応する matrix 操作がない `Matrix` 演算子の組合せは、scalar 操作へ lower せず check 時に拒否する。
  - `Value` が期待される位置で `Codec` record に `json.stringify` を使うと、Rust build failure でなく型自身の `encode` を指す check error となる（#4272）。
  - `Secret` など stdlib 型と同名のユーザー型は、package と `Codec` derive でもユーザーの型のままである（#4273）。
- **モジュールとパッケージ：** 依存が自分のモジュールを bare import するとき、root project に同名モジュールがあっても circular import を報告せず、自分の package に解決する（#4270）。
- **codegen と lowering：**
  - plain value への pipe された `!` は no-op（#4215）。
  - `@intrinsic` の sibling への非修飾呼出しは、その symbol を使う（#4216）。
  - runtime symbol は Almide 本体を持つ関数と衝突しない（#4217）。
  - generic caller の型パラメーターは callee のものと分離する（#4218）。
  - `/` への `path.join` は root を保持する。
  - `Int64` と `Float64` の演算子が動く。
  - `Matrix` の単項 minus が動く。
  - clock receiver の未定義 method を報告する。
- **`Result` を返す pure fn は effect fn と同様に err 経路で `mut` パラメーターの buffer を保持する。** また、借用した map read の match は payload を参照として束縛する。wasm で trap していた拒否経路は native と一致し、native build は `AlmideStr: Borrow<&AlmideStr>` で失敗しなくなった（#4274）。
- **不変 binding を `bytes.as_mut_ptr` に渡すことは check 時に拒否する**（#3975、issue #3966、C-062）。

<a id="gates-and-evidence"></a>

## ゲートと証拠

- 新しい nightly gate は、各クロスターゲットプログラムから生成した Rust を Miri と AddressSanitizer で実行し、過去のバグを再注入した checked allocator の下で wasm corpus を実行する。
- MemorySafe 証明は言語の型付き core を対象にする。bounds と init witness は出荷する wasm byte に結び付けられ、native wall は verified native renderer が出す各 certificate を判定する。
- runtime の `unsafe` は行ごとに gate を設け、未使用の `burn` backend は削除した。
- PR CI は heavy corpus gate の commit ごとにローテーションする一部を check し、push は corpus 全体を実行する。
- ADR-0030 はコンパイルコストを contract とする。
