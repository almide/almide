**リリース候補 2**（#1484）：安定化確認期間向けのプレリリースとして公開され、「latest」には含まれない。このリリースが提供する epoch-14 の機能面は引き続き rc1 のノートで説明されており、以下はすべて rc1 の切り出し後に取り込まれた。主に安定化確認中の修正で、両ターゲットでの引数再束縛、String 引数を捕捉する `fan` の arm、自己参照 variant で指数的になっていた検査、標準ライブラリ検査の最終再実行で見つかった修正を含む。リリース阻害要因は 0。v0.67.1 に対する公開 stdlib インターフェース差分は rc1 から変わらず、削除 34、追加 2 の破壊的変更で、各削除は `proofs/dialect-epochs.toml` の epoch 14 に宣言されている。

<a id="correctness"></a>

## 正しさ

- **先行する引数が読む変数を再束縛する引数を、両ターゲットで正しく順序付ける**（#3823、#3844；#3815、#3835、C-258）。`st |> set.fold({ st = set.from_list([0]); 0 }, f)` は native で rustc E0506 により失敗していた。同じ形で借用引数を持つ `list.contains`、`set.contains`、`map.get`、`string.contains`、`fs.fold_lines`、ユーザー関数も同様だった。wasm では先行する読み取りがビューで、後続引数がそれを解放していた。先行引数は再束縛する引数の前に、ソース順で束縛されるようになった。
- **String 引数を捕捉する `fan` の arm が native でコンパイルできる**（#3844；#3819、C-004）。以前は std の `String` を `AlmideString` の束縛へ出力していた（rustc E0308）。fixture は String、List、Map、record、variant、Option、Bytes、`let` の捕捉をカバーする。
- **呼び出しを綴りではなく定義によって解決する**（#3844；#3825、#3831、#3832、新契約 C-388）。インタープリタは名前付き呼び出し、末尾呼び出し、fuel メーターのユーザー関数を識別子の同一性で解決し、wasm の小さなスカラー関数のインライナはまず各呼び出しをそのモジュール内で解決する。そのため、異なるモジュールの同名関数を混同しなくなった。
- **`if` による選択がまだ借用中のリストを、所有版の対になる関数呼び出しへ move しなくなった**（#3872；#3870）。これは検査の再実行で見つかった native ビルド失敗（rustc E0505）。テストは所有版が対になっている全リスト操作をカバーする。
- **NaN を生成するすべての stdlib 関数が、すべての実行経路で固定の +qNaN を返す**（#3872；#3846）。そのため Float に対する `list.min` / `list.max` が native と wasm で一致する。
- **http クライアントとサーバーは、シグナルによって中断された読み取りを再試行する**（#3872；#3857）。
- **`fan.bounded`、`fan.timeout`、`fan.min` が単一呼び出し本体の引数を計量する**（#3822、C-204、C-205）。`fan.bounded(…) { id(heavy(1000)) }` では、引数 `heavy(1000)` が予算領域に入る前に実行され、消費量が一切計上されていなかった。非アトミックな引数は、すべての実行経路で同じく計量領域内で評価されるようになった。

<a id="performance"></a>

## 性能

- **自己参照 variant の検査が指数的にならなくなった**（#3821；#3818）。期待される effect の探索は、訪問済み箇所を記憶せずにすべての名前付き型を深さ 8 までたどっていた。15 文法のパーサーの `almide build --release` は停止させるまで 30 分以上走っていたが、今は 26.7 秒で、v0.67.1 の 32 秒と対比される。
- **native の `Value` プログラムが wasm ビルドより遅くなくなった**（#3826；#2157）。`value.array`、`value.object`、`value.as_array` は寿命が終わる入力を deep copy せず move する（`@reuse` 宣言）。`value.stringify` は一つのバッファに書き、`json.parse` はエスケープのない文字列を入力から直接構築する。50,000 レコードの JSON 往復処理は wasm 時間の 1.26 倍から 0.69 倍となり、新しいゲートが `jsonround`、`wordfreq`、`wordfreq-group` で native ≤ wasm を維持する。
- **リリースビルドは順序を維持する浮動小数点の集約をスカラーのままにする**（#3824）。aarch64 ではループベクトライザが厳密な `Float` の加算を不適切にベクトル化し、spectralnorm の `--release` が既定プロファイルより遅くなっていた。今は `-force-ordered-reductions=false` を渡す（x86 では何もしない）。fold の先頭の範囲リテラル（`list.fold(0..<n, …)`）も、どちらの実行経路でもリストとして構築しなくなった（#3810）。
- **コールド native ビルドが 17% 高速化**：runtime rlib は codegen unit 4 個、ローカル ThinLTO パスなしでコンパイルし、同一 runner 上の最新リリースとの A/B 比較でコールドビルドをゲートする（#3844；#3829）。
- **正本のアロケータは上限を超えるブロックを O(1) で解放する**（#3872；#3849）。また、**`zlib.crc32` はテーブル駆動**となり、wasm 側が native より 3–10 倍遅い状態を解消した（#3872；#3848）。

<a id="gates-and-evidence"></a>

## ゲートと証拠

- stdlib 検査は各関数の wasm emitter arm をその指紋に組み込み、計数する判定器は最長の実行で k を制限する。変更された全行を再検査し、台帳の未検査件数は 0（#3872；#3796、#3859）。
- wasm-runtime と build-speed の台帳を再作成可能なクラウドマシンクラスで再記録し、判定前にそのクラスを確認する（#3828）。
- fixture ごとの制限で打ち切られた corpus fixture は、スレッドを走らせたままにせずインタープリタ実行を停止する（#3817；#3809）。そのテストも負荷の高い runner で不安定にならなくなった（#3844）。
- `wordfreq` の性能行を両方とも 4M 語から 8M 語へ変更し、高速化された native Map 経路が計時の下限を上回るようにした（#3844）。ratchet-separation の負の対照も、自らのクリーンアップで失敗しなくなった（#3833）。
