每种被移除的写法现在都有指明替代项的诊断。rc1、rc2 的说明描述 epoch-14 表面、正确性修复与性能工作。以下内容全部在 rc2 后落地。

<a id="breaking-changes"></a>

## 破坏性变更

- **约 600 种 stdlib 写法被删除或改名**（epoch 15、R-L0-30、R-L0-40）。多数有结果相同的直接替代项，例如：
  - `fs.write` → `fs.write_text`、`map.entries` → `map.to_list`、`string.chars` → `string.to_list`、`value.str` → `value.string`。
  - `math.fmax` → `float.max`、`int.to_float(n)` → `float.from(n)`、`float.to_int(x)` → `int.from_saturating(x)`、`int64.to_int8(x)` → `int8.from_wrapping(x)`。
  - `list.get_or(xs, i, d)` → `list.get(xs, i) ?? d`，`error.context(r, msg)` → `result.map_err(r, (e) => "${msg}: ${e}")`。
  - `bytes.set_u8` → `bytes.put_u8`，`bytes.cmp` → `bytes.compare`。
  - 用运算符形式替代 `matrix.add`、`sub`、`mul`、`div`，`Bytes + Bytes` 执行连接。
- **整体或部分移出的模块：**
  - 移除 `error` 模块；使用插值与 `result.map_err`。
  - 移除 `bytes.Endian`、`path.SafePath`、`json.JsonPath` 类型。字节序写在函数名中（`bytes.get_u32_le`），由 `value.root()`、`value.key`、`value.index` 构建 `value.Path`。
  - 另有五个 `matrix` kernel 移到包 `almide-graphics/nn` 的 `nn.kernels` 模块：`linear_row`、`linear_row_no_bias`、`conv1d`、`linear_f32_row_no_bias`、`select_rows_f32`。写 `import nn.kernels`，用相同参数调用 `kernels.linear_row(…)`。
- **map callback 以一个 `(K, V)` tuple 接收 entry**（R-map-09、#4004）。`map.filter`、`any`、`all`、`count`、`find` 把 entry 作为一个 tuple 交给 callback，`map.fold` 则传 accumulator 与该 tuple，与 `map.to_list` 产生的元素相同：
  - `map.filter(m, ((k, v)) => v > 0)` 和 `map.fold(m, 0, (acc, (k, v)) => acc + v)`。
  - 双参数 lambda `(k, v) => …` 仍可通过检查：参数被解释为 tuple 的元素。
  - `map.fold(m, init, (acc, k, v) => …)` 为 E004。应写 `map.fold(m, init, (acc, (k, v)) => …)`。
  - 作为此类 callback 传入的命名函数现在接收 tuple：`fn keep(e: (String, Int)) -> Bool`，而非先前的 key 与 value。
- **`regex` 接收编译后的 `Regex`。** 用 `regex.new(pat)` 创建，想获得 `Result` 时用 `regex.compile(pat)`。engine 拒绝的 literal pattern 在 check 时为 E102。`regex.captures` 返回 `List[String?]`。
- **系统模块使用带类型 handle：**
  - `io` 提供 `Stdin`、`Stdout`、`Stderr` handle 以及通用 `io.read`、`write`、`close`。`io.read_line` 返回 `String?`。
  - `net.TcpStream`、`net.TcpListener` 为 opaque 类型。
  - Unix socket 与共享内存移到新 `unix` 模块。
  - `process` 用 `ProcessCommand` record、`output`、`run` 及 `start` / `poll` / `wait` / `stop` handle 替代 `exec_*`、`run_in`、`spawn` 形式。
  - `http` request 与 response 值统一为 `HttpMessage`，headers 为 `List[(String, String)]`，配合 `http.send` 和 `http.start(req, limits)`。
- **一些返回结果改变：**
  - `matrix.get` 返回 `Option[Float]`，`matrix.from_bytes_f16_le`、`f32_le`、`f64_le` 返回 `Option[Matrix]`（C-282、C-341）。
  - `datetime.from_parts` 返回 `Result`，按与 `parse_iso` 相同规则拒绝越界字段。
  - `int.wrap_add`、`wrap_mul`、`rotate_left`、`rotate_right` 不再接收宽度，作用于 64-bit Int（R-int-12）。将 `int.wrap_add(a, b, bits)` 改为 `int.wrap(int.wrap_add(a, b), bits)`；宽度 8、16、32 的旋转改用固定位宽模块在对应值上的 `rotate_left`。三参数调用为 arity error。
  - `env.set` 可失败。
  - `zlib.inflate`、`decompress`、`gunzip` 为 plain function。
  - `hash.fnv1a32`、`hash.sha256_hex` 接收 `Bytes`。
  - `args.positional`、`args.positional_at` 接收程序读取的 option 名称，命名 `--option` 后的参数是其值而非位置参数：对 `--out report.txt input.txt` 调用 `args.positional(["out"])` 得到 `["input.txt"]`（#4144、C-181）。不传列表为 arity error。
  - `args.flag(name)` 不再响应 `-<first letter>`，只由 `--name` 设置。`--` 结束 option 解析：flag 与 option reader 忽略其后内容，位置参数 reader 包含后续内容（#4144）。
  - 在 `list`、`string`、`bytes`、`matrix` 中，负计数或范围界限按 0 读取。
  - `http.decode_json[T](req)` 将输入类型作为类型参数，并严格 decode。
- **effect 与权限更严格：**
  - 作为值传递的 effect fn 也是 effect：pure fn 中的 `list.map(xs, fs.read_text)` 为 E006。
  - `[permissions] allow` 使用更细分类：文件为 `FS`，进程为 `Proc`，网络为 `Net.fetch`、`Net.listen`，时钟为 `Time`，输出与 abort 为 `IO.stdout`、`IO.stderr`、`Abort`。
  - `allow = []` 现在什么都不允许。
  - `process.env`、`process.pid`、`process.sleep`、`io.write`、`net.tcp_is_open` 是 `effect fn`。
- **raw-memory 函数需要显式 import。** 它们移至新 `ffi` 模块，调用文件必须有 `import ffi`（E100）。五个 `bytes` raw-pointer 函数被弃用，改用该模块。

<a id="migration"></a>

## 迁移

1. **运行 `almide check`。** 已移除写法的调用是错误（E002，或已移除模块的 module-not-found error），hint 给出 epoch-15 台账中的替代调用。移除项不自动改写，应手动应用各 hint。多数只改一个名称，参数不变。
2. 对仍为弃用（E052）而非已移除的写法，**运行 `almide fix`**：
   - `regex.full_match` → `regex.is_full_match`。
   - `int.pop_count` → `int.count_ones`、`int.bit_width` → `int.bit_length`、`float.sign` → `float.signum`。
   - `bytes` raw-pointer 函数 → `ffi.*`。`almide fix` 仅在文件已有 `import ffi` 时提出此改写。
   - `almide fix` 也会把 literal regex pattern 包在 `regex.new(…)` 中。
   - 使用旧参数名的命名参数为 E004，hint 指出新参数名。位置调用不变。
3. **修正形状改变的调用。** 这些是带 hint 的 check error，不是移除项：
   - `map.fold(m, init, (acc, k, v) => …)` → `(acc, (k, v)) => …`，命名 map callback 接收 `(K, V)` tuple。
   - `matrix.get` 与 `matrix.from_bytes_*_le` loader 返回 Option：添加 `?? default` 或对其 match。
   - `datetime.from_parts` 返回 `Result`，`env.set` 可失败：在 effect fn 中用 `!` 传播，或用 `??` 提供后备值。
   - regex 操作接收 `Regex`：传入 `regex.new(pat)`，而非 pattern 文本（`almide fix` 会包装 literal pattern）。
   - `int.wrap_add(a, b, bits)` → `int.wrap(int.wrap_add(a, b), bits)`，`int.rotate_left(a, n, 8)` → 固定位宽模块的 `rotate_left`。
   - `args.positional()` → `args.positional(["<option>", …])`，列出程序读取的每个 option。
   - `http.decode_json(req, decode)` → `http.decode_json[T](req)`，`T` 声明为 `: Decode`。
   - `hash.fnv1a32`、`hash.sha256_hex` 接收 `Bytes`：传 `bytes.from_string(s)`。
   - 将 effect fn 作为值传入的 pure fn（`list.map(xs, fs.read_text)`）必须变为 `effect fn`（E006）。
4. **更新 `almide.toml`：**
   - manifest 若用 `IO` 访问文件，添加 `FS`；若用 `Env` 调用 `process.*`，添加 `Proc`。
   - 打印或断言的程序需要 `IO` 和 `Abort`。
   - 用 `[permissions] native = ["<dep>"]` 按名称授予 native-code 依赖权限。
   - 将 `github.com/almide` 以外的 git 依赖 owner 列在 `[trust] owners` 下，或运行 `almide trust <owner>`。
5. **包：** 神经网络 kernel 是 `almide-graphics/nn` 的模块 `nn.kernels`：运行 `almide add almide-graphics/nn@v0.2.0 --trust github.com/almide-graphics`，写 `import nn.kernels` 并调用 `kernels.gelu(m)`。从 rc1 或 rc2 导入 `nnlib` 的程序迁移到此包。`almide/llm` 必须使用采用 epoch-15 写法的发布版本。

逐写法列出替代项的完整清单在 `proofs/dialect-epochs.toml`（epoch 14、15）。重设计记录在 `docs/roadmap/stdlib-redesign/`。

<a id="stdlib"></a>

## Stdlib

- **新模块：**
  - `deque`（两端 push/pop 的 `Deque[A]`）和 `heap`（`Heap[A]`，最小值优先，支持 key 和 comparator 顺序）。
  - 带 `parse`、`compare`、`to_string` 的 `bool`。
  - `uuid`（v4、v7、parse、字节转换）、`unix`、`ffi`、`secret`。
- **八种固定位宽整数的数值 family 已完整。** 每种都有 `compare`、`min`、`max`、`clamp`、`floor_div`、`modulo`、`pow`、`is_even`、`is_odd`、位运算与位计数、wrapping 算术、旋转、`bit_length`、`parse`。
  - `float32`、`float64` 满足浮点要求：全序比较、分类、舍入、`signum`、bits 与常量。
  - 可执行 matrix gate 检查各 family。
- **现有模块的新函数：**
  - `list` 增加 sort、min、max、binary search 的 `_by`、`_with` 项，以及 `unzip`、`range_step`。`set`、`map` 增加序列算法。
  - `string` 增加 Text、Container 函数。
  - `math` 增加反三角与双曲函数、`hypot`、`cbrt`、`expm1`、`log1p`。
  - `hash` 增加 `crc32`、`adler32`、`sha512`，以及基于 `Secret[Bytes]` key 和 tag、采用常数时间验证的 HMAC-SHA256 与 HMAC-SHA512。stdlib 没有 MD5 或 SHA-1。
  - `url` 增加 `encode_form`、`decode_form`、`parse_query`、`resolve`（RFC 3986 §5）。
  - `path` 增加 `components`、`relative_to`、`with_extension`。
  - `env` 增加 `vars`、`remove`、以 `Option[Secret[String]]` 读取变量的 `secret`。
  - 其他新增：`random.Rng`（带 seed 生成器）、`datetime.now_ms`、`args.has_flag`、`matrix.zip_with`、`matrix.concat_rows`。
- **`fs.open_root`** 打开以 root 为界的文件系统 family，在两目标上拒绝任何离开 root 的路径。
- **自动 import 模块仅在源码触及时加载**，因此不用某模块的程序不检查该模块。

<a id="security-hardening"></a>

## 安全加固

本发布完成 toolchain 与 stdlib 的安全审查。每个修复都有带已记录 negative control 的 contract 或 gate。逐行状态见 `docs/roadmap/active/security-by-construction.md`。

- **toolchain 与 supply chain：**
  - git 依赖仅从受信 owner 获取。
  - 依赖中的 native code 和 `@inline_rust` 需要明确授权。
  - native build 检查 rustc 最低版本。
  - 源码中的 Unicode 双向控制字符为 E101。
  - release build 忽略开发用环境开关。
- **installer、updater、cache：**
  - self-update 使用树内 HTTPS client，拒绝隐式降级；安装脚本要求 HTTPS。
  - `almide install` 只向 bin 目录内的普通名称写入，并应用 trust check 和 native-code 授权。
  - build cache 位于每用户私有目录，只有 digest 匹配才运行 cache binary。
  - `almide build` 输出名必须为普通名称。
- **editor 与 agent 集成：**
  - `almide mcp` 工具把 path 参数限制在项目内，将其作为参数而非 flag 传递。
  - read-only `almide mcp` 工具从不获取依赖或写入 `almide.lock`。
  - language server 将 workspace root 作为绝对路径，并保持在其内。
  - 对目录执行 `almide fmt` 跳过 `.git`、`target`、`node_modules`，`fmt` 和 `test` 都不跟随 symlink。
- **manifest：**
  - `almide.toml`、`almide.lock` 仅作为大小受限的普通文件读取。
  - 拒绝 manifest 文本中的控制字符和双向字符。
  - 每次 build 都强制编译器版本要求。
- **effect 与权限：**
  - 检查函数值携带的 effect，以及经 protocol bound 调用的 effect method。
  - capability 分类更细；`[permissions] fs` 在 native 和内嵌 wasm host 上把文件访问限制到已授权目录。
- **不可信输入：**
  - `json.parse` 严格遵循 RFC 8259 和 I-JSON，嵌套上限为 1000。
  - `url.parse`、`url.resolve`、HTTP client 的 URL splitter 按浏览器方式读取 URL。
  - `base64` 解码仅接受规范形式。
  - `datetime.parse_iso` 限制年份范围。
  - case mapping 绝不把非 ASCII 字母折叠为 ASCII。
  - 数字解析仅接受经 ASCII 空白裁剪的有限十进制文本。
  - regex engine 为线性时间（Pike VM），拒绝深嵌套。
  - map 的 hash index 被碰撞 key 淹没时，在两目标上回退到按 key 排序的 index，避免 flood 恶化每次 lookup。
- **http.serve：**
  - RFC 9112 不允许的 request head 返回 400。
  - router 读取一个规范 path。
  - 用 64-slot pool 服务连接，head deadline 为 10 秒。
  - handler error 返回固定 500 body，并在 server 记录日志。
  - handler 中的 runtime abort 只使该 request 失败。
  - response 带 `X-Content-Type-Options: nosniff`。
  - 带类型 request decode 在每个深度都拒绝未知 key。
- **runtime 上限：**
  - `zlib` 输出上限 256 MiB，更大界限使用 `_max` variant。
  - whole-file `fs` reader 只接受最多 1 GiB 的普通文件。
  - network read 与接收 descriptor 有界。
  - native fan thread 限为每 CPU 一个。
  - 内嵌 wasm host 按一个 memory budget 计量所有 store，该预算遵循环境内存限制，并检查每个 guest pointer。
  - 内存耗尽不在故障隔离范围内。
- **复杂度：** substring 与 byte search、`value.merge`、`pick`、`omit`、`json.set_path`、`path.normalize`、`math.factorial`、`bigint` 文本转换及 `pow`、`url.parse_query`、`string.from_utf16`、`list.range_step`、`math.choose`（#4212）、wasm `map.remove` 与 `set.remove` 不再有二次复杂度或无界情况。
- **secret 与随机性：**
  - 新 `Secret[A]` 类型打印为隐去内容，按常数时间比较。含 `Secret` 的 `Codec` 类型只派生 decode（encode 为 E023）。
  - `bytes`、`string` 有 `is_equal_constant_time`。
  - Codec field 接受 `@skip`、`@skip_decode`，`T.decode_strict` 拒绝未知 key。
  - `random` 在每个目标上都取自 OS entropy。
- **错误文本：**
  - runtime error text 对引用的 path、command、host 和其他值中的控制／双向字符进行 escape。
  - 引用 URL 的 HTTP error 遮蔽 password。
  - `process.kill` 直接使用 kill(2)，检查 pid 与 signal。

<a id="correctness"></a>

## 正确性

- **wasm：传入函数结果调用的 module global 保持自身值**（#4115）。
- **整数窄化：** constant folding 的 `MIN / -1` 保持 C-002 guard（#4161），`Int8`、`Int16`、`Int32` 的一元负号执行窄化（#4163）。
- **拒绝寿命超过重新绑定 block 的 raw address**（#4153、#4169）。
- **派生的 `Codec.decode`** 对过短 tuple-variant payload 返回 err 而非 abort，两目标报告相同 error path（#4164、#4165）。
- **native 与 wasm 一致：**
  - `io.read_all`、`read_line`、binary `io.write`（#4138、#4142）。
  - `http.query_params`（#4117）。
  - `env.set`（#4200）。
  - 深嵌套 `regex.compile`（#4195）。
  - 跨 fan arm 共享的 net handle（#4199）。
  - HTTP value 和 `JsonPath` 的插值（#4204、C-432）。
- **native：**
  - JSON key interning 有界（#4202）。
  - 由 `process.start` 启动且从未 wait 的子进程在程序退出时停止（#4214、C-437）。
- **checker：**
  - 调用后才解析类型的 protocol bound 在 solve 后判定。例如非数值元素上的 `list.sum` 现在是 check error，而非 build panic（#4235）。
  - 拒绝 `Numeric`、`Integer`、`Text` bound 上的 container、tuple、function 类型。
  - plain fn slot 中的 effect fn value 在 check 时拒绝（#4173）。
  - 命名 record literal 对照它构建的类型检查。
  - E033 仅应用于内置模块自身的 opaque 类型，而非具有相同裸名称的用户类型。
  - 声明的 generic 类型缺少类型参数为 E093。
  - 不同种类 scalar 间的 `==` 为 E037。
  - 任何模块都不能重新声明内置 protocol 名（#4190）。
  - 对其他模块的 opaque record（如 `Secret`）做 record update 或解构 pattern 为 E033。
  - 声明为 `-> Never`、但函数体以值完成的 fn 被拒绝。
  - 背后无 matrix 操作的 `Matrix` 运算符配对在 check 时拒绝，而非 lower 为 scalar 操作。
  - 在预期 `Value` 的位置对 `Codec` record 调用 `json.stringify`，会得到指向该类型自身 `encode` 的 check error，而非 Rust build failure（#4272）。
  - 与 stdlib 类型同名的用户类型（如 `Secret`），在 package 及 `Codec` derive 中仍是用户的类型（#4273）。
- **模块与包：** 依赖裸导入自己的模块时，即使 root project 有同名模块，也解析至其自身 package，而非报告 circular import（#4270）。
- **代码生成与 lowering：**
  - 对 plain value 管道传入的 `!` 为 no-op（#4215）。
  - 对 `@intrinsic` sibling 的非限定调用使用其 symbol（#4216）。
  - runtime symbol 不与 Almide 函数体的函数冲突（#4217）。
  - generic caller 的类型参数与 callee 的分开（#4218）。
  - 对 `/` 执行 `path.join` 保留 root。
  - `Int64`、`Float64` 运算符可用。
  - `Matrix` 一元负号可用。
  - 报告 clock receiver 上的未定义 method。
- **返回 `Result` 的 pure fn 与 effect fn 一样，在 err 路径保留 `mut` 参数的 buffer**；对借用 map read 的 match 以引用绑定 payload。曾在 wasm trap 的拒绝路径现在与 native 一致，native build 不再以 `AlmideStr: Borrow<&AlmideStr>` 失败（#4274）。
- **向 `bytes.as_mut_ptr` 传入不可变 binding 在 check 时被拒绝**（#3975、issue #3966、C-062）。
