# v0.68.0-rc1 — ドメインカーネルが stdlib を離れ、fan.min が fan.race を置き換える

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](v0.68.0-rc1.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](v0.68.0-rc1.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](v0.68.0-rc1.zh-CN.md)

> [正本](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/releases/v0.68.0-rc1.md)を 35297a612fb29e3f78f6587aba253aa91d51f466 に固定した非規範的な読者向け翻訳です。自動同期されず、原本が引き続き権威を持ちます。以下のリリース状態・計画・実装・セキュリティ・検査・性能の主張はこの歴史的リリース記録のものであり、公開、コマンド、ベンチマーク、advisory、保証をここで独立に検証していません。リリース予定の記述は実際の公開の証拠ではありません。

**リリース候補 1**（#1484）: soak 期間用のプレリリースとして公開し、「latest」から除外します。v0.67.1 以降に `develop` に入ったすべてを含み、soak が問題なく終わった時点で最終 v0.68.0 をタグ付けします。

この候補で **dialect epoch 14** が始まり、裁定で定めた箇所では非推奨期間なしに表面の削除・改名を行います。書かれたコードに影響する変更は 2 つです。ベンダー・モデル固有のドメインカーネルが stdlib からパッケージへ移り、fan の選択形式が改名されます（`fan.race` は `fan.min(clock)` になり、`fan.any` はなくなります）。削除した各表記には移行先を示す診断が出ます。これらの変更の裏では、公開 stdlib 関数すべてが両ターゲットで検査済みになりました。

<a id="breaking-at-epoch-14"></a>

## epoch 14 の破壊的変更

- **ベンダー・モデル固有の 33 関数が stdlib からパッケージへ移ります。** プロバイダーのストリーミングクライアント（OpenAI、Anthropic）、Qwen3 ブロック、Q1_0/Q8_0 量子化カーネル、transformer の構成部品は `almide/llm` と `almide-graphics/nn`（モジュール `nn.kernels`）へ移り、`mem` モジュールは削除されます。削除した関数の呼び出しには、新しいパッケージ名か呼び出しの削除を指示する診断が出ます。cheatsheet と `llms.txt` は各移行先を示します（#3797、#3806）。
- **`fan.race` は `fan.min(clock) { … }` / `fan.min(clock, xs, f)` になり、時計が必須です**（ADR-0028）。時計の型が「最小」を何で測るかを示します。`compute` は予算内で決定的計算量が最小の分岐を選び、同点ならソース順です。時計なしの `fan.min` は構文解析エラーになります（#3808）。
- **`fan.any` を削除します。** ソース順で最初の `Ok` を取るには `a() ?? b() ?? fallback`、リストには `list.find_map(xs, (x) => f(x)?) ?? fallback` と書きます。どちらも両ターゲットで effect callback と既に動作します。旧表記（`fan.race` の全 4 形式、`fan.any { }`、`fan.any(xs, f)`）はそれぞれ E027 となり、代替を示します。`fan.bounded` と `fan.timeout` は名前を維持します（#3808）。
- **`testing.assert_throws` を `testing.assert_aborts(expected, () => …)` で置き換えます**（ADR-0029）。クロージャは native では子プロセス、wasm では新しいインスタンスで実行します（C-384、新コード E098 と E099）。新しい Process capability がこれを許可します（#3806、#3808）。
- **#3338 より前の native callback alias を削除します。** 非推奨化時に予告したとおりです。epoch ゲートは非推奨の期限を過ぎると失敗するようになりました（#3806）。

<a id="language-surface"></a>

## 言語の表面

- **`fan { }` は名前付き arm のレコード形式を受け付けます。** 通常のレコードリテラルとして型付けし、タプル形式の fan をレコードへ分解する形に lower します。1 行 1 フィールドに整形し、arm 内に入れ子の fan があっても正しく安定します（#3808、issue #1388）。
- **識別子に非 ASCII を使えます。** lexer は UAX #31 XID クラスで識別子を分類し、NFC で保存します。大文字・小文字の区別がない名前は、モジュール内の宣言方法で型側か値側かを決めます。モジュール名と import alias は ASCII のままで、それ以外は構文解析時に拒否します（C-387、#3808、issue #1456）。
- **parser は他言語の慣用表現を、それぞれ 1 エラーで回復し、解析を続けます。** 例は `return EXPR`、`let mut`、波括弧形式の `if`、`===`/`!==`、`elif`、三項式 `c ? a : b`、`&&`/`||`/前置 `!`、`->`/`:`/`case` で書いた match arm、トップレベルの `def`/`function`/`func`/`fun`/`proc`、`const`/`val`、`println!`/`assert_eq!` 型のマクロ、`int`/`i64`/`string` 型の型名、Rust のクロージャです（#3746）。
- **`${` の次の行で式が始まる埋め込み穴を受理します。** 通常の文字列と heredoc の両方です（#3746、issue #2810）。
- **波括弧のない `then`/`else` 分岐には任意の代入文を置けます。** 入れ子の代入先も含みます（#3808、issue #3757）。
- **`Result` 値を扱う `if` と `match` は `let`/`var` 注釈に照らして合流します。** effect fn で、各分岐が `Result` 値であり `Result` 注釈付き let に束縛される場合、E041 を出さなくなりました（#3808、issue #3777）。
- **型注釈で `Duration` と `Compute` を名指せます。** 以前は E029 でした（#3773）。

<a id="fan"></a>

## fan

- **`fan { }` の arm が `@ordered` の stdlib fn に到達すると、native でもブロックを arm 順で実行します。** `env.set`、fs の書き込み、stdin の読み取り、プロセス起動が対象で、native と wasm は同じ状態を観測します（ADR-0024 D3、C-004）（#3808）。
- **両 meter が 1 つの charge 表に従います。** native の既定経路では、ループのないラッパーの入口と文字列埋め込みを課金しなくなり、`fan.bounded` の判定と `fan.min` の勝者がターゲット間で一致します（C-204、C-294）（#3808）。
- **`fan { list.map }` 内の複数要素が trap すると、時間的に最初ではなく最小インデックスの trap を報告します。** 軽い `fan.map` は管理コストを要素ごとでなく要素ブロックごとに 1 回払うようになりました（C-200）（#3808）。
- **fan 意味論の監査による修正:**
  - Float、List、レコード型の勝者がコンパイルできる。
  - 空の `fan.bounded`/`fan.timeout` 本体は全ターゲットで Unit ブロックになる。
  - wasm の `fan.timeout` は replay を尊重し、単調時計を使う。

  監査自体、言語間比較、受け入れテストも入りました（#3785、#3786）。
- **native fan がより多くのプログラムで並列に動きます。**
  - `String` と `List`/`Set`/`Map`/`Result` 型の値が対象になります（#3569）。
  - ヒープパラメータの傍らにスカラー `var` を保持する行カーネルも対象です（#3724）。
  - effect callback が証明済みの pure な仕事だけに fan-out する `fan.map` も対象です（#3775）。
  - プログラム全体が v1 render から外れても、native は `fan.race`/`bounded` 領域を計測します（#3683）。
  - `fs.fold_lines_chunked` は accumulator または callback が Rc を持つと逐次実行します（#3681）。
  - `fs.fold_lines_chunked` はスレッド数を制限します（#3711）。
- **native fan ランタイムを高速化のため再構築しました。**
  - スレッドは常駐し、呼び出し元も仕事を取る 1 つの共有プールから、要素をブロック単位で取得します（#3759、#3767）。
  - 提案をポーリングするスレッドへ公開し、それらがブロックを steal します（#3774）。
  - コストモデルをレッグごとに再較正しました（#3763、#3765）。

  fan floor 台帳（`docs/benchmarks/fan-floor.md`、#3766、#3764）では、測定した 2 台の GCE マシンで全行が Rayon・Go・Zig の最速と同等以下になりました。Intel で 0.48–0.92x、AMD で 0.47–0.85x です。以前は 24 行中 22 行が 1.06–5.05x でした（#3775）。
- **wasm fan worker はスカラーのリストをキャプチャとして受け取り、仕事をブロック単位で受け取ります。** 組み込みホストのスレッドは実行全体を通じて常駐します（#3730、#3732、#3748）。

<a id="correctness"></a>

## 正しさ

- **wasm の `error.message` は借用しただけの payload を解放しなくなりました**（use-after-free）。`error.context` がリークしていたブロックも解放します（#3610）。
- **`check` を通るのに native ビルドに失敗していたプログラムがコンパイルできるようになりました。** 修正したケース:
  - `Bytes`/`Matrix` の fold accumulator、および runtime 結果のラップ（#3581、#3582）。
  - Almide でコンパイルした fn へ渡す `Bytes` の `if`/`match`（#3609）。
  - effect fn 内で巻き上げた `list.set` 値（#3594）。
  - effect fn 内の `some`/`ok`/`err` の `Result` payload（#3632）。
  - 同名のトップレベル `let` を宣言する 2 モジュール（#3728）。
  - パラメータへの `matrix.concat_cols`、および呼び出し引数を決して自動 `?` にしないこと（#3675）。
  - runtime の `Fn` スロットへ渡すクロージャ値（#3693）。
  - 展開した matmul、キャプチャした var への mut-param 呼び出し、不透明 stdlib 型の順序比較（#3773）。
- **`Matrix` または `Value` に対する `list.sort`/`min`/`max` は check 時に E030 です。** 以前は native ビルドが不正な Rust を生成していました（#3589）。wasm は `Bytes`、`Result`、`Unit` の要素を拒否せず、native と同じように順序付けします（#3593）。
- **native の末尾再帰はすべての返り値型で定数スタックで動きます。** レコード、variant、`Set`、`Bytes` も含みます（#3563）。
- **sandbox 化した effect fuzz キャンペーンで見つかった欠陥を修正しました。**
  - `fs.read_lines`/`list_dir`/`walk` の失敗ごとに起きる wasm リーク。
  - ディレクトリの `fs.copy`。
  - Unit let 内の Unit effect（#3621）。
- **wasm のリーク分を解放します。**
  - host-leaf 呼び出し結果（#3624）。
  - `io.read_n_bytes`/`read_byte` の staging ブロック（#3629、#3631）。
  - `fs.read_bytes`/`read_bytes_if_exists`/`stat` の staging ブロック（#3680）。
- **ターゲット間の値の修正:**
  - wasm の `bytes.read_string_at`/`read_string_be` は損失を許して decode し、String が不正な UTF-8 を持たないようにする（#3566）。
  - bytes のすべての浮動小数書き込み関数が両レッグで canonical NaN を書く（C-210、#3701）。
  - wasm の `json.to_map` は重複キーごとに 1 エントリーを残す（C-380、#3702）。
  - wasm の `json.remove_path` はルートではタグ付き Null を返す（#3806）。
  - rope rotation と multi-head attention は、対または列のない head をたどらなくなる（#3583）。
  - native の複数の不一致: NaN の append、空の rope、hidden-width 乗算、ディレクトリに対する `fold_lines_range`（#3675）。
  - `mut` パラメータを転送する自己・相互末尾呼び出しは wasm でも末尾呼び出しのままになる（#3675、#3693）。
- `almide fix` は import 済みモジュールを認識し、effect 呼び出しの `??` fallback 内の `!` を診断が名指します（#3527）。

<a id="wasm-and-hosts"></a>

## wasm とホスト

- **`process.stdin_lines` はすべての wasm レッグで動きます**（#3629）。**`net.tcp_*` は組み込み wasm レーンで動き**、分類済みエラーを持つ 1 つの native core 上に構築しています（#3693）。**全レスポンスの http クライアント**は WASI 0.3 component 上で動きます（#3675）。unix/shm には暫定の組み込み host op が入ります（C-382、C-383）（#3806）。
- **http クライアントはすべてのレーンで本体のフレーミングを自ら行い**、呼び出し元の `Content-Length` を破棄します（C-385）。**`http.serve` は**最終応答でない status、token でないヘッダー名、ヘッダー値の制御バイトを**拒否**し、handler のフレーミングフィールドを破棄します。すべてのホストで同じ挙動です（C-367、C-375）（#3806）。

<a id="performance"></a>

## 性能

- **native Almide の `String` は既定で共有の参照カウント付きバッファになりました**（ADR-0013 stage 2）。そこに至る手順:
  - 生成コード中の 1 つの `AlmideString` alias（#3716）。
  - Miri ジョブ付きの `AlmideStr` crate（#3717）。
  - alias 経由で render するリテラル（#3719）。
  - alias を用いて記述した runtime ABI（#3746）。
  - 切り替えそのものと、`ALMIDE_SHARED_STR` の削除（#3806）。

  移行計画と GCE A/B 手順は #3720 と #3715 に記録しています。
- **x86_64 の `--release` は既定で x86-64-v3 基準（AVX2 + FMA）を対象とします。** `--target-cpu portable`（または rustc の任意の CPU 名）で上書きできます。他のアーキテクチャは rustc の generic CPU を維持します（#3740）。以前の既定値 `native` は、表記比率ゲートが x86 の 1.25x の退行を検出した後で撤回しました（#3727、#3734）。
- **in-place 編集は各 stdlib 関数の 1 つの `@reuse` 宣言から生まれ**、両レッグがそこから in-place 経路を導出します。元の値が最後の使用地点にあるとき、以下の関数は in-place に書き込みます。
  - `list.set`/`swap`/`update` と `bytes.set`（#3598）。
  - `set.insert`/`remove`（#3603、#3713）。
  - `map.update`（#3708）。
  - wasm 上の連鎖した `map.set`/`upsert`/`update`（#3729）。
  - `string.push`（#3675）。
  - `map.delete`/`remove`、`map.merge`、`bytes.copy_within`/`fill`/`clear`（#3675）。

  `@implements` は名前リストなしで self-hosted な本体を登録します（#3587、#3626）。fold callback 内または自己末尾呼び出し前の push/set ループは線形のままです（#3682）。
- **二次の経路が線形になりました。**
  - wasm の prepend accumulator（`[e] + acc`、および fold callback 内での同じ push）（#3529、#3531）。
  - wasm の `list.flatten`（#3536）。
  - `option.collect` と wasm の `map.from_list`（#3553）。
  - wasm の `set.from_list` と `list.unique`/`unique_by`、さらに native の `list.unique`（#3703、#3706）。
  - `string.take_end`/`drop_end`/`ends_with`（#3612）。
  - `http.wrap` と `http.with_headers`（#3773）。
  - `map.delete`/`set.remove` は償却 O(1)（#3693）。
  - wasm 上の `value.merge`（#3675）。
- **小さな改善:**
  - enumerate の表記が両レッグで融合する（#3592）。
  - native の region alloc は x86 で bump になる（#3597）。
  - `Int % literal` はマジックナンバー乗算になる（#3771）。
  - `option.is_some`/`is_none` は引数を借用する（#3723）。
  - `option.collect` は結果領域を 1 回予約する（#3725）。
  - wasm の `list.intersperse` は 1 回割り当て（#3596）、リテラル末尾の wasm `flat_map` は結果領域を予約する（#3714）。
  - wasm の文字列比較は一度に 8 バイトで進む（#3714）。
  - wasm の `option.zip`/`result.partition` は credit を正しく取得する（#3546）。
  - 生きたローカル値を読み取り専用で `if`/`match` 選択する場合は clone でなく借用し、v1 native render では if-arm の一時値を合流先へ move する（#3731、#3808）。
  - wasm の `matrix.fma`/`fma3` はオペランドの重なる範囲だけに触れる（#3808）。
  - `for` の先頭として使う所有リストは move する（#3746）。

<a id="stdlib-inspection"></a>

## stdlib 検査

- **公開 stdlib 関数すべてを両ターゲットで検査しました。** `proofs/stdlib-inspection.toml` の 999 行中、未検査は 0 行です。各行には 5 基準 — native/wasm parity、計算量、割り当て、200 プログラムの fuzz キャンペーン、diamond — の GCE stamp があります。generic 関数は Int と String の両方で測定し、すべての probe は成功経路を実行します（#3797、#3806、#3772、#3773）。
- **検査の仕組み:**
  - 台帳と harness（#3541）。
  - 実装の fingerprint が変わると stamp は無効になる（#3547）。
  - 命令数と移動バイト数に基づき、5 サイズへ当てはめる計数式の計算量判定器（#3568、#3576、#3613、#3721）。
  - effect 関数は seed 付き sandbox 世界で検査する（ADR-0027、#3616、#3617、#3627）。
  - generator を Bytes、サイズ付き数値、Set、Matrix、Value、import 専用モジュール、nominal 型へ拡張した（#3551、#3562、#3580、#3602、#3606、#3614）。
  - harness の修正（#3545、#3710、#3712）。
- stamp 付与のバッチ: #3572、#3578、#3601、#3607、#3675、#3693。

## 原本に関する注意

冒頭の「問題のない soak 後に最終 v0.68.0 をタグ付けする」という予定は歴史的なものです。後続の [v0.68.0 記録](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/releases/v0.68.0.md) は、その最終版はタグ付けされず v0.69.0 に置き換えられたと記述しています。この読者版は先の計画を黙って書き換えず保持します。上記の epoch 14 での置換にもかかわらず、歴史的な実装項目には旧 fan.race 表記も残っています。fan の性能比較は 2 台の GCE マシンで測定した台帳行に限られ、普遍的な速度の主張ではありません。999 行の検査、200 プログラムのキャンペーン、成功経路の probe は原本のその時点の証拠であり、すべての挙動の証明や独立した再検証ではありません。
