<a id="correctness"></a>

## 正确性

- **若一个参数重新绑定了较早参数读取的变量，两种目标现在都能正确排序**（#3823、#3844；#3815、#3835、C-258）。`st |> set.fold({ st = set.from_list([0]); 0 }, f)` 在 native 上因 rustc E0506 失败；具有同样借用参数形状的 `list.contains`、`set.contains`、`map.get`、`string.contains`、`fs.fold_lines` 及用户函数也如此。在 wasm 上，较早的读取是一个视图，却被后续参数释放。现在，较早参数按源码顺序在重新绑定的参数之前绑定。
- **捕获 String 参数的 `fan` 分支能在 native 上编译**（#3844；#3819、C-004）。以前它将标准库 `String` 发出到 `AlmideString` 绑定中（rustc E0308）。测试 fixture 覆盖 String、List、Map、record、variant、Option、Bytes 和 `let` 捕获。
- **按定义而非拼写解析调用**（#3844；#3825、#3831、#3832，新契约 C-388）。解释器按身份解析命名调用、尾调用及 fuel 计量器中的用户函数；wasm 的小标量函数内联器先在每个调用自身的模块中解析，因此不再混淆不同模块中的同名函数。
- **仍被 `if` 选择借用的列表不再移入其拥有型对应函数的调用**（#3872；#3870）。这是检查重跑发现的 native 构建失败（rustc E0505）。测试覆盖每个拥有对应拥有型版本的列表操作。
- **每个产生 NaN 的 stdlib 函数在每条执行路径都返回固定的 +qNaN**（#3872；#3846），因此 Float 上的 `list.min` / `list.max` 在 native 与 wasm 间一致。
- **http 客户端和服务器重试被信号中断的读取**（#3872；#3857）。
- **`fan.bounded`、`fan.timeout` 和 `fan.min` 计量单调用主体的参数**（#3822、C-204、C-205）。在 `fan.bounded(…) { id(heavy(1000)) }` 中，参数 `heavy(1000)` 在进入预算之前运行，没有计入任何消耗；现在非原子参数在计量区域内求值，各执行路径一致。

<a id="performance"></a>

## 性能

- **自引用 variant 上的检查不再呈指数增长**（#3821；#3818）。预期 effect 搜索对每个命名类型追踪八层，却不记忆访问过的位置。一个含 15 个文法的解析器，其 `almide build --release` 运行超过 30 分钟后被终止；现在耗时 26.7 秒，对比 v0.67.1 的 32 秒。
- **native 的 `Value` 程序不再比其 wasm 构建慢**（#3826；#2157）。`value.array`、`value.object` 和 `value.as_array` 移动即将结束生命周期的源值，而非深拷贝（声明为 `@reuse`）；`value.stringify` 写入一个缓冲区，`json.parse` 直接从输入构建无需转义的字符串。50,000 条记录的 JSON 往返从 wasm 耗时的 1.26 倍变为 0.69 倍，新门禁使 `jsonround`、`wordfreq`、`wordfreq-group` 保持 native ≤ wasm。
- **发布构建让保序浮点归约保持标量形式**（#3824）。在 aarch64 上，循环向量化器错误地向量化严格的 `Float` 求和，导致 spectralnorm 的 `--release` 比默认配置慢；现在传入 `-force-ordered-reductions=false`（在 x86 上无操作）。作为 fold 开头的范围字面量（`list.fold(0..<n, …)`）也不再在任何执行路径上构建为列表（#3810）。
- **冷 native 构建快 17%**：runtime rlib 使用 4 个 codegen 单元编译，且不进行本地 ThinLTO pass；在同一 runner 上对比最新发布的 A/B 测试现在为冷构建设置门禁（#3844；#3829）。
- **权威分配器以 O(1) 释放超过其上限的块**（#3872；#3849），且 **`zlib.crc32` 改为表驱动**，其 wasm 路径不再比 native 慢 3–10 倍（#3872；#3848）。

<a id="gates-and-evidence"></a>

## 门禁与证据

- stdlib 检查将每个函数的 wasm emitter 分支纳入其指纹，计数判定器以最长运行限制 k；每个更改行均重新检查，台账中未检查项为 0（#3872；#3796、#3859）。
- wasm-runtime 和 build-speed 台账在可重建的云机器类别上重新盖戳，其判定在判断前检查该类别（#3828）。
- 被单 fixture 限制截断的语料 fixture 现在停止其解释器运行，不再让线程继续运行（#3817；#3809）；对应测试在高负载 runner 上也不再不稳定（#3844）。
- 两条 `wordfreq` 性能行都从 4M 词改为 8M 词，使现已更快的 native Map 路径仍高于计时下限（#3844）；ratchet-separation 负对照也不再因自身清理而失败（#3833）。
