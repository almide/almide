## ALS-M1 模式匹配的绑定规范

Option/Result 的构造与匹配、嵌套构造器模式、测试变体构造器的元组模式、let 解构中的嵌套子模式，都**按声明绑定每个叶子**；匹配自上而下执行第一个匹配分支。堆载荷（如 String）的绑定可以借用方式读取，不转移所有权。分支体本身还是变体匹配的嵌套形态，也会在 `let` 绑定中（因堆值而被 branch_lift 提升为辅助函数的位置）绑定所有层级的载荷。

**构造器模式指定 subject 拥有的分支（静态规范）**：`some`/`none` 解构 Option，`ok`/`err` 解构 Result，用户变体只匹配自己的分支。模式若指定 subject 不拥有的分支，会在**检查时以 E048** 拒绝，两目标一致（类型检查先于目标分流）。四个单元：两个方向的家族不匹配、用户变体上的内置承载类型、来自其他变体（或承载类型）的用户分支。#1341 之前只拒绝标量 subject，因此 `match list.get(xs, 0) { ok(a) => … }`（`list.get` 返回 `T?`）会把载荷绑定为 `Ty::Unknown`，一直存活到代码生成；native 上出现 `[COMPILER BUG]` 横幅（用户分支不匹配时为**无效 Rust 输出**），wasm 上则碰到可执行子集的 wall。此规则仅针对结构已确定的 subject；推断中的类型和表示不透明别名的 `Named` 会静默放行。
测试：`spec/wasm_cross/nested_variant_match_bind.almd`、`tests/diagnostics/e048-cross-family-variant-pattern/`、`tests/diagnostics/e048-foreign-ctor-case/`。
契约：C-044、C-070、C-073、C-091、C-113、C-114、C-269。

<a id="als-m2-レコード意味論"></a>

## ALS-M2 记录语义

记录的展开更新 `{ ...r, f: v }` 创建**新值**（原值不变，遵循 ALS-C5 的值语义）。无论推断还是显式指定，字段表示都相同。泛型字段按构造时的实例化类型确定大小。phantom 类型参数不影响可观察表示。跨模块单态化具有相同观察结果。
契约：C-046、C-072、C-078、C-092、C-123。

<a id="als-m3-変種型adt"></a>

## ALS-M3 变体类型（ADT）

用户定义变体具有独立命名空间（可与 `Box` 等标准名称共存）。相互递归变体、以匿名记录为载荷的变体，以及模块内部构造、外部观察，均按声明行为，且不依赖目标。
契约：C-043、C-076、C-079、C-093。

<a id="als-m4-effect-fn-の脱糖規範"></a>

## ALS-M4 effect fn 的脱糖规范

> **一致性注记（非规范性，2026-10-31）**：以下自动 `?` 的说明记录旧实现。已采纳的 [ADR-0008](../../../../../adr/0008-explicit-propagation-only.md) 与 C-217 记录移除隐式传播，C-345 记录在实参位置保留 Result。当前用法见 [effect-fn-call-semantics](../../../../../specs/effect-fn-call-semantics.md) 和 `spec/lang/explicit_propagation_test.almd`。C-064 的契约正文仍保留旧自动 `?` 描述；此注记不改写该契约，只明确应在 judge 一侧解决的不一致。

effect fn 内对 can-err 调用自动附加 `?`，**不依赖绑定形态**（let / 尾部 / 实参位置使用相同规则）。构造器位置的自动 `?` 也相同。`!` 的 Err 即使从 `for` 循环体内也传播到函数边界。尾部自递归会**转换为 O(1) 栈用量的循环**（深度 10^6 也不溢出），但显式 `err($var)` 重新包装的尾部除外；这是 C-069 在 v1 分支上有意不进行循环改写的形态。
契约：C-064、C-068、C-069、C-119、C-135。

<a id="als-m5-ジェネリクスと推論"></a>

## ALS-M5 泛型与推断

空的 `map.from_list`/`set.from_list` 从使用处解析元素类型。推断参数的 lambda 内的泛型函数、UFCS 协议调用、嵌套 lambda 的高阶函数参数均保留推断链接。类型参数上的 `+` 遵循实际类型（字符串/列表/数值）的规范。引用前置参数的默认实参在每次调用时求值。`unwrap_or` 的载荷类型也可从默认值一侧解析。组合子即使实例化为 Float，也会在两个目标上生成有效代码。
契约：C-080、C-081、C-082、C-089、C-094、C-097、C-126、C-127、C-142、C-145、C-151。

<a id="als-m6-蓄積ループの規範"></a>

## ALS-M6 累加循环规范

`var` 累加（标量、拥有的句柄、相互依赖、混合变异）、列表迭代与调用结果元素的物化、尾递归累加形态、循环内 let 绑定的堆分支，与顺序语义（逐次按序求值迭代的结果）在观察上相符。
契约：C-102、C-104、C-105、C-117、C-174。

<a id="als-m7-識別子の独立性"></a>

## ALS-M7 标识符的独立性

函数和变量名称即便与目标语言保留字（如 Rust 关键字）冲突，也可以原样使用。名称不得因代码生成的需要而泄漏到观察结果中。
契约：C-088。

<a id="als-m8-演算子の全域規範"></a>

## ALS-M8 运算符在所有操作数形态上的规范

比较与相等运算符在所有操作数形态（字面量、变量、字段、调用结果、复合值）上产生相同结果。`-9223372036854775808`（i64::MIN）字面量是可表示的值，不得折叠为 0。
契约：C-083、C-099。

<a id="als-m9-静的検査unit-変異子"></a>

## ALS-M9 静态检查（Unit 变异操作）

将返回 Unit 的原地变异操作结果**重新赋给非 Unit 绑定**的表达式（`xs = list.push(xs, x)`）会以 **E001** 拒绝。变异操作原地执行，将其“返回值”写回的写法会被检测为类型不匹配。裸 `let x = list.push(…)` 只绑定 Unit，仅产生未使用警告（0.59.1 实测）。
契约：C-057。

<a id="als-m10-分岐からの-heap-束縛"></a>

## ALS-M10 来自分支的堆绑定

从 if/match 分支绑定的堆值（`let s = if c then "a" else make()`）就是被选中分支的值本身；观察到空值或另一分支的值均不合规。管道传入具有块体的 lambda 也相同。
契约：C-106、C-115。

<a id="als-m11-unwrap-の脱糖"></a>

## ALS-M11 unwrap 的脱糖

> **上下文补充（非规范性）**：以下说明 C-108 涵盖的 Result 传播上下文，并非将 `test` 内等位置的普通 unwrap（C-222 区分的失败时停止），或 Option 的 `!`，都解释为返回 Err。各上下文的用法见 [result-option-effect](../../../../../specs/result-option-effect.md)。

`!`（unwrap）和 let-unwrap 在所有位置（let / 尾部 / 实参 / 嵌套）使用单一规则：“取出 Ok 载荷；若为 Err，则作为函数的 Err 传播”。
契约：C-108。

<a id="als-m12-heap-要素リスト操作の一般性"></a>

## ALS-M12 堆元素列表操作的通用性

List[String]/List[Value] 的参数传递、join/len/索引/迭代、分类/变换操作（包括 zip_with 的元素类型路由）不破坏元素所有权，并与 native 在观察上相符。
契约：C-045、C-100、C-101、C-141、C-147、C-148。

<a id="als-m13-mut-パラメータの-in-place-変異"></a>

## ALS-M13 mut 参数的原地变异

对 `mut` 参数的原地变异反映到调用者的 `var`（ALS-C5 的例外）。调用方只能传入 `var` 绑定；`let`、非 `mut` 参数和临时值为 E032。只有声明的 `mut` 才开启此例外：标准库原地变异操作（`list.push`/`pop`/`clear`、`map.clear`、`string.push`/`clear`、`bytes` 写入家族）也将接收者声明为 `mut`，没有通过非 `mut` 参数修改调用者值的路径（`Bytes` 的普通参数路径已在 dialect epoch 5 关闭，C-132）。这对**重新分配**的容器（List / String / Bytes 容量增长）也成立，在所有调用位置都会写回调用者槽位，包括返回值的被调函数、嵌套表达式位置、记录字段实参（`f(b.items, …)`）。实参在调用时复制、调用后写回：如果被调函数读取作为实参根的模块级 `var`，它会看到调用前的值（C-132）。
契约：C-061、C-110、C-132、C-136。

<a id="als-m14-整数リテラルの型域静的規範"></a>

## ALS-M14 整数字面量的类型范围（静态规范）

整数字面量必须是**上下文类型可表示的值**。不可表示的字面量在两个目标上都为 **checker 错误（E024）**，不会静默折叠为 0，也不会只在一个目标上构建失败。偏离有三类，各需不同修复：

- **大小**——值超出位宽（如给 `Int` 的 `i64::MAX + 1`）。改用更小字面量或更宽类型。
- **符号**——无符号类型使用负字面量（如给 `UInt64` 的 `-5`）。无符号类型完全不含负值，所以不是大小问题。去掉 `-`，或使用相同位宽的有符号类型（`UInt64` → `Int64`）。`-0` 就是 `0`，因此合规。
- **承载类型（已解决）**——UInt64 上半范围的值，如 `18446744073709551615`，曾触发 E024；0.37.0 引入无符号通道（C-179、C-173 的 SUPERSEDED 节），如今已接受，并始终以 unsigned 运算和打印。剩余偏离是上述两类（大小、符号）。

契约：C-173、C-179。

<a id="als-m15-effect-fn-型スロット"></a>

## ALS-M15 effect fn 类型槽

函数类型加 `effect` 前缀成为**效果槽**：`effect (A) -> B`（或 `effect fn(A) -> B`）。按效果槽检查的 lambda 获得 effect fn 的函数体规则：允许效果调用，`!` 向该 lambda 自己的失败通道传播。槽的运行时形态只有**一种**，即效果承载类型 `(A) -> Result[B, String]`：纯 lambda 的末尾值包为 `ok(...)`，使用 `!` 的 lambda 保持原样；调用方（高阶函数）无论接受哪种写法，都得到相同形态。

- 效果槽接受纯 lambda 和可失败 lambda **两者**。
- 调用 effect fn 类型的**值**本身就是效果调用，产生承载类型 `Result[B, String]`（纯上下文中为 E006）。
- 对于未写 `effect` 的普通 `(A) -> B` 槽，#1108 2b-iii 的 Cell 1 子集内的可失败 lambda 会路由到生成的 `__fallible__` 对应实现并**执行**（C-221、`fallible_user_hof_test.almd`）；子集外仍为 E005。
- 偏离（如仅一个目标缺少 ok 包装、err 消息不同）由 C-221 测试夹具检测。
