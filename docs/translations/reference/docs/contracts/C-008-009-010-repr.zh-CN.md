`"${value}"` 将值渲染回字符串。对于以下形态，它渲染为 **Almide 字面量形式**——与重建该值时所写源码相同，也与 `Repr` 约定产生的格式相同；递归组合，并在 **native 与 wasm 上逐字节相同**。native 使用 `AlmideRepr` trait；结构化 Wasm emitter 有自己的 repr lowering。下文 `__repr_*` helper 名称及 export 冲突机制描述引用修复背后的历史 MIR/WAT 实现，不是当前 emitter 的公开 ABI。fixture 独立于内部 helper 名称，保留可观测格式。

<a id="per-type-repr-format"></a>

## 各类型 repr 格式

| 种类 | Almide 字面量 repr | 契约 |
|------|---------------------|----------|
| List | `[a, b, c]`，空为 `[]` | C-008 |
| Map | `["a": 1, "b": 2]`（方括号，插入顺序，见 C-013） | C-008 |
| Set | `set.from_list([3, 1, 2])`（去重，插入顺序，见 C-014） | C-008 |
| Tuple | `(1, "two", true)`（异构） | C-008 |
| Option | `some(42)` / `none` | C-008 |
| Result | `ok(7)` / `err("boom")` | C-008 |
| String（容器内） | 加引号，并转义 `"`、`\n`、`\t`、`\\` | C-008 |
| Float（容器内） | 最短往返形式（C-023），如 `0.30000000000000004` | C-008 |
| Record | `Point { x: 1, y: 2 }`（声明字段顺序、声明名称；模块的 `m.Point` 显示为 `Point`，#1836） | C-009 |
| 元组 variant | `Click(10, 20)` | C-009 |
| 记录 variant | `Scroll { dy: 3 }` | C-009 |
| 无参 variant | `Empty` | C-009 |
| 匿名记录 | `{ x: 1, y: 2 }`——**无类型名，字段按名称排序** | C-009 |
| 自递归 ADT | 经 `__repr_Tree` 生成 `Node(Leaf(1), Leaf(2))`（通过调用递归） | C-010 |
| 自递归／互递归记录 | `Node { val: 1, kids: [...] }` | C-010 |
| 泛型记录／variant | 按实例化键控：`__repr_Tree_Int` 与 `__repr_Tree_String` | C-010 |

<a id="the-four-subtle-invariants-the-fixtures-lock"></a>

## fixture 锁定的四个细微不变量

1. **匿名记录在两个目标上均按名称排序字段**（C-009）。匿名记录没有声明类型名，因此没有可继承的规范字段顺序。native 合成按名称顺序存储字段的 `AlmdRec_*` struct，wasm 遍历也排序以匹配。`{ y: 2, x: 1 }` 和 `{ x: 1, y: 2 }` 均 repr 为 `{ x: 1, y: 2 }`。

2. **递归通过有限值上的调用进行，而非编译期类型展开**（C-010）。自递归的 `Tree = Leaf(Int) | Node(Tree, Tree)` 无法在 wasm 上以类型驱动的内联遍历 repr，因为类型图无限。它通过 `__repr_Tree`，在*值*上递归调用自身，在有限数据上终止。

3. **泛型 repr 函数以实例化为键，而非裸名称**（C-010）。过去 `Tree[T]` 的 repr 函数按裸名称（`__repr_Tree`）单态化，因此将 `T` 载荷读作原始 `TypeVar`，渲染成 `Leaf(T {  })`。修复后按具体实例化（`__repr_Tree_Int`、`__repr_Tree_String`、`__repr_Tree_List_Int` …）键控，沿递归引用替换所在位置的类型参数（`Node` 的子节点为 `Tree[T]` -> 同一实例化）。同一程序同时有 `Tree[Int]` 和 `Tree[String]`，就是此前按名称单态化会破坏其中一种的冲突案例。

4. **实例化是唯一键——每实例化一个 helper，而非每个位置一个**（C-010）。元素 repr（`__repr_Tree_Int`）及其容器遍历器（`__repr_list_Tree_Int`、`__repr_opt_Tree_String` 及其 `_go` 循环）无论被多少 `"${…}"` 位置引用，每个实例化都只生成一次。对同一值插值两次只改变输出文本，别无其他。按位置生成不仅浪费：生成的 helper 作为 wasm export 进入模块，第二份就会成为重复 export 名——无效模块，wasmtime 在任何 Almide 语义运行前的 parse 阶段就拒绝它（#1357）。现在 renderer 对重复 export 名报出边界，而非交付这样的产物。

<a id="the-type-name-is-the-declared-one-on-every-leg-c-009-1836"></a>

## 每条路径的类型名均为声明名（C-009，#1836）

repr 使用类型**声明时**的名称。在模块 `m` 中声明为 `type Cfg = { a: Int, b: Int }` 的记录，repr 为 `Cfg { a: 1, b: 2 }`——与入口程序自身的 `type Cfg` 输出完全一样。值来自哪个模块不属于其 repr，正如入口文件不是根类型 repr 的一部分（两个模块的同名类型会输出相同裸名称，与两个文件的情况一样）。修复前，每条路径输出各自内部拼写：native 是 flatten 后的 Rust struct `almide_rt_m_Cfg { … }`，wasm（两个 emitter）和 interp 是 flatten 前的限定声明 `m.Cfg { … }`，模块类型的 `deriving Repr` 又将 `m.Cfg { … }` 固化到 IR，因此 native 上连 `${p}` 与 `m.Pt.repr(p)` 都不一致。一个 helper `almide_ir::declared_type_name`（flatten 前带点名称的最后一段——类型名的其他位置不会出现点）决定每条路径的拼写；native 通过 `repr_names` 注解将其保留到 flatten 改名之后，因为 `almide_rt_<mod>_<Type>` 的任一部分含下划线时，就无法反向拆分。

<a id="display-vs-repr--the-0-distinction-c-011"></a>

## Display 与 repr——`.0` 的区别（C-011）

插值中**单独的**整数值 float（`"${f}"`）以 **Display** 形式渲染，会去掉 `.0` 后缀。但**容器内的** float 走 repr 路径，`float.to_string` 保留 `.0`。两种形式在跨目标时都逐字节相同；区别在于值经过哪条路径，该区别由 C-011 与这些契约共同锁定。
