`"${value}"` は値を文字列へ描画し直す。以下の形では、値を再構成するために書くのと同じソース、`Repr` 規約と同じ形式である **Almide リテラル形式**に描画する。再帰的に合成され、**native と wasm でバイト同一**となる。native は `AlmideRepr` trait を使い、構造的 Wasm emitter は独自の repr lowering を持つ。以下の `__repr_*` ヘルパー名と export 衝突の仕組みは、引用した修正の背景にある過去の MIR/WAT 実装を説明するもので、現行 emitter の公開 ABI ではない。fixture は内部ヘルパー名とは独立に、観測可能な形式を保持する。

## 型ごとの repr 形式

| 種類 | Almide リテラル repr | 契約 |
|------|---------------------|----------|
| List | `[a, b, c]`、空なら `[]` | C-008 |
| Map | `["a": 1, "b": 2]`（角括弧、挿入順。C-013参照） | C-008 |
| Set | `set.from_list([3, 1, 2])`（重複除去、挿入順。C-014参照） | C-008 |
| Tuple | `(1, "two", true)`（異種の型） | C-008 |
| Option | `some(42)` / `none` | C-008 |
| Result | `ok(7)` / `err("boom")` | C-008 |
| String（コンテナ内） | 引用符で囲み、`"`、`\n`、`\t`、`\\` をエスケープ | C-008 |
| Float（コンテナ内） | 最短の往復変換形式（C-023）、例：`0.30000000000000004` | C-008 |
| Record | `Point { x: 1, y: 2 }`（宣言フィールド順、宣言名。モジュールの `m.Point` は `Point` と表示、#1836） | C-009 |
| タプル variant | `Click(10, 20)` | C-009 |
| レコード variant | `Scroll { dy: 3 }` | C-009 |
| 引数なし variant | `Empty` | C-009 |
| 匿名レコード | `{ x: 1, y: 2 }` — **型名なし、フィールドは名前順にソート** | C-009 |
| 自己再帰 ADT | `__repr_Tree` 経由の `Node(Leaf(1), Leaf(2))`（呼び出しで再帰） | C-010 |
| 自己／相互再帰レコード | `Node { val: 1, kids: [...] }` | C-010 |
| ジェネリックなレコード／variant | インスタンス化をキーとする：`__repr_Tree_Int` と `__repr_Tree_String` | C-010 |

<a id="the-four-subtle-invariants-the-fixtures-lock"></a>

## fixture が固定する4つの細かな不変条件

1. **匿名レコードは両ターゲットでフィールドを名前順にソートする**（C-009）。匿名レコードには宣言型名がないため、引き継ぐべき標準フィールド順がない。native はフィールドを名前順で格納する `AlmdRec_*` struct を合成し、wasm の走査も一致するようソートする。`{ y: 2, x: 1 }` と `{ x: 1, y: 2 }` はともに `{ x: 1, y: 2 }` と repr される。

2. **再帰は有限の値に対する呼び出しであり、コンパイル時の型展開ではない**（C-010）。自己再帰の `Tree = Leaf(Int) | Node(Tree, Tree)` は型グラフが無限なので、wasm で型に従うインライン走査によって repr できない。`__repr_Tree` を経由し、*値*に対して自身へ再帰することで、有限データ上で終了する。

3. **ジェネリック repr 関数は、裸の名前でなくインスタンス化をキーとする**（C-010）。以前 `Tree[T]` の repr 関数は裸の名前（`__repr_Tree`）による単相化だったため、`T` ペイロードを生の `TypeVar` として読み、`Leaf(T {  })` と描画した。修正では具体的インスタンス化（`__repr_Tree_Int`、`__repr_Tree_String`、`__repr_Tree_List_Int` …）をキーにし、その箇所の型引数を再帰参照全体へ代入する（`Node` の子は `Tree[T]` -> 同じインスタンス化）。1プログラム内に `Tree[Int]` と `Tree[String]` の両方がある場合は、以前どちらかを壊していた名前だけの単相化の衝突ケースである。

4. **唯一のキーはインスタンス化であり、箇所ごとではなくインスタンス化ごとに1ヘルパー**（C-010）。要素 repr（`__repr_Tree_Int`）とコンテナ走査関数（`__repr_list_Tree_Int`、`__repr_opt_Tree_String`、およびその `_go` ループ）は、それを参照する `"${…}"` 箇所がいくつあっても、インスタンス化ごとに正確に一度出力される。同じ値を2回補間して変わるのは出力テキストだけである。箇所ごとの出力は単なる無駄ではない。生成ヘルパーは wasm export としてモジュールに入るため、2つ目のコピーは重複 export 名となり、wasmtime が Almide の意味論を動かす前、parse 時点で拒否する無効モジュールになる（#1357）。現在 renderer は、そのような成果物を出荷する代わりに、export 名重複で壁を出す。

<a id="the-type-name-is-the-declared-one-on-every-leg-c-009-1836"></a>

## すべての経路で型名は宣言名（C-009、#1836）

repr は型を**宣言時の**名前で表す。モジュール `m` で `type Cfg = { a: Int, b: Int }` と宣言したレコードは `Cfg { a: 1, b: 2 }` と repr され、エントリープログラム自身の `type Cfg` が表示するものと同じになる。値の由来モジュールが repr の一部でないのは、ルート型の repr にエントリーファイルを含めないのと同じである（2つのモジュールの同名型は、2つのファイルの場合と同様、同じ裸の名前を表示する）。修正前は各経路が内部表記を表示していた。native は flatten 後の Rust struct `almide_rt_m_Cfg { … }`、wasm（両 emitter）と interp は flatten 前の修飾付き宣言 `m.Cfg { … }`。さらにモジュール型の `deriving Repr` は `m.Cfg { … }` を IR に焼き付けていたため、native では `${p}` と `m.Pt.repr(p)` すら一致しなかった。1つのヘルパー `almide_ir::declared_type_name`（flatten 前のドット付き名の最終部分。型名の他の箇所にドットは現れない）が全経路の表記を決める。native は `repr_names` 注釈で flatten による改名後までそれを保持する。`almide_rt_<mod>_<Type>` はどちらかの部分がアンダースコアを持つと元に分割できないためである。

<a id="display-vs-repr--the-0-distinction-c-011"></a>

## Display と repr — `.0` の違い（C-011）

補間内の**単独の**整数値 float（`"${f}"`）は **Display** 形式で描画され、`.0` 接尾辞を落とす。一方、**コンテナ内の** float は repr 経路を通り、`float.to_string` は `.0` を保持する。どちらの形式もターゲット間でバイト同一であり、違いは値がどの経路を通るかにある。この違いは、これらの契約とともに C-011 が固定する。
