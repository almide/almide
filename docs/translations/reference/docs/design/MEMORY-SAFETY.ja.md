# メモリ安全性 — 証明されるもの、信頼に置くもの

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](MEMORY-SAFETY.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](MEMORY-SAFETY.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](MEMORY-SAFETY.zh-CN.md)

> [正本](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/design/MEMORY-SAFETY.md)の非規範な履歴参照用スナップショット。固定コミット：35297a612fb29e3f78f6587aba253aa91d51f466。自動同期されない。安全性・証明・測定・実装の主張はここで独立に再検証しておらず、検証コマンドも実行していない。正本を優先する。本文の証明書検査は記載された証明書とチェッカーの機構を指し、第三者による安全認証を意味しない。

測定ページ（[docs/benchmarks/README.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/benchmarks/README.md)）にはこの説明の 1 段落版があり、このページが完全版である。そこで参照する監査済み定理数は `proofs/check.sh` が計算し、`proofs/TRUSTED_BASE.md`、`proofs/receipt.sh`、測定ページに対して検査するため、ここで繰り返さずそちらに記載している。

所有権注釈もライフタイムも `free` も書かない。メモリ管理は、コンパイラ内の [Perceus](https://www.microsoft.com/en-us/research/publication/perceus-garbage-free-reference-counting-with-reuse/) 方式の所有権推論が決定する。ガベージコレクター不要、停止時間なし。推論は各ヒープ値が導入・複製・消費される場所を計算し、ターゲット間で異なるのは、その決定を実現する実行機構だけである。証明を伴って出荷するコンパイラには、その境界を示す責任がある。以下に示す。

**「メモリ安全」の意味。** 定義は 1 つで、カーネル検査済み：[`proofs/MemorySafe.v`](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/proofs/MemorySafe.v)（#4013）。ヒープトレース（各割当て、store、load、参照の増減が対象ブロックを明示する）上で、`MemorySafe` は 4 条件からなる。各 load/store が生存するブロックの内側にある（空間）、解放済みブロックに触れず、割当てが生存中ブロックを渡さない（時間）、読まれるすべてのバイトが割当て以後に書かれている（初期化）、各アクセスがブロックの割当て時の表現を使う（型）。トレースチェッカーは、この定義に対して健全かつ完全と証明されている。以下の証明は**時間**条件（`rc_check_gives_temporal`）に到達し、structural wasm 経路がビルドごとに各 `xs[i]` / `b[i]` アクセスについて出力する境界証明書（#3345 が検査を省略し得るが、証明書が再導出する）については**空間**条件（[`proofs/SpatialCert.v`](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/proofs/SpatialCert.v)、`accepts_spatial`。証明書のイベントがバイト列のアクセスに一致することを、出荷バイト列に対してビルドごとに検査、#4011 (d)）に到達する。ソースレベルでは Almide の型付き core が 4 条件すべてについて MemorySafe に実行されることを証明済み（[`proofs/CoreSafe.v`](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/proofs/CoreSafe.v)、`typed_core_memory_safe`、#4014 — core であり、lowering にはまだ結び付いていない）。ビルドごとの 2 つの証明書を単一トレース上で合成すると空間・時間・型の条件が得られ、constructor discipline を明示的な仮定に置けば 4 条件すべてが得られる（[`proofs/Certified.v`](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/proofs/Certified.v)、`certified_with_bounds_cert`、`certified_memory_safe`）。まだトレースを出力するビルドはないので、この定義が目指す定理 — ビルドごとのチェッカーが成果物を受理すればその成果物が `MemorySafe` である — は未解決である：#4005（MIR 上の空間条件）、#4006（native）、#1696（structural wasm 経路）。計画と残るすべての欠落：#4011。

- **カーネル証明済みチェッカー — witness の対象となる MIR について証明済み。** **カーネル証明済みチェッカーが再検証する**所有権証明書（Rocq/Coq の中核、追加公理なし、`coqchk` による独立再検査）は、witness 対象の MIR が RC-balanced — モデル化した断片で二重解放もリークもない — で、名前が全域的、capability が上限内であることを確立する。これらの MIR witness を判定するのは現在 `proofs/gate.sh` と `proofs/corpus-wall.sh` のみである。#2761 以降、MIR lowering から wasm バイト列は生成されないため、`almide verify app.almd` は代わりに structural 経路の証明書を判定する（#4011、後述）。WasmEncode/WasmExec/WasmRcDec の定理も同様に、モデル化したランタイム（廃止済みの旧来のもの）について成立する。証明は IR レベルの Inc/Dec バランスについてであり、コンパイラ内部についてではない。証明書で検査された関数でも誤った値を計算し得るため、それを検出するために別の [クロスターゲット契約台帳](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/contracts/README.md) と差分ゲートがある。どのパイプライン段階が証明済みで、どれを信頼し、各ゲートが何を主張し何を主張しないかという正確な境界は、**[proven-vs-trusted.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/contracts/proven-vs-trusted.md)** の図にある。
- **WebAssembly、structural 経路 — 証明書検査対象コーパスでビルドごとに検査、記録は信頼。** 唯一の wasm renderer（#1599 以降は既定、#2752/#2761 以降は唯一の経路。[docs/wasm/](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/wasm/README.md) を参照）は、出力時に証明書を記録する（#1696、完了）。フレームごとの所有権 witness、出荷する stock-WASI バイト列についての呼出しモード・名前の全域性・capability、各添字演算子アクセスの `bounds` witness（#4005）である。`proofs/structural-wall.sh` は `crates/almide-wasm/tests/golden/witness-fixtures.txt` の各 fixture（954 件中 954 件が証明書検査済み）を製品経路でビルドし、出荷ファイルの SHA-256 を bundle に固定し、すべての witness について抽出チェッカー、Rocq カーネル、almide-verify の判定を一致させる。bounds と init の witness については、記録したイベントがバイト列内の命令であることをビルドごとに検査する。`almide-anchor-check` が出荷モジュール自体をデコードし、位置が特定された各イベントをそれが指す命令と照合する（#4011 (d)）。所有権 witness については信頼に残る。コンパイラの隣に `almide-verify` がインストールされていれば、`almide build --target wasm` 自体が証明書を記録し、書込み前に verifier に判定させる。証明書を拒否すると成果物を書き出さない（`scripts/check-build-certifies.sh`）。その他の証拠は差分的（`wasm_cross` コーパス上で native とバイト同一）および動的（checked allocator、nightly）なもの。ランタイムの RC と allocator のバイト列は `proofs/check-structural-bytes.sh` により Coq デコーダーモデル `StructuralDecode.v` と照合される。
- **Native（Rust）— verified renderer のプログラムはビルドごとに検査、残りは信頼。** `proofs/native-wall.sh`（#4006）は、verified native renderer が描画する各プログラム（958 個の `wasm_cross` プログラムのうち 106 個）の所有権証明書を、描画した Rust ソースに固定して、抽出チェッカー、カーネル、almide-verify で判定する。他のプログラムは標準 codegen へフォールバックし、証明書を持たない。同じ決定は Rust 自身の所有権機構によって実現される。コンパイラは所有権を慣用的に扱う Rust を出力し、各ヒープ値は Rust のスコープ終端の drop によって解放される。現在この経路を覆う証明はない。証拠は差分的（契約コーパス上で wasm 経路との出力がバイト同一）である。両 renderer 間で証明書検査済み Perceus MIR を共有するのが [native trust-spine ladder](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/active/native-trust-spine.md)（[#764](https://github.com/almide/almide/issues/764)）であり、共通の scalar/list op はすでに同じ MIR から両ターゲットへ描画される。

## 欠落の表（2026-10-24、#4011）

`MemorySafe` の条件ごとに 1 行（[`proofs/MemorySafe.v:165`](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/proofs/MemorySafe.v)。条件は `spatial_ev` :126、`temporal_ev` :132、`init_ev` :141、`type_ev` :147）。各セルは、何が**証明済み**（カーネル検査済み、追加公理なしの定理）で、何が**ビルドごとに検査**されるか（各ビルドの成果物または証明書を判定するゲートとその方法）、何を**信頼**するか（何も検査しない）を示す。structural 経路の「ビルドごと」は、証明書検査対象コーパスの CI ビルド（`proofs/structural-wall.sh`、trust-spine workflow）を意味する。`almide build` 自体はチェッカーを実行しない。`almide verify app.almd` は同じ経路でプログラムをビルドし、同じ bundle（`crates/almide-wasm/src/witness_bundle.rs`）を書き出し、ファイルがある場合はビルドされた `app.wasm` に SHA-256 で固定し、`almide-verify` に判定させる（#4011）。

旧来の v1 wasm 経路はなくなった（#2761）ため、その列は残していない。native 経路の verified renderer（`crates/almide-mir/src/pipeline_native_rungs.rs:321`）が既定であり、wall に当たると v0 にフォールバックする（`src/cli/build.rs:289`）。958 個の `spec/wasm_cross` プログラムのうち 106 個を描画する（`proofs/native-verified-floor.txt:4`）。

この定義が目指す、出荷成果物 `a` についての定理 `K(c, a) accepts ⟹ MemorySafe a` には、次の順にさらに 3 つが必要である。リストリテラルだけでなく全割当て箇所の構築箇所記録（全トレースの INITIALIZATION と TYPE、#4013 — チェッカーと定理は存在する）；添字演算子以外のヒープアクセスの証明書（#4005）；記録したイベントがバイト列内の命令であることを確認する翻訳検査。この検査は structural wasm 経路の bounds/init witness について、bounds 比較のオペランドを含め現在存在する（`almide-anchor-check`、#4011 (d)）。ただし表現は信頼に残る。wasm 上の所有権 witness の記録規律と native 経路（#4006）は引き続き信頼する。

Rust が所有権注釈という代価でゼロコスト抽象を提供するのに対し、Almide は**注釈ゼロ**の抽象を提供する。注釈を書かず、解放はコンパイラが決定し、それを再検証するチェッカーは証明済みである（structural 経路は bundle を出力する。`almide verify` と証明書検査対象コーパスのゲートは、上述のカバレッジと信頼の制限内で、対応する core 成果物を検査する。component は対象外）。
