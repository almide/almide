# ADR-0016: 数値の決定性は一度だけ記述する単一の規範ファミリーである — ターゲット間でたまたま共有される性質ではない

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](0016-numeric-determinism-is-normative.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](0016-numeric-determinism-is-normative.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](0016-numeric-determinism-is-normative.zh-CN.md)

- **日付**: 2026-08-21（同日提案・承認）
- **背景**: 浮動小数点は「すべてのターゲットでバイト単位同一」が最も失われやすく、最も見えにくい領域である。NaN の符号ビットは x86 と aarch64 で異なり、エンジンによって payload を伝播する場合としない場合があり、ホスト libm の `sin` の丸めは同梱実装と異なり得る。コンパイラは一方のターゲットでは `a*b+c` を 1 回の FMA 丸めに融合し、もう一方ではそうしない可能性があり、プロセスから flush-to-zero モードを継承することもある。ALS は既にこれらの一部を節ごとに固定している。`float.parse` は正しく丸める（ALS-T2、C-024）、`float.to_string` は往復可能な最短の十進表記（ALS-T13）、`float.to_fixed` は正確な二進値に対する最近接偶数丸め（ALS-T9）、NaN はすべての観測境界で canonical（ALS-T2 配下の C-210：`float.to_bits` は `0x7FF8000000000000` を返す）、符号と `min/max` の NaN 規則（ALS-T15）、`-0 < +0` によるソートの `totalOrder`（ALS-C9）、等値性では `NaN != NaN`（ALS-M10、collections.md）、非有限定数は `inf`/`-inf`/`NaN` と表示（ALS-R4）、`-0.0` は符号付き表示（ALS-E3）。実装は全ターゲットで単一の同梱 libm を共有する（「host libm dependence is non-conforming」、text-and-numbers.md）。存在しないのはファミリー全体である。読者は数値決定性のドクトリンを 1 か所で見つけられず、3 つの規則は一度も書かれていない。航空分野の観点（ADR / greenfield ARCHITECTURE §6.6(b)：「数値の決定性を仕様に固定 — 全境界で canonical NaN、interp と backend を通じて単一の同梱 libm/softfloat 方針、±0 と fmin/fmax の同値時規則を一度だけ記述」）は、これを実装が独自に考案しなくてよいはずの unit-6 義務とする。DO-178C のプログラムでは浮動小数点をプラットフォーム詳細ではなく要求事項として扱う（実装の flight-evidence-gaps 台帳の F7 はまさにその例で、`float.parse` の 1-ulp 境界ずれを正確なアルゴリズムで解消した）。これは 2 リポジトリの順序規則の下で要求先行として書ける最初の規範バッチでもあり、構成上、その契約は `proofs/contract-provenance.toml` で `requirements-first` になる。
- **決定**: 数値の決定性は ALS 内の単一の規範ファミリーとする。`T` 接頭辞の下に、各々の契約と fixture を持つ名前付きの節群を設け、実装変更より先にここへ着地させる。既に規範である上記規則（移動せず、ファミリーの先頭節から再参照する）と、初めて記述する以下の規則から成る。
  1. ⚖ **丸めモードと融合。** すべての Float 演算は最近接・同距離なら偶数に丸める。他の丸めモードは観測できない。融合しない：`a * b + c` はすべてのターゲットで 2 回丸める（wasm には融合積和がない。native backend はソースが `math.fma` を明示しない限り発行してはならず、それが存在するなら独立した節を持つ）。
  2. ⚖ **非正規化数を保持する。** どのターゲットでも flush-to-zero も denormals-are-zero も行わない。`5e-324` は最小の非正規化数として parse・表示・計算される（parse は ALS-T2 が既に固定している）。
  3. ⚖ **単一の libm、明記した精度。** すべての超越関数とべき乗系関数（`math.sin`、`cos`、`tan`、`exp`、`log`、`pow`、`sqrt`、`tanh`、`atan`、…）を、全ターゲットで共有する単一の同梱実装で計算する。ホストの実装は決して使わない。`sqrt` は正しく丸める（IEEE の要件）。他は精度上限を明記する（≤ 1 ulp、fixture ファミリーが関数ごとに測定・固定する。「正しく丸める」という主張ではなく、その保証はしていない）。ターゲット間のバイト同一性が規則であり、真値への近さは明記した上限である。
  4. ⚖ **符号付きゼロ。** 算術は IEEE 754 に従ってゼロの符号を保持する。`0.0 == -0.0` は true、`-0.0` は `-0.0` と表示する（ALS-E3）。`float.min(-0.0, 0.0)` は `-0.0`、`float.max` は `0.0` となる。これは IEEE 754-2019 の `minimum`/`maximum` のゼロ順序で、`totalOrder`（ALS-C9）と ALS-T15 の NaN 無視規則（min/max の片方の引数が NaN → もう片方、両方 NaN → NaN）と整合する。
  5. ⚖ **Float → Int 変換は丸めと範囲規則を明示する。** 各変換関数は、切り捨て・丸め、および範囲外または NaN 入力を飽和・エラー・abort のどれにするかを直説的に記述し、すべての境界（`±inf`、NaN、`±2^63`、`-0.0`）に fixture を置く。
  6. **すべての観測境界で canonical NaN** — C-210 を記載どおりとし、ファミリー先頭から再参照することで、境界一覧（`to_bits`、`to_string`、JSON/Value エンコード、Float をキーとする場合の hashing）を 1 か所に列挙し、各境界に fixture を置く。
  ファミリー先頭節はドクトリンを「*Float 計算の観測可能な結果は、プログラムだけの関数である*」という 1 文で示し、全構成節を列挙する。
- **理由**: (1) 規則は実装には動作として、分散した節には文章として存在する。航空分野のレビュアーが求めるのは構成要素ではなくファミリーである。(2) ここへ先に書くことだけが、来歴台帳にある程度の規模の `requirements-first` バッチを載せる方法である。現時点では C-300/C-301 が全件である。(3) 各 ⚖ 規則は、wasm エンジンと native backend の間で気付かず分岐し得る種類のもの。特に融合と FTZ は言語意味論ではなくコンパイラ・プロセスのフラグであり、禁止しない仕様には不一致をバグと呼ぶ根拠がない。(4) 「超越関数を正しく丸める」は裏付けられない主張になってしまうが、「単一 libm、明記した精度」は正直である。CR-libm 級の実装は存在するものの、この実装が出荷するのは移植した同梱 libm であり、fixture ファミリーは実際にあるものを固定する。
- **代案**: (a) 数値規則を関数別の節のままにし、一致によって判断する — 却下。一致では両ターゲットが共有する偏差を見抜けず（QUALIFICATION.md の限界 2）、書かれていない規則も見抜けない。(b) 超越関数の正しい丸めを要求する — 現時点では裏付けがなく却下。下記の反証条件で再検討する。(c) cert profile を固定小数点専用にし、Float は固定しない — 却下。Float は bounded profile だけでなく全員の言語にある。ADR-0017 は同 profile における Float の許容性を、このファミリーの存在に依存する別問題として扱う。
- **帰結**: `text-and-numbers.md` に新しい `## ALS-T<n>` ファミリー先頭と約 5 つの構成節、約 6 契約、上記全境界に対応する `spec/wasm_cross` の fixture を置く。すべて実装がコミットを pin する前に着地させる。実装は既に適合している（大半の規則）か、gate を追加する（融合なし・FTZ なしはビルドフラグ監査、libm 精度上限は実測表）。費用は fixture 作業と超越関数ごとの正直な測定 1 回である。
- **反証条件**: いずれかのターゲットで、ある超越関数の測定誤差が固定上限を超えたら規則 3 を再検討する（上限または libm を引き締める）。第 2 の丸めモードまたは `fma` 意味論への必要性が文書化されたら規則 1 を再検討する（名前付き関数とし、周囲の暗黙モードには決してしない）。ファミリー着地後も来歴台帳の `requirements-first` 件数が動かないなら、2 リポジトリの順序が守られていないことになり、数値ではなくプロセスの所見である。
