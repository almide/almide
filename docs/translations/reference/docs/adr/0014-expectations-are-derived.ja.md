# ADR-0014: 固定する期待値は機械から導出するか、持たない。手作業では維持しない

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](0014-expectations-are-derived.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](0014-expectations-are-derived.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](0014-expectations-are-derived.zh-CN.md)

> [固定原文](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/adr/0014-expectations-are-derived.md)の非規範的な読者用翻訳です。原文を正本とし、自動同期は行いません。



- **状態**: Accepted（採択済み）
- **日付**: 2026-08-20
- **背景**: `spec/wasm_cross` はターゲット間の一致を検査し、期待出力はコミットしない。一方、診断コーパスは `meta.toml` に期待値を固定する。参照調査は、Roc の二部構成のフィクスチャ（人間が書く前半、機械から導出する期待値の後半、相互排他的な check/bless）を特に優れたコーパス設計の一つと評価している。QUALIFICATION.md にはこのリポジトリの同時ドリフトという盲点が明記されている。一致の検査では、両ターゲットが同じように誤っている場合を検出できない。2026-08-20 のグリーンフィールドへの切り替え時にも、隣のセッションがプレースホルダーのハッシュを使ってゴールデン行を手書きしているのが見つかった。これは、この決定がまさに禁止する失敗である。
- **決定**: このリポジトリで期待値を固定するときは、計測手段によって構造化データから導出する（当時は、ランナーが検査する診断の `meta.toml` フィールド、および検査済み評価器が出力する λ_almd のカーネル適合性トレース）。期待出力ファイルの手書きは禁止する。`spec/wasm_cross` の Roc 形式への移行（フィクスチャごとに期待トレースをコミットする）は、参照評価器が導入されたときに、その出力形式としてのみ実施する。それは λ_almd belt を基礎に育て、制限 #2 を解消するために指定された手段であり、導入前には移行しない。
- **理由**: 期待値ファイルの価値は、その由来そのものである。Roc の仕組みを支える重要な点は、EXPECTED をレポートデータから生成し、再解析や手編集をしないことだ。導出する手段なしにファイル形式だけを取り入れると、591 個の手作業で維持するファイルが増える。これは調査の否定的対照例（Koka、MoonBit）が記録している、ドリフトが生じる範囲そのものである。
- **代替案**: (a) 手作業で初期期待値を入れて今すぐ移行する — 上述の理由で不採用。(b) トレースを固定せず、永続的に一致の検査だけを続ける — 同時ドリフトの盲点が永久に残るため不採用。
- **帰結**: 「二部構成のフィクスチャ」という項目は参照評価器の作業に組み込み、別には追跡しない。それまでは、一致の検査と各実装に対する第三の検証系でターゲット間の正しさを支える。その制限は QUALIFICATION.md に明示したままにする。
- **反証条件**: 同時ドリフトのバグがリリースに到達すれば、一致の検査と制限の明示だけでは不十分であることを示し、評価器の導入を前倒しする。
- **参照**: ../almide-references 調査（B2、項目 2）、QUALIFICATION.md の制限 2、C-280（λ_almd カーネル適合性）。
