# E026 — 无法用 `[]` 索引 String

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E026.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E026.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E026.zh-CN.md)



> 原文：[E026.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E026.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

`String` 是 UTF-8 码点序列，不是字节或字符数组，因此没有 `[]` 元素索引。过去 `s[i]` 会以 `Unknown` 通过类型检查（检查器的索引访问没有 `String` 分支），所以 `check` 通过，随后两个后端都会输出归责于用户的 `[COMPILER BUG] unresolved IndexAccess`。现在会在检查阶段拒绝。

```almide
fn main() -> Unit = {
  let s = "hello"
  println(s[1])            // ← E026
}
```

<a id="fix"></a>

## 修复

使用按码点索引的标准库访问函数：

```almide
let c = string.get(s, 1) ?? ""   // Option[String] — empty if out of range
```

范围切片已受支持，不受影响：`s[0..<3]` 返回子字符串。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**conditional** — 使用 string.get 进行码点访问还是按字节访问，取决于索引的含义。（`mechanical` = 无人值守的修复器可以应用重写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）
