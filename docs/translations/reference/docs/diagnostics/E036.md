# E036 — map_err lambda never uses the error value (warning)

A lambda passed to `map_err` declares a named error parameter but
never reads it. The replacement message type-checks (String → String),
so the original error is silently destroyed — the most common slip in
the context idiom.

## Common cases

```almide
fs.read_text(p) |> result.map_err((e) => "loading config")     // E036
// Error: loading config          ← "No such file…" is gone
```

## Diagnostic

```
warning[E036]: map_err's lambda never uses the error value 'e' — the
               original error is silently discarded
  hint: interpolate it ((e) => "context: ${e}") or discard deliberately ((_) => …)
```

## Fix

- The canonical context idiom keeps the original at the end:
  ```almide
  fs.read_text(p) |> result.map_err((e) => "loading config: ${e}")
  ```
- Deliberate replacement is spelled with the discard parameter:
  ```almide
  fs.read_text(p) |> result.map_err((_) => "friendly message")
  ```

## Why

Error context should be a *chain*, not a replacement: nested calls
produce `starting server: loading config: No such file…`, which reads
as the failure's story. Silent replacement amputates the chain at an
arbitrary depth.
