# E014 — 到達不能な match arm

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E014.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E014.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E014.zh-CN.md)



> 原文：[`docs/diagnostics/E014.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E014.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

`match` の arm が先行する arm に静的に包含され、実行時に選ばれることがない。Almide は警告ではなくエラーとして扱う。到達不能な arm はほぼ常に生成時の誤りであり、作者が先行パターンの範囲を誤って記述し、後続の arm が実際には届かないケースを受け止めると考えたことを示すためである。

<a id="common-cases"></a>

## よくある例

```almide
type Shape = | Circle | Square | Triangle

fn area(s: Shape) -> Int =
    match s {
        _ => 0,
        Circle => 1,   // E014: `_` above already matches Circle
    }
```

```almide
match n {
    5 => "five",
    5 => "again",  // E014: the preceding unguarded literal covers 5
    _ => "other",
}
```

```almide
type Tree = | Leaf | Node(Tree, Tree)

fn size(t: Tree) -> Int =
    match t {
        Leaf => 0,
        Node(_, _) => 1,
        Node(Leaf, _) => 2,   // E014: earlier `Node(_, _)` catches this
    }
```

<a id="fix"></a>

## 修正

到達不能な arm を削除するか、先行 arm の条件を狭めて後続 arm に到達できるようにする。

```almide
// Option A — drop the dead arm
match s {
    _ => 0,
}

// Option B — make the earlier arm more specific
match s {
    Circle => 1,
    _ => 0,
}
```

<a id="guarded-arms"></a>

## ガード付き arm

ガード付き arm（`pat if cond => ...`）は後続 arm を覆い隠さず、他からも覆い隠されない。ガードは実行時に失敗し得るため、到達可能性解析では両方向とも「常に到達する可能性がある」と扱う。

```almide
match n {
    x if x > 0 => "positive",
    x if x < 0 => "negative",
    _ => "zero",     // OK: guarded arms above don't cover 0
}
```

<a id="why-not-a-warning"></a>

## 警告にしない理由

LLM は警告をノイズとして扱う。また dojo MSR では、到達不能な arm はほぼ例外なくパターン記述の誤りの兆候である（作者が `Leaf` の意味を、実際に一致するものと違う意味に考えていた）。エラーレベルで示すことで、最初のフィードバックループ内に修正を留める。
