# E102 — `regex.new` の無効なパターン

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E102.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E102.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E102.zh-CN.md)



> 原文: [E102.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E102.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

`regex.new("…")` は、プログラムが有効だと把握しているパターンから `Regex` を作ります。パターンが文字列リテラルの場合、`almide check` は正規表現エンジン自身の検査器で調べ、エンジンが拒否するものを拒否します。同じパターンを実行時に構築すると `Error: invalid regex: <reason>` で中止します（C-395）。理由は `regex.compile` が err に返すものと同じです。`unclosed group`、`unmatched )`、`unclosed character class`、`nothing to repeat`、`malformed repetition`、`repetition minimum exceeds maximum`、`invalid class range`、`trailing backslash`、`unsupported escape \X`（および `… in a class`）、`named groups are not supported`、`lookaround is not supported`、`flags are only supported at the start of the pattern`、`unsupported group syntax`、`groups nested deeper than 250`、`pattern too large: more than 20000 states` です。

```almide
import regex

fn main() -> Unit = println("${regex.is_match(regex.new("(a|b"), "abc")}")   // ← E102
```

```
error[E102]: invalid regex: unclosed group
  hint: write the pattern in the syntax docs/stdlib/regex.md lists; a pattern built at run time goes through regex.compile, which answers err(reason) instead of aborting
```

<a id="fix"></a>

## 修正

1. [docs/stdlib/regex.md](../../../../stdlib/regex.md) に示された構文でパターンを書きます。グループや文字クラスを閉じ、文字そのものとして使いたいメタ文字をエスケープし（文字列には `regex.escape` が行います）、グループは名前でなく番号を使います。
2. 大きすぎるパターンは Pike VM 状態が20,000を超えています。入れ子の反復回数は掛け算されます（`((a){200}){200}` は `a` の40,000コピー）。回数を展開するのではなく形を照合するか、コードで回数を検査してください。
3. 入力由来のパターンには `regex.compile(p)` を使います。`err(reason)` を返し、プログラムが判断できます。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**not-fixable**：拒否された文字が文字そのものの意図（エスケープする）なのか、エンジンにない構文の意図（パターンを書き換える）なのかは作者の選択です。状態数制限を超えたパターンには別のパターンが必要です。診断は理由を示し、コードを書き換えません。（`mechanical` = 無人の書き換え、`conditional` = 修正案にレビューが必要、`not-fixable` = 自動書き換えは存在しません。#1486 の適用可能性の原則。）

<a id="why"></a>

## 理由

以前のエンジンは文法外のパターンを寛容に読んでいました。`(` はどこにでも一致する空グループ、`a{` はリテラルの波括弧、`(?P<n>a)` は `P<n>a` の通常グループでした。それぞれ、誰も書いていない意味をエラーなしに返していました（#3942）。プログラムに書かれたパターンは実行前に拒否します。
