# E071 — no allocation inside a counted loop

The `@bounded` attribute (ALS §B, the bounded profile) narrows what the
checker admits inside the attributed function: statically bounded time and
storage, a closed acyclic call graph, capability-bounded effects. E071
rejects constructing a list/map/string, concatenating, pushing, or creating a closure inside a `@bounded` function's counted loop.

```
error[E071]: ... is not admissible in a @bounded function
```

```almide check-fail=E071
@bounded
fn squares() -> List[Int] = {
  var xs: List[Int] = []
  for i in 0..<8 { xs = xs + [i * i] }
  xs
}

fn main() -> Unit = println("bounded")
```

## The fix

Allocate before the loop and keep each iteration allocation-free: accumulate scalars, write into pre-sized storage, or hoist the construction out of the loop.

```almide
@bounded
fn sum_of_squares() -> Int = {
  var acc = 0
  for i in 0..<8 { acc = acc + i * i }
  acc
}

fn main() -> Unit = println("bounded")
```

The rule binds only inside `@bounded` functions — removing the attribute
removes the rejection (the profile is a subset, not a dialect: ALS-B2).

## Fix-it verdict

**conditional** — the diagnostic's hint names the admissible form; which
spelling replaces the rejected one depends on what the code was doing.
