# E008 — 並行実行される本体から `var` に到達する

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E008.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E008.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E008.zh-CN.md)



> 原文: [E008.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E008.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

同じ本体の別の呼び出しと同時に実行され得る本体が、外側で宣言された `var` を読み書きしています。並行実行される本体とは次のものです。

- `fan { … }` ブロックと、`fan.settle`、`fan.min`、`fan.bounded`、`fan.timeout` のブロック形式の各 arm。
- `fan.map`、`fan.settle`、`fan.min` の関数値を取る各引数。
- `http.serve`、`http.route`、`http.mount`、`http.wrap` に渡すハンドラー（ハンドラーとミドルウェア）。
- 自作関数の引数のうち、上記のいずれかへ渡されるもの（`fn serve_on(port: Int, h: HttpHandler) = http.serve(port, h)` では `h` が `serve_on` のハンドラー引数となり、検査はその呼び出し元に及びます）。

「到達する」は本体が実行できるものを追跡します。呼び出す関数、`let` から読み取るクロージャ（ローカルとトップレベルの両方。レコードやリストに格納したクロージャも含む）、ファクトリーが返すクロージャが対象です。本体内または本体が呼び出す関数内で宣言した `var` は呼び出しごとに独立しているため問題ありません。`list.map` のような標準ライブラリのコールバックに直接渡した lambda は、それを含む本体の中で実行されるため、その本体の `var` を使えます。

<a id="common-cases"></a>

## よくある例

```almide
effect fn broken() -> Int = {
  var count = 0
  fan {
    count = count + 1         // E008: the arm reaches `count`
    count = count + 2
  }
  count
}
```

```almide
import http

var hits = 0

effect fn bump() -> Int = {
  hits = hits + 1
  hits
}

// E008: the handler reaches `hits` through `bump`
let app = http.router([http.route("GET /", (req) => http.response(200, "n=${bump()!}"))])

effect fn main() -> Unit = http.serve(8080, app!)!
```

<a id="diagnostic"></a>

## 診断

```
error[E008]: cannot capture mutable variable 'count' inside fan block
  hint: Use a `let` binding instead of `var` for values shared across fan expressions
```

```
error[E008]: this fan.map callback can reach `total`, a `var` — fan bodies run concurrently
  in the callback passed to fan.map
  hint: return each element's contribution and combine the results after the fan, e.g. `fan.map(xs, f)! |> list.sum`, or bind a `let` copy of the value before the fan
```

```
error[E008]: this handler can reach `hits`, a `var` — handlers run concurrently
  in the handler passed to http.route (reached through fn `bump` at line 5)
  hint: a handler cannot share mutable state between requests. For a value fixed before serving, use a top-level `let` instead of `var`, or bind a `let` copy before the handler
```

文脈表示は該当箇所を示し、別の関数を介して `var` に到達する場合は、その経路も示します。`var` がどこでも代入されない場合、ヒントはまずその点を伝えます。`let` として宣言するだけで修正は完了です。

<a id="fix"></a>

## 修正

- 各分岐や要素を独立して計算し、fan の後で結果を集約します。
  ```almide
  effect fn fixed() -> Int = {
    let (a, b) = fan {
      compute_a()
      compute_b()
    }
    a + b
  }
  ```
- 本体が読み取りのみ行う値は、その箇所の前で `let` のコピーを束縛します（`let scale = scale0`）。本体の外で得た `let` はスナップショットです。
- サービス開始前に固定する値は、トップレベルの `let` とし、`var` にはしません。main 内の `let` コピーでは、サービスするハンドラーの解決にはなりません。`http.serve` に渡すアプリは main のローカル変数を読み取れないためです（E095）。

<a id="why"></a>

## 理由

同じ `var` への並行書き込みは順序が定まらない更新を生み、読み取りもその書き込みと競合します。Almide は競合するコードを出力するのではなく、検査器でこのパターンを拒否します。そのため、fan やサーバーの実行基盤を変更してもプログラムの意味は変わりません。`let` 束縛は並行実行される本体から常に安全に読み取れます。制限されるのは `var` のみです。この規則は dialect epoch 6（`proofs/dialect-epochs.toml`）のものです。それ以前の E008 は、`fan { … }` の arm が `var` を直接キャプチャする場合だけでした。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**conditional** — 到達する `var` に一度も代入されない場合、`let` として宣言することが修正になります。それ以外の場合は、状態を並行実行される本体の外へ移す必要があり、レビューが必要です。（`mechanical` = 無人の修正ツールが書き換えを適用可能、`conditional` = 提案された修正にレビューが必要、`not-fixable` = 自動書き換えは存在しません。#1486 の適用可能性の原則。）
