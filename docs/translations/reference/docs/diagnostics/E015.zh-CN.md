# E015 — 可能重新实现了标准库

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E015.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E015.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E015.zh-CN.md)



> 原文：[`docs/diagnostics/E015.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E015.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

顶层 `fn` 与某个计算型标准库模块中的纯函数具有相同名称和兼容签名。这是提示性警告：仅比较名称与类型，函数体可能实现不同操作。E015 不提供替换编辑或委托 shim。

包括 `args` 在内的宿主／环境模块即使函数签名看似纯函数，也被排除。不能把将空字符串变成 `none` 的辅助函数替换为命令行选项查找。

## 常见情况

```almide
// ~30 lines of algorithm:
fn binary_search(xs: List[Int], target: Int) -> Option[Int] = {
    let lo = 0
    let hi = list.len(xs) - 1
    // ... loop implementation ...
}
// warning[E015]: has the same signature as stdlib `list.binary_search`
```

## 修复

确认标准库函数具有预期语义后，可以委托给它：

```almide
fn binary_search(xs: List[Int], target: Int) -> Option[Int] =
    list.binary_search(xs, target)
```

如果算法有意不同，也可以重命名自己的 fn：

```almide
fn my_search_descending(xs: List[Int], target: Int) -> Option[Int] = ...
```

## 哪些情况不会触发 E015

- **名称不同** — `optional` 和 `option` 等相近名称不匹配。
- **宿主／环境模块或 effect 函数** — 排除在候选之外。
- **参数类型、返回形状或参数数量不同** — 排除在候选之外。

标准库一侧可以是泛型（`binary_search[T: Ord]`），用户一侧是单态（`List[Int]`），仍算匹配；非对称的 `TypeVar` 通配是有意设计。

## 为什么是警告，而非错误？

没有正确性问题：你的 fn 能工作。测量假设（`docs/roadmap/done/reimpl-lint.md`）是，知道存在同名标准库函数有助于 LLM 重试循环。改成错误会破坏合理的特殊化实现。
