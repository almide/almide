# E098 — the closure passed to `testing.assert_aborts` captures a local

`testing.assert_aborts(expected, f)` runs only `f`, and runs it in a child: the
native test binary re-executes itself for that one closure, and the wasm lane
starts a fresh instance of the same module (ADR-0029). The child starts the
program afresh, so the test's locals — its `let`s and `var`s, its `where`
bindings, an outer lambda's parameters — do not exist there.

The closure must therefore be a lambda written in the call, and every name it
reads that it does not bind itself must be a top-level item: a fn, a top-level
`let` or `var` (seen at its initial value), an imported module, the stdlib.

```almide
import testing

test "reading past the end aborts" {
  let xs = [1, 2, 3]
  testing.assert_aborts("index out of bounds", () => xs[5])   // ← E098: captures `xs`
}
```

A fn value held by a local is refused too: what it captures cannot be seen
where it is passed.

```almide
import testing

test "a panic aborts" {
  let boom = () => panic("boom")
  testing.assert_aborts("boom", boom)                          // ← E098: `boom` is a fn value
}
```

## Diagnostic

```
error[E098]: the closure passed to testing.assert_aborts captures `xs`, a local of the test
  in a call of testing.assert_aborts
  hint: the closure runs in a separate process (native) or instance (wasm), where the test's locals do not exist. Inline the value into the closure, or make it a top-level `let`.
```

The error points at the first read of each captured local.

## Fix

Compute the value inside the closure:

```almide check
import testing

test "reading past the end aborts" {
  testing.assert_aborts("index out of bounds", () => {
    let xs = [1, 2, 3]
    xs[5]
  })
}
```

or make it a top-level `let`, which the child computes itself.

## Fix-it verdict

**conditional** — moving the binding into the closure is the fix when the
value is the program's own, but a value the test computed from its run has to
be recomputed inside the closure or made a top-level `let`, which is the
writer's choice. (`mechanical` = an unattended rewrite; `conditional` = a
suggested fix needs review; `not-fixable` = no automatic rewrite exists.
#1486's applicability doctrine.)
