# E092 — `@pure` fn が純粋ではない

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E092.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E092.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E092.zh-CN.md)



> 原文：[`docs/diagnostics/E092.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E092.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

`@pure` は空の effect 集合を約束する。fn とそこから呼ぶすべてが effect category を持たず、出力を書かず、abort を宣言しない。以前この属性は受理されて無視されたため、作者の認識に反して `@pure` 関数が表示・abort・ホスト呼び出しを行えた（#3250）。現在は検査する。

`@pure` fn は次の場合に E092 となる。

- `effect fn` である。
- `@extern` fn である — 外部本体は検査できない。
- 到達する呼び出しに `println`、`eprintln`、`panic`、`assert`、`assert_eq`、`assert_ne` がある（ADR-0022 が通常の `fn` では認める出力・abort。そちらでは認めるが、ここでは認めない）。
- 到達する呼び出しに effect category を持つ標準ライブラリ関数がある（`io.write`、`process.pid`、`args.has_flag`、…）。表は `crates/almide-ir/src/effect.rs` の `STDLIB_MODULE_EFFECTS`。
- 到達する呼び出しに `@extern` fn がある。

```almide
fn checked(n: Int) -> Int = {
  assert(n >= 0)
  n
}

@pure
fn double(n: Int) -> Int = checked(n) * 2   // ← E092
```

```
error[E092]: `@pure` fn `double` reaches `assert` via `checked`, and `assert` aborts the program when it fails
  --> main.almd:7:28
```

エラー位置は、不純な呼び出しへつながる `@pure` fn 内の呼び出しであり、経路を示す。不純な呼び出しが `@pure` fn のファイルより後に推論されるモジュールにある場合、そのモジュール内の経路の最初の呼び出しで報告し、`@pure` fn とそのファイル・行を示す。

<a id="what-does-not-count"></a>

## 対象に数えないもの

- 関数型のパラメーターやローカル値を通じた呼び出し。`@pure fn apply(f: (Int) -> Int,
  x: Int) -> Int = f(x)` は純粋であり、渡された関数は記述箇所で判定される（ADR-0026 D1）。
- 言語定義の trap：ゼロ除算、範囲外添字。これらでも実行は終了し得るが、宣言された abort ではない。

<a id="fix"></a>

## 修正

不純な呼び出しを `@pure` でない呼び出し元に移すか、`@pure` を取り除く。入力を守る assertion は通常、全域的な式（`if n >= 0 then n else 0`）または呼び出し元が処理する `Result` にできる。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**not-fixable**：不純な呼び出しを呼び出し元へ移すか、全域的な式にするか、属性を削除するかは設計上の選択であり、コンパイラには決められない。エラーは呼び出しと経路を示し、fn を書き換えない。
