# E050 — local `fn` or `let` collides with a selectively-imported name

[![English](https://img.shields.io/badge/English-24292f?style=flat-square)](E050.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E050.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E050.zh-CN.md)

A file declares a top-level `fn` whose name is also brought in by a selective
import (`import module.{name}`). The two are different functions, and a bare
call `name(x)` cannot mean both — so the collision is a hard error. A
top-level `let` collides the same way: a selective import binds a module's
top-level `let` too (`import self.k.{LIMIT}`), and a bare `LIMIT` cannot name
both lets (`error[E050]: local let 'LIMIT' collides with selective import
'k.{LIMIT}'`).

```almide
import json.{parse, stringify}

fn parse(s: String) -> Int = string.len(s)   // ← E050: collides with `json.{parse}`

effect fn main() -> Unit = {
  let n = parse("hi")
  println("${n}")
}
```

Before this diagnostic existed, the compiler silently split: the type checker
resolved `parse("hi")` against the local `fn parse`, while code generation
resolved it to `json.parse` — a call that type-checks against one function and
executes another (edit-locality hunt V2, almide#1425). Adding a local `fn`
must never silently change what an existing call executes.

## Fix

Either rename the local function:

```almide
import json.{parse, stringify}

fn parse_len(s: String) -> Int = string.len(s)
```

or drop the name from the selective import list and call the module function
qualified:

```almide
import json

fn parse(s: String) -> Int = string.len(s)

effect fn main() -> Unit = {
  let v = json.parse("[1]") ?? value.null()
  println("${parse(json.stringify(v))}")
}
```

## Diagnostic shape

```
error[E050]: local fn 'parse' collides with selective import 'json.{parse}'
  fn parse
  hint: Rename the local fn, or drop 'parse' from the import list and call
        'json.parse' qualified. A bare call must have exactly one meaning.
```

## Fix-it verdict

**conditional** — renaming the local vs unimporting is a choice. (`mechanical` = an unattended fixer may apply the
rewrite; `conditional` = a suggested fix needs review; `not-fixable` = no
automatic rewrite exists. #1486's applicability doctrine.)
