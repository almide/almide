# E035 — branching on the text of an error message (warning)

A branch condition compares an err-pattern binding against string
content (`string.contains(e, …)`, `e.contains(…)`, `e == "…"`).
Error message text is a report for humans, not an API for programs —
it may be reworded, and the branch silently stops matching.

This is the pattern that forced Go to retrofit `errors.Is`/`errors.As`
after a decade of `strings.Contains(err.Error(), …)` in production
(ADR-0004 doctrine).

## Common cases

```almide
match fs.read_text(p) {
  ok(t)  => ok(t),
  err(e) =>
    if string.contains(e, "No such file")   // E035
    then ok(default) else err(e),
}
```

## Diagnostic

```
warning[E035]: branching on the text of an error message
  hint: define a variant error type and match on it (ADR-0004);
        for a kind-independent fallback use ??
```

## Fix

- **Kind-independent fallback** — don't read the error at all:
  ```almide
  fs.read_text(p) ?? default
  ```
- **Your own domain** — define a variant error type and branch on
  structure (ADR-0003 D1):
  ```almide
  type LoadError = | NotFound(String) | Other(String)
  match load(p) { err(NotFound(_)) => …, err(Other(m)) => …, ok(v) => … }
  ```
- **stdlib absence checks** — use the `*_if_exists` readers
  (`fs.read_text_if_exists`, #1106) that return `none` for absence.

## Why

Contract-pinned messages make string-matching *appear* safe in almide —
until user code depends on the text, at which point every diagnostic
improvement becomes a breaking change (Hyrum freeze). The lint keeps
the escape hatches (`??`, variant E, Option-returning APIs) the only
spellings.
