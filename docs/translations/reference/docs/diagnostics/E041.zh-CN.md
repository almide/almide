# E041 — 隐式传播已移除

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E041.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E041.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E041.zh-CN.md)



> 原文：[`docs/diagnostics/E041.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E041.md)，固定提交 `9a95b285`。这是供读者参考的非规范性译文，CLI 诊断输出仍为英文。

在 effect fn 内，可能失败的调用所产生的 err，过去会在九种位置无标记地经外围失败通道返回：语句、无注解绑定、条件、值模式 match 的对象、插值中的调用，以及四种尾部位置（effect fn 的尾值、`match` 分支值、`if` 分支值、`guard` 的 else）。ADR-0008 停用了这一机制：所有位置统一用 `!` 表示传播。经过 0.54 弃用窗口（此代码当时是警告）后，隐式形式已不复存在；值保持为 `Result`，原本会自动解包的位置产生此错误。

<a id="common-cases"></a>

## 常见情况

```almide
effect fn main() -> Unit = {
  let r = int.parse(s)        // E041 — write: int.parse(s)!
  if flag() then ...          // E041 — write: flag()!
  println("${get()}")         // E041 — write: "${get()!}"
}
```

在语句位置被丢弃的 Result 属于对应的 [E042](E042.zh-CN.md) 错误（must-use）。

effect fn 内的 lambda 函数体属于同一上下文（#2254）：lambda 原本也不会自行传播，但其中无注解的 `let t = fs.read_text(p)` 面临相同选择。`fs.read_text(p)!` 会使 lambda 可失败（ADR-0006，此时外围 `list.map(...)` 调用也需要自己的 `!`），或者将 Result 作为值消费。在 lambda 内，`!` 会显示在 `try` 中，但不附带位置；这不是单点编辑，因为接收 lambda 的调用还需要自己的 `!`。纯 fn 或其中的 lambda 合法持有 `Result` 值，不会被报告。

<a id="diagnostic"></a>

## 诊断

```
error[E041]: implicit propagation of this binding's value was removed — this value is a Result (ADR-0008)
  try: !          ← a suggestion; choose whether propagation is intended
```

<a id="fix"></a>

## 修复

追加 `!` 进行传播，或将 Result 作为值消费：`?? fallback`、`?`（转为 Option）、`match r { ok(v) => …, err(e) => … }`。此错误提供的是建议，不是可无人值守应用的 machine-applicable 编辑；插值中的调用也必须显式书写（`"${get()!}"`）。

<a id="why"></a>

## 原因

隐式形式依赖位置（某些位置适用，其他位置不适用），也对注解敏感；同一表达式会因类型注解或模式形状而改变运行时行为。在每个位置使用同一显式标记，是 Rust/Swift/Zig 的模型（ADR-0008 的调查：没有语言采用依赖位置的隐式传播）。
