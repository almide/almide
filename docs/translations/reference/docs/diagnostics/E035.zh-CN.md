# E035 — 根据错误消息文本分支（警告）

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E035.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E035.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E035.zh-CN.md)



> 原文：[`docs/diagnostics/E035.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E035.md)，固定提交 `9a95b285`。这是供读者参考的非规范性译文，CLI 诊断输出仍为英文。

分支条件将 err 模式绑定与字符串内容比较（`string.contains(e, …)`、`e.contains(…)`、`e == "…"`）。错误消息文本是面向人的报告，不是程序的 API；措辞可能改变，分支随后就会静默地不再匹配。

这正是 Go 在生产环境使用了十年的 `strings.Contains(err.Error(), …)` 后，不得不补上 `errors.Is`/`errors.As` 的模式（ADR-0004 原则）。

<a id="common-cases"></a>

## 常见情况

```almide
match fs.read_text(p) {
  ok(t)  => ok(t),
  err(e) =>
    if string.contains(e, "No such file")   // E035
    then ok(default) else err(e),
}
```

<a id="diagnostic"></a>

## 诊断

```
warning[E035]: branching on the text of an error message
  hint: define a variant error type and match on it (ADR-0004);
        for a kind-independent fallback use ??
```

<a id="fix"></a>

## 修复

- **与错误种类无关的回退**：完全不读取错误。
  ```almide
  fs.read_text(p) ?? default
  ```
- **自己的业务领域**：定义变体错误类型，并按结构分支（ADR-0003 D1）。
  ```almide
  type LoadError = | NotFound(String) | Other(String)
  match load(p) { err(NotFound(_)) => …, err(Other(m)) => …, ok(v) => … }
  ```
- **标准库中的不存在检查**：使用 `*_if_exists` 读取函数（`fs.read_text_if_exists`，#1106），不存在时返回 `none`。

<a id="why"></a>

## 原因

由契约固定的消息，会让字符串匹配在 almide 中*看起来*安全；但用户代码一旦依赖文本，每次诊断改进都会成为破坏性变更（Hyrum freeze）。此 lint 将替代途径（`??`、变体 E、返回 Option 的 API）保留为唯一写法。
