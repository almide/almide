# E052 — 非推奨関数の呼び出し

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E052.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E052.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E052.zh-CN.md)



> 原文：[`docs/diagnostics/E052.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E052.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

呼び出しが `@deprecated` の付いた関数を指定している。警告は代替を示し、編集にどの程度の作業が必要か伝える。純粋な改名なら `almide fix` が実行する。

```almide
@deprecated(since = 3, use = "shout")
fn yell(s: String) -> String = shout(s)

fn shout(s: String) -> String = s + "!"

effect fn main() -> Unit = println(yell("hi"))
//                                 ^^^^ E052: `yell` is deprecated since dialect 3
//                                 hint: Use `shout` — same signature — the name is the whole edit.
```

<a id="the-attribute"></a>

## 属性

```almide
@deprecated(since = N, use = "replacement")   // renamed or superseded
@deprecated(since = N, note = "why")          // removed with no successor
@deprecated(since = N, use = "...", note = "...")
```

- **`since`** はリリースではなく DIALECT EPOCH（`proofs/dialect-epochs.toml`）である。ファイルの `@dialect(N)` が記録するものと同じ単位で、古いファイルと古くなった理由を同じ尺度で示す。
- **`use`** は代替名を示す。他モジュールなら完全修飾する（`string.trim_start`）。
- **`use`** は演算子も指定できる（`use = "??"`）。代替は呼び出し形式の書き換えとなる（`option.unwrap_or(o, d)` → `o ?? d`、パイプ段 `o |> option.unwrap_or(d)` も同様）。`almide fix` の AST ファミリーがこれを行う — ADR-0005 D4。
- **`note`** は自由記述。`use` がない場合は必須である。どちらもなければ呼び出し側が対処できる情報がないため、コンパイラは宣言箇所で拒否する。

不正な `@deprecated` は宣言箇所のエラーであり、黙って何もしないのではない。防ぐべき失敗は、作者が呼び出し側に警告が出ていると信じているのに実際は出ていないことである。

<a id="how-the-edit-is-classified"></a>

## 編集の分類

コンパイラは手書きのマーカーを信頼せず、両シグネチャを比較して分類を**導出**する。後から代替の型が変われば、次のコンパイルで自動的に再分類される。

| 両シグネチャ | ヒント | `almide fix` |
|---|---|---|
| 同一（パラメーター名は異なってよい） | 「同じシグネチャ — 編集は名前だけ」 | **適用する** |
| パラメーター型、戻り型、effect 性のいずれかが異なる | 「シグネチャが異なる — 引数を確認」 | `try:` を示し、適用しない |
| ここから代替が見えない | 「ここから代替が見えない」 | `try:` を示し、適用しない |
| 代替が演算子（`use = "??"`） | 「`??` 演算子 — `value ?? default` を使う」 | **適用する**（両呼び出し形式の AST 書き換え） |

machine-applicable なのは最初の行だけ。シグネチャ変更をまたいで自動書き換えすると `almide fix` が誤コンパイルを引き起こすため、意図的に自動適用せず、読者が編集する。

<a id="every-call-spelling-warns"></a>

## すべての呼び出し記法で警告する

非推奨 fn を呼ぶどの場所でも警告する。直接呼び出し（`list.length(xs)`）、パイプ段（`xs |> list.length`）、メソッド形式（`xs.length()`。修正はメソッド名だけを `xs.len()` に変える）すべてが対象となる。`import` なしで到達する標準ライブラリモジュール（`matrix`、`bytes`）も import されたものと同じく警告する（#3085）。

標準ライブラリ自身の同義名もこの方式で非推奨になる。`string.length`、`list.length`、`matrix.row_dot`、`matrix.concat_cols_many` が該当し、一つの標準ライブラリモジュールの二つの公開 fn が別名同士なのに複数が有効なら `tests/stdlib_synonym_gate_test.rs` が失敗する。

<a id="why-this-exists"></a>

## 存在理由

Almide の利用者の多くはコード生成器であり、モデルは学習した dialect で書く。「そのような関数はない」としか言わない診断では、修正を推測するために再試行を一回消費する。代替を示す診断なら一度の編集で適用できる修復指示となり、編集が機械的なら手で編集せずに済む。この違いが言語の最適化対象となる指標である。

## Fix-it 判定

**mechanical** — シグネチャが一致すれば、編集は名前の置換だけである。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
