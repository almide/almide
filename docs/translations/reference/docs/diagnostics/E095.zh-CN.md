# E095 — 传给 `http.serve` 的应用读取局部变量

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E095.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E095.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E095.zh-CN.md)



> 原文：[E095.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E095.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

`http.serve`（以及 `http.serve_with_limits`）的参数是**应用**，必须*在实例内闭合*：读取但未自行绑定的每个名称，都必须是顶层项——fn、顶层 `let`、类型或构造器。调用 `serve` 的 fn 中的 `let`、`var` 或参数（通常是 main 的局部变量）会被拒绝。

应用在多个实例中运行：原生中每个工作线程一个，wasi:http 导出宿主中每个请求一个，而后者根本不会运行 `main`。main 的局部变量在这些实例中都不存在，因此请求不可能看到 main 在 `serve` 之前计算的值。

```almide
import http
import random

effect fn main() -> Unit = {
  let boot = random.int(1, 1000000)
  http.serve(8080, (req) => http.response(200, "boot=${boot}"))!   // ← E095: captures `boot`
}
```

在 main 内构造的路由器也是局部变量：

```almide
import http

effect fn main() -> Unit = {
  let app = http.router([http.route("GET /", (req) => http.response(200, "home"))])!
  http.serve(8080, app)!                                           // ← E095: captures `app`
}
```

应用自行绑定的名称没有问题：处理器参数、主体内的 `let`、嵌套 lambda 自己的参数。顶层 fn 和 `let`、导入项及标准库也都允许。将自身参数传给 `http.serve` 的 fn（`effect fn serve_on(port: Int, h: HttpHandler) = http.serve(port, h)!`）会将规则传递给调用方：每个调用方传入的应用，在其书写位置接受检查。

## 诊断

```
error[E095]: the app passed to http.serve captures `boot`, a local of main
  in the app passed to http.serve
  hint: the app runs in several instances — one per worker natively, one per request on a wasi:http host — and main's locals do not exist there. Make `boot` a top-level `let`, or compute it inside the handler.
```

错误指向应用捕获的每个局部变量的第一次读取。

## 修复

- 由程序文本固定的值应为顶层 `let`。顶层初始化器不能调用 effect fn，所以在每个实例中相同：
  ```almide
  import http

  let app = http.router([http.route("GET /", (req) => http.response(200, "home"))])

  effect fn main() -> Unit = http.serve(8080, app!)!
  ```
  `router` 返回 `Result`，而顶层初始化器不允许 `!`，所以 main 在用于服务时写 `app!`。
- 依赖本次运行的值（随机抽样、读取时钟）应在处理器内按请求计算。

## 原因

ADR-0020 §5.2。C-367 曾承诺 main 在 `serve` 前计算的值，在一次运行的所有请求中相同。任何在多个实例中运行应用的宿主都无法兑现此承诺，因此承诺被撤销，依赖它的形状变成了此错误。

## Fix-it 判定

**conditional** — 只有不依赖本次运行的值才能移到顶层 `let`；依赖运行的值必须在处理器内计算，这由作者选择。（`mechanical` = 无人值守重写；`conditional` = 修复建议需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）
