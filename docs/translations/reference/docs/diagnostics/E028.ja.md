# E028 — main() は引数を取らない

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E028.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E028.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E028.zh-CN.md)



> 原文: [E028.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E028.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

`main` はプログラムの入口で、引数を取りません。引数付き形式（`fn main(args: List[String])`）は構造上の型検査には通りますが、どのコード生成経路も引数を結び付けません。ネイティブのドライバーは入口を引数なしで呼び、wasm の `_start` 接続処理も同様です。以前は、言語が一度も対応していないシグネチャなのに、どちらも後段でコンパイラの責任とするエラー（「codegen produced invalid Rust — this is an Almide bug」）になっていました。現在は検査器が早い段階で拒否します。

```almide
effect fn main(args: List[String]) -> Result[Unit, String] = ok(())   // ← E028
```

<a id="fix"></a>

## 修正

本体内で `env.args()` を使ってプログラム引数を読み取ります（`env` は Tier 2 標準ライブラリモジュールなので、import を追加してください）。

```almide
import env

effect fn main() -> Result[Unit, String] = {
  let args = env.args()
  println(int.to_string(list.len(args)))
  ok(())
}
```
