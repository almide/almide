# E050 — 本地 `fn` 或 `let` 与选择性导入名称冲突

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E050.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E050.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E050.zh-CN.md)



> 原文：[`docs/diagnostics/E050.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E050.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

文件声明的顶层 `fn` 名称也由选择性导入（`import module.{name}`）引入。两者是不同函数，直接调用 `name(x)` 不能同时表示两者，因此冲突是硬错误。顶层 `let` 也一样：选择性导入也会绑定模块顶层的 `let`（`import self.k.{LIMIT}`），单独的 `LIMIT` 不能指代两个 let（`error[E050]: local let 'LIMIT' collides with selective import
'k.{LIMIT}'`）。

```almide
import json.{parse, stringify}

fn parse(s: String) -> Int = string.len(s)   // ← E050: collides with `json.{parse}`

effect fn main() -> Unit = {
  let n = parse("hi")
  println("${n}")
}
```

此诊断出现之前，编译器会静默分歧：类型检查器将 `parse("hi")` 解析到本地 `fn parse`，而代码生成解析到 `json.parse`——同一调用依据一个函数检查类型，却执行另一个函数（edit-locality hunt V2，almide#1425）。新增本地 `fn` 绝不能静默改变已有调用执行的内容。

## 修复

可以重命名本地函数：

```almide
import json.{parse, stringify}

fn parse_len(s: String) -> Int = string.len(s)
```

或从选择性导入列表移除该名称，并使用限定名调用模块函数：

```almide
import json

fn parse(s: String) -> Int = string.len(s)

effect fn main() -> Unit = {
  let v = json.parse("[1]") ?? value.null()
  println("${parse(json.stringify(v))}")
}
```

## 诊断形式

```
error[E050]: local fn 'parse' collides with selective import 'json.{parse}'
  fn parse
  hint: Rename the local fn, or drop 'parse' from the import list and call
        'json.parse' qualified. A bare call must have exactly one meaning.
```

## Fix-it 判定

**conditional** — 重命名本地定义还是取消导入，是一个选择。（`mechanical` = 无人值守的修复器可以应用改写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动改写。#1486 的适用性原则。）
