# E034 — 将错误通道运算符用于非 Option/Result 操作数

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E034.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E034.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E034.zh-CN.md)



> 原文：[`docs/diagnostics/E034.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E034.md)，固定提交 `9a95b285`。这是供读者参考的非规范性译文，CLI 诊断输出仍为英文。

`!`、`?` 或 `??` 被应用于既不是 `Option[T]` 也不是 `Result[T, E]` 的值。这些运算符作用于错误通道，而普通值没有错误通道。

<a id="common-cases"></a>

## 常见情况

```almide
let n = 5!                  // E034: Int has no error channel
let o = "hi"?               // E034
let v = 3 ?? 0              // E034
```

<a id="diagnostic"></a>

## 诊断

```
error[E034]: operator '!' requires Option or Result type but got Int
  hint: Use '!' only on Option[T] or Result[T, E] values
```

<a id="fix"></a>

## 修复

- 去掉运算符；普通值已经是解包后的值。
  ```almide
  let n = 5
  ```
- 如果本意是进行可能失败的计算，操作数应来自返回 `Result`/`Option` 的调用（`int.parse(s)!`）。

<a id="why"></a>

## 原因

在普通值上接受该运算符，会让它成为静默的空操作，从而掩盖真实错误（例如重构移除了可能失败的调用，却留下了运算符）。
