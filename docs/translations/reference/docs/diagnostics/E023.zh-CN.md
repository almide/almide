# E023 — 字段类型不满足派生协议

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E023.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E023.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E023.zh-CN.md)



> 原文：[E023.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E023.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

`Codec`、`Ord` 和 `Hash` 是**按字段递归**的协议：在结构体或变体上派生其中一个，会生成逐字段操作，要求*每个字段类型也满足同一协议*。

- `Codec` — 派生的 `encode`/`decode` 调用 `Field.encode` / `Field.decode`。
- `Ord` / `Hash` — 转换为针对各字段的 Rust `#[derive(Ord/Hash)]`，因此每个字段的底层类型都必须实现它。

如果字段类型没有派生该协议，生成代码就会引用不存在的方法（或 trait 实现）。检查器现在从结构上拒绝这种情况，而不是让它稍后以代码生成错误失败。

## 常见情况

```almide
type Raw = { x: Int }                  // NOT : Codec
type Wrap: Codec = { item: Raw }       // E023: Raw does not derive Codec

type Point = { x: Int, y: Int }        // NOT : Ord
type Edge: Ord = { a: Point, b: Point } // E023: Point does not derive Ord
```

容器是透明的：`List[Raw]` / `Option[Raw]` 字段仍要求 `Raw` 派生该协议。

## 诊断

```
error[E023]: type 'Wrap' derives 'Codec' but field 'item' has type 'Raw', which does not derive 'Codec'
  hint: Add `: Codec` to the declaration of type 'Raw' (every field of a `: Codec` type must itself be `Codec`)
```

## 修复

- 也为字段类型派生该协议：
  ```almide
  type Raw: Codec = { x: Int }
  type Wrap: Codec = { item: Raw }
  ```
- 仅有手写的 codec 方法不能保证字段通过此派生检查。请在字段类型上声明支持的协议，或者显式编写外层编码／解码，而不是派生它。检查完整的类型声明，而不只是两个方法名是否存在。

## 原因

派生是结构递归：只有各组成部分都是 `Codec`，类型才能是 `Codec`。如果 `Raw` 不是 Codec 却接受 `Wrap: Codec`，就会编译出对不存在的 `Raw.encode` 的调用——这是代码生成失败，而不是清晰的诊断。在类型层面强制此要求，可以让“此类型派生 P”成为真实且可传递的陈述，并使修复显而易见且局部化。

`Eq` 和 `Repr` **不受** E023 限制：每个生成的结构体都会无条件获得 `PartialEq` 和 repr 路径，因此字段无需声明它们。
