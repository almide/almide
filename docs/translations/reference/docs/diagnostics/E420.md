# E420 — Function visibility violation

A call reaches a function outside its declared visibility scope. `local fn`
is restricted to its defining file; `mod fn` is restricted to its project.
An underscore in a name alone is not the visibility declaration. E420 is
the stable code; E014 already names unreachable match arms.

## Common cases

```almide
// my_module.almd
fn public_helper() -> Int = 42
local fn private_helper() -> Int = 0   // same file only

// main.almd
import self.my_module
fn main() -> Unit = {
    let n = my_module.private_helper()    // E420
    println(int.to_string(n))
}
```

## Diagnostic

```
error[E420]: function 'my_module.private_helper' is not accessible
  hint: 'private_helper' is declared as `local` (same-file only)
```

The `hint:` line names the visibility scope the callee actually has.

## Fix

- If the function is intended to be public, change its visibility declaration
  deliberately, or add a public wrapper in the defining file.
- Otherwise keep the call within the declared file/project boundary.
- Renaming an underscore-prefixed function does not itself change visibility.

## Why visibility at all

Internal helpers should be refactorable without exposing their implementation
to unrelated callers. Explicit visibility, not a naming convention, sets the
boundary.
