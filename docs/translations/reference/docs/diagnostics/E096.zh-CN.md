# E096 — 将带 `mut` 参数的 fn 用作函数值

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E096.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E096.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E096.zh-CN.md)



> 原文：[E096.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E096.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

声明 `mut` 参数的 fn 可以调用，但不能转为函数值。不构成调用的单独引用会被拒绝：`let`、传给其他 fn 的参数、记录字段、列表元素、返回值；模块限定的 fn（`counter.bump`、`list.push`）也一样。

`mut` 参数会写回调用方的 `var`（C-226）。此承诺属于 fn 签名的一部分，而函数类型没有容纳它的位置：`bump` 的值是 `(St) -> Unit`，经由它调用时，`s` 被作为普通参数传入。在此错误出现之前，这种调用在 wasm 上丢失写入，在原生上构建失败。

```almide
type St = { count: Int }

fn bump(mut s: St) -> Unit = {
  s.count = s.count + 1
}

effect fn main() -> Unit = {
  var s = St { count: 0 }
  let f = bump          // ← E096
  f(s)
  println(int.to_string(s.count))
}
```

<a id="diagnostic"></a>

## 诊断

```
error[E096]: fn 'bump' has a `mut` parameter 's' and cannot be used as a function value
  in bump used as a value
  hint: A `mut` parameter writes back to the caller's `var`, and a function value cannot carry that. Call it directly (`bump(s)` with `var s`), or pass a lambda that names the `var` (`() => bump(s)`). If 'bump' only changes its own copy, drop `mut` from 's' and rebind it with `var` inside the body
```

错误指向引用。提示中的调用和 lambda 使用 fn 自己的参数名：对 `list.push`，显示为配合 `var xs` 的 `list.push(xs, x)`，以及 `(x) => list.push(xs, x)`。标准库 fn 不会得到最后一句，因为不能移除其 `mut`。

如果引用作为实参填入函数类型参数（`list.map(groups, grow)`），则没有可以点名的调用方 `var`：每次调用接收一个元素。提示此时会建议一个与该参数元数一致的 lambda，使用 lambda 自行绑定的名称，将每个 `mut` 实参复制进局部 `var`：

```
error[E096]: fn 'grow' has a `mut` parameter 'xs' and cannot be used as a function value
  hint: A `mut` parameter writes back to the caller's `var`, and a function value cannot carry that. Pass a lambda that copies into a local `var`: `(item) => { var copy = item; grow(copy); copy }`. If 'grow' only changes its own copy, drop `mut` from 'xs' and return the new value
```

当 fn 返回 `Unit`，而参数期待返回值（`list.map` 的 `(A) -> B`）时，lambda 以副本结束，使新值成为结果；否则以调用结束。对双参数位置的标准库 fn，`list.fold(xs, init, list.push)` 会建议 `(a1, a2) => { var copy = a1; list.push(copy, a2); copy }`。

<a id="fix"></a>

## 修复

- 在写入应当落到的位置直接调用 fn：对 `var s` 使用 `bump(s)`。
- 作为回调实参，传入提示中的 lambda：把元素复制进局部 `var`，在其上调用 fn，然后返回副本：
  ```almide
  let grown = list.map(groups, (item) => { var copy = item; grow(copy); copy })
  ```
- 需要函数值时，传入明确点名写入目标 `var` 的 lambda。lambda 捕获 `s`，所以写入会落到它：
  ```almide
  let tick = () => bump(s)
  tick()
  ```
- 如果 fn 只把参数作为自身的临时副本修改，而调用方从不需要写回，该参数就不需要 `mut`。删除它，在主体内重新绑定，并返回新值：
  ```almide
  fn next(x: Int) -> Int = {
    var y = x
    y = y + 1
    y
  }
  ```
  `next` 随后就是普通的 `(Int) -> Int` 值（`xs |> list.map(next)`）。

<a id="why"></a>

## 原因

既按引用传递、又允许函数值的语言，会把传递模式放在函数类型中：Swift 写 `(inout Int) -> Void`，Rust 写 `fn(&mut i32)`。Almide 函数类型没有这种模式，因此转为值会丢失写回。Koka 的局部 `var` 走另一条路：完全不能传给其他函数。Almide 只拒绝转换，因此直接调用和点名 `var` 的 lambda 都保留含义。
