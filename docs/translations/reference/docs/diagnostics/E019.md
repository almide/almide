# E019 — Ambiguous constructor

[![English](https://img.shields.io/badge/English-24292f?style=flat-square)](E019.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E019.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E019.zh-CN.md)

A bare variant constructor name is declared in **more than one** variant
type, so a use of it by itself is ambiguous — the checker cannot tell
which type you meant. This example concerns duplicate constructors in the same module.
Constructors owned by different modules are resolved with module ownership;
a shared spelling alone is not a cross-package collision.

Almide resolves the name to the first declared candidate so checking can
continue, but reports the conflict instead of silently constructing the
wrong type — which would otherwise surface much later as a cryptic
generated-Rust error (`E0769`/`E0308`).

## Common cases

```almide
type Cmd   = | Stop | Send(Int)
type Event = | Tick | Send(Int)   // `Send` now lives in two types

fn main() -> Unit = {
  let x = Send(5)   // E019: ambiguous constructor 'Send': declared in Cmd and Event
  println("${x}")
}
```

## Fix

Rename the constructor in one of the types so the name is unique. A
qualified `Type.Ctor` form is not yet supported, so renaming is the way
to disambiguate.

```almide
type Cmd   = | Stop | Send(Int)
type Event = | Tick | Emit(Int)   // renamed `Send` → `Emit`

fn main() -> Unit = {
  let x = Send(5)   // unambiguous: only Cmd declares `Send`
  println("${x}")
}
```

## Fix-it verdict

**not-fixable** — the error reports a semantic/design problem no automatic rewrite can decide. (`mechanical` = an unattended fixer may apply the
rewrite; `conditional` = a suggested fix needs review; `not-fixable` = no
automatic rewrite exists. #1486's applicability doctrine.)
