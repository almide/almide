# E011 — pure fn 内のクロージャーで可変 var を変更

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E011.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E011.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E011.zh-CN.md)



> 原文：[`docs/diagnostics/E011.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E011.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

純粋関数（`fn`）で宣言した `var` が、その関数内にネストした lambda／クロージャーの中から再代入されている。Almide の純粋な意味論ではクロージャーは値でキャプチャする。クロージャー内からキャプチャ済み `var` を変更するには隠れた共有セルが必要となり、参照透過性が壊れる。

## よくある例

```almide
fn count_evens(xs: List[Int]) -> Int = {
    var count = 0
    let _ = list.map(xs, (x) => {
        if x % 2 == 0 then count = count + 1    // E011: closure mutation
        x
    })
    count
}
```

## 診断

```
error[E011]: mutable variable 'count' is mutated inside a closure in a pure function — use effect fn instead
  hint: Move the mutation out of the closure, or mark the enclosing function as `effect fn`
```

## 修正 — pure fn では関数型の形を優先

数え上げ／累積には `list.fold` / `list.count` を使う。

```almide
fn count_evens(xs: List[Int]) -> Int =
    list.count(xs, (x) => x % 2 == 0)
```

変換には `list.map` を使う。

```almide
// ✗
fn doubles(xs: List[Int]) -> List[Int] = {
    var out: List[Int] = []
    let _ = list.map(xs, (x) => {
        out = out + [x * 2]
        x
    })
    out
}

// ✓
fn doubles(xs: List[Int]) -> List[Int] = xs |> list.map((x) => x * 2)
```

## 修正 — 本当に変更が必要なら `effect fn` にする

変更が実際にエフェクトを伴う場合（例えば I/O 結果を蓄積する場合）、外側の関数を `effect fn` にする。

```almide
effect fn gather(xs: List[String]) -> Result[List[String], String] = {
    var out: List[String] = []
    for x in xs {                     // `for` is allowed; it's not a closure
        let text = fs.read_text(x)!
        out = out + [text]
    }
    ok(out)
}
```

`for` / `while` ループはクロージャーではない。外側の `var` を変更しても E011 にはならない。検査の対象は `lambda`（`(x) => ...`）のキャプチャだけである。

## 理由

純粋関数は参照透過でなければならず、`f(x)` を二度呼ぶと同じ値になる必要がある。クロージャーが外側の状態を変更できると、この不変条件が壊れる。Almide はこれを静的に検出し、関数型の基本操作へ書き換えるか（通常はこちらの方が短く、LLM にも書きやすい）、`effect fn` に引き上げるよう作者に求める。
