# E010 — 不穷尽的 match

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E010.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E010.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E010.zh-CN.md)



> 原文：[E010.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E010.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

`match` 表达式没有覆盖匹配对象的所有可能情况。

<a id="common-cases"></a>

## 常见情况

```almide
type Color = | Red | Green | Blue

fn name(c: Color) -> String =
    match c {
        Red   => "red",
        Green => "green",
        // E010: missing Blue
    }
```

```almide
let o: Option[Int] = some(5)
match o {
    some(n) => n,
    // E010: missing `none`
}
```

<a id="diagnostic"></a>

## 诊断

```
error[E010]: non-exhaustive match: missing `Blue`
  --> main.almd:4:5
  hint: add an arm for `Blue`, or use `_ => ...` to cover the rest
  in match
```

诊断会按名称列出具体缺失的构造器。

<a id="fix"></a>

## 修复

- 显式添加缺失的分支：
  ```almide
  match c {
      Red   => "red",
      Green => "green",
      Blue  => "blue",          // added
  }
  ```
- 将通配符 `_` 用作最后一个分支，覆盖所有剩余情况：
  ```almide
  match c {
      Red => "red",
      _   => "other",
  }
  ```
- 对于 `Option[T]`：`some(x) => ...` + `none => ...`
- 对于 `Result[T, E]`：`ok(x) => ...` + `err(e) => ...`
- 对于 `List[T]`：`[] => ...` + `[head, ..tail] => ...`，或最后一个 `_ => ...` 分支。支持列表剩余元素模式。

<a id="why-exhaustive"></a>

## 为什么要求穷尽

穷尽性可以发现重构错误：如果为 `Color` 添加新的变体，所有不使用 `_` 的 `match` 都会无法编译，迫使你决定如何处理新情况。这就是“modification survival rate”的实际意义——代码不会悄然忽略新的值。

## Fix-it 判定

**not-fixable** — 此错误报告的是自动重写无法决定的语义／设计问题。（`mechanical` = 无人值守的修复器可以应用重写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）
