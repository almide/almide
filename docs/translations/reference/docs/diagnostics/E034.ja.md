# E034 — Option/Result 以外のオペランドにエラーチャネル演算子を適用した

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E034.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E034.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E034.zh-CN.md)



> 原文：[`docs/diagnostics/E034.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E034.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

`Option[T]` でも `Result[T, E]` でもない値に、`!`、`?`、`??` のいずれかを適用した。これらの演算子はエラーチャネルに作用するが、通常の値にはそれがない。

## よくある例

```almide
let n = 5!                  // E034: Int has no error channel
let o = "hi"?               // E034
let v = 3 ?? 0              // E034
```

## 診断

```
error[E034]: operator '!' requires Option or Result type but got Int
  hint: Use '!' only on Option[T] or Result[T, E] values
```

## 修正

- 演算子を取り除く。通常の値はすでに unwrap された状態である。
  ```almide
  let n = 5
  ```
- 失敗し得る計算を意図していたなら、オペランドは `Result`/`Option` を返す呼び出しから得るべきである（`int.parse(s)!`）。

## 理由

通常の値への演算子適用を受理すると、黙って何もしない操作になり、本当の間違い（リファクタリングで失敗し得る呼び出しを除去したのに演算子を残した、など）を隠してしまう。
