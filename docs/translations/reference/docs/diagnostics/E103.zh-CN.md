# E103 — 对无法进行常量时间比较的 Secret 使用 `==`

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E103.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E103.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E103.zh-CN.md)



> 原文：[E103.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E103.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

`secret.Secret[A]`（#4107）只有在 `A` 是 `String` 或 `Bytes` 时，才能用 `==` / `!=`（以及 `assert_eq` / `assert_ne`）比较：此时比较以常量时间运行（`string.is_equal_constant_time` / `bytes.is_equal_constant_time`），即使 Secret 位于被比较的记录、元组、列表、option 或 result 中也是如此。其他任何会读取 Secret 的比较都会触发 E103：

- 其他类型的 `Secret`（`Secret[Int]`、`Secret[MyRecord]`）；
- 任意载荷中含 Secret 的变体；
- 含 Secret 的 map 或 set。

```almide
import secret

fn main() -> Unit = {
  let a = secret.new(1234)
  println(if a == secret.new(1234) then "same" else "different")   // ← E103
}
```

```
error[E103]: operator '==' cannot compare 'Secret[Int]': a Secret compares only when it holds a String or Bytes (in constant time)
  hint: Compare what the secrets hold, explicitly: `secret.reveal(a) == secret.reveal(b)`. `==` on Secret[String] / Secret[Bytes] is constant time; a variant or map holding a Secret compares by `match` / per key.
```

<a id="fix"></a>

## 修复

1. 显式比较揭示后的值：`secret.reveal(a) == secret.reveal(b)`。揭示操作在调用点可见，正是此设计的目的。
2. 对含 Secret 的变体，对这一对值进行 `match`，并用 `==` 比较 Secret 载荷（String / Bytes 为常量时间）。

<a id="why"></a>

## 原因

派生的 `==` 在第一个不同的字节处停止，因此耗时会透露猜测的秘密有多少部分正确。String 和 Bytes 的 Secret 改用常量时间比较；其他载荷没有可提供的常量时间比较，因此会拒绝比较，而不是悄然产生时间差。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**not-fixable**：是否可以接受揭示后的比较，取决于秘密是什么。诊断指出类型和显式写法。
