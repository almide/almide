# E025 — 具体型を推論できない（制約のない型スロット）

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E025.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E025.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E025.zh-CN.md)



> 原文: [E025.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E025.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

束縛の型に、どの文脈からも確定できないスロットが含まれます。典型例は、静的に常に `ok(...)` となる値のエラー型です。使われない `err` 分岐を通してしか到達しないため、制約が付かないままになります。

```almide
fn main() -> Unit = {
  let r0: Result[Int, String] = ok(7)
  let r = result.or_else(r0, (e) => ok(0))   // ← error type never pinned
  println("done")
}
```

Almide は Rust/Swift の規則に従います（Rust E0282 参照）。決定できない型スロットは、その型の値が一度も構築されなくてもコンパイルエラーです。暗黙に既定の型を与えることはありません（そうすると `check` が通ってコード生成で失敗することになるためです）。

## 修正

束縛（または lambda の結果）に完全な型を注釈し、スロットを確定させます。

```almide
let r: Result[Int, String] = result.or_else(r0, (e) => ok(0))
```

## 何によっても決まらない型パラメーター

型パラメーターがどの引数にも現れず、結果からも確定しないジェネリック fn の呼び出しにも同じ規則が適用されます（Rust E0282 の「関数 `tag` で宣言された型パラメーター `T` の型を推論できない」を参照）。

```almide
fn tag[T](s: String) -> Int = string.len(s)

effect fn main() -> Unit = {
  println(int.to_string(tag("abc")))   // ← nothing determines `T`
}
```

呼び出しで型引数を指定します（`tag[Int]("abc")`）。または、シグネチャがそのパラメーターを使わないなら宣言から削除します（`fn tag(s: String) -> Int`）。パラメーターが結果に及ぶ場合（`fn dekode[T](s: String) -> Option[T]`）、呼び出しは代わりに制約のない結果型について1度だけ報告します。

## Fix-it 判定

**conditional** — 具体的な型は作者が指定する必要があります。（`mechanical` = 無人の修正ツールが書き換えを適用可能、`conditional` = 提案された修正にレビューが必要、`not-fixable` = 自動書き換えは存在しません。#1486 の適用可能性の原則。）
