# E112 — too many generic instances

Monomorphization passed the `generic_instances` compile-cost budget
(ADR-0030): the program needs more specialized instances of protocol-bounded
generic fns than the compiler makes for one program, or an instance whose type
arguments passed the `type_size` budget. The shape that reaches it is a
chain of generic fns that each pass a larger type argument to the next: every
step is a new instance, and each one's type is larger than the last:

```almide
fn l0[T: Hash](x: T) -> Int = l1((x, x))
fn l1[T: Hash](x: T) -> Int = l2((x, x))
// … twelve steps: the last instance's type has 2^12 leaves
```

## Fix

Pass the same type on: collect the values in a list, or count the steps in an
`Int`.

## Why

Before the budget, monomorphization stopped at 1000 instances with a warning
and went on with an incomplete program (and the module-generic loop had no
bound at all). Like every compile-cost budget the figure is counted, the
source cannot raise it, and `--budget generic_instances=N` on the command line
can (`almide budgets`).

Fixtures: `tests/diagnostics/e112-instance-doubling-through-*` (checked with
`almide check --target wasm`, the route that links).

## Fix-it verdict

**not-fixable**: the recursion's shape is a decision about the program.
(`mechanical` = an unattended fixer may apply the rewrite; `conditional` = a
suggested fix needs review; `not-fixable` = no automatic rewrite exists.
#1486's applicability doctrine.)
