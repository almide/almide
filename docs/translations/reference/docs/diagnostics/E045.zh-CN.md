# E045 — 对非元组使用元组索引，或索引越界

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E045.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E045.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E045.zh-CN.md)



> 原文：[`docs/diagnostics/E045.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E045.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

`.k` 位置访问仅对元组值定义，且索引必须小于元组元素数。两种误用过去都能通过 `almide check`（“No errors found”），表达式保留为 `Unknown` 类型，随后在构建时以 ConcretizeTypes 提示失败，把用户自己的类型错误说成编译器 bug，并要求向上游报告（#1266）。现在 checker 会提前拒绝两者，并指出观察到的类型。

```almide
let n = 5
let a = n.0        // ← E045: tuple index .0 on non-tuple type Int

let t = (1, 2)
let b = t.5        // ← E045: tuple index .5 is out of range for (Int, Int)
                   //         (valid: .0 through .1)
```

类型仍为未定推断变量的对象（等待调用位置的 lambda 参数）不会在此被拒绝。索引会延后，等 union-find 绑定元组类型后再解析，因此 `xs |> list.map((p) => p.1)` 这样的链仍可工作。

## 修复

对元组在其元素数范围内索引，或使用解构代替索引：

```almide
let t = (1, 2)
let b = t.1

let (x, y) = t
```

## Fix-it 判定

**not-fixable** — 错误报告的是自动改写无法判断的语义／设计问题。（`mechanical` = 无人值守的修复器可以应用改写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动改写。#1486 的适用性原则。）
