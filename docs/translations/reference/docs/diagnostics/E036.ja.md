# E036 — map_err の lambda がエラー値を使っていない（警告）

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E036.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E036.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E036.zh-CN.md)



> 原文：[`docs/diagnostics/E036.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E036.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

`map_err` に渡した lambda が、名前付きエラーパラメーターを宣言しているのに読み取らない。置換後のメッセージは型検査を通る（String → String）ため、元のエラーが黙って失われる。文脈を追加するイディオムで最もよくある間違いである。

## よくある例

```almide
fs.read_text(p) |> result.map_err((e) => "loading config")     // E036
// Error: loading config          ← "No such file…" is gone
```

## 診断

```
warning[E036]: map_err's lambda never uses the error value 'e' — the
               original error is silently discarded
  hint: interpolate it ((e) => "context: ${e}") or discard deliberately ((_) => …)
```

## 修正

- 標準的な文脈追加のイディオムでは、元のエラーを末尾に残す。
  ```almide
  fs.read_text(p) |> result.map_err((e) => "loading config: ${e}")
  ```
- 意図的な置換は、破棄パラメーターを使って表す。
  ```almide
  fs.read_text(p) |> result.map_err((_) => "friendly message")
  ```

## 理由

エラーの文脈は置換ではなく*連鎖*にすべきである。入れ子の呼び出しが `starting server: loading config: No such file…` を作れば、失敗に至る経緯として読める。黙って置換すると、この連鎖が任意の深さで切れてしまう。
