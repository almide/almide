# E005 — 引数型の不一致（コンストラクター／関数呼び出し）

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E005.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E005.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E005.zh-CN.md)



> 原文：[`docs/diagnostics/E005.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E005.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

バリアントのコンストラクター、レコードのビルダー、または関数呼び出しが、宣言されたパラメーターに一致しない型の引数を受け取った。

## よくある例

```almide
type Point = Pt(Int, Int)
let p = Pt("x", "y")                  // expected Int, got String

type Box = { value: Int }
let b = Box { value: "abc" }          // record field type mismatch

fn gt2(n: Int) -> Bool = n > 2
let r = gt2("5")                      // expected Int, got String
```

## 修正 — 名前の語幹が同じ標準ライブラリ関数（#2097）

引数が標準ライブラリ関数の直接呼び出しで、同じモジュールに名前の語幹を共有し、期待される型を正確に返す関数がある場合、ヒントでその関数を示す。`try:` 行は呼び出し先だけを改名した同じ呼び出しとなる。

```almide
fn at(i: Int?) -> Int = i ?? -1
fn main() -> Unit = {
  let hit = list.find(["a", "b"], (s) => s == "b") // Option[String]
  println(int.to_string(at(hit)))                  // ← E005: expects Option[Int]
}
```

```
hint: `list.find` returns Option[String] — `list.find_index`
      returns Option[Int], which is what this argument expects
try:
    // Try:
    list.find_index(["a", "b"], (s) => s == "b")
```

これは推測ではなく検索である。語幹が同じ（`find` / `find_index`）、引数の数が同じ、戻り型が完全一致という条件を使う。そのような関数がなければ以下のヒントを使う。

## 修正 — 変換の補助関数

期待する型との差がプリミティブ変換だけである場合、標準ライブラリの変換を挿入する。

| 実際の型 | 期待される型 | 変換 |
|---|---|---|
| `Int` | `String` | `int.to_string(n)` |
| `String` | `Int` | `int.parse(s)!`（対応する失敗チャネル）または `int.parse(s) ?? 0` |
| `Int` | `Float` | `float.from(n)` |
| `Float` | `Int` | `int.from_saturating(x)`（小数部切り捨て）、または `int.from(x)`（Int の範囲外で中止）。丸める場合は先に `float.round(x)` |
| `List[A]` | `Option[A]`（単一要素） | `list.first(xs)` |
| `Option[A]` | `A` | `x ?? default` または `x!`（対応する失敗チャネル） |
| `Result[A, E]` | `Option[A]` | `r?`（値を変換し、伝搬しない） |
| `Result[A, E]` | `A` | `r!`（対応する失敗チャネル。Err を伝搬する） |

既知のプリミティブ型の組の不一致では、診断の `hint:` 行で具体的な変換を示すことが多い。

## 修正 — 構造

- ペイロードのないバリアントは `MyVariant` として呼ぶ（括弧なし）。`MyVariant()` は引数ゼロの関数呼び出しであり、引数ゼロのバリアントには一致しない。
- レコードでは必須フィールドをすべて含める。`Record { ...old, changed_field: new_value }` の spread 構文を使えば、既存レコードをコピーしつつフィールドを上書きできる。
- ジェネリック関数では、`E005` の背後にチェッカーの制約（型変数の推論が伝わらなかった）がある場合がある。`fn_call[TypeArg](args)` のように型引数を明示する。
