# E420 — 関数の可視性違反

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E420.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E420.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E420.zh-CN.md)



> 原文：[`docs/diagnostics/E420.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E420.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

呼び出しが、宣言された可視性の範囲外の関数に到達している。`local fn` は定義したファイル内、`mod fn` はそのプロジェクト内に制限される。名前にアンダースコアを付けるだけでは可視性の宣言にならない。安定したコードは E420 であり、E014 はすでに到達不能な match arm を表している。

## よくある例

```almide
// my_module.almd
fn public_helper() -> Int = 42
local fn private_helper() -> Int = 0   // same file only

// main.almd
import self.my_module
fn main() -> Unit = {
    let n = my_module.private_helper()    // E420
    println(int.to_string(n))
}
```

## 診断

```
error[E420]: function 'my_module.private_helper' is not accessible
  hint: 'private_helper' is declared as `local` (same-file only)
```

`hint:` 行は、呼び出し先が実際に持つ可視性の範囲を示す。

## 修正

- 公開すべき関数なら、意図して可視性の宣言を変えるか、定義元ファイルに公開ラッパーを追加する。
- そうでなければ、宣言されたファイル／プロジェクト境界の中に呼び出しを留める。
- アンダースコア接頭辞の関数を改名しても、それ自体では可視性は変わらない。

## 可視性が必要な理由

内部の補助関数は、無関係な呼び出し元へ実装を公開せずにリファクタリングできるべきである。境界を決めるのは命名規則ではなく、明示的な可視性である。
