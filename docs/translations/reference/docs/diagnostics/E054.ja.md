# E054 — fmt の検証失敗

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E054.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E054.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E054.zh-CN.md)



> 原文: [E054.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E054.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

`almide fmt` は、整形するとプログラムが保持されないためファイルへの書き込みを拒否しました。これはフォーマッターの `--safe` 検証器（Black モデル、#1309）です。書き込み前に、整形後の出力が (1) 依然として構文解析でき、(2) 同一の AST を持ち、(3) すべてのコメントを保持する必要があります。いずれかが満たされない場合、ファイルは変更せず、理由をこの診断で示します。

```
error[E054]: fmt verification failed — AST changed by formatting at $.decls[3].body
  hint: Formatting this file would not conserve the program (parse, AST, or
        comments), so it was left untouched. This is a FORMATTER bug, not a
        source problem — please report it ...
```

<a id="what-it-means"></a>

## 意味

[E083](../../../../diagnostics/E083.md) と同様、**欠陥はソースではなくコンパイラ側にあります**。検証器は、フォーマッターのバグを暗黙の破損ではなく明確な拒否にするために存在します。メッセージには最初に不一致となる AST パス（または構文エラー、コメント数）が含まれ、コンパイラ側で対処可能な報告になります。

<a id="what-to-do"></a>

## 対処

- 指定されたファイルは整形せずに残してください（fmt はすでにそうしています。拒否は安全性の仕組みが働いた結果です）。
- <https://github.com/almide/almide/issues> にファイルを報告してください。E054 はそれぞれ、回帰フィクスチャで固定できるフォーマッターの欠陥です。
- 周囲のファイルは通常どおり整形できます。拒否はファイル単位です。

既知の無害な例として、式の途中に置かれたインラインコメント（`f(1 /* x */, 2)`）があります。構文解析では合法ですが、fmt はまだ結び付けられません。対応は `#1326` で追跡しています。そのようなファイルはコメントを失う代わりに未整形のまま残ります。

<a id="where-it-fires"></a>

## 発生箇所

E054 のソースフィクスチャが `tests/diagnostics/` にないのは意図的です。引き金はフォーマッター内部の欠陥であり、コミットされたソースファイルが意図的に再現できる（またはすべき）ものではありません。検証器自体のロジックは `crates/almide-tools/tests/fmt_corpus_test.rs` が固定しています。破損した「整形後」出力を `verify_format` へ直接渡し、拒否を確認します。
