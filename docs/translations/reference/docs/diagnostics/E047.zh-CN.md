# E047 — 字符串字面量中的无效转义

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E047.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E047.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E047.zh-CN.md)



> 原文：[`docs/diagnostics/E047.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E047.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

字符串字面量内的 `\` 开始转义。Almide 恰好定义以下转义：

| 转义 | 适用位置 | 含义 |
|---|---|---|
| `\n` `\t` `\r` | `"…"` `'…'` `"""…"""` | 换行、制表、回车 |
| `\\` | 全部 | 一个字面反斜杠 |
| `\"` | `"…"` `"""…"""` | 双引号 |
| `\'` | `'…'` | 单引号 |
| `\$` | `"…"` `"""…"""` | 字面的 `$`（抑制 `${…}` 插值孔） |
| `\xNN` | 全部 | `0x00..0xFF` 内的码点，恰好两位十六进制数字 |
| `\u{…}` | 全部 | 任意 Unicode 标量值，一至六位十六进制数字 |

其他写法均为 E047。原始字符串（`r"…"`、`r"""…"""`）完全没有转义层：`r"\q"` 就是反斜杠和 q，永不报告 E047。

```almide
let a = "bad:\q"          // ← E047: unknown escape sequence `\q`
let b = "bad:\u{110000}"  // ← E047: `\u{110000}` is not a Unicode scalar value
```

两者过去都静默通过 `almide check`，求值为自身拼写：`"bad:\q"` 是六个字符 `b a d : \ q`，`"\u{110000}"` 是其十字符源码文本。这与 E024 对整数字面量禁止的静默重解释相同：值不符合表述的字面量是编译器必须指出的 bug，而非继续携带的内容。

<a id="fix"></a>

## 修复

**未知转义**——转义反斜杠，或使用原本想要的转义：

```almide
let path = "C:\\Users"    // a literal backslash is \\
let tab  = "col1\tcol2"   // \t, not \T
```

正则模式是普通字符串，因此正则字符类需写双反斜杠；也可使用无需加倍的原始字符串：

```almide
regex.find(regex.new("\\d+"), s)     // the regex \d+
regex.find(regex.new(r"\d+"), s)     // same, no doubling
```

这里 `regex.new` 将模式编译为 `find` 接收的 Regex 值。

**越界码点**——Unicode 标量值范围为 `U+0000..U+D7FF` 和 `U+E000..U+10FFFF`。代理项范围 `D800..DFFF` 是 UTF-16 编码产物，不表示字符；`U+10FFFF` 之上没有码点：

```almide
let ok  = "\u{10FFFF}"    // the highest codepoint there is
let nul = "\u{0}"         // NUL — `\0` is not an Almide escape
```
