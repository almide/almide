# E080 — or-pattern alternative binds a variable

[![English](https://img.shields.io/badge/English-24292f?style=flat-square)](E080.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E080.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E080.zh-CN.md)

An or-pattern arm `a | b | c => body` is taken when **any** alternative
matches — so the body cannot depend on which one did. A variable binder
inside an alternative would have no single value on the alternatives where
it does not appear (or would bind different payloads on different paths),
so alternatives are **binder-free**.

```almide
fn class(x: Option[Int]) -> String = match x {
  some(n) | none => "?",   // ← E080: `n` binds in one alternative only
}
```

Wildcards are fine — they bind nothing:

```almide
fn class(x: Option[Int]) -> String = match x {
  some(_) | none => "either",
}
```

When the body needs the payload, write separate arms:

```almide
fn class(x: Option[Int]) -> String = match x {
  some(n) => "got ${n}",
  none => "nothing",
}
```

The rule covers binders at any depth — inside constructor arguments,
tuples, lists, and record-pattern fields alike.

## Fix-it verdict

**conditional** — replacing the binder with `_` is mechanical, but whether
the body wanted the payload (and the arm should split instead) is intent.
(`mechanical` = an unattended fixer may apply the rewrite; `conditional` =
a suggested fix needs review; `not-fixable` = no automatic rewrite exists.
#1486's applicability doctrine.)
