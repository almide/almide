# E041 — 暗黙の伝搬は廃止された

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E041.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E041.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E041.zh-CN.md)



> 原文：[`docs/diagnostics/E041.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E041.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

effect fn 内では、失敗し得る呼び出しの err が、かつて9つの位置でマーカーなしに外側の失敗チャネルへ返されていた。文、型注釈のない束縛、条件、値パターン match の対象、補間された呼び出し、および4つの末尾位置（effect fn の末尾値、`match` arm の値、`if` 分岐の値、`guard` の else）である。ADR-0008 はこれを廃止した。伝搬はすべての位置で一律に `!` と書く。0.54 の非推奨期間（このコードが警告だった期間）の後、暗黙の形式はなくなった。値は `Result` のままで、自動 unwrap していた位置はこのエラーになる。

<a id="common-cases"></a>

## よくある例

```almide
effect fn main() -> Unit = {
  let r = int.parse(s)        // E041 — write: int.parse(s)!
  if flag() then ...          // E041 — write: flag()!
  println("${get()}")         // E041 — write: "${get()!}"
}
```

文位置で捨てられた Result は、関連する [E042](E042.ja.md) エラー（must-use）となる。

effect fn 内の lambda 本体も同じ文脈である（#2254）。lambda 自体が伝搬していたわけではないが、そこでの型注釈のない `let t = fs.read_text(p)` は同じ選択を迫られる。`fs.read_text(p)!` は lambda を失敗可能にする（ADR-0006。その場合、外側の `list.map(...)` 呼び出しにも自身の `!` が必要）。あるいは Result を値として消費する。lambda 内では `!` を `try` に示すが、位置は付けない。lambda を受け取る呼び出しにも `!` が必要となり、1か所だけの編集ではないためである。純粋な fn、またはその内側の lambda が `Result` 値を保持するのは正当であり、報告しない。

<a id="diagnostic"></a>

## 診断

```
error[E041]: implicit propagation of this binding's value was removed — this value is a Result (ADR-0008)
  try: !          ← a suggestion; choose whether propagation is intended
```

<a id="fix"></a>

## 修正

伝搬するには `!` を追加する。または Result を値として消費する：`?? fallback`、`?`（Option へ）、`match r { ok(v) => …, err(e) => … }`。このエラーが提供するのは提案であり、無人適用可能な machine-applicable 編集ではない。補間された呼び出しも明示的に書く（`"${get()!}"`）。

<a id="why"></a>

## 理由

暗黙の形式は位置依存（適用される位置とされない位置がある）かつ型注釈依存だった。同じ式でも型注釈やパターンの形によって実行時の振る舞いが変わっていた。あらゆる位置で1つの明示マーカーを使うのが Rust/Swift/Zig のモデルである（ADR-0008 の調査：位置依存の暗黙伝搬を採用する言語はない）。
