# E038 — `??` 与其回退值分离

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E038.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E038.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E038.zh-CN.md)



> 原文：[`docs/diagnostics/E038.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E038.md)，固定提交 `9a95b285`。这是供读者参考的非规范性译文，CLI 诊断输出仍为英文。

在语句层面，`??` 的回退值必须与运算符在同一行开始。`??` 本身可以像其他中缀运算符一样放在续行开头（#3155）：`xs\n  |> list.first\n  ?? 0`。过去，跨行的 `??` 会静默地把下一条语句吞为回退表达式；程序不报错，却按错误含义运行。

缺失操作数的形式（后面没有内容的 `expr??`）使用同一代码。

<a id="common-cases"></a>

## 常见情况

```almide
let v = int.parse("x")??
-5                          // ← silently became the fallback (pre-E038)
println("${v}")
```

<a id="diagnostic"></a>

## 诊断

```
error[E038]: the ?? fallback is not on this line
  hint: write the fallback on the same line; multiline uses parens with ?? trailing
```

<a id="fix"></a>

## 修复

- 同一行：`let v = int.parse("x") ?? -5`
- 多行（在括号内，`??` 放在行末）：
  ```almide
  let v = (int.parse("x") ??
    -5)
  ```

<a id="why"></a>

## 原因

这是 JS-ASI 类风险：语句边界被静默重新连接为操作数。在 `(`/`[` 定界符内部，表达式仍像以前一样跨换行继续；只对语句层面的形式做保护。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**conditional** — 重新接上回退值通常是机械操作，但预期操作数仍是猜测。（`mechanical` = 无人值守的修复工具可以应用改写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动改写。#1486 的适用性原则。）
