# E062 — `-S` のない shebang（警告）

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E062.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E062.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E062.zh-CN.md)



> 原文: [E062.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E062.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

`#!/usr/bin/env almide run` は macOS で動きますが、Linux では失敗します。

Darwin のカーネルは `env` を呼ぶ前に shebang 行を空白で分割します。Linux の `binfmt_script` は分割しません。`env` は残りの行を1つの引数として受け取り、文字どおり `almide run` という名前のプログラムを探します。

```
$ /usr/bin/env "almide run" --version
env: almide run: No such file or directory
```

`env -S`（coreutils 8.30、2018）はまさにこの分割のためにあります。スクリプトを書いたマシンでは失敗が再現せず、作者が思い付くのは誤った書き方です。それまで見た shebang はすべて1語（`#!/usr/bin/env python3`）なので、2語目を追加するだけで `-S` を学びません。この警告以前、5本連続でこれを省いたスクリプトが書かれました（#2159）。

```almide
#!/usr/bin/env almide run        // ← E062: this shebang does not run on Linux

fn main() -> Unit = println("hi")
```

<a id="fix"></a>

## 修正

`env` の直後に `-S` を挿入します。

```almide
#!/usr/bin/env -S almide run

fn main() -> Unit = println("hi")
```

警告の下にある `try:` 行は、まさにこの書き換えです。

<a id="when-it-does-not-fire"></a>

## 発生しない場合

判定は1行目のテキストだけで行い、PATH 検索もホスト調査もしません。

- インタープリターが `env` ではない（`#!/usr/local/bin/almide run` — 両プラットフォームで、カーネルは `run` を almide に直接渡します）
- `-S` / `--split-string` がある。フラグの組（`-iS`）の中でも該当します
- `env` の後ろのプログラム語が1つだけ（`#!/usr/bin/env almide`）。フラグと `NAME=value` 代入は数えません

`--deny-warnings` の下では、ほかの警告と同様にエラーになります。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**mechanical** — `env` の後ろへの `-S` 挿入は、同じコマンドラインの純粋な表記変更です。インタープリター、プログラム、引数は同じで、両カーネルで同じように分割されるようになります。`almide fix` が無人で適用します（出力処理は `with_machine_fix`、1行目全体を置換）。（`mechanical` = 無人の修正ツールが書き換えを適用可能、`conditional` = 提案された修正にレビューが必要、`not-fixable` = 自動書き換えは存在しません。#1486 の適用可能性の原則。）
