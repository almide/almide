# E098 — 传给 `testing.assert_aborts` 的闭包捕获局部变量

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E098.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E098.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E098.zh-CN.md)



> 原文：[E098.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E098.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

`testing.assert_aborts(expected, f)` 只运行 `f`，且在子环境中运行：原生测试二进制为该闭包重新执行自身，wasm 路径则启动同一模块的新实例（ADR-0029）。子环境重新启动程序，因此测试的局部内容——`let`、`var`、`where` 绑定、外层 lambda 参数——在那里不存在。

因此，闭包必须是在调用处直接书写的 lambda，且读取但未自行绑定的每个名称都必须是顶层项：fn、顶层 `let` 或 `var`（看到其初始值）、导入模块、标准库。

```almide
import testing

test "reading past the end aborts" {
  let xs = [1, 2, 3]
  testing.assert_aborts("index out of bounds", () => xs[5])   // ← E098: captures `xs`
}
```

保存在局部变量中的 fn 值也会被拒绝：在传入位置无法看出其捕获内容。

```almide
import testing

test "a panic aborts" {
  let boom = () => panic("boom")
  testing.assert_aborts("boom", boom)                          // ← E098: `boom` is a fn value
}
```

<a id="diagnostic"></a>

## 诊断

```
error[E098]: the closure passed to testing.assert_aborts captures `xs`, a local of the test
  in a call of testing.assert_aborts
  hint: the closure runs in a separate process (native) or instance (wasm), where the test's locals do not exist. Inline the value into the closure, or make it a top-level `let`.
```

错误指向每个被捕获局部变量的第一次读取。

<a id="fix"></a>

## 修复

在闭包内部计算该值：

```almide check
import testing

test "reading past the end aborts" {
  testing.assert_aborts("index out of bounds", () => {
    let xs = [1, 2, 3]
    xs[5]
  })
}
```

或者改为顶层 `let`，由子环境自行计算。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**conditional** — 如果值来自程序自身，将绑定移入闭包就是修复；但测试从其运行中计算出的值，必须在闭包内重新计算或改为顶层 `let`，这由作者选择。（`mechanical` = 无人值守重写；`conditional` = 修复建议需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）
