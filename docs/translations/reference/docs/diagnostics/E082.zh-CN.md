# E082 — --target wasm 的 wasm 路径无法 lower 此程序

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E082.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E082.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E082.zh-CN.md)



> 原文：[`docs/diagnostics/E082.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E082.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

`--target wasm` 只有一个引擎：structural 路径（`crates/almide-wasm`）。E082 表示它在所用路径——标准 WASI 构建（`almide build`）或嵌入式宿主（`almide run`）——**拒绝了**程序。原因会出现在错误行和机器可读的 `wall:` 行，来源函数出现在 `-->` 行（#2807）。以构建路径为例：

- emitter 无法 lower 的形态（`expr:Todo`——如 `todo("later")` 的 typed hole，无论是否可达都被有意拒绝，C-268）；
- p1 `to_wasi` shim 没有标准 WASI 服务的已生成 host op（`host op N has no stock-WASI service`；fs op 自 #2742 起已在此提供）；
- 声明的 `@export(wasm, "sym")` 函数体无法 lower，或两个 export 占用同一名称；覆盖产物中的任何模块，包括入口文件与链接模块（#3281）；
- generic fn 上声明 `@export(wasm, "sym")`：wasm export 需要一个具体签名，因此应导出调用该泛型函数的非泛型 fn（#3285）。

在 #2752 之前，structural 路径拒绝的程序会交给第二个 renderer（原有 v1 路径），E082 表示两者都拒绝（#1922）。该回退已移除：没有第二条路径，因此一次拒绝就是全部判定，绝不静默更换 renderer。代码编号保留（原来为 E082 的程序现在仍为 E082；原先由回退处理的程序现在也为 E082）。

```text
error[E082]: the wasm target cannot lower this program: expr:Todo
  --> in fn `later` (entry file, line 1)
  note: this is the stock-WASI BUILD route; `almide run --target wasm` (the embedded host serves every op) may still run it
  note: `almide check --target wasm` reports this verdict at check time; the native target (`--target rust`) is unaffected
wall: expr:Todo
```

`almide check --target wasm` 不执行构建，但运行同一路径，在检查时报告 E081 / E082。它由构建路径本身测量，而非声明表，因此不会偏离 `build` 的行为。构建路径的注记将嵌入式宿主指出为仍可能运行程序的路径（其 shim 提供每个 op，剩下的因素是形态壁垒）。这一 wasm 专属拒绝并不确立独立的 `--target rust` 构建是否成功。
