# E101 — 読んだ見た目とコンパイルされる内容が異なるソース

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E101.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E101.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E101.zh-CN.md)



> 原文: [E101.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E101.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

E101 は、読み手とコンパイラで異なって見えるソーステキストを拒否します。`.almd` ファイル内のどこにあっても生の隠し文字（#4092、#4266）、および読み手が他と見分けられない識別子（#4266）が対象です。

<a id="hidden-characters"></a>

## 隠し文字

対象集合は C-418 のエスケープ表（`crates/almide-base/src/err_text.rs` の `ALMIDE_RT_ERRTEXT_ESCAPED`）から TAB、LF、CR を除いたものです。ランタイムエラーテキストでエスケープが必要な文字と、ソースファイルに生のまま置いてはいけない文字は一致します。

- 表示行の順序を変える双方向制御文字（下表）。
- U+2028 LINE SEPARATOR と U+2029 PARAGRAPH SEPARATOR。エディターやウェブ表示では改行に見えますが、字句解析器は改行として扱いません。
- その他の General Category Cf 文字すべて — U+200B..U+200D、U+2060..U+2064、ファイル途中の U+FEFF、U+00AD など。画面上では不可視です。
- Tags ブロック U+E0000..U+E007F。ソースを読むモデルにはテキストとして読める不可視 ASCII です（ASCII smuggling）。
- TAB、LF、CR 以外の生の C0 と C1 制御文字。

先頭のバイト順マークは走査前に取り除きます。9つの双方向制御文字：

| コードポイント | 名前 |
|---|---|
| U+202A | LEFT-TO-RIGHT EMBEDDING |
| U+202B | RIGHT-TO-LEFT EMBEDDING |
| U+202C | POP DIRECTIONAL FORMATTING |
| U+202D | LEFT-TO-RIGHT OVERRIDE |
| U+202E | RIGHT-TO-LEFT OVERRIDE |
| U+2066 | LEFT-TO-RIGHT ISOLATE |
| U+2067 | RIGHT-TO-LEFT ISOLATE |
| U+2068 | FIRST STRONG ISOLATE |
| U+2069 | POP DIRECTIONAL ISOLATE |

コメント、文字列リテラル、heredoc、生文字列、そしてすべてのターゲットで同じ規則です。フロントエンドのエラーとして扱います。

`U+202E } U+2066 if admin then U+2069 {`（名前ではなく実際の文字）を含む行コメントは、エディターやコードレビューページでは順序を逆にしたコードとして表示されますが、コンパイラはコメントとして読みます。このページには生の文字を表示できません。それこそが要点です。

```
error[E101]: raw hidden character U+202E RIGHT-TO-LEFT OVERRIDE at line 5, column 6
  hint: this character makes the source display differently from how it compiles (Trojan Source), or hides text from a reader that a model still reads. Remove it from a comment; inside a string literal, write the escape `\u{202E}` if the character is intended
```

<a id="fix"></a>

## 修正

- コメント内：文字を削除します。
- 本当にその文字を必要とする文字列リテラルや heredoc 内：エスケープを書きます。ソース上のエスケープは ASCII なので、レビュー担当者が読むテキストとコンパイラが読むテキストが一致し、デコード後はその文字になります。

```almide
let s = "user\u{202E} txt.exe"   // the escape, not the raw character
```

生文字列（`r"…"`）にはエスケープ層がありません。代わりに通常のリテラルから値を作ってください。絵文字の ZWJ 列では結合子をエスケープで書きます：`"👨\u{200D}👩\u{200D}👧"`。

<a id="homoglyph-identifiers"></a>

## 同形文字の識別子

UTS #39 の2つの規則を、非 ASCII 文字を含む識別子だけに適用します（rustc の `mixed_script_confusables` と `confusable_idents` も警告として同じ境界を採用しています）。

- **文字体系の混在。** 非 ASCII 識別子は UTS #39 の *Moderately Restrictive* 以下の範囲でなければなりません。1つの文字体系、Latin と Han／Hiragana／Katakana／Hangul／Bopomofo の組合せ、または Latin と Cyrillic・Greek 以外の他の1文字体系です。すべての文字が General Security Profile の `Allowed` である必要もあります。Cyrillic の `а`（U+0430）を含む `аdmin` は Latin + Cyrillic なので拒否されます。
- **混同可能な識別子。** 1ファイル内に同じ UTS #39 skeleton を持つ異なる綴りがあり、少なくとも一方が非 ASCII の場合、後の方を拒否します。例えば `ace` の隣にある、すべて Cyrillic の `асе` です。補間ホール内の識別子も数えます。

```
error[E101]: identifier `аdmin` mixes scripts a reader cannot tell apart at line 4, column 4
  hint: its non-ASCII characters are `а` U+0430 (Cyrillic). An identifier must be written in one script, …
```

修正：名前自身の文字体系の文字を書きます。または2つのうち片方を改名します。`привет`、`名前`、`user名`、`π` はすべて問題ありません。

<a id="why"></a>

## 理由

Trojan Source（CVE-2021-42574）：これらの文字がソースに入ると、レビュー担当者とコンパイラが読むコードが異なります。rustc はコメントとリテラルの双方向制御文字を既定で拒否します（`text_direction_codepoint_in_comment`、`text_direction_codepoint_in_literal`）。同形文字の識別子は CVE-2021-42694 です。最初の関数と同じに見える2つ目の関数によって、差分に見えるものとは異なるコードを変更後に呼び出せてしまいます。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**not-fixable**：コメント内なら文字を削除すべきですが、リテラル内では意図された文字かもしれず、その場合はエスケープにすべきです。診断はその選択をしません。

フィクスチャ：`tests/diagnostics/e101-*`（コメント、リテラル、heredoc、インラインブロックコメント、生文字列内の双方向制御文字、タグ文字、コメント内の U+2028、リテラル内の U+200B、混在文字体系と混同可能な識別子、補間ホール内の同形文字）。近いが該当しない例：`tests/diagnostics/silent/bidi-control-written-as-escape.almd` と `tests/diagnostics/silent/non-ascii-identifiers-a-reader-can-tell-apart.almd`。
