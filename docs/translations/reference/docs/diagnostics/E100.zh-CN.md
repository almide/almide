# E100 — 位于内存安全保证之外

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E100.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E100.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E100.zh-CN.md)



> 原文：[E100.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E100.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

能够读写 Almide 值之外内存的构造，在两个位置被拒绝。

<a id="without-import-ffi-4043"></a>

## 未声明 `import ffi`（#4043）

原始内存需要显式选择启用，类似 Rust 的 `unsafe`。能够触及外部代码也可访问的内存的标准库函数，在 `.almd` 源码中声明为 `@memory_unsafe`：所有 `ffi.*` 函数（`ffi.region`、`ffi.alloc`、`ffi.len`、`ffi.is_writable`、`ffi.read`、`ffi.write`、`ffi.to_bytes`）。在标准库外，调用它们需要调用方文件写出 `import ffi`。启用按文件计：触及原始内存的模块必须自己声明，无论导入它的文件写了什么。因此，所有文件都没有 `import ffi` 和 `@extern` 的程序，在任何目标上都无法触及其值之外的内存。因为只有 `ffi` 模块含 `@memory_unsafe` 函数，且从不自动导入，没有 import 的文件甚至无法命名它：调用会触发 E003（`undefined variable 'ffi'`），提示就是导入。E100 用于拒绝通过任何其他方式触及 `@memory_unsafe` 函数。

每次 `ffi` 访问都会根据 `Region` 长度检查边界（[ADR-0031](../../../../adr/0031-raw-pointers-carry-provenance.md)）：越界的 `ffi.read` 或 `ffi.write` 返回 `err`。仍然要求导入，因为 `Region` 可查看外部代码也能触及的内存（交给 `@extern(c)` fn 的缓冲区，或由带 `@region(len = …)` 的 `@extern` 返回的内存）。

```almide
effect fn main() -> Unit = {
  let small = bytes.from_list([1, 2, 3, 4])
  let copied = ffi.read(ffi.region(small), 0, 4)!   // ← E003: no `import ffi`
  println(int.to_string(bytes.len(copied)))
}
```

```
error[E003]: undefined variable 'ffi'
  hint: Add `import ffi` (stdlib: bounds-checked memory regions shared with foreign functions)
```

修复就是文件顶部的一行：

```almide check
import ffi

effect fn main() -> Unit = {
  let small = bytes.from_list([1, 2, 3, 4])
  let copied = ffi.read(ffi.region(small), 0, 4)!
  println(int.to_string(bytes.len(copied)))
}
```

此规则过去涉及的将地址当指针的写法（`ffi.address`、`ffi.to_int`、`bytes.as_ptr`、`bytes.as_mut_ptr`、`bytes.data_ptr`、`bytes.from_raw_ptr`、`bytes.copy_to_ptr`）已移除（ADR-0031 D4，dialect epoch 15）：`Bytes` 的只读视图是 `ffi.region(b)`，可写缓冲区是 `ffi.alloc(n)!`，读写指定的是区域内偏移（`ffi.read(r, off, n)`、`ffi.write(r, off, b)`），绝不是地址。

<a id="under---profile-critical-4008"></a>

## 在 `--profile critical` 下（#4008）

`almide check --profile critical` 只接受处于 Almide 内存安全保证内的代码。两类内容在保证之外，即使有 `import ffi` 也都会触发 E100：

- 调用任何 `ffi.*` 函数。`Region` 可查看外部代码也能触及的内存，外部区域的长度由绑定声明（`@region(len = …)`），因此即使经过边界检查的 `ffi.read` 也会被拒绝；
- 声明 `@extern` fn：其主体是外部代码。

不同于能力限制（E076），任何 `--allow` 授权都不能允许这些内容。不使用该配置时，同一程序（带 `import ffi`）仍按原方式通过检查：critical 是语言子集，不是 dialect。

```almide
import ffi

effect fn main() -> Unit = {
  let b = bytes.from_string("abc")
  let c = ffi.read(ffi.region(b), 0, 3)!   // ← E100 under --profile critical
  println(int.to_string(bytes.len(c)))
}
```

```
error[E100]: `ffi.region` is outside the memory-safety guarantee and is not admissible under `--profile critical`
  hint: the critical profile admits only code inside the memory-safety guarantee — keep raw-address and foreign code in a module that is not checked with `--profile critical`
```

<a id="fix"></a>

## 修复

1. 使用区域原本代替的安全操作：`bytes.slice`、`bytes.copy_from`、`bytes.get` 和带类型的读取函数，将每次访问限定在缓冲区长度内，无需导入。
2. 如果程序确实与外部代码交互，在执行交互的文件内写 `import ffi`，将该文件保留为独立模块，并用 `--profile critical` 检查程序其他部分。

<a id="why"></a>

## 原因

ADR-0031 之前，使用未经检查的长度进行原始读取，是普通 Almide 代码破坏内存的唯一途径：从3字节缓冲区的地址读取一百万字节，会复制其后的任何内容。`Region` 现在携带长度，所以 `ffi` 本身改为返回 `err`；保证之外剩下的是 `Region` 与外部代码共享的内存。`import ffi` 行将触及此内存的文件标记在读者、审查者或模型最先查看的位置；critical 配置承诺程序完全不触及它，因此拒绝所有能够触及它的构造。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**not-fixable**：替代方式取决于原始访问的目的。诊断指出构造以及缺失的 import 或配置，不会重写代码。

被拒绝的标准库函数是在其 `.almd` 源码（stdlib/ffi.almd）中声明为 `@memory_unsafe` 的函数；检查器读取声明，而不是名称列表。标准库自身源码免于 import 规则，与 E085 一样。

这不是 ALS §B（`@bounded`）规则：`@bounded` fn 调用 `ffi` 会触发 E076，与访问任何声明能力之外的模块相同。夹具：`tests/diagnostics/e100-critical-*`（每个 `meta.toml` 设置 `check_profile = "critical"`）以及 `tests/diagnostics/e003-no-import-ffi-region-*`（#4043 探针）。矩阵：`tests/critical_profile_test.rs`（`memory_unsafe_surface_is_refused_under_critical`）、`tests/memory_unsafe_import_gate_test.rs`、`tests/raw_ptr_surface_test.rs`。
