# E112 — ジェネリックインスタンスが多すぎる

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E112.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E112.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E112.zh-CN.md)



> 原文：[`docs/diagnostics/E112.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E112.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

単相化が `generic_instances` コンパイルコスト予算（ADR-0030）を超えた。プログラムが必要とするプロトコル制約付きジェネリック fn の特殊化インスタンス数が、1プログラムに対してコンパイラが作る上限を超えているか、インスタンスの型引数が `type_size` 予算を超えている。この状態に達する形は、次の関数へより大きな型引数を渡すジェネリック fn の連鎖である。各段階で新たなインスタンスが生じ、その型は前より大きい。

```almide
fn l0[T: Hash](x: T) -> Int = l1((x, x))
fn l1[T: Hash](x: T) -> Int = l2((x, x))
// … twelve steps: the last instance's type has 2^12 leaves
```

## 修正

同じ型を渡し続ける。値をリストに集めるか、段数を `Int` で数える。

## 理由

予算導入前は、単相化は1000インスタンスで警告して止まり、不完全なプログラムのまま続行していた（モジュールジェネリックのループには上限すらなかった）。すべてのコンパイルコスト予算と同じく、数量を数えて制限する。ソースから引き上げることはできないが、コマンドラインの `--budget generic_instances=N` では変更できる（`almide budgets`）。

フィクスチャ：`tests/diagnostics/e112-instance-doubling-through-*`（リンクを行う経路である `almide check --target wasm` で検査）。

## Fix-it 判定

**not-fixable**：再帰の形はプログラムに関する判断である。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
