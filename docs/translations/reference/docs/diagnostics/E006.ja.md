# E006 — エフェクトの分離：純粋な fn が effect fn を呼び出す

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E006.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E006.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E006.zh-CN.md)



> 原文: [E006.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E006.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

非エフェクト関数（`fn`）がエフェクト関数（`effect fn`）を呼び出そうとしました。Almide は型システムでエフェクトを追跡します。純粋な関数はエフェクトを持つ関数に依存できません。

## よくある例

```almide
effect fn read_text(path: String) -> String = ...

fn pure_fn() -> String = read_text("a.txt")    // E006: pure calls effect
```

## 診断（補足注記付き）

```
error[E006]: cannot call effect function 'read_text' from a pure function
  --> main.almd:3:25
  hint: Mark the calling function as `effect fn`, and propagate the call's error with `!`: `read_text(..)!` (the call's type is `Result[String, String]`)
  note: 'read_text' declared as effect fn here
        main.almd:1:1
```

補足の `note` は effect fn の宣言を指し、呼び出し先が制限される理由を確認できるようにします。

`effect fn` の呼び出しは失敗し得ます。Result ではない戻り型 `T` は `Result[T, String]` になり、宣言された `Result[T, E]` はエラー型を保持します（ADR-0002 §D6）。したがって、呼び出し元に印を付けるだけでは修正の半分です。`effect fn` 内での伝搬は明示的なので（ADR-0008）、呼び出しに `!` が必要です。呼び出しの `Result` をその `ok` 型として使いたい場合、ヒントは両方の手順を示します。同じ式が生じさせる `expected String but got Result[String, String]` は別には報告されません。このエラーに伴う残りの問題であり、`!` で修正できるためです（#3515）。呼び出しに対する `!`、`??`、`?`、`match` などがすでに `Result` を処理している場合、ヒントは呼び出し元を `effect fn` にする指定だけを示します。lambda 内の呼び出しには、lambda 固有のヒント（外側の関数に印を付ける）を維持します。

## 修正

- 呼び出し元を `effect fn` にし、呼び出しのエラーを伝搬します。
  ```almide
  effect fn pure_fn() -> String = read_text("a.txt")!
  ```
- またはエフェクト呼び出しを上位の `effect fn` に移し、計算済みの値を下位に渡します。
  ```almide
  effect fn setup() -> String = read_text("a.txt")!

  fn use_text(text: String) -> String = text        // stays pure
  ```
- 「effect fn」の呼び出し自体が誤りなら（純粋な変換のつもりで `fs.read_text` を呼んだ場合など）、呼び出しを修正します。

## 理由

エフェクト呼び出しは Result を伴います。Almide の伝搬は明示的です（`expr!`）。バックエンドはその印を実装しますが、ソースでの伝搬を暗黙にはしません。`fn` から `effect fn` を呼び出せると、エラー追跡が暗黙のうちに失われ、人間にも LLM にもエフェクトについて推論できなくなります。この境界は静的に強制されます。
