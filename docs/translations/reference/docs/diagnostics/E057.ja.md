# E057 — fn に本体がない

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E057.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E057.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E057.zh-CN.md)



> 原文: [E057.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E057.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

`= body` がない関数宣言です。

```
error[E057]: fn 'f' has no body
  hint: Write the body after '=': `fn f(...) -> T = expr` (or `= { ... }`).
        Only @extern / @intrinsic declarations may omit it
```

<a id="what-it-means"></a>

## 意味

構文解析器が本体なしの形式を残しているのは、`@extern` 束縛と `@intrinsic` ランタイム宣言という2系統に正当な用途があるためです（標準ライブラリの `= _` プレースホルダーも本体として解析されます）。通常の fn で `=` を省略すると、以前は検査器の本体照合分岐を完全にすり抜けていました。check は通り、未使用の宣言なら実行さえでき、最初の呼び出しでネイティブビルドが関数不足エラーにより失敗していました（受理の一致に関する問題。check は build が実現できないものをすべて拒否する必要があります）。

<a id="what-to-do"></a>

## 対処

- 本体 `fn f() -> Int = 42`、またはブロック `= { ... }` を書きます。
- 本当に Almide 外で実装する fn なら、`@extern(...)` と宣言します。`@intrinsic` は標準ライブラリ実装専用で、ユーザーの抜け道ではありません（[E085](../../../../diagnostics/E085.md) 参照）。ユーザーの本体 `= _` は型付きホールであり、外部実装ではありません。ネイティブで到達すると中止し、structural Wasm エミッターでは未対応です。

<a id="where-it-fires"></a>

## 発生箇所

検査中の宣言箇所で、何かが呼び出す前に発生します。
