# E036 — map_err 的 lambda 从不使用错误值（警告）

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E036.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E036.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E036.zh-CN.md)



> 原文：[`docs/diagnostics/E036.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E036.md)，固定提交 `9a95b285`。这是供读者参考的非规范性译文，CLI 诊断输出仍为英文。

传给 `map_err` 的 lambda 声明了具名错误参数，却从不读取它。替换后的消息通过类型检查（String → String），因此原始错误被静默销毁；这是添加上下文惯用写法中最常见的失误。

<a id="common-cases"></a>

## 常见情况

```almide
fs.read_text(p) |> result.map_err((e) => "loading config")     // E036
// Error: loading config          ← "No such file…" is gone
```

<a id="diagnostic"></a>

## 诊断

```
warning[E036]: map_err's lambda never uses the error value 'e' — the
               original error is silently discarded
  hint: interpolate it ((e) => "context: ${e}") or discard deliberately ((_) => …)
```

<a id="fix"></a>

## 修复

- 标准的上下文惯用写法将原始错误保留在末尾。
  ```almide
  fs.read_text(p) |> result.map_err((e) => "loading config: ${e}")
  ```
- 有意替换时，使用丢弃参数表达。
  ```almide
  fs.read_text(p) |> result.map_err((_) => "friendly message")
  ```

<a id="why"></a>

## 原因

错误上下文应是*链条*，而不是替换。嵌套调用产生 `starting server: loading config: No such file…`，读起来就是失败的来龙去脉。静默替换会在任意深度截断这条链。
