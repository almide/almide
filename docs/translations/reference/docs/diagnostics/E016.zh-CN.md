# E016 — 需要相等性或哈希的位置包含函数

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E016.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E016.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E016.zh-CN.md)



> 原文：[`docs/diagnostics/E016.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E016.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

包含函数（闭包）的类型位于要求相等性或哈希的位置：`Set` 元素、`Map` 的**键**，或 `==` / `!=` / `assert_eq` / `assert_ne` 的操作数。函数类型从不具有 Eq，也不可哈希（docs/specs/type-system.md）；包含函数的 Result、Option、列表、元组、记录或变体也一样，因此不能去重、查找或比较。

这在**两个**目标上都是硬错误。过去两者存在分歧：Rust 拒绝它（不满足 `Eq`/`Hash`），而 WASM 能编译，却静默丢弃每次插入（`Set[() ->
Unit]` 总是报告长度 0）。在类型检查时拒绝它，使两个目标保持一致。

闭包作为 `Map` 的**值**没有问题，只有键受约束。

比较形式过去会通过 `check`，却在生成的 Rust 中失败（`binary operation == cannot be applied to type
Rc<dyn Fn(..)>`，#2606）；现在在检查时就产生此错误。

## 常见情况

```almide
var handlers: Set[() -> Unit] = set.new()
set.insert(handlers, () => {})
// error[E016]: a `Set` element type cannot contain a function
```

```almide
var routes: Map[() -> Unit, String] = map.new()
// error[E016]: a `Map` key type cannot contain a function
```

```almide
fn make(n: Int) -> Result[(Int) -> Int, String] = if n > 0 then ok((x) => x + n) else err("neg")
test "t" { assert_eq(make(-1), err("neg")) }
// error[E016]: type 'Result[fn(Int) -> Int, String]' has no equality — assert_eq() cannot compare it
```

## 修复

比较时，比较该值允许观察的内容：标签、错误或函数的输出。

```almide
assert_eq(result.to_err_option(make(-1)), some("neg"))
assert(result.is_ok(make(2)))
```

对于 `Set` 或 `Map` 键，将闭包保存在 `List` 中（它不要求排序／哈希）：

```almide
var handlers: List[() -> Unit] = []
list.push(handlers, () => {})
```

如果确实需要 set/map 语义，使用可比较值（名称、id）作为键，并在其旁边存储闭包：

```almide
var handlers: Map[String, () -> Unit] = map.new()  // closure as VALUE — allowed
handlers = map.set(handlers, "on_click", () => {})
```

## Fix-it 判定

**not-fixable** — 错误报告的是自动改写无法判断的语义／设计问题。（`mechanical` = 无人值守的修复器可以应用改写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动改写。#1486 的适用性原则。）
