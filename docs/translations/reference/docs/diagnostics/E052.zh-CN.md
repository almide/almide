# E052 — 调用已弃用函数

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E052.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E052.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E052.zh-CN.md)



> 原文：[`docs/diagnostics/E052.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E052.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

调用指定了标记为 `@deprecated` 的函数。警告指出替代项，并说明编辑所需工作量；如果只是重命名，`almide fix` 会执行它。

```almide
@deprecated(since = 3, use = "shout")
fn yell(s: String) -> String = shout(s)

fn shout(s: String) -> String = s + "!"

effect fn main() -> Unit = println(yell("hi"))
//                                 ^^^^ E052: `yell` is deprecated since dialect 3
//                                 hint: Use `shout` — same signature — the name is the whole edit.
```

<a id="the-attribute"></a>

## 属性

```almide
@deprecated(since = N, use = "replacement")   // renamed or superseded
@deprecated(since = N, note = "why")          // removed with no successor
@deprecated(since = N, use = "...", note = "...")
```

- **`since`** 是 DIALECT EPOCH（`proofs/dialect-epochs.toml`），不是发布版本。它与文件的 `@dialect(N)` 标记使用同一单位，因此旧文件与其过时原因按同一尺度表述。
- **`use`** 指定替代项；来自其他模块时使用完全限定名（`string.trim_start`）。
- **`use`** 也可以指定运算符（`use = "??"`）：替换是调用形态改写（`option.unwrap_or(o, d)` → `o ?? d`，管道阶段 `o |> option.unwrap_or(d)` 也适用），由 `almide fix` 的 AST 系列执行——ADR-0005 D4。
- **`note`** 是自由文本。没有 `use` 时必填；两者都没有的弃用声明无法给调用者可操作信息，因此编译器会在声明处拒绝它。

格式不正确的 `@deprecated` 是声明处错误，而非静默无操作。需要防止的失败模式是作者以为调用者收到警告，实际却没有。

<a id="how-the-edit-is-classified"></a>

## 如何分类编辑

编译器通过比较两个签名来**推导**分类，而不是信任手写标记，因此替代项的类型日后变化时，会在下一次编译自动重新分类：

| 两个签名 | 提示 | `almide fix` |
|---|---|---|
| 相同（参数名称可以不同） | “相同签名——全部编辑就是名称” | **应用** |
| 任意参数类型、返回类型或 effect 属性不同 | “签名不同——检查参数” | 显示 `try:`，不应用 |
| 替代项在此不可见 | “替代项在此不可见” | 显示 `try:`，不应用 |
| 替代项是运算符（`use = "??"`） | “使用 `??` 运算符——`value ?? default`” | **应用**（两种调用形态的 AST 改写） |

只有第一行是 machine-applicable。跨签名变更自动应用改写会让 `almide fix` 造成错误编译，因此有意不自动应用，由读者进行编辑。

<a id="every-call-spelling-warns"></a>

## 每种调用写法都会警告

只要调用已弃用 fn 就会警告：直接调用（`list.length(xs)`）、管道阶段（`xs |> list.length`）以及方法形式（`xs.length()`，修复只把方法名改成 `xs.len()`）。无需 `import` 即可访问的标准库模块（`matrix`、`bytes`）与显式导入的模块一样会警告（#3085）。

标准库自身的同义名也按此方式弃用：`string.length`、`list.length`、`matrix.row_dot`、`matrix.concat_cols_many`。如果同一标准库模块中的两个公开 fn 是别名，却有多个仍有效，`tests/stdlib_synonym_gate_test.rs` 会失败。

<a id="why-this-exists"></a>

## 存在原因

Almide 的用户主要是代码生成器，模型会按它学过的 dialect 编写。只说“没有这个函数”的诊断需要整轮重试来猜测修复；指出替代项的诊断则是一次编辑即可应用的修复指令，如果编辑是机械性的，甚至无需手工编辑。这一差异就是语言优化的指标。
