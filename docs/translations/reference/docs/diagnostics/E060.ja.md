# E060 — import の整理（警告）

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E060.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E060.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E060.zh-CN.md)

何も役割を果たさない import です。インポートしたモジュールが一度も使われない、または同じモジュールが2つの名前で二重にインポートされています。

```
warning[E060]: unused import 'regex'
warning[E060]: module 'regex' is already imported as 'regex'
```

```almide
import regex                 // ← E060: nothing below mentions regex
import json
import json as j             // ← E060: json already has a name in this file

effect fn main() -> Unit = println(j.stringify(json.parse("1")!))
```

どちらもエラーではありません。プログラムは書かれたとおりの意味を持ちます。ただし、どちらも次の読み手を誤解させる残骸です。未使用 import はファイルにない依存を示し、重複 import は1つのモジュールに2つの名前を与えるため、同じ意味の2つの呼び出しが違うものに見えます。

修正は未使用の行を削除し、モジュールごとに名前を1つだけ残すことです。文書の例として残すなど、意図的に未使用とする import は、アンダースコア接頭辞 `import _regex` で警告を抑制できます。

## 使用と見なされるもの

判定は検査器が偶然解決したものではなく、ファイルの記述から行います。import の名前が修飾表記の先頭に現れると使用済みです。対象は呼び出し（`h.open()`）、コンストラクター（`m.Box { .. }`、`c.Red`）、型の位置（`-> g.Point`、引数、`let x: g.Point`、ジェネリック引数、プロトコルメソッドのシグネチャ）、パターン（`m.Some(x)`）、テストの `where` 上書きパスです。また、インポートされたモジュールが宣言するプロトコルを、制約や適合一覧に修飾なしで書いた場合（`fn go[S: Store]`、`type Mem: Store`）も該当します。プロトコルはモジュールをまたいで非修飾で解決されるので、表記に別名は現れず、宣言元モジュールを照合します。

標準ライブラリのモジュールが所有する型（`net` の `IpAddr`、`fs` の `FileStat`、`process` の `ProcessStatus`、`url` の `Url` など）も同様です。型を非修飾で書くこと — `fn f(a: IpAddr)`、`let xs: List[IpAddr]`、`FileStat { .. }` — またはそのコンストラクター（`V4(..)`）を使うことは、そばに `net.*` 呼び出しがあってもなくても、そのモジュールの import を使用したことになります（#1853）。型だけでもモジュールの宣言をプログラムに取り込むため、import は未使用ではありません。ファイル自身が宣言した型はそのファイルのものです（`type IpAddr = ..` は標準ライブラリの型を隠します、#1837）。その型の非修飾表記は import を使用せず、そばにある `import net` は引き続き警告されます。

自己モジュール import（`import self.ports`、`import self.helper as h`）も同じ規則で判定します（#1783）。0.62 より前は例外だったため、参照されなくても検査に通っていました。

パーサーが回復処理を必要としたファイル（何らかの構文エラーがある場合）には、未使用 import の判定を出しません。使用箇所だったかもしれないテキストが回復処理で失われ、構文エラーですでに診断されているためです。

## Fix-it 判定

**mechanical** — 未使用 import 行の削除は、無人の修正ツールが適用する純粋な表記変更です（`almide fix`）。重複の場合は表示専用のままです。重複行を消すとその別名への参照が取り残される可能性があり、行削除ではなく参照の書き換えが必要だからです。（`mechanical` = 無人の修正ツールが書き換えを適用可能、`conditional` = 提案された修正にレビューが必要、`not-fixable` = 自動書き換えは存在しません。#1486 の適用可能性の原則。）
