# E090 — `@extern(c)` 签名没有 C 表示

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E090.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E090.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E090.zh-CN.md)



> 原文：[`docs/diagnostics/E090.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E090.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

`@extern(c, "lib", "fn")` 绑定 C 函数。只有具有 C 形式的值能跨越该边界。对应表位于 `almide_lang::types::extern_abi`，checker 与 Rust renderer 都读取它：

| Almide | C 侧 | 注释 |
|---|---|---|
| `Int` | `int`（`i32`） | 双向都以 `as` 缩窄 |
| `Int8`..`Int64`、`UInt8`..`UInt64` | `i8`..`i64`、`u8`..`u64` | 相同宽度 |
| `Float` / `Float64`、`Float32` | `double`、`float` | |
| `Bool` | `int` | 传出为 `1` / `0`，传回为 `!= 0` |
| `Handle` | `*mut u8` | 不透明外部 token（`FILE*`、`sqlite3*`），只能传回 `@extern` fn |
| `Region`（参数） | `uint8_t *buf, size_t len` | 两个 C 参数：基址与 runtime 持有的长度，绝不是调用者手写的长度（[ADR-0031](../../../../adr/0031-raw-pointers-carry-provenance.md) D3） |
| `Region`（返回） | `uint8_t *` | 仅当声明有 `@region(len = …, release = "…")`（D2）；只读、长 `len` 字节的 Region，最后一份副本 drop 时由 `release` 释放（D6） |
| `String`（仅参数） | `*const u8` | 截至首个 NUL 的文本副本，以 NUL 终止，调用期间有效 |
| `Unit`（仅返回） | `void` | |

其他类型没有 C 形式，`mut` 参数也没有（C 无法把新值写回调用者的 `var`）。包括列表、`Bytes`、map、set、记录、变体、`Option`、`Result`、元组、fn 值，以及没有所有者负责释放的 `String` 返回值。这类声明过去能通过 `almide check`，随后 native 构建在 rustc 处失败，因为包装器把类型写成了 debug 文本。E090 在检查期报告该失败。

```almide
@extern(c, "c", "sum_all")
fn sum_all(xs: List[Int]) -> Int = _   // ← E090: parameter 'xs' has type List[Int]
```

```
error[E090]: @extern(c) fn 'sum_all': parameter 'xs' has type List[Int], which has no C representation
  hint: an @extern(c) parameter is one of Int, Int8..Int64, UInt8..UInt64, Float, Float32, Float64, Bool, String, Handle, Region;
        bind it through an `@extern(rust, "crate::host", "f")` fn in `native/*.rs` instead, …
```

表外返回类型会显示返回类型列表：

```
  hint: an @extern(c) return is one of Int, Int8..Int64, UInt8..UInt64, Float, Float32, Float64, Bool, Handle, Unit, and Region with `@region(len = …, release = "…")`; …
```

### `Region` 返回值需要长度

程序通过其读取的外部指针是 `Region`，声明是唯一能陈述长度的位置。没有 `@region(len = …, release = "…")`，返回值就产生 E090：

```almide
import ffi

@extern(c, "z", "zbuf_new")
fn zbuf_new(n: Int) -> Region = _   // ← E090: a Region return needs its length
```

```
error[E090]: @extern(c) fn 'zbuf_new': a Region return needs the length the foreign function returns
  hint: state it on the declaration: `@region(len = n, release = "free_fn")`, with `n` a parameter or an integer, and `free_fn` the C function that frees the buffer — or return `Handle` and read it through accessor functions (ADR-0031 D2)
```

`len` 指定整数类型参数名，或为非负整数字面量；`release` 是以字符串写出的 C 函数名。格式不正确的子句（`len` 不对应任何参数、缺少 `release`、未知参数，或在不返回 `Region` 的 fn 上使用 `@region`）也产生 E090。

## 修复

传递标量、`Handle` 和 `Region`，或通过 Rust 绑定。程序读取的外部缓冲区须声明长度：

```almide
import ffi

@extern(c, "z", "zbuf_new")
@region(len = n, release = "zbuf_free")
fn zbuf_new(n: Int) -> Region = _

@extern(c, "z", "zfill")
fn zfill(buf: Region, byte: Int) -> Unit = _   // C: void zfill(uint8_t *buf, size_t len, int byte)
```

不透明外部对象为 `Handle`，传回库自身的函数：

```almide
@extern(c, "sqlite3", "sqlite3_close")
fn db_close(db: Handle) -> Int = _
```

`@extern(rust)` fn 以普通 Rust 类型接收 Almide 值（`&[i64]`、`&[u8]`、`&str`、`&Record`、…；表见 [module-system.md §11.1](../../../../specs/module-system.md)）。其 `native/*.rs` 函数体可以转换这些值并自行调用 C 函数。

```almide
@extern(rust, "crate::host", "sum_all")
fn sum_all(xs: List[Int]) -> Int = _   // native/host.rs: pub fn sum_all(xs: &[i64]) -> i64
```

## Fix-it 判定

**not-fixable**：修复可能是新的 `@extern(rust)` shim 与 `native/*.rs` 中的宿主函数、不同的 C prototype，或外部缓冲区长度，这些只有绑定作者知道。仅凭声明无法确定任何一种。编译器指出有问题的类型与表，不改写签名。

检查适用于 native 构建实际绑定的属性，即第一个指定 `rust` / `rs` / `c` 的 `@extern`。
