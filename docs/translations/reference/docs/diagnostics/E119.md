# E119 — a Region lent to an `@export(c)` fn escapes its call

[![English](https://img.shields.io/badge/English-24292f?style=flat-square)](E119.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E119.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E119.zh-CN.md)

An `@export(c)` fn's `Region` parameter views its C caller's buffer, as
`(const uint8_t *ptr, size_t len)`, or `(uint8_t *ptr, size_t len)` for a
parameter named by `@region(out = p)`. The caller lends the buffer for the one
call and may free it as soon as the call returns. A copy of the Region must not
outlive the call (ADR-0031 amendment A2).

```almide
import ffi

var kept: Region = ffi.region(bytes.new())

@export(c, "keep")
fn keep(buf: Region) -> Int = {
  kept = buf   // ← E119
  ffi.len(buf)
}
```

```
error[E119]: a Region lent to @export(c) fn 'keep' escapes its call: it is stored in the top-level var `kept`
  hint: a lent Region views the C caller's buffer only for the call: copy what you need out with `ffi.read` / `ffi.to_bytes` and keep the Bytes (ADR-0031 amendment A2)
```

The check refuses each way a copy can leave the fn's body:

- stored in a top-level `var` (or a field or element of one);
- returned (the fn's return type holds a Region);
- captured by a closure;
- put into a container (`[buf]`, `some(buf)`, a record) or a slice
  (`ffi.slice(buf, 0, 4)!`) that then does one of the above.

It follows local `let` / `var` bindings and reads the checker's types, so
`let n = ffi.len(buf)` (an `Int`) is fine. It does not follow a call that
passes the Region to another fn. That case is caught at run time instead: the
wrapper stops the process if any copy is still held when the call returns.

## Fix

Copy the bytes you need, and keep the `Bytes`:

```almide
import ffi

var kept: Bytes = bytes.new()

@export(c, "keep")
effect fn keep(buf: Region) -> Int = {
  kept = ffi.read(buf, 0, ffi.len(buf))!
  ffi.len(buf)
}
```

## Fix-it verdict

**not-fixable**: which bytes to keep, and in what form, is a decision about the
program. (`mechanical` = an unattended fixer may apply the rewrite;
`conditional` = a suggested fix needs review; `not-fixable` = no automatic
rewrite exists. #1486's applicability doctrine.)
