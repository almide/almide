# E013 — レコード以外へのフィールドアクセス／フィールドの欠落

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E013.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E013.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E013.zh-CN.md)



> 原文：[`docs/diagnostics/E013.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E013.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

`.field` アクセスの対象は、そのフィールドを宣言していない型の値（またはそもそもレコードでない値）である。

## よくある例

```almide
type Point = { x: Int, y: Int }

let p = Point { x: 1, y: 2 }
let z = p.z                      // E013: no field `z` on Point

let n: Int = 42
let bad = n.value                // E013: Int has no fields
```

## 診断

```
error[E013]: no field `z` on type `Point`
  --> main.almd:4:9
  hint: Available fields on `Point`: x, y. Check spelling or verify the record type.
  in field access .z
```

型がレコードなら診断にフィールド一覧を示す。単独のメンバーアクセスと UFCS 呼び出しは別であり、`s.to_upper()` は関数として解決され得るが、`s.to_upper` はフィールドを要求する。

### 標準ライブラリ型と同名のユーザー型

```almide
import json
type Value = { n: Int }
let v = json.parse("{}")!
let n = v.n                      // E013: no field `n` on Value — the type has no fields
```

`json.parse` が返すのは標準ライブラリの `Value`。ユーザーの `type Value` は別の型（エントリープログラムでは `self.Value`、モジュール `m` では `m.Value`）であり、標準ライブラリの型を再束縛しない（#1828）。ヒントは両者を示す。「ここで `Value` は `value` モジュールの型であり、あなたの `type Value`（すなわち `self.Value`）ではない」。標準ライブラリの値はそのモジュール（`value.*`、`json.*`）を通じて読むか、自分の型を改名する。これは標準ライブラリ所有のすべての名前、`HttpRequest`、`HttpResponse`、`FileStat`、`ProcessStatus`、`Url`、`TcpStream`、`TcpListener`、`SafeHtml`、`IpAddr`、`Deque`、`Path` に適用され、宣言の形も問わない。OPAQUE alias（`mod type Value =
String`）は、同じ `self.Value` / `m.Value` という識別子の下でプログラムが所有する newtype である（#1835）。したがって json 値のフィールド読み取りは同じヒント付きの E013 となり、その newtype のパターン `Value(s)` を json 値に適用すると E048 となる。

## 修正

- 綴り：宣言したフィールド名を確認する。レコードは大文字と小文字を区別する。
- レコードの誤り：別の型に存在するフィールドを参照している可能性がある。`p` の宣言型が期待するフィールドと一致するか確認する。
- メソッド形式の誤用：`xs.head` / `s.length` はフィールドではなく、他言語のイディオムの持ち込みである。`list.first(xs)` / `string.len(s)` に書き換える。型に基づく正確なプロパティから関数への書き換えは machine-applicable となり得るが、曖昧一致のフィールド名提案には依然としてレビューが必要。

## 理由

レコードフィールドとタプル添字（`.0`、`.1`、...）は値へのアクセスである。括弧付きのメソッド形式呼び出しは UFCS 解決を使い、暗黙のプロパティ読み取りではない。意図が明確になる場合は `module.function(value)` を使う。
