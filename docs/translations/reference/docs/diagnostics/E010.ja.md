# E010 — 網羅的でない match

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E010.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E010.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E010.zh-CN.md)



> 原文: [E010.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E010.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

`match` 式が対象の取り得るすべての場合をカバーしていません。

<a id="common-cases"></a>

## よくある例

```almide
type Color = | Red | Green | Blue

fn name(c: Color) -> String =
    match c {
        Red   => "red",
        Green => "green",
        // E010: missing Blue
    }
```

```almide
let o: Option[Int] = some(5)
match o {
    some(n) => n,
    // E010: missing `none`
}
```

<a id="diagnostic"></a>

## 診断

```
error[E010]: non-exhaustive match: missing `Blue`
  --> main.almd:4:5
  hint: add an arm for `Blue`, or use `_ => ...` to cover the rest
  in match
```

診断は不足している具体的なコンストラクターの名前を列挙します。

<a id="fix"></a>

## 修正

- 不足する arm を明示的に追加します。
  ```almide
  match c {
      Red   => "red",
      Green => "green",
      Blue  => "blue",          // added
  }
  ```
- 最後の arm にワイルドカード `_` を使い、残りすべての場合をカバーします。
  ```almide
  match c {
      Red => "red",
      _   => "other",
  }
  ```
- `Option[T]`：`some(x) => ...` + `none => ...`
- `Result[T, E]`：`ok(x) => ...` + `err(e) => ...`
- `List[T]`：`[] => ...` + `[head, ..tail] => ...`、または最後に `_ => ...` の arm。リストの残りの要素に一致するパターンに対応しています。

<a id="why-exhaustive"></a>

## 網羅性を求める理由

網羅性はリファクタリング時の誤りを検出します。`Color` に新しいバリアントを追加すると、`_` を使っていないすべての `match` がコンパイルに失敗するようになり、新しい場合の扱いを決める必要が生じます。これが「modification survival rate」の実践的な意味です。新しい値を暗黙のうちに無視しないコードになります。
