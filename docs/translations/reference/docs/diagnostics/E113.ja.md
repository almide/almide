# E113 — match が複雑すぎて網羅性を検査できない

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E113.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E113.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E113.zh-CN.md)



> 原文：[`docs/diagnostics/E113.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E113.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

1つの `match` の網羅性・到達可能性検査が、`exhaustiveness_steps` コンパイルコスト予算（ADR-0030）を超えた。パターン集合がすべての値を覆うかの判定は、最悪の場合に指数的となる。`Bool` のタプルで、arm が各列について `true` と `false` の両方を指定すると、検査は列ごとに2つへ分岐する。

```almide
fn f(a: Bool, b: Bool, c: Bool /* … 24 more */) -> Int = match (a, b, c /* … */) {   // ← E113
  (true, _, _ /* … */) => 0,
  (_, true, _ /* … */) => 1,
  // … one arm per column and constructor
}
```

<a id="fix"></a>

## 修正

match を分割する。最初の要素で match し、その各 arm 内で残りに match するか、残る場合をまとめて扱う `_ =>` arm を追加する。

<a id="why"></a>

## 理由

コンパイラは信頼できないソースを処理するため、検査はタイムアウトではなく、回数を数える予算で制限する。同じ match はどのマシンでも同じ判定になる。検査を完了できない match を網羅的とはみなさない。ソースから予算を引き上げることはできないが、コマンドラインの `--budget exhaustiveness_steps=N` では変更できる（`almide budgets`）。

フィクスチャ：`tests/diagnostics/e113-{bool,option,variant}-matrix-too-complex`。ゲートは `tests/compile_budget_test.rs`。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**not-fixable**：match の分割方法はプログラムに関する判断である。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
