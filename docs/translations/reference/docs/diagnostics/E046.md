# E046 — placeholder `_` in a call argument

[![English](https://img.shields.io/badge/English-24292f?style=flat-square)](E046.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E046.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E046.zh-CN.md)

`_` in a call ARGUMENT slot is not a value and never becomes one. It parses
(`ExprKind::Placeholder`), but lowering has nothing to put there and turns it
into `Unit`, so `add(_, 10)` used to check clean ("No errors found") and then
die at build with

```
codegen produced invalid Rust — this is an Almide bug.
error[E0308]: mismatched types
    let v: i64 = add((), 10i64);
                     ^^ expected `i64`, found `()`
```

— the compiler blaming itself for a user error, the same failure mode E045
closed for tuple indexing (#1266). It is a check-time error now.

```almide
fn add(a: Int, b: Int) -> Int = a + b

let v = add(_, 10)        // ← E046: argument 1 of add()
let w = 5 |> add3(_, 10)  // ← E046 on the pipe path too
```

## This is NOT partial application

Almide has no `_`-section syntax, and the placeholder never behaved like one.
Measured on the pre-fix compiler:

- `let v = add(_, 10)` typed `v` as add's **return** type (`i64`), not as a
  function — the emitted Rust was `let v: i64 = add((), 10i64)`.
- In pipe position the `_` counts as an **extra positional argument**:
  `5 |> add(_, 10)` is E004, "add() expects 2 argument(s) but got 3". A callee
  with one more parameter (`5 |> add3(_, 10)`) absorbed the extra argument and
  reached codegen — that shape is what made this a silent build-time crash
  rather than a merely confusing one.

## Fix

Name the missing value with a lambda — the construct that actually expresses
"supply this one later":

```almide
let f = (x) => add(x, 10)
let v = f(5)

xs |> list.map((x) => add(x, 10))
```

## Not to be confused with a typed hole

`_` in EXPRESSION position is a different, sanctioned construct: a **typed
hole** that takes whatever type the context demands, lets the rest of the
program type-check, and panics if execution reaches it.

```almide
fn compute(x: Int) -> Int = _                  // typed hole — checks, panics
fn compute(x: Int) -> Int = todo("no impl")    // same, with your own message
```

Those are not E046. See [docs/CHEATSHEET.md](../../../../CHEATSHEET.md).

## Fix-it verdict

**conditional** — the lambda parameter's name and arity are intent. (`mechanical` = an unattended fixer may apply the
rewrite; `conditional` = a suggested fix needs review; `not-fixable` = no
