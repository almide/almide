# E082 — --target wasm の wasm 経路でプログラムを lower できない

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E082.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E082.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E082.zh-CN.md)



> 原文：[`docs/diagnostics/E082.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E082.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

`--target wasm` のエンジンは structural 経路（`crates/almide-wasm`）一つ。E082 は、選択した経路、標準 WASI ビルド（`almide build`）または組み込みホスト（`almide run`）でプログラムを**拒否した**ことを意味する。理由はエラー行と機械可読の `wall:` 行に表示し、原因の関数は `-->` 行に示す（#2807）。ビルド経路では例えば：

- emitter が lower しない形（`expr:Todo` — `todo("later")` のような typed hole。到達可能かによらず意図して拒否する、C-268）。
- p1 `to_wasi` shim に標準 WASI サービスがない出力済み host op（`host op N has no stock-WASI service`。fs op は #2742 以降そこで提供される）。
- 宣言された `@export(wasm, "sym")` の本体を lower できない場合や、二つの export が同じ名前を要求する場合。エントリーファイルでもリンクされたモジュールでも、成果物内の任意のモジュールが対象（#3281）。
- ジェネリック fn に宣言された `@export(wasm, "sym")`。wasm export には一つの具体的なシグネチャが必要なので、ジェネリック関数を呼ぶ非ジェネリック関数を export する（#3285）。

#2752 までは structural 経路が拒否したプログラムを第二の renderer（既存の v1 経路）に渡し、E082 は両方が拒否したことを意味した（#1922）。そのフォールバックはなくなった。第二の経路はなく、拒否が判定の全体であり、renderer を黙って切り替えることはない。コード番号は保持する（以前 E082 だったプログラムは今も E082。以前フォールバックが処理していたものも今は E082）。

```text
error[E082]: the wasm target cannot lower this program: expr:Todo
  --> in fn `later` (entry file, line 1)
  note: this is the stock-WASI BUILD route; `almide run --target wasm` (the embedded host serves every op) may still run it
  note: `almide check --target wasm` reports this verdict at check time; the native target (`--target rust`) is unaffected
wall: expr:Todo
```

`almide check --target wasm` はビルドせず同じ経路を動かし、検査時に E081 / E082 を報告する。宣言表ではなくビルド経路自体で計測するため、`build` の動作と乖離しない。ビルド経路の注記では、プログラムを実行できる可能性のある経路として組み込みホストを示す（shim は全 op を提供するため、残る要因は構造上の壁）。この wasm 固有の拒否は、独立した `--target rust` ビルドの成否を立証するものではない。

## Fix-it 判定

**not-fixable** — 修正はプラットフォームの判断（組み込みホスト経由で実行、native 実行、壁となる構造の再構成）であり、無人の修正ツールが適用する書き換えではない。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
