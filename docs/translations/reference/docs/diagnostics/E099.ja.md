# E099 — test ブロック内の直接呼び出し以外での `testing.assert_aborts`

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E099.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E099.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E099.zh-CN.md)



> 原文: [E099.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E099.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

`testing.assert_aborts(expected, f)` は、`f` を子プロセスまたは新しいインスタンスで動かすテスト表明です（ADR-0029）。呼び出し箇所が子で実行するクロージャを特定し、テストハーネスが判定を報告するため、呼び出しは `test` ブロックに直接書く必要があります。その中の `if`、`match`、`for`、lambda に入れ子にするのは問題ありません。次の3つの形は拒否されます。

- `fn`（テストが呼ぶヘルパーも含む）、`main`、トップレベルの `let` 内の呼び出し。プログラムには報告先のハーネスがなく、中止したいプログラムはそのまま中止します。

  ```almide
  import testing

  fn check_aborts() -> Unit = testing.assert_aborts("boom", () => panic("boom"))   // ← E099
  ```

- 呼び出し箇所を隠してしまう第一級値としての使用。

  ```almide
  import testing

  test "a panic aborts" {
    let check = testing.assert_aborts                          // ← E099
    check("boom", () => panic("boom"))
  }
  ```

- 別の `assert_aborts` クロージャ内での呼び出し。そのクロージャはすでに子側で動いており、孫が必要になってしまいます。

<a id="diagnostic"></a>

## 診断

```
error[E099]: testing.assert_aborts is called outside a test block
  in a call of testing.assert_aborts
  hint: assert_aborts runs only in a test: move the call into a `test "…" { }` block. A program that wants to abort just aborts.
```

<a id="fix"></a>

## 修正

中止1回ごとに、テスト内で直接呼び出します。

```almide check
import testing

test "a panic aborts" {
  testing.assert_aborts("boom", () => panic("boom"))
  testing.assert_aborts("index out of bounds", () => [1][3])
}
```

<a id="fix-it-verdict"></a>

## Fix-it 判定

**conditional** — 呼び出しはテストブロックに属すべきですが、どのテストか、ヘルパーの呼び出しを各テスト箇所での1回の呼び出しにするかは作者の選択です。（`mechanical` = 無人の書き換え、`conditional` = 修正案にレビューが必要、`not-fixable` = 自動書き換えは存在しません。#1486 の適用可能性の原則。）
