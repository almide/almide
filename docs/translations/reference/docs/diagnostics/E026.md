# E026 — cannot index a String with `[]`

[![English](https://img.shields.io/badge/English-24292f?style=flat-square)](E026.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E026.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E026.zh-CN.md)

A `String` is a sequence of UTF-8 codepoints, not a byte or character array, so
it has no `[]` element-indexing. Writing `s[i]` used to type-check as `Unknown`
(the checker had no `String` case for index access), so `check` passed and both
backends then emitted a `[COMPILER BUG] unresolved IndexAccess` blamed on the
user. It is now rejected at check time.

```almide
fn main() -> Unit = {
  let s = "hello"
  println(s[1])            // ← E026
}
```

## Fix

Use the codepoint-indexed stdlib accessors:

```almide
let c = string.get(s, 1) ?? ""   // Option[String] — empty if out of range
```

Range slicing is supported and unaffected: `s[0..<3]` yields a substring.

## Fix-it verdict

**conditional** — codepoint access with string.get vs byte access depends on what the index meant. (`mechanical` = an unattended fixer may apply the
rewrite; `conditional` = a suggested fix needs review; `not-fixable` = no
automatic rewrite exists. #1486's applicability doctrine.)
