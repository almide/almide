# E035 — エラーメッセージの文字列で分岐している（警告）

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E035.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E035.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E035.zh-CN.md)



> 原文：[`docs/diagnostics/E035.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E035.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

分岐条件が err パターンの束縛を文字列の内容と比較している（`string.contains(e, …)`、`e.contains(…)`、`e == "…"`）。エラーメッセージの文字列は人間向けの報告であり、プログラム向けの API ではない。文言が変わると、分岐が黙って一致しなくなる。

これは、Go が本番環境で10年にわたり `strings.Contains(err.Error(), …)` を使った末、`errors.Is`/`errors.As` を後付けせざるを得なくなったパターンである（ADR-0004 の原則）。

## よくある例

```almide
match fs.read_text(p) {
  ok(t)  => ok(t),
  err(e) =>
    if string.contains(e, "No such file")   // E035
    then ok(default) else err(e),
}
```

## 診断

```
warning[E035]: branching on the text of an error message
  hint: define a variant error type and match on it (ADR-0004);
        for a kind-independent fallback use ??
```

## 修正

- **種類に依存しない代替値**：エラーを一切読まない。
  ```almide
  fs.read_text(p) ?? default
  ```
- **独自のドメイン**：バリアントのエラー型を定義し、構造で分岐する（ADR-0003 D1）。
  ```almide
  type LoadError = | NotFound(String) | Other(String)
  match load(p) { err(NotFound(_)) => …, err(Other(m)) => …, ok(v) => … }
  ```
- **標準ライブラリでの不在確認**：不在の場合に `none` を返す `*_if_exists` 読み取り関数（`fs.read_text_if_exists`、#1106）を使う。

## 理由

契約で固定されたメッセージは、almide での文字列マッチングを安全に*見せる*。しかしユーザーコードが文言に依存すると、診断の改善がすべて破壊的変更になってしまう（Hyrum freeze）。この lint は、回避手段（`??`、バリアント E、Option を返す API）だけを表記として残す。
