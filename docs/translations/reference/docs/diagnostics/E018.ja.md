# E018 — 要素型を推論できない空コレクション

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E018.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E018.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E018.zh-CN.md)



> 原文：[`docs/diagnostics/E018.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E018.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

空コレクションのリテラル（`[]`、`[:]`）、または要素を含む引数を取らないジェネリックなコレクションコンストラクター（`set.new()`、`map.new()`、`list.with_capacity(n)`）が、**周囲の文脈から要素型を確定できない位置**で使われている。空コレクションには推論の元となる要素がないため、要素型を決定できない。

Almide は **Rust と Swift** に従う。型を決定できない空コレクションは、明示的な型注釈を要求するコンパイルエラーとなり、任意の要素型へ黙って既定化されることはない。Rust/Swift と同じく、観測可能性は関係しない。要素を一度も読まなくても `for _ in []` はエラーとなる。

コード生成前のフロントエンド型チェッカーで報告するため、**両方**のターゲットで必ずエラーとなる。以前は挙動が分かれ、Rust は生成された `Vec::<_>::new()` で `rustc` の `error[E0282]: type annotations needed` を「Almide bug」として漏出させたが、要素型を持たない WASM はコンパイル・実行された。型検査時に拒否することで両ターゲットを一致させ、対処可能なメッセージを出す。

<a id="common-cases"></a>

## よくある例

```almide
let n: Int = list.len([])            // element of `[]` never constrained
let c: Int = set.len(set.new())      // element of the set never constrained
for _ in [] { }                      // iterated element type undecidable
```

```text
error[E018]: cannot infer the element type of empty list `[]`
```

<a id="fix"></a>

## 修正

要素型を注釈する。最も確実なのは型付き束縛である。

```almide
let xs: List[Int] = []
let n: Int = list.len(xs)

let s: Set[Int] = set.new()
let c: Int = set.len(s)

let empty: List[Int] = []
for _ in empty { }                   // for over an explicitly-typed list
```

呼び出し引数の位置にある単独のリストリテラルには、インラインで注釈することもできる。

```almide
let n: Int = list.len([]: List[Int])
```

空コレクションがフィールド値、フィールドの既定値、または代入である場合は、宣言されたフィールド／変数の型から要素型を取得するため、追加の注釈は不要である。

```almide
type Bag = { items: List[Int] }
let b = Bag { items: [] }            // element inferred as Int from the field
```

<a id="fix-it-verdict"></a>

## Fix-it 判定

**conditional** — 要素型の注釈は意図からしか判断できない。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
