# E119 — 借给 `@export(c)` fn 的 Region 逃逸出该次调用

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E119.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E119.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E119.zh-CN.md)



> 原文：[`docs/diagnostics/E119.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E119.md)，固定提交 `9a95b285`。这是供读者参考的非规范性译文，CLI 诊断输出仍为英文。

`@export(c)` fn 的 `Region` 参数以 `(const uint8_t *ptr, size_t len)` 形式查看 C 调用方的缓冲区；由 `@region(out = p)` 指定的参数则是 `(uint8_t *ptr, size_t len)`。调用方只为这一次调用借出缓冲区，调用返回后即可立即释放。Region 的副本不得活得比该次调用更久（ADR-0031 amendment A2）。

```almide
import ffi

var kept: Region = ffi.region(bytes.new())

@export(c, "keep")
fn keep(buf: Region) -> Int = {
  kept = buf   // ← E119
  ffi.len(buf)
}
```

```
error[E119]: a Region lent to @export(c) fn 'keep' escapes its call: it is stored in the top-level var `kept`
  hint: a lent Region views the C caller's buffer only for the call: copy what you need out with `ffi.read` / `ffi.to_bytes` and keep the Bytes (ADR-0031 amendment A2)
```

检查会拒绝副本离开 fn 函数体的各种方式：

- 存入顶层 `var`（或其字段／元素）；
- 返回（fn 的返回类型持有 Region）；
- 被闭包捕获；
- 放入容器（`[buf]`、`some(buf)`、记录）或切片（`ffi.slice(buf, 0, 4)!`），随后发生上述任一行为。

它跟踪本地 `let` / `var` 绑定并读取检查器的类型，因此 `let n = ffi.len(buf)`（一个 `Int`）没有问题。它不跟踪把 Region 传给另一个 fn 的调用；该情况改由运行时捕获：调用返回时若仍持有任何副本，包装器会停止进程。

<a id="fix"></a>

## 修复

复制所需字节，并保留 `Bytes`。

```almide
import ffi

var kept: Bytes = bytes.new()

@export(c, "keep")
effect fn keep(buf: Region) -> Int = {
  kept = ffi.read(buf, 0, ffi.len(buf))!
  ffi.len(buf)
}
```
