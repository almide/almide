# E093 — 类型实参数量不正确

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E093.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E093.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E093.zh-CN.md)



> 原文：[E093.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E093.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

带方括号的类型（`Pair[Int]`、`Cell[Int, String]`）为声明中的每个参数传入一个类型。数量不同没有意义：要么多出的实参没有可替换的字母，要么某个字母没有对应值。过去这会静默通过 `almide check`：多余实参被丢弃，或泛型别名保持为不透明名称，随后元组索引或列表调用以无关错误拒绝它。因此 E093 在类型书写处报告数量。

```almide
type Pair[T] = (T, T)

fn first(p: Pair[Int, Int]) -> Int = p.0   // ← E093: 'Pair[T]' takes 1 type argument, but is applied to 2
```

它适用于所有已声明类型：泛型别名、泛型记录或变体，以及未声明参数、因而不接受类型实参的类型：

```almide
type Score = Int

fn bump(s: Score[Int]) -> Score = s + 1    // ← E093: 'Score' takes no type arguments, but is applied to 1
```

内置泛型类型以同样方式计数（#3408）：`List`、`Option` 和 `Set` 接受一个实参，`Map` 和 `Result` 接受两个，内置标量（`Int`、`String` 等）不接受实参。数量来自解析器的内置表，即识别内置类型名称的唯一位置：

```almide
fn total(xs: List[Int, Int]) -> Int = 0     // ← E093: 'List[T]' takes 1 type argument, but is applied to 2

type Index = { names: Map[String] }          // ← E093: 'Map[K, V]' takes 2 type arguments, but is applied to 1
```

不带方括号的写法不是类型应用，绝不会触发 E093。

## 修复

为每个声明参数写一个类型——消息会列出声明（`Pair[T]`）——或对无参数类型去掉方括号：

```almide
type Pair[T] = (T, T)

fn first(p: Pair[Int]) -> Int = p.0
```

透明泛型别名在应用正确数量的实参后，就是将各实参代入的本体（`Pair[Int]` 是 `(Int, Int)`），正如非泛型别名就是其本体；见 `docs/specs/language.md` 的“Type Alias”。

## Fix-it 判定

**not-fixable** — 哪个实参多余、缺失的实参本来用于哪个参数，属于作者意图；消息指出声明参数，不会重写注解。
