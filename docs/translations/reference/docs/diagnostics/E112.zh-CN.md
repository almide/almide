# E112 — 泛型实例过多

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E112.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E112.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E112.zh-CN.md)



> 原文：[`docs/diagnostics/E112.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E112.md)，固定提交 `9a95b285`。这是供读者参考的非规范性译文，CLI 诊断输出仍为英文。

单态化超出了 `generic_instances` 编译成本预算（ADR-0030）：程序需要的带协议约束的泛型 fn 特化实例，比编译器为一个程序构造的数量更多；或者某实例的类型实参超出了 `type_size` 预算。导致这一问题的形式，是一串泛型 fn，每个都把更大的类型实参传给下一个；每一步产生新实例，每个实例的类型又比上一个更大。

```almide
fn l0[T: Hash](x: T) -> Int = l1((x, x))
fn l1[T: Hash](x: T) -> Int = l2((x, x))
// … twelve steps: the last instance's type has 2^12 leaves
```

<a id="fix"></a>

## 修复

继续传递同一类型：将值收集在列表中，或用 `Int` 统计步骤数。

<a id="why"></a>

## 原因

预算加入前，单态化在1000个实例时发出警告并停止，然后以不完整程序继续执行（模块泛型循环甚至完全没有上限）。和所有编译成本预算一样，这个数值是计数得到的，源码不能提高它，而命令行上的 `--budget generic_instances=N` 可以（`almide budgets`）。

测试样例：`tests/diagnostics/e112-instance-doubling-through-*`（使用会执行链接的路径 `almide check --target wasm` 检查）。
