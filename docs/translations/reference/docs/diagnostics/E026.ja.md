# E026 — `[]` で String にインデックスアクセスできない

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E026.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E026.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E026.zh-CN.md)



> 原文: [E026.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E026.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

`String` は UTF-8 コードポイントの列であり、バイト配列や文字配列ではないため、`[]` による要素アクセスはありません。以前は `s[i]` が `Unknown` として型検査を通過していました（検査器のインデックスアクセス処理に `String` の場合がありませんでした）。そのため `check` は通り、その後両バックエンドがユーザーに責任を帰す `[COMPILER BUG] unresolved IndexAccess` を出していました。現在は検査時点で拒否します。

```almide
fn main() -> Unit = {
  let s = "hello"
  println(s[1])            // ← E026
}
```

## 修正

コードポイント単位でインデックスを指定する標準ライブラリのアクセサーを使います。

```almide
let c = string.get(s, 1) ?? ""   // Option[String] — empty if out of range
```

範囲スライスは対応済みで、影響を受けません。`s[0..<3]` は部分文字列を返します。

## Fix-it 判定

**conditional** — string.get によるコードポイントアクセスかバイトアクセスかは、インデックスの意図によります。（`mechanical` = 無人の修正ツールが書き換えを適用可能、`conditional` = 提案された修正にレビューが必要、`not-fixable` = 自動書き換えは存在しません。#1486 の適用可能性の原則。）
