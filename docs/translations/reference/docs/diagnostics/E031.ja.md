# E031 — 廃止された範囲の表記

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E031.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E031.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E031.zh-CN.md)



> 原文：[`docs/diagnostics/E031.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E031.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

Rust 形式の範囲演算子は、意味が表記に現れる Swift の組に置き換えられた（#966）。`..<` は終端を含まない範囲、`...` は終端を含む範囲である。旧表記 `..` / `..=` は、machine-applicable な fix-it を伴う診断エラーとなる。`..` と `..=` の1文字の違いは、どちらの方向にも気づかず取り違えられたが、`..<` は `<` を表記自体に含む。

```almide
fn main() -> Unit = {
  var s = 0
  for i in 0 .. 5 { s = s + i }     // ← E031: '..' was retired, write '..<'
  for j in 1 ..= 3 { s = s + j }    // ← E031: '..=' was retired, write '...'
  println(int.to_string(s))
}
```

## 修正

```almide
fn main() -> Unit = {
  var s = 0
  for i in 0 ..< 5 { s = s + i }    // end-exclusive: 0,1,2,3,4
  for j in 1 ... 3 { s = s + j }    // end-inclusive: 1,2,3
  println(int.to_string(s))
}
```

`almide fix <file>` を実行すると、ファイル中のすべての範囲を機械的に移行できる。適用するのは演算子の書き換えだけで、他は変更しない。

E031 は、他の位置で拒否される `..` / `..=` についても説明する。範囲パターンと範囲型は存在しない。match では個別の arm または guard を、型注釈では `List[Int]` のような要素型を指定した型を使う。呼び出しは引数スプレッドに対応していない。リスト式は `xs + [item]` で結合できる。これらの形式には自動書き換えがない。`..rest` はリストパターンの最後の位置（`[head, ..tail]`）では引き続き有効である。

残る用途に注意：`..` はレコードの残余マーカーとして有効（パターンと開いたレコード型での `{ x, .. }`。式の位置では使えない）。また `...` はレコード／リストのスプレッド（`{ ...base, x: 1 }`）にも使う。前置ならスプレッド、中置なら終端を含む範囲を意味する。

## Fix-it 判定

**mechanical** — 範囲演算子の表記変更（`..<` / `...`）は正確である。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
