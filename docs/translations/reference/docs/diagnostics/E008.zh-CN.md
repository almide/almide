# E008 — 并发执行的主体可触及 `var`

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E008.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E008.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E008.zh-CN.md)



> 原文：[E008.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E008.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

可能与自身其他调用同时执行的主体，读取或写入了在其外部声明的 `var`。并发主体包括：

- `fan { … }` 块的每个分支，以及 `fan.settle`、`fan.min`、`fan.bounded` 和 `fan.timeout` 块形式的每个分支；
- `fan.map`、`fan.settle` 和 `fan.min` 的每个函数值参数；
- 传给 `http.serve`、`http.route`、`http.mount` 和 `http.wrap` 的处理器（处理器和中间件）；
- 自己编写的函数中，继续传给上述任一位置的参数（`fn serve_on(port: Int, h: HttpHandler) = http.serve(port, h)` 使 `h` 成为 `serve_on` 的处理器参数位置，检查随之转移到其调用方）。

“触及”会沿主体能够运行的内容追踪：它调用的函数、从 `let` 读取的闭包（局部或顶层，包括保存在记录和列表中的闭包），以及工厂返回的闭包。在主体内或其调用的函数内声明的 `var` 属于单次调用，因此没有问题。直接传给 `list.map` 等标准库回调的 lambda 在包含它的主体内运行，所以可以使用该主体的 `var`。

<a id="common-cases"></a>

## 常见情况

```almide
effect fn broken() -> Int = {
  var count = 0
  fan {
    count = count + 1         // E008: the arm reaches `count`
    count = count + 2
  }
  count
}
```

```almide
import http

var hits = 0

effect fn bump() -> Int = {
  hits = hits + 1
  hits
}

// E008: the handler reaches `hits` through `bump`
let app = http.router([http.route("GET /", (req) => http.response(200, "n=${bump()!}"))])

effect fn main() -> Unit = http.serve(8080, app!)!
```

<a id="diagnostic"></a>

## 诊断

```
error[E008]: cannot capture mutable variable 'count' inside fan block
  hint: Use a `let` binding instead of `var` for values shared across fan expressions
```

```
error[E008]: this fan.map callback can reach `total`, a `var` — fan bodies run concurrently
  in the callback passed to fan.map
  hint: return each element's contribution and combine the results after the fan, e.g. `fan.map(xs, f)! |> list.sum`, or bind a `let` copy of the value before the fan
```

```
error[E008]: this handler can reach `hits`, a `var` — handlers run concurrently
  in the handler passed to http.route (reached through fn `bump` at line 5)
  hint: a handler cannot share mutable state between requests. For a value fixed before serving, use a top-level `let` instead of `var`, or bind a `let` copy before the handler
```

上下文会指出位置；如果经由其他函数触及 `var`，还会指出到达它的路径。如果 `var` 从未在任何位置被赋值，提示会先说明这一点：将其声明为 `let` 就是完整的修复。

<a id="fix"></a>

## 修复

- 独立计算每个分支或元素，然后在 fan 之后汇总结果：
  ```almide
  effect fn fixed() -> Int = {
    let (a, b) = fan {
      compute_a()
      compute_b()
    }
    a + b
  }
  ```
- 对于主体只读取的值，在该位置之前绑定一个 `let` 副本（`let scale = scale0`）；在主体外取得的 `let` 是快照。
- 服务开始前固定的值应当是顶层 `let`，而不是 `var`。在 main 内创建 `let` 副本无法帮助用于服务的处理器：传给 `http.serve` 的应用不能读取 main 的任何局部变量（E095）。

<a id="why"></a>

## 原因

对同一 `var` 的并发写入会产生顺序未定义的更新，读取也会与之竞争。Almide 在检查器中拒绝这种模式，而不是输出存在竞争的代码，因此 fan 或服务器的执行基底可以变化，而不改变程序含义。从并发主体读取 `let` 绑定始终是安全的；只有 `var` 受到限制。该规则属于 dialect epoch 6（`proofs/dialect-epochs.toml`）；在此之前，只有 `fan { … }` 分支直接捕获 `var` 才会触发 E008。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**conditional** — 如果触及的 `var` 从未被赋值，将其声明为 `let` 就是修复；否则必须将状态移出并发主体，需要审查。（`mechanical` = 无人值守的修复器可以应用重写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）
