# E102 — an invalid pattern in `regex.new`

[![English](https://img.shields.io/badge/English-24292f?style=flat-square)](E102.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E102.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E102.zh-CN.md)

`regex.new("…")` makes a `Regex` from a pattern the program knows is valid.
When the pattern is a string literal, `almide check` checks it with the
regex engine's own checker and refuses it when the engine would: the same
pattern built at run time aborts with `Error: invalid regex: <reason>`
(C-395). The reasons are the ones `regex.compile` answers in its err:
`unclosed group`, `unmatched )`, `unclosed character class`,
`nothing to repeat`, `malformed repetition`,
`repetition minimum exceeds maximum`, `invalid class range`,
`trailing backslash`, `unsupported escape \X` (and `… in a class`),
`named groups are not supported`, `lookaround is not supported`,
`flags are only supported at the start of the pattern`,
`unsupported group syntax`, `groups nested deeper than 250`, and
`pattern too large: more than 20000 states`.

```almide
import regex

fn main() -> Unit = println("${regex.is_match(regex.new("(a|b"), "abc")}")   // ← E102
```

```
error[E102]: invalid regex: unclosed group
  hint: write the pattern in the syntax docs/stdlib/regex.md lists; a pattern built at run time goes through regex.compile, which answers err(reason) instead of aborting
```

## Fix

1. Write the pattern in the syntax [docs/stdlib/regex.md](../../../../stdlib/regex.md)
   lists: close the group or class, escape a metacharacter meant literally
   (`regex.escape` does it for a string), number groups instead of naming them.
2. A pattern too large has more than 20,000 Pike VM states: nested counts
   multiply (`((a){200}){200}` is 40,000 copies of `a`). Match the shape
   instead of counting it out, or check the count in code.
3. A pattern that comes from input belongs in `regex.compile(p)`, which
   answers `err(reason)` and lets the program decide.

## Fix-it verdict

**not-fixable**: whether a refused character was meant literally (escape it)
or as syntax the engine does not have (rewrite the pattern) is the writer's
choice, and a pattern past the state limit needs a different pattern. The
diagnostic names the reason; it does not rewrite the code. (`mechanical` = an
unattended rewrite; `conditional` = a suggested fix needs review;
`not-fixable` = no automatic rewrite exists. #1486's applicability doctrine.)

## Why

The engine used to read a pattern outside its grammar leniently: `(` was an
empty group that matched everywhere, `a{` a literal brace, `(?P<n>a)` an
ordinary group of `P<n>a`. Each answered something nobody wrote, with no
error (#3942). A pattern written in the program is refused before it runs.
