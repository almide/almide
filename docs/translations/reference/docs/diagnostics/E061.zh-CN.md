# E061 — 顶层 `let` 绑定到函数值

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E061.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E061.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E061.zh-CN.md)



> 原文：[E061.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E061.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

初始化器为 lambda 的模块级 `let` 会被拒绝：该绑定在编译输出中没有容身之处（闭包不能放在模块常量中），而且无法从任何地方调用。

```
error[E061]: top-level 'let double' cannot be bound to a function value
```

```almide
let double = (x: Int) => x * 2      // ← E061

fn main() -> Unit = println(int.to_string(double(4)))
```

## 修复

将其声明为函数——函数体相同，调用点也相同：

```almide
fn double(x: Int) -> Int = x * 2

fn main() -> Unit = println(int.to_string(double(4)))
```

fn 或 test 主体内部以 `let` 绑定的 lambda 没有问题——在那里它是局部值，可以像其他值一样被捕获和传递：

```almide
fn apply_twice() -> Int = {
  let double = (x: Int) => x * 2
  double(double(3))
}
```

## 为什么报错而不是降级转换

在此诊断之前，程序会被接受，随后以各种写法失败：原生构建把闭包放入非 `Sync` 的 static（rustc E0277），而对该绑定的调用也无法解析（E002）。在检查时报告错误并提示改写为 `fn`，才是符合实际的表层行为（#1540）。

## Fix-it 判定

**conditional** — 对带注解的 lambda，改写为 `fn` 是机械的（`let f = (x: Int) => …` → `fn f(x: Int) -> … = …`）；但未注解参数的类型仅存在于已被拒绝的绑定不再能获得的推断中，所以改写需要作者写出签名。包含推断类型的建议修复值得审查，而非无人值守应用。
