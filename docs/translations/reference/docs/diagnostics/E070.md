# E070 — `@bounded` requires counted loops

The `@bounded` attribute (ALS §B, the bounded profile) narrows what the
checker admits inside the attributed function: statically bounded time and
storage, a closed acyclic call graph, capability-bounded effects. E070
rejects a `while` loop, a `for` over a container, or a range with run-time bounds inside a `@bounded` function.

```
error[E070]: ... is not admissible in a @bounded function
```

```almide check-fail=E070
@bounded
fn count_down(n: Int) -> Int = {
  var k = n
  while k > 0 { k = k - 1 }
  k
}

fn main() -> Unit = println("bounded")
```

## The fix

Use a counted range — `for i in a..<b` / `for i in a...b` with compile-time-constant bounds. The trip count is then the range length, statically known; nesting multiplies the counts.

```almide
@bounded
fn count_down() -> Int = {
  var k = 3
  for i in 0..<3 { k = k - 1 }
  k
}

fn main() -> Unit = println("bounded")
```

The rule binds only inside `@bounded` functions — removing the attribute
removes the rejection (the profile is a subset, not a dialect: ALS-B2).

## Fix-it verdict

**conditional** — the diagnostic's hint names the admissible form; which
spelling replaces the rejected one depends on what the code was doing.
