# E030 — type has no ordering

[![English](https://img.shields.io/badge/English-24292f?style=flat-square)](E030.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E030.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E030.zh-CN.md)

`list.sort`, `list.min`, `list.max`, and `list.sort_by`'s key require an
ORDERABLE element — the native runtime's `T: Ord` bound. A bare `Float`
element is fine (it routes to the IEEE-754 totalOrder `_float` twins), but a
`Map`, `Set`, or function element — or a `Float` nested inside a compound
element — has no order. Previously `check` accepted these while native rustc
rejected the monomorph (`AlmideMap: Ord is not satisfied` — the
check-vs-build acceptance-parity gap, differential-fuzz seed 20260718 index
629).

```almide
fn main() -> Unit = {
  let xs: List[Map[String, Int]] = [["a": 1]]
  let s = list.sort(xs)                       // ← E030: Map has no ordering
  println("${list.len(s)}")
}
```

## Fix

Sort by an explicit orderable key instead:

```almide
fn main() -> Unit = {
  let xs: List[Map[String, Int]] = [["a": 1], ["b": 2]]
  let s = list.sort_by(xs, (m) => map.len(m))   // Int key — orderable
  println("${list.len(s)}")
}
```

Orderable: `Int` (all widths), `Bool`, `String`, bare `Float`, and
tuples/lists/`Option`s built only from those.

A user record or variant is orderable too — a record lexicographically in
FIELD DECLARATION order, a variant by CASE order and then the payload, the
same order native's derive gives them — but **only when the type declares the
derive**:

```almide
type Score: Ord = { points: Int, name: String }   // orders
type Level: Ord = | Low | Mid | High              // Low < Mid < High
```

Without `: Ord` the type is not orderable, and that is deliberate (#1521):
structural orderability of the fields is not enough, because the native
monomorph must satisfy `T: Ord` and only the declared derive puts it there.

Not orderable: `Map`, `Set`, functions, and `Float` inside a compound element
(compare via an explicit key).
