# E057 — fn 没有函数体

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E057.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E057.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E057.zh-CN.md)



> 原文：[E057.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E057.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

没有 `= body` 的函数声明：

```
error[E057]: fn 'f' has no body
  hint: Write the body after '=': `fn f(...) -> T = expr` (or `= { ... }`).
        Only @extern / @intrinsic declarations may omit it
```

## 含义

解析器保留无函数体形式，因为两类声明确实需要它——`@extern` 绑定和 `@intrinsic` 运行时声明（标准库的 `= _` 占位符也会被解析为函数体）。省略 `=` 的普通 fn 过去会完全绕过检查器匹配函数体的分支：check 通过，未使用的声明甚至能运行，而第一次调用才在原生构建时因函数缺失而失败（接受一致性问题——check 必须拒绝 build 无法兑现的一切）。

## 应该怎么做

- 编写函数体：`fn f() -> Int = 42`，或代码块：`= { ... }`。
- 如果函数确实在 Almide 外实现，明确声明：`@extern(...)`。`@intrinsic` 保留给标准库实现，不是用户的逃生通道（见 [E085](../../../../diagnostics/E085.md)）。用户函数体 `= _` 是带类型的空洞，而非外部实现：原生执行触及它时会中止，structural Wasm 发射器不支持它。

## 触发位置

检查期间，在声明处触发——发生于任何调用之前。

## Fix-it 判定

**not-fixable** — 任何重写都无法凭空创造函数体；修复内容只有作者知道。（`mechanical` = 无人值守的修复器可以应用重写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）
