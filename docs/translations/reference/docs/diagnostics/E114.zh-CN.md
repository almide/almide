# E114 — 泛型 fn 以不断增大的类型调用自身

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E114.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E114.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E114.zh-CN.md)



> 原文：[`docs/diagnostics/E114.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E114.md)，固定提交 `9a95b285`。这是供读者参考的非规范性译文，CLI 诊断输出仍为英文。

泛型 fn 按每种调用类型分别编译一次。如果 fn 使用由自身类型参数构造的类型，直接或经其他泛型 fn 调用自身，那么递归每一层都需要新实例，永远没有最后一个（#4287）。

```almide
fn depth[T: Hash](x: T, n: Int) -> Int =
  if n <= 0 then 0 else 1 + depth((x, x), n - 1)   // ← E114
```

```
error[E114]: `depth` calls itself at a growing type: its `T` is `(T, T)` at this call
  hint: A generic fn is compiled once for each type it is called at, so a recursion whose type grows with every call needs an instance for every level and never ends. Recurse at the type `depth` was called with: collect the values in a `List[T]`, or count the levels in an `Int`.
```

同一代码也覆盖经过多个 fn 的循环（`wrap[T]` 调用 `unwrap([x])`，`unwrap[U]` 调用 `wrap(y)`）；消息会列出循环经过的 fn。

同一类型上的递归可以通过，只重命名或交换类型参数的循环也可以通过（`f[A, B]` 调用 `f(b, a)`），因为它们只需要有限个实例。

<a id="fix"></a>

## 修复

在 fn 被调用时的类型上递归。

```almide
fn depth[T: Hash](xs: List[T], n: Int) -> Int =
  if n <= 0 then 0 else 1 + depth(xs + xs, n - 1)
```

<a id="why"></a>

## 原因

此检查加入前，程序会通过 `almide check`；单态化只生成一个实例，并在其中保留类型错误的自调用，首个错误来自后端：`--target wasm` 下为 E082，原生下为 rustc E0308。规则是扩张循环检查：泛型调用循环中，只要某条边使类型参数增长就拒绝；参数不变地传递的循环则不拒绝。

测试样例：`tests/diagnostics/e114-self-recursion-at-growing-type`、`e114-mutual-recursion-at-growing-type`、`e114-cycle-grows-through-option`。
