# E095 — the app passed to `http.serve` reads a local

[![English](https://img.shields.io/badge/English-24292f?style=flat-square)](E095.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E095.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E095.zh-CN.md)

The argument of `http.serve` (and `http.serve_with_limits`) is the **app**,
and it must be *instance-closed*: every name it reads that it does not bind
itself must be a top-level item — a fn, a top-level `let`, a type or a
constructor. A `let`, `var` or parameter of the fn that calls `serve` (main's
locals, usually) is refused.

The app runs in several instances: one per worker thread natively, and one
per request on a wasi:http export host, which never runs `main` at all. A
local of main exists in none of them, so a value main computed before `serve`
cannot be what a request sees.

```almide
import http
import random

effect fn main() -> Unit = {
  let boot = random.int(1, 1000000)
  http.serve(8080, (req) => http.response(200, "boot=${boot}"))!   // ← E095: captures `boot`
}
```

A router built inside main is a local too:

```almide
import http

effect fn main() -> Unit = {
  let app = http.router([http.route("GET /", (req) => http.response(200, "home"))])!
  http.serve(8080, app)!                                           // ← E095: captures `app`
}
```

Names the app binds itself are fine: the handler's parameters, a `let`
inside its body, a nested lambda's own parameters. So are top-level fns and
`let`s, imported items and the stdlib. A fn that passes its own parameter to
`http.serve` (`effect fn serve_on(port: Int, h: HttpHandler) = http.serve(port, h)!`)
moves the rule to its callers: the app each caller passes is checked where
it is written.

## Diagnostic

```
error[E095]: the app passed to http.serve captures `boot`, a local of main
  in the app passed to http.serve
  hint: the app runs in several instances — one per worker natively, one per request on a wasi:http host — and main's locals do not exist there. Make `boot` a top-level `let`, or compute it inside the handler.
```

The error points at the first read of each local the app captures.

## Fix

- A value fixed by the program text is a top-level `let`. A top-level
  initializer cannot call an effect fn, so it is the same in every instance:
  ```almide
  import http

  let app = http.router([http.route("GET /", (req) => http.response(200, "home"))])

  effect fn main() -> Unit = http.serve(8080, app!)!
  ```
  `router` returns a `Result`, and `!` is not allowed in a top-level
  initializer, so main writes `app!` where it serves it.
- A value that depends on the run (a random draw, a clock read) is computed
  inside the handler, per request.

## Why

ADR-0020 §5.2. C-367 used to promise that a value main computed before
`serve` is the same on every request of a run. No host that runs the app in
more than one instance can keep that promise, so the promise was retired and
the shape that relied on it became this error.

## Related

## Fix-it verdict

**conditional** — moving the value to a top-level `let` works only when it
does not depend on the run; a run-dependent value has to be computed inside
the handler, which is the writer's choice. (`mechanical` = an unattended
rewrite; `conditional` = a suggested fix needs review; `not-fixable` = no
automatic rewrite exists. #1486's applicability doctrine.)
