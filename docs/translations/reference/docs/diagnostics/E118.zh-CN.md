# E118 — 媒体类型所有者未获授权、不唯一，或类型不是字面量

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E118.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E118.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E118.zh-CN.md)



> 原文：[`docs/diagnostics/E118.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E118.md)，固定提交 `9a95b285`。这是供读者参考的非规范性译文，CLI 诊断输出仍为英文。

`Body` 类型说明其响应以什么 Content-Type 提供（ADR-0032）。类型可以通过 `@media_owns(...)` 拥有媒体类型，使 `http.typed` 无法将字节标记为其中一种。拥有浏览器会运行脚本的类型——`stdlib/html.almd` 声明为 `@script_capable` 的模式：HTML、XHTML、SVG、XML——就是将脚本呈现给用户的权限，因此会被检查（D7）。

- 拥有脚本能力类型的依赖项，只有在根 `almide.toml` 按其来源给该包授予该类型时才能构建。

  ```toml
  [trust]
  media = { "almide/svg" = ["image/svg+xml"] }
  ```

- 给包未声明的类型授权，或给不是依赖项的包授权，会被拒绝。
- 两个所有者——标准库、依赖项或应用——的模式若可能指向同一媒体类型，会被拒绝，从而使每种类型只有一个所有者。
- `Body` 类型的 media fn 必须是字符串字面量；有脚本能力的类型必须被该 fn 自身的 `@media_owns` 覆盖，因此类型只能提供获授权的内容。

应用自身的类型不需要授权（因为是开发者自己写的）；它们与所有其他所有者一起由 `almide deps` 列出。

```almide
type Chart: Body = { markup: String }

fn Chart.media_type(self) -> String = "image/svg+xml"   // ← E118
```

```
error[E118]: `Chart.media_type` serves `image/svg+xml`, which runs script in a browser, without owning it
```

```
error[E118]: dependency `svg` (almide/svg) owns `image/svg+xml`, which runs script in a browser, and ./almide.toml does not grant it
```

<a id="fix"></a>

## 修复

在 media fn 上用 `@media_owns(...)` 声明该类型提供什么，将媒体类型写成字面量，并在 `[trust] media` 中给拥有脚本能力类型的依赖项授权——仅当你信任它能安全构造该类型时才这样做。HTML 属于 `html.*`，应使用其构造器构建页面。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**not-fixable**：授予包提供脚本的权利，是信任决策。（`mechanical` = 无人值守的修复工具可以应用改写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动改写。#1486 的适用性原则。）
