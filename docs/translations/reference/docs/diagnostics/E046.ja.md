# E046 — 呼び出し引数のプレースホルダー `_`

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E046.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E046.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E046.zh-CN.md)



> 原文：[`docs/diagnostics/E046.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E046.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

呼び出しの引数位置にある `_` は値ではなく、値になることもない。構文解析は通る（`ExprKind::Placeholder`）が、lowering は置く値がないため `Unit` に変える。このため以前は `add(_, 10)` が検査を通過し（「No errors found」）、ビルド時に次のように失敗していた。

```
codegen produced invalid Rust — this is an Almide bug.
error[E0308]: mismatched types
    let v: i64 = add((), 10i64);
                     ^^ expected `i64`, found `()`
```

これはユーザーの誤りなのにコンパイラ自身を原因とするもので、タプル添字について E045 が解消したものと同じ失敗形態である（#1266）。現在は検査時のエラーとなる。

```almide
fn add(a: Int, b: Int) -> Int = a + b

let v = add(_, 10)        // ← E046: argument 1 of add()
let w = 5 |> add3(_, 10)  // ← E046 on the pipe path too
```

## これは部分適用ではない

Almide に `_` セクション構文はなく、このプレースホルダーがそのように振る舞ったこともない。修正前のコンパイラでの計測：

- `let v = add(_, 10)` は `v` を関数型ではなく add の**戻り型**（`i64`）にした。生成 Rust は `let v: i64 = add((), 10i64)` だった。
- パイプ位置では `_` は**追加の位置引数**として数えられる。`5 |> add(_, 10)` は E004「add() expects 2 argument(s) but got 3」となる。パラメーターが一つ多い呼び出し先（`5 |> add3(_, 10)`）は追加引数を受け入れ codegen まで進んだ。この形により、単に混乱を招くだけでなく、検査を黙って通過してビルド時にクラッシュする問題となっていた。

## 修正

「これだけ後から与える」を実際に表す lambda を使って、欠けている値に名前を付ける。

```almide
let f = (x) => add(x, 10)
let v = f(5)

xs |> list.map((x) => add(x, 10))
```

## typed hole と混同しないこと

式の位置にある `_` は別の、正式に認められた構文である。**typed hole** として文脈が要求する型を受け取り、プログラムの残りの型検査を可能にし、実行が到達したら panic する。

```almide
fn compute(x: Int) -> Int = _                  // typed hole — checks, panics
fn compute(x: Int) -> Int = todo("no impl")    // same, with your own message
```

これらは E046 ではない。[docs/CHEATSHEET.md](../../../../CHEATSHEET.md) を参照。

## Fix-it 判定

**conditional** — lambda のパラメーター名と引数の数は意図に依存する。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
