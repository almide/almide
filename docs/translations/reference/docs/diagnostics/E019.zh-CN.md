# E019 — 有歧义的构造器

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E019.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E019.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E019.zh-CN.md)



> 原文：[`docs/diagnostics/E019.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E019.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

单独的变体构造器名在**多个**变体类型中声明，因此单独使用会产生歧义：checker 无法判断你意指哪种类型。本例涉及同一模块内的重复构造器。不同模块拥有的构造器按模块归属解析，仅共享拼写不会构成跨包冲突。

Almide 将名称解析为最先声明的候选，以便继续检查，但会报告冲突，而不是静默构造错误类型；后者原本会很久以后才表现为难懂的生成 Rust 错误（`E0769`/`E0308`）。

<a id="common-cases"></a>

## 常见情况

```almide
type Cmd   = | Stop | Send(Int)
type Event = | Tick | Send(Int)   // `Send` now lives in two types

fn main() -> Unit = {
  let x = Send(5)   // E019: ambiguous constructor 'Send': declared in Cmd and Event
  println("${x}")
}
```

<a id="fix"></a>

## 修复

重命名其中一个类型中的构造器，使名称唯一。目前尚不支持限定的 `Type.Ctor` 形式，因此通过重命名消除歧义。

```almide
type Cmd   = | Stop | Send(Int)
type Event = | Tick | Emit(Int)   // renamed `Send` → `Emit`

fn main() -> Unit = {
  let x = Send(5)   // unambiguous: only Cmd declares `Send`
  println("${x}")
}
```

<a id="fix-it-verdict"></a>

## Fix-it 判定

**not-fixable** — 错误报告的是自动改写无法判断的语义／设计问题。（`mechanical` = 无人值守的修复器可以应用改写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动改写。#1486 的适用性原则。）
