# E030 — 类型没有顺序

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E030.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E030.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E030.zh-CN.md)



> 原文：[E030.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E030.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

`list.sort`、`list.min`、`list.max` 以及 `list.sort_by` 的键，要求元素可排序——即原生运行时的 `T: Ord` 约束。单独的 `Float` 元素没有问题（会路由到 IEEE-754 totalOrder 的 `_float` 对应实现），但 `Map`、`Set`、函数元素，或嵌套在复合元素中的 `Float` 没有顺序。过去 `check` 会接受它们，而原生 rustc 会拒绝单态化结果（`AlmideMap: Ord is not satisfied`——check 与 build 的接受一致性缺口，差分模糊测试 seed 20260718、index 629）。

```almide
fn main() -> Unit = {
  let xs: List[Map[String, Int]] = [["a": 1]]
  let s = list.sort(xs)                       // ← E030: Map has no ordering
  println("${list.len(s)}")
}
```

## 修复

改为按显式的可排序键排序：

```almide
fn main() -> Unit = {
  let xs: List[Map[String, Int]] = [["a": 1], ["b": 2]]
  let s = list.sort_by(xs, (m) => map.len(m))   // Int key — orderable
  println("${list.len(s)}")
}
```

可排序：`Int`（所有位宽）、`Bool`、`String`、单独的 `Float`，以及仅由这些类型构成的元组／列表／`Option`。

用户记录或变体也可排序：记录按字段声明顺序进行字典序比较，变体先按分支顺序，再按载荷比较，与原生 derive 给出的顺序相同。但**仅当类型声明了派生时才成立**：

```almide
type Score: Ord = { points: Int, name: String }   // orders
type Level: Ord = | Low | Mid | High              // Low < Mid < High
```

没有 `: Ord`，类型就不可排序，这是有意为之（#1521）：字段在结构上可排序还不够，因为原生单态化结果必须满足 `T: Ord`，而只有已声明的派生才会提供它。

不可排序：`Map`、`Set`、函数，以及复合元素中的 `Float`（请通过显式键比较）。
