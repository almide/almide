# E051 — file stamped for a dialect this compiler does not speak

A file carries a `@dialect(N)` stamp whose epoch is HIGHER than the dialect
this compiler implements.

```almide
@dialect(2147483647)           // ← E051: deliberately beyond this compiler's epoch

fn main() -> Unit = println("hi")
```

## What the stamp means

`@dialect(N)` records the language dialect a file was last **verified**
against. It is not a release number: Almide cuts releases constantly and
almost none of them change anything a writer can observe, so the epoch
advances only when the language surface changes in a way that can break
already-written code. The normative list of epochs, and what each one broke,
is [`proofs/dialect-epochs.toml`](../../../../../proofs/dialect-epochs.toml).

The stamp exists because Almide's users are largely code generators. A model
writes against whatever dialect it learned; recording that dialect in the file
is what lets the compiler distinguish *"this program is wrong"* from *"this
program was written for an older language"* — and what lets modification
survival be measured per dialect instead of as one blended number.

## Why a stamp AHEAD of the compiler is an error

Three of the four standings are silent:

| stamp | meaning | behavior |
|---|---|---|
| absent | written before stamps existed, or unstamped on purpose | silent |
| equal to the compiler's | verified against this dialect | silent |
| **lower** than the compiler's | verified against an older dialect | **silent** — it keeps compiling until it actually uses something that moved |
| **higher** than the compiler's | verified against a language this binary has never seen | **E051** |

The last row is the only one where success would be misleading. A stamp above
this compiler says some *newer* Almide checked the file; nothing here has. If
it happens to compile, that is luck rather than evidence — precisely the case
where a generator's output looks fine and is not.

## Fixing it

- **Upgrade the compiler** — the usual cause is a file written against a newer
  Almide than the one on `PATH`.
- **Or lower the stamp**, if the file genuinely targets this dialect. On a
  clean check, `almide check <file> --stamp` writes the correct epoch for you.
  It only ever moves the stamp *forward*: a stamp from a newer compiler is
  left alone, because walking it backwards would forge a verification this
  binary cannot perform.
