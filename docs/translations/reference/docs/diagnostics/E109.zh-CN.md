# E109 — 纯 fn 通过函数值运行 effect fn

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E109.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E109.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E109.zh-CN.md)

普通 `fn` 运行了作为值获得的 `effect fn`：传入的回调、记录字段、列表元素、option 内部值，或另一个函数构造的闭包。E006 拒绝调用处可见的形式——直接调用、持有 effect fn 的名称（#3274）、作为实参具名传入的 effect fn；但函数值会传播到调用点之外，最终调用它的纯 fn 曾在无人拒绝的情况下运行 effect（#4151）。

```almide
import fs

type Reader = { read: (String) -> Result[String, String] }

fn pure_looking(r: Reader) -> Result[String, String] = (r.read)("s.txt")   // ← E109

effect fn main() -> Unit = {
  let r = Reader { read: fs.read_text }
  println(pure_looking(r) ?? "none")
}
```

```
error[E109]: pure function `pure_looking` runs an effect function it does not call by name
  --> main.almd:5:56
  = path: pure_looking → field `read` → closure (line 8:26 in main) → fs.read_text (line 8:26)
  hint: A plain `fn` cannot run an `effect fn`, even one it receives as a value — a callback, a record field, a list element (ADR-0009 D2). Mark `pure_looking` as `effect fn` if it is meant to do I/O, or pass it a function that does none
```

## 如何判定

effect 位像 effect 类别一样随函数值传播（ADR-0026 D1，`crates/almide-codegen/src/effect_flow`）：`effect fn` 携带它，调用 effect fn 的闭包也携带它；存入字段、列表或 option 的值保留它。单纯的函数类型参数是透明的（ADR-0009 D2）：普通 fn 可以调用它，而将 effect fn 传入的调用点会被计入 effect。因此 `fn apply(f: (A) -> B, x: A) = f(x)` 没有问题，`apply(fs.read_text, p)` 则是 effect 调用（从纯 fn 中调用为 E006）。E109 覆盖剩余情况：纯 fn 自己的函数体运行带该位的值，而非通过它自身的参数。

分析是全程序且保守的：离开所跟踪位置的值（列表、变体内部值、传给未知被调用方的值），会与相同签名的所有其他未跟踪值汇入一个池。从这些位置读回的值，其调用会按该池计入 effect。因此，只要程序任何位置将同签名且执行 I/O 的函数放入列表，调用从列表读取的函数的纯 fn 就会被拒绝。

`process.exit`（结果为 `Never` 的 `effect fn`）不携带该位：结束程序是 ADR-0022 的 abort，普通 fn 可以执行。

## 修复

1. 如果函数本来就要执行 I/O，请明确标记为 `effect fn`（其调用方随后看到 `Result`，并用 `!` 传播）。
2. 如果它应保持纯净，传入不执行 I/O 的函数；在构造该值的 effect fn 中完成 I/O，将数据交给纯 fn。

## Fix-it 判定

**not-fixable**：函数应改成 `effect fn` 还是接收不同的值，是设计决策；诊断会指出纯 fn 到其触及的 effect fn 的路径（`= path:`）。
