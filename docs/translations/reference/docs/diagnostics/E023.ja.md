# E023 — フィールド型が導出プロトコルを満たさない

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E023.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E023.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E023.zh-CN.md)



> 原文: [E023.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E023.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

`Codec`、`Ord`、`Hash` は**フィールドに再帰的に適用される**プロトコルです。構造体やバリアントに導出すると、フィールドごとの処理を生成し、*すべてのフィールド型にも同じプロトコルを満たすこと*を要求します。

- `Codec` — 導出した `encode`/`decode` は `Field.encode` / `Field.decode` を呼び出します。
- `Ord` / `Hash` — 各フィールドに対する Rust の `#[derive(Ord/Hash)]` へ変換されるため、各フィールドの基になる型がそれを実装している必要があります。

フィールド型がそのプロトコルを導出していないと、生成コードは存在しないメソッド（または trait 実装）を参照します。検査器は現在、後のコード生成エラーに任せず、これを構造的に拒否します。

<a id="common-cases"></a>

## よくある例

```almide
type Raw = { x: Int }                  // NOT : Codec
type Wrap: Codec = { item: Raw }       // E023: Raw does not derive Codec

type Point = { x: Int, y: Int }        // NOT : Ord
type Edge: Ord = { a: Point, b: Point } // E023: Point does not derive Ord
```

コンテナーは透過的です。`List[Raw]` / `Option[Raw]` フィールドでも `Raw` がそのプロトコルを導出する必要があります。

<a id="diagnostic"></a>

## 診断

```
error[E023]: type 'Wrap' derives 'Codec' but field 'item' has type 'Raw', which does not derive 'Codec'
  hint: Add `: Codec` to the declaration of type 'Raw' (every field of a `: Codec` type must itself be `Codec`)
```

<a id="fix"></a>

## 修正

- フィールド型にもプロトコルを導出します。
  ```almide
  type Raw: Codec = { x: Int }
  type Wrap: Codec = { item: Raw }
  ```
- 手書きの codec メソッドだけでは、この導出検査にフィールドが通るとは保証されません。フィールド型に対応するプロトコルを宣言するか、外側のエンコード／デコードを導出せず明示的に書きます。2つのメソッド名の有無だけでなく、型宣言全体を確認してください。

<a id="why"></a>

## 理由

導出は構造的な再帰です。型が `Codec` であるには、その構成要素も `Codec` である必要があります。`Raw` が Codec ではないのに `Wrap: Codec` を受け入れると、存在しない `Raw.encode` の呼び出しにコンパイルされ、明確な診断ではなくコード生成の失敗になります。型の段階で要件を強制すれば、「この型は P を導出する」が推移的にも真であることを保ち、修正も明白かつ局所的になります。

`Eq` と `Repr` は E023 の対象**ではありません**。生成される構造体には無条件で `PartialEq` と repr 経路が付くため、フィールド側で宣言する必要はありません。
