# E093 — type applied to the wrong number of type arguments

[![English](https://img.shields.io/badge/English-24292f?style=flat-square)](E093.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E093.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E093.zh-CN.md)

A type written with brackets (`Pair[Int]`, `Cell[Int, String]`) passes one
type per parameter its declaration names. A different count has no meaning:
there is no letter for the extra argument to replace, or a letter is left
with nothing. This used to pass `almide check` silently — the extra argument
was dropped, or a generic alias stayed an opaque name that a tuple index or a
list call then refused with an unrelated error — so E093 reports the count
where the type is written.

```almide
type Pair[T] = (T, T)

fn first(p: Pair[Int, Int]) -> Int = p.0   // ← E093: 'Pair[T]' takes 1 type argument, but is applied to 2
```

It applies to every declared type: a generic alias, a generic record or
variant, and a type declared WITHOUT parameters, which takes none:

```almide
type Score = Int

fn bump(s: Score[Int]) -> Score = s + 1    // ← E093: 'Score' takes no type arguments, but is applied to 1
```

A builtin generic type counts the same way (#3408): `List`, `Option` and
`Set` take one argument, `Map` and `Result` two, and a builtin scalar
(`Int`, `String`, …) none. The counts come from the resolver's builtin table,
the one place a builtin type name is recognised:

```almide
fn total(xs: List[Int, Int]) -> Int = 0     // ← E093: 'List[T]' takes 1 type argument, but is applied to 2

type Index = { names: Map[String] }          // ← E093: 'Map[K, V]' takes 2 type arguments, but is applied to 1
```

A bare spelling (no brackets) is not an application and is never E093.

## Fix

Write one type per declared parameter — the message spells the declaration
(`Pair[T]`) — or drop the brackets for a type without parameters:

```almide
type Pair[T] = (T, T)

fn first(p: Pair[Int]) -> Int = p.0
```

A generic transparent alias applied to its own count is its body with each
argument substituted (`Pair[Int]` is `(Int, Int)`), as a non-generic alias is
its body; see `docs/specs/language.md` "Type Alias".

## Fix-it verdict

**not-fixable** — which argument is extra, or which parameter the missing one
was meant for, is the writer's intent; the message names the declared
parameters, it does not rewrite the annotation.
