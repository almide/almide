# E038 — `??` separated from its fallback

[![English](https://img.shields.io/badge/English-24292f?style=flat-square)](E038.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E038.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E038.zh-CN.md)

At statement level, the fallback of `??` must start on the same line as
the operator. `??` itself may open a continuation line, like any infix
operator (#3155): `xs\n  |> list.first\n  ?? 0`. A line-crossing
`??` used to silently swallow the NEXT STATEMENT as the fallback
expression — the program ran with the wrong meaning and no error.

The missing-operand form (`expr??` with nothing following) carries the
same code.

## Common cases

```almide
let v = int.parse("x")??
-5                          // ← silently became the fallback (pre-E038)
println("${v}")
```

## Diagnostic

```
error[E038]: the ?? fallback is not on this line
  hint: write the fallback on the same line; multiline uses parens with ?? trailing
```

## Fix

- Same line: `let v = int.parse("x") ?? -5`
- Multiline (inside parentheses, `??` trailing):
  ```almide
  let v = (int.parse("x") ??
    -5)
  ```

## Why

This is the JS-ASI class of hazard: a statement boundary silently
re-attached as an operand. Inside `(`/`[` delimiters the expression
continues across newlines as before — only the statement-level form is
guarded.

## Fix-it verdict

**conditional** — reattaching the fallback is usually mechanical but the intended operand is a guess. (`mechanical` = an unattended fixer may apply the
rewrite; `conditional` = a suggested fix needs review; `not-fixable` = no
automatic rewrite exists. #1486's applicability doctrine.)
