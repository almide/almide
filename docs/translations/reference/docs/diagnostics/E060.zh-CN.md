# E060 — import 整理（警告）

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E060.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E060.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E060.zh-CN.md)



> 原文：[E060.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E060.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

不起作用的导入：模块被导入后从未使用，或同一模块以两个名称重复导入。

```
warning[E060]: unused import 'regex'
warning[E060]: module 'regex' is already imported as 'regex'
```

```almide
import regex                 // ← E060: nothing below mentions regex
import json
import json as j             // ← E060: json already has a name in this file

effect fn main() -> Unit = println(j.stringify(json.parse("1")!))
```

两者都不是错误——程序含义与写法一致——但都是会误导下一位读者的残留：未使用的导入宣称了文件没有的依赖，而重复导入让一个模块拥有两个名称，使含义相同的两个调用点看起来不同。

修复方法：移除未使用的行，每个模块只保留一个名称。刻意未使用的导入（例如为文档示例保留）可以用下划线前缀抑制警告：`import _regex`。

<a id="what-counts-as-a-use"></a>

## 怎样才算使用

判定依据文件的写法，而不是检查器碰巧解析出了什么。当导入名称出现在任意限定写法的开头时，就算使用：调用（`h.open()`）、构造器（`m.Box { .. }`、`c.Red`）、类型位置（`-> g.Point`、参数、`let x: g.Point`、泛型实参、协议方法签名）、模式（`m.Some(x)`）、测试的 `where` 覆盖路径；或者，导入模块声明的协议在约束或符合列表中以非限定名称出现（`fn go[S: Store]`、`type Mem: Store`）。协议跨模块按非限定名称解析，所以该写法没有提及别名；匹配的是声明模块。

标准库模块拥有的类型也一样（`net` 的 `IpAddr`、`fs` 的 `FileStat`、`process` 的 `ProcessStatus`、`url` 的 `Url` 等）：以非限定形式写类型——`fn f(a: IpAddr)`、`let xs: List[IpAddr]`、`FileStat { .. }`——或使用其构造器（`V4(..)`），都会使用该模块的导入，无论旁边是否有 `net.*` 调用（#1853）。单独的类型就会把模块声明带入程序，因此导入并非未使用。文件自己声明的类型属于文件自身（`type IpAddr = ..` 会遮蔽标准库类型，#1837）：其非限定写法不使用任何导入，旁边的 `import net` 仍会警告。

自身模块导入（`import self.ports`、`import self.helper as h`）也按同一规则判断（#1783）。在 0.62 之前它们属于例外，所以即使未被引用也能无警告地通过检查。

解析器需要恢复的文件（存在任意解析错误）不会得到未使用导入判定：恢复会丢掉可能是使用位置的文本，而解析错误本身已是诊断。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**mechanical** — 删除未使用的 import 行是无人值守修复器可应用的纯粹表记改写（`almide fix`）。重复导入部分仍只显示提示：删除重复项可能使其别名引用失效，需要改写引用，而非仅删除行。（`mechanical` = 无人值守的修复器可以应用重写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）
