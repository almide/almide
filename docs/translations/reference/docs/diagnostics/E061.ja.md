# E061 — トップレベルの `let` が関数値に束縛されている

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E061.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E061.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E061.zh-CN.md)



> 原文: [E061.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E061.md)。これは読者向けの非規範的な翻訳です。CLI に埋め込まれる診断解説は英語原文のままです。

初期化式が lambda であるモジュールレベルの `let` は拒否されます。束縛をコンパイル後の出力に置く場所がなく（クロージャはモジュール定数に置けません）、どこからも呼び出せないためです。

```
error[E061]: top-level 'let double' cannot be bound to a function value
```

```almide
let double = (x: Int) => x * 2      // ← E061

fn main() -> Unit = println(int.to_string(double(4)))
```

<a id="the-fix"></a>

## 修正

関数として宣言します。本体も呼び出し箇所も同じです。

```almide
fn double(x: Int) -> Int = x * 2

fn main() -> Unit = println(int.to_string(double(4)))
```

fn や test の本体内で `let` に束縛した lambda は問題ありません。そこではローカル値なので、ほかの値と同様にキャプチャしたり渡したりできます。

```almide
fn apply_twice() -> Int = {
  let double = (x: Int) => x * 2
  double(double(3))
}
```

<a id="why-an-error-and-not-a-lowering"></a>

## 低水準化ではなくエラーにする理由

この診断以前はプログラムが受理され、どの書き方でも後から失敗していました。ネイティブビルドはクロージャを非 `Sync` の static に置き（rustc E0277）、束縛への呼び出しも何も解決しませんでした（E002）。検査時にエラーを出し、`fn` への書き換えを示すのが実態に合った表面仕様です（#1540）。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**conditional** — 注釈付き lambda の `fn` 書き換えは機械的です（`let f = (x: Int) => …` → `fn f(x: Int) -> … = …`）。ただし、注釈のない引数の型は、拒否された束縛がもはや受けられない推論の中にしかないため、書き換えには作者によるシグネチャの明記が必要です。推論型を含む修正案はレビューする価値がありますが、無人適用向きではありません。
