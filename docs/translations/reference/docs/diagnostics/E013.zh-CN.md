# E013 — 对非记录值访问字段／缺失字段

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E013.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E013.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E013.zh-CN.md)



> 原文：[`docs/diagnostics/E013.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E013.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

`.field` 访问的目标值，其类型未声明该字段，或根本不是记录。

## 常见情况

```almide
type Point = { x: Int, y: Int }

let p = Point { x: 1, y: 2 }
let z = p.z                      // E013: no field `z` on Point

let n: Int = 42
let bad = n.value                // E013: Int has no fields
```

## 诊断

```
error[E013]: no field `z` on type `Point`
  --> main.almd:4:9
  hint: Available fields on `Point`: x, y. Check spelling or verify the record type.
  in field access .z
```

类型为记录时，诊断会列出其字段。单独的成员访问不等于 UFCS 调用：`s.to_upper()` 可能解析为函数，而 `s.to_upper` 请求的是字段。

### 与标准库类型同名的用户类型

```almide
import json
type Value = { n: Int }
let v = json.parse("{}")!
let n = v.n                      // E013: no field `n` on Value — the type has no fields
```

`json.parse` 返回标准库的 `Value`；用户的 `type Value` 是另一种类型（入口程序中为 `self.Value`，模块 `m` 中为 `m.Value`），从不重新绑定标准库类型（#1828）。提示会明确两者：“这里的 `Value` 是 `value` 模块的类型，而不是你的 `type Value`（它是 `self.Value`）。”请通过相应模块（`value.*`、`json.*`）读取标准库值，或重命名自己的类型。这适用于所有标准库拥有的名称：`HttpRequest`、`HttpResponse`、`FileStat`、`ProcessStatus`、`Url`、`TcpStream`、`TcpListener`、`SafeHtml`、`IpAddr`、`Deque`、`Path`，也适用于各种声明形式。OPAQUE alias（`mod type Value =
String`）是程序拥有的 newtype，身份同样为 `self.Value` / `m.Value`（#1835）。因此读取 json 值的字段会产生带相同提示的 E013；将该 newtype 的模式 `Value(s)` 用于 json 值则产生 E048。

## 修复

- 拼写：核对声明的字段名。记录区分大小写。
- 错误记录：可能正在访问存在于另一类型上的字段。核实 `p` 的声明类型与预期字段一致。
- 方法式误用：`xs.head` / `s.length` 不是字段，而是从其他语言带入的惯用法。改写为 `list.first(xs)` / `string.len(s)`。精确、由类型指导的属性到函数改写可以是 machine-applicable；模糊字段名建议仍需审查。

## 原因

记录字段和元组索引（`.0`、`.1`、...）是值访问。带括号的方法式调用使用 UFCS 解析，不是隐式属性读取。当能更清晰表达意图时，使用 `module.function(value)`。
