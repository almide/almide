# E038 — `??` が代替値から離れている

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E038.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-24292f?style=flat-square)](E038.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E038.zh-CN.md)



> 原文：[`docs/diagnostics/E038.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E038.md)、固定コミット `9a95b285`。読者向けの非規範的な翻訳であり、CLI の診断出力は英語のまま。

文のレベルでは、`??` の代替値は演算子と同じ行で始める必要がある。`??` 自体は他の中置演算子と同様に継続行の先頭に置ける（#3155）：`xs\n  |> list.first\n  ?? 0`。以前の行をまたぐ `??` は、次の文を代替式として黙って取り込んでしまい、プログラムがエラーなしで誤った意味のまま実行されていた。

オペランドがない形式（後ろに何もない `expr??`）にも同じコードを使う。

<a id="common-cases"></a>

## よくある例

```almide
let v = int.parse("x")??
-5                          // ← silently became the fallback (pre-E038)
println("${v}")
```

<a id="diagnostic"></a>

## 診断

```
error[E038]: the ?? fallback is not on this line
  hint: write the fallback on the same line; multiline uses parens with ?? trailing
```

<a id="fix"></a>

## 修正

- 同じ行：`let v = int.parse("x") ?? -5`
- 複数行（括弧内で `??` を行末に置く）：
  ```almide
  let v = (int.parse("x") ??
    -5)
  ```

<a id="why"></a>

## 理由

これは JS-ASI と同じ種類の危険である。文の境界が、黙ってオペランドとして再接続されてしまう。`(`/`[` の区切り内では従来どおり改行をまたいで式が続く。保護されるのは文レベルの形式だけである。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**conditional** — 代替値の再接続は通常機械的にできるが、意図されたオペランドは推測となる。（`mechanical` = 無人の修正ツールが書き換えを適用できる。`conditional` = 提案された修正はレビューが必要。`not-fixable` = 自動書き換えが存在しない。#1486 の適用可能性の原則。）
