# E113 — match too complex to check for exhaustiveness

The exhaustiveness and reachability check of one `match` passed the
`exhaustiveness_steps` compile-cost budget (ADR-0030). Deciding whether a set
of patterns covers every value is exponential in the worst case: a tuple of
`Bool`s whose arms name both `true` and `false` in every column makes the
check branch twice per column.

```almide
fn f(a: Bool, b: Bool, c: Bool /* … 24 more */) -> Int = match (a, b, c /* … */) {   // ← E113
  (true, _, _ /* … */) => 0,
  (_, true, _ /* … */) => 1,
  // … one arm per column and constructor
}
```

## Fix

Split the match: match on the first component, then on the rest inside each
arm, or add a `_ =>` arm that handles the remaining cases together.

## Why

The compiler runs on untrusted source, so the check is bounded by a counted
budget rather than a timeout: the same match gets the same verdict on every
machine. A match the check cannot finish is not assumed exhaustive. The source
cannot raise the budget; `--budget exhaustiveness_steps=N` on the command line
can (`almide budgets`).
