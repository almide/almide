# E006 — 效应隔离：纯 fn 调用了 effect fn

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E006.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E006.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E006.zh-CN.md)



> 原文：[E006.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E006.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

非效应函数（`fn`）试图调用效应函数（`effect fn`）。Almide 在类型系统中跟踪效应；纯函数不能依赖有副作用的函数。

<a id="common-cases"></a>

## 常见情况

```almide
effect fn read_text(path: String) -> String = ...

fn pure_fn() -> String = read_text("a.txt")    // E006: pure calls effect
```

<a id="diagnostic-with-secondary-note"></a>

## 诊断（含补充注释）

```
error[E006]: cannot call effect function 'read_text' from a pure function
  --> main.almd:3:25
  hint: Mark the calling function as `effect fn`, and propagate the call's error with `!`: `read_text(..)!` (the call's type is `Result[String, String]`)
  note: 'read_text' declared as effect fn here
        main.almd:1:1
```

补充的 `note` 指向 effect fn 的声明，帮助用户了解被调用方为何受到限制。

`effect fn` 的调用可能失败：非 Result 返回类型 `T` 会变为 `Result[T, String]`，而已声明的 `Result[T, E]` 保留其错误类型（ADR-0002 §D6）。因此，给调用方添加标记只完成了一半修复：在 `effect fn` 内，传播是显式的（ADR-0008），调用需要 `!`。当需要将调用的 `Result` 用作其 `ok` 类型时，提示会列出两个步骤。同一表达式还会引起的 `expected String but got Result[String, String]` 不会另行报告：它是此错误的残留问题，`!` 会修复它（#3515）。如果已有其他结构处理该 `Result`——例如调用上的 `!`、`??`、`?` 或 `match`——提示只要求将调用方声明为 `effect fn`。lambda 内的调用保留 lambda 自己的提示（标记外层函数）。

<a id="fix"></a>

## 修复

- 将调用方改为 `effect fn`，并传播调用的错误：
  ```almide
  effect fn pure_fn() -> String = read_text("a.txt")!
  ```
- 或者将效应调用移到更高层的 `effect fn`，把已经算出的值传给下层：
  ```almide
  effect fn setup() -> String = read_text("a.txt")!

  fn use_text(text: String) -> String = text        // stays pure
  ```
- 如果调用“effect fn”本身就是错误（例如本想做纯转换，却调用了 `fs.read_text`），请修正调用。

<a id="why"></a>

## 原因

效应调用携带 Result。Almide 的传播是显式的（`expr!`）；后端实现该标记，但不会让源码传播变为隐式。允许 `fn` 调用 `effect fn` 会悄然丢失错误跟踪，使人和 LLM 都无法推理效应。该边界在静态阶段强制执行。
