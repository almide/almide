# E031 — 已停用的范围写法

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E031.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E031.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E031.zh-CN.md)



> 原文：[`docs/diagnostics/E031.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E031.md)，固定提交 `9a95b285`。这是供读者参考的非规范性译文，CLI 诊断输出仍为英文。

Rust 风格的范围运算符已替换为 Swift 的自解释组合（#966）：`..<` 是不包含终点的范围，`...` 是包含终点的范围。旧的 `..` / `..=` 写法会产生带有 machine-applicable 修复的诊断错误。`..` 与 `..=` 仅差一个字符，容易在两个方向上被悄然混淆，而 `..<` 本身就带有 `<`。

```almide
fn main() -> Unit = {
  var s = 0
  for i in 0 .. 5 { s = s + i }     // ← E031: '..' was retired, write '..<'
  for j in 1 ..= 3 { s = s + j }    // ← E031: '..=' was retired, write '...'
  println(int.to_string(s))
}
```

<a id="fix"></a>

## 修复

```almide
fn main() -> Unit = {
  var s = 0
  for i in 0 ..< 5 { s = s + i }    // end-exclusive: 0,1,2,3,4
  for j in 1 ... 3 { s = s + j }    // end-inclusive: 1,2,3
  println(int.to_string(s))
}
```

运行 `almide fix <file>` 可机械地迁移文件中的所有范围；它只应用运算符改写，不触碰其他内容。

E031 也解释在其他位置被拒绝的 `..` / `..=`。范围模式和范围类型不存在：在 match 中使用独立分支或 guard，在类型注解中使用 `List[Int]` 这类指定元素类型的类型。调用不支持参数展开；列表表达式可通过 `xs + [item]` 合并。这些形式没有自动改写。`..rest` 在列表模式的最后一个位置（`[head, ..tail]`）仍然有效。

注意保留的用途：`..` 仍可作为记录剩余部分标记（模式和开放记录类型中的 `{ x, .. }`，不能用于表达式位置）；`...` 也用于记录／列表展开（`{ ...base, x: 1 }`）。前缀位置表示展开，中缀位置表示包含终点的范围。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**mechanical** — 范围运算符的拼写替换（`..<` / `...`）是精确的。（`mechanical` = 无人值守的修复工具可以应用改写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动改写。#1486 的适用性原则。）
