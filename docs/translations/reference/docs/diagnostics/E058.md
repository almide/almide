# E058 — unhashable Map key

[![English](https://img.shields.io/badge/English-24292f?style=flat-square)](E058.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E058.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E058.zh-CN.md)

A `Map` key type that cannot be hashed: `Float` (IEEE-754 equality makes it
unusable for lookup), a `Map`, or a record/variant carrying one of those
anywhere in its fields.

```
error[E058]: type 'Float' is not hashable — cannot be used as a Map key (it contains a Float)
```

```almide
fn main() -> Unit = {
  let m: Map[Float, Int] = [:]   // ← E058: Float keys have no stable equality
  println(int.to_string(map.len(m)))
}
```

The rule fires in the frontend so both targets agree — an unhashable key used
to pass `check`, then natively fail rustc's `Hash` bound while wasm silently
collapsed distinct keys (#598).

A key blocked by a **function** in its type (including a fn-typed field inside
a named record) is reported as [E016](../../../../diagnostics/E016.md), the closure-in-key class, with
its own wording.

The fix: key on hashable data (`String`, `Int`, `Bool`, or a record/variant of
those) and carry the unhashable value on the VALUE side:

```almide
fn main() -> Unit = {
  let m: Map[String, Float] = [:]   // Float as VALUE — allowed
  println(int.to_string(map.len(m)))
}
```
