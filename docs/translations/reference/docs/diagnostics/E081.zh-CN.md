# E081 — 函数在所选 wasm 目标上不可用

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E081.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E081.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E081.zh-CN.md)



> 原文：[`docs/diagnostics/E081.md`](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E081.md)，固定提交 `9a95b285`。这是面向读者的非规范性译文；CLI 诊断输出仍为英语。

所选 wasm 路径无法提供指定函数或已生成的宿主操作。可用性按路径区分：标准 preview1、直接 component 与嵌入式宿主并不公开完全相同的服务。当前矩阵为 `proofs/target-availability.toml`；CI 将声明的壁垒与 renderer 核对。应读取所选路径的原因，而非假定不存在任何 wasm 执行路径。

例如，标准 preview1 的 HTTP 客户端壁垒不意味着嵌入式宿主或 WASI 0.3 HTTP component 路径不存在。component 构建也会验证所选 shim 提供的操作。

存在可移植替代项时，诊断会指出它（`try:` 行，例如 `testing.assert_gt` → `assert(a > b)`），可用性矩阵对应行会记录它。每行还标明解除不可用状态的 `class`：`pending-self-host`（由自举函数体补齐）、`pending-port`（由宿主移植补齐，行中的 `issue` 指明哪一项）、`native-only-forever`（按规格该 fn 无法存在于 wasm 目标，行中的 `justification` 解释原因）。`host-capability` 行指出标准产物所需的私有 import：子进程支持在嵌入式宿主上使用 `almide:process/spawn`（ADR-0025），而非 wasm 的普遍禁令。两个 pending 计数在 CI 中只能减少。

直接 `--component` 构建也会在写出文件前，将生成的宿主操作与所选 p2 或 p3 shim 核对。失败会指出操作及 component 版本。例如，直接 p2 和 p3 当前缺少 argv import，因此通过 `args.option` 的调用会报告 `env.args`、`args.option` 和 host op 29。普通 preview1 构建提供 argv，不会被这项 component 专属检查拒绝。`almide check --target wasm` 检查标准构建路径，不选择 component profile。

native 或嵌入式执行可能提供所需宿主操作。
