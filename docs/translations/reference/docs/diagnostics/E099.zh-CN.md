# E099 — `testing.assert_aborts` 不在测试块的直接调用中

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E099.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E099.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E099.zh-CN.md)

`testing.assert_aborts(expected, f)` 是在子进程或新实例中运行 `f` 的测试断言（ADR-0029）。调用点标识子环境运行的闭包，测试框架报告判定，因此调用必须直接写在 `test` 块内——在其中嵌套于 `if`、`match`、`for` 或 lambda 内没有问题。三种形状会被拒绝：

- 在 `fn`（包括测试调用的辅助函数）、`main` 或顶层 `let` 中调用。程序没有可报告的测试框架，想中止的程序直接中止即可：

  ```almide
  import testing

  fn check_aborts() -> Unit = testing.assert_aborts("boom", () => panic("boom"))   // ← E099
  ```

- 隐藏调用点的第一类值用法：

  ```almide
  import testing

  test "a panic aborts" {
    let check = testing.assert_aborts                          // ← E099
    check("boom", () => panic("boom"))
  }
  ```

- 在另一个 `assert_aborts` 闭包内部调用；该闭包已经在子环境中运行，将需要孙环境。

## 诊断

```
error[E099]: testing.assert_aborts is called outside a test block
  in a call of testing.assert_aborts
  hint: assert_aborts runs only in a test: move the call into a `test "…" { }` block. A program that wants to abort just aborts.
```

## 修复

在测试中直接调用，每次中止对应一次调用：

```almide check
import testing

test "a panic aborts" {
  testing.assert_aborts("boom", () => panic("boom"))
  testing.assert_aborts("index out of bounds", () => [1][3])
}
```

## Fix-it 判定

**conditional** — 调用应当位于测试块，但属于哪个测试，以及辅助函数中的调用是否应变为每个测试位置的一次调用，由作者选择。（`mechanical` = 无人值守重写；`conditional` = 修复建议需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）
