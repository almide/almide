# E021 — 无效的记录构造或模式

[![English](https://img.shields.io/badge/English-d0d7de?style=flat-square)](E021.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E021.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-24292f?style=flat-square)](E021.zh-CN.md)



> 原文：[E021.md @ 9a95b285](https://github.com/almide/almide/blob/9a95b28519b90ae535dc9918bfed04805dc4675c/docs/diagnostics/E021.md)。这是供读者参考的非规范性翻译。CLI 内嵌的诊断说明仍使用英文原文。

记录（或以记录为载荷的变体分支）在构造或匹配时使用了错误的**形状**。记录通过**命名字段**构造；元组分支通过**位置参数**构造。在此检查出现之前，混用两者或指定不存在的字段会悄然破坏值（参数被丢弃，后续行为在各目标之间也不一致）。

`Cfg { name: "x" }`（花括号）是规范写法。`Cfg(name: "x")`（圆括号、命名参数调用语法）是接受的**别名**，会规范化为完全相同的构造，但仅适用于构造，而且仅限普通记录类型。变体的记录载荷分支（例如 `type Shape = Circle { radius: Float } | ...` 中的 `Circle { radius: Float }`）只能用花括号模式匹配，不能用 `Circle(radius)`，见最后一个示例。

<a id="common-cases"></a>

## 常见情况

对记录使用位置参数：

```almide
type Cfg = { name: String }
let c = Cfg("x")          // E021: 'Cfg' takes named fields, not positional arguments
let ok1 = Cfg(name: "x")  // ✓ normalized to the brace form
let ok2 = Cfg { name: "x" } // ✓
```

未知／重复／缺失字段（两种写法都会检查）：

```almide
type User = { name: String, age: Int = 0 }
let a = User { nmae: "x" }            // E021: 'User' has no field 'nmae'
let b = User { name: "x", name: "y" } // E021: field 'name' given more than once
let c = User { }                      // E021: missing field 'name' ('age' has a default — fine)
```

对元组分支使用命名参数，或用花括号构造元组分支：

```almide
type W = Wrap(Int) | E
let w = Wrap(value: 1)   // E021: constructor 'Wrap' takes positional arguments
let v = Wrap { x: 1 }    // E021: case 'Wrap' does not take named fields
```

对记录载荷分支使用圆括号模式：

```almide
type Tag = | SetEmotion { name: String } | Other
fn f(t: Tag) -> String = match t {
  SetEmotion(_) => "s",       // E021: use a record pattern
  _ => "o",
}
// ✓ write: SetEmotion { .. }  (or bind fields: SetEmotion { name })
```

<a id="why-this-is-an-error"></a>

## 为什么这是错误

按位置绑定命名字段，会在每次插入字段或调整字段顺序时悄然改变含义；而记录类型存在的目的正是承受这类修改。命名字段构造不依赖顺序，并会根据声明验证，因此拼写错误或必填字段缺失会在这里被发现，而不是泄漏为生成 Rust 的错误（`E0560`/`E0063`）或 wasm 陷阱。

<a id="fix-it-verdict"></a>

## Fix-it 判定

**not-fixable** — 此错误报告的是自动重写无法决定的语义／设计问题。（`mechanical` = 无人值守的修复器可以应用重写；`conditional` = 建议的修复需要审查；`not-fixable` = 不存在自动重写。遵循 #1486 的适用性原则。）
