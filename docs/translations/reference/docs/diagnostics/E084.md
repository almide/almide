# E084 — literal exit code outside the exit-status range

[![English](https://img.shields.io/badge/English-24292f?style=flat-square)](E084.md) [![日本語](https://img.shields.io/badge/%E6%97%A5%E6%9C%AC%E8%AA%9E-d0d7de?style=flat-square)](E084.ja.md) [![简体中文](https://img.shields.io/badge/%E7%AE%80%E4%BD%93%E4%B8%AD%E6%96%87-d0d7de?style=flat-square)](E084.zh-CN.md)

`process.exit` accepts the POSIX exit status, from `0` through `255`. When a
direct call passes an integer literal outside that range, the checker points to
the argument and rejects the program.

```almide
import process
effect fn main() -> Unit = process.exit(256) // E084
```

Choose `0` for success or a code from `1` through `255` for failure:

```almide
import process
effect fn main() -> Unit = process.exit(1)
```

This check includes module aliases, selective imports, pipe calls, radix
literals, parentheses, and unary minus. A computed argument is checked at
runtime. A value outside the range aborts with
`Error: exit code must be in 0..=255`. The checker does not evaluate arbitrary
expressions or follow aliases stored in function-valued variables.

The check is the same on every target. A WASI preview-1 build
(`almide build --target wasm`, run on a stock runtime) delivers only
`0..=125`. It refuses 126..=255 at runtime with
`Error: a WASI preview-1 build cannot exit with a code in 126..=255` and exit 1,
not at check time (C-350).

Dialect 4 (0.63) introduced this diagnostic over `0..=125`. Since #2780 the
range is `0..=255` again, which only accepts more programs, so no dialect
change was needed.

## Fix-it verdict

**conditional** — the appropriate failure code depends on the program's
protocol, so the compiler does not select a replacement automatically.
