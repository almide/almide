## 区分本记录与当前实现

本目录保存重设计的比较、采纳判定和改订顺序。下文“当前”“新增”“撤除”及函数数量，均以各次调查、裁定时点为准，不是当前未实现列表。后续轮次推翻的提案也保留，以免丢失理由。

- 当前可用名称、签名参见[标准库参考](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/stdlib/README.md)，迁移参见 [dialect epoch 台账](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/proofs/dialect-epochs.toml)。不要把 R-L0-14 的 epoch 15/16 计划读为全部 API 通用的当前撤除时间表。
- [target-surface](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/target-surface.md) 是由采纳提案组装的设计目标。[距离检查](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/scripts/check-stdlib-target.py) 比较名称、签名、弃用状态，不证明语义、性能、host 支持或完整协议层级已实现。
- 未完成构想仍保留。例如不能仅因达到函数列表就将 R-string-15 撤除 `slice` 默认参数、R-url-05 的 `userinfo`、`TimeAmount` 设想设计视为完成。R-map-04、R-zlib-03 等暂缓也保留。
- 将负数范围提取设为 abort 的旧裁定，应与后续 clamp 迁移（epoch 台账 #4147）区分。外部指针设计已推进到 [ADR-0031](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/adr/0031-raw-pointers-carry-provenance.md) 的 `Handle` / `Region`。

以下为当时记录。

这是将 Almide 标准函数 1,001 个（44 模块；第一轮统计 999 个，第二轮找到遗漏的 `bytes.heap_save`、`heap_restore`）与 9 种语言（Rust、Go、Python、TypeScript/JavaScript、Gleam、Elixir、OCaml、Kotlin、Swift）标准库并列复查的记录。此处不做实现。所有采纳案（○）均已建 issue。

第二轮（2026-10-22）：对重设计接口（[target-surface.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/target-surface.md)）按 L0 规则机械检查，并复查集合、数据格式、系统、数值四个领域，填补跨模块不一致及函数族空缺。对应 R-L0-22–26 和各 L2 第二轮提案。

第三轮（2026-10-22）：外部评审重设计列表，并与记录对照。修正记录错误（`net` 撤除后的目标名称），增加 R-L0-27/28、R-L1-30（`bool`）及各 L2 第三轮提案。已有理由支持的决定不变（`map.map` 回调、时间参数为 `Int` 毫秒、定宽类型不放算术函数等）。

第四轮（2026-10-22）：同样对照第二次外部评审。复查两次评审共同指出的拼写（`value.str`、`hash` 的 `_hex` 输入），改名、变更，并暂缓 R-L0-29（负位置 abort），等待 Dojo 测量。也修正列表生成错误（撤除列空迁移目标、截断注释、运算符脱糖目标行）。

第五轮（2026-10-22）：机械检查列表全部函数的命名统一性，每种职责确定一个参数名（R-L0-30）。再对照第三、第四次外部评审，将类型组按 `TimeAmount` 同样形态统一为协议（R-L0-31：`HttpMessage`、`Integer`、`FloatingPoint`、`Sized`），越界和窄化转换统一向“不静默返回不同值”靠拢（R-L0-29 从暂缓改采纳、R-L0-32/33、`map.update`、NaN 统一值）。重号的 `string.slice` 提案改编号为 R-string-15。不采纳和暂缓案连同理由汇总在 [target-surface.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/target-surface.md) 末表。

第六轮（2026-10-22）：第五、第六次外部评审重点指出规则、函数表、注释、采纳表之间的不一致。按 R-L0-32 改写旧规则（无标记转换回绕等），后案改变判定的 ×、暂缓案加“→ 当前有效提案”并另表列出。整数回绕改为 `_wrapping` 单元（R-L0-34，因为 `int.wrap` 不能处理 `UInt64` 上半区），按目标类型规定转换舍入（R-L0-35），明确每种类型宽度只有一个 NaN（R-float-10），`http.start` 改为接收构造好的请求（R-http-14）。仅以“类型错误”为不采纳理由的 `map.map` 暂缓，交 Dojo 测量（R-L0-36）。通过列表组装阶段检查阻止不一致复发（CI 门禁 issue #3997）。

第七轮（2026-10-22）：按 Swift 为范本的协议层级重组标准类型（R-L0-37、[protocol-view.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/protocol-view.md)）。补齐层级要求空缺，增加 164 函数（R-sized-10/11、R-bigint-07、R-bool-03、R-list-20、R-string-16、R-deque-03/04），将 `Repr` 方法改为 `to_string`（R-L0-38）。`Bool` 是否有序（R-bool-02）、`string.chars` 是否改为 `to_list` 暂缓，交 Dojo 测量。

第八轮（2026-10-22）：发现 `6 ^ 3` 静默乘方得 216 的陷阱，撤去 `^` 乘方，只保留 `**`（R-L0-39；Rust、Go、Python、JS、Swift 的 `^` 为 XOR）。位运算拼写（`band`、`bit_and` 或运算符）由 Dojo 测量决定（R-int-10）。[target-surface.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/target-surface.md) 增加协议函数只计一次的“实体数”（需记忆名称约 700）。

第九轮（2026-10-22）：清理剩余接口问题。数值转换变为目标类型的四个泛型函数 `from`、`from_checked`、`from_saturating`、`from_wrapping`（R-L0-40，与 Swift 四个初始化器相同；347 函数→44 函数）。位运算改为 `&`、`|`、`^`、`~`、`<<`、`>>` 运算符（R-L0-41，取消 `>>` 函数组合）。通过 `bit_width`→`bit_length`（R-int-11）、N bit 运算按类型宽度（R-int-12）、`map` 作为键值对 `Container`（R-map-09）、`regex.compile`（R-regex-11）、`string.to_list`（R-string-17）弥合接缝。重设计后 1,100 函数，需记忆名称 690。

第十轮（2026-10-22）：将原来仅 `list` 的 30 个序列算法（`enumerate`、`zip`、`sort`、`chunk` 等）作为 `Sequence`、`Ordered` 默认实现只写一次，使 `deque`、`set`、`string`、`bytes`、`map` 也能同名同形使用（R-L0-42，与 Swift `Sequence` 扩展相同）。将 `min`、`max`、`clamp` 移出 `Ord`（与 `duration.min` 冲突），为 `bytes` 补齐 `Text` 要求（R-bytes-27），统计子串的 `string.count` 改为 `count_matches`（R-string-18，与 `Container.count` 冲突）。每次生成都检查协议要求的参数名在各类型一致。

第十一轮（2026-10-22）：重新并列 9 种语言的 `Bool` 顺序，遵循 7 种有序语言（Rust、Python、JS、Gleam、Elixir、OCaml、Kotlin），将 `Bool` 纳入 `Ord` 并增加 `bool.compare`（R-bool-02 暂缓→采纳）。仅 Go、Swift 无顺序。暂缓项只剩 R-map-04 等待测量者。

第十二轮（2026-10-22）：确立“不以其他含义复用撤除符号”（R-L0-43）。撤销第九轮位运算符方案（R-L0-41），`^` 仅取消乘方别名并报错，`>>` 保持函数组合，位运算仍为函数（`band` 等），作为 `Integer` 要求（R-int-10）。也进行了全体机械检查（要求形态、改写动词、Bool 名称、类型参数名），将 `bytes.new(len)` 改为 `bytes.zeros(n)`，让 `bytes.new()` 统一为空字节串（R-bytes-28）。

兼容处理（R-L0-14）：改名、撤除在 epoch 15 标 `@deprecated(since=15, use=…)`，epoch 16 撤除。`almide fix` 机械改写能处理的部分，形态改变者给提示。
