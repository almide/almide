## Distinguishing this record from current implementation

This directory preserves redesign comparisons, decisions, and revision order. “Current,” “addition,” “removal,” and function counts below refer to each investigation/decision date, not today's unimplemented backlog. Later-overturned proposals remain to retain their rationale.

- For currently available names/signatures, see the [standard-library reference](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/stdlib/README.md); for migration, the [dialect epoch ledger](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/proofs/dialect-epochs.toml). Do not read R-L0-14's epoch 15/16 plan as the current universal removal schedule for all APIs.
- [target-surface](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/target-surface.md) is a design target assembled from accepted proposals. The [distance check](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/scripts/check-stdlib-target.py) compares names/signatures/deprecation, not proof of semantics, performance, host support, or complete protocol-hierarchy implementation.
- Unfinished concepts remain. Do not consider R-string-15's removal of `slice` default arguments, R-url-05's `userinfo`, or the intended `TimeAmount` design complete merely because the function list is reached. Holds such as R-map-04 and R-zlib-03 remain.
- Distinguish the old decision to abort negative range inputs from the later clamp migration (epoch ledger #4147). External-pointer design has advanced to [ADR-0031](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/adr/0031-raw-pointers-carry-provenance.md)'s `Handle` / `Region`.

The following is the record from that time.

This records reviewing Almide's 1,001 standard functions (44 modules; round one counted 999, but round two found omitted `bytes.heap_save`/`heap_restore`) alongside standard libraries of 9 languages: Rust, Go, Python, TypeScript/JavaScript, Gleam, Elixir, OCaml, Kotlin, Swift. No implementation takes place here. Every accepted proposal (○) has an issue.

Round two (2026-10-22): mechanically checked the redesigned surface ([target-surface.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/target-surface.md)) against L0 and reviewed 4 areas (collections, data formats, systems, numbers), filling cross-module inconsistencies and family holes. These are R-L0-22–26 and each L2's second-round proposals.

Round three (2026-10-22): external review of the redesigned list, reconciled against records. Corrected a record error (the `net` removal destination name); added R-L0-27/28, R-L1-30 (`bool`), and L2 third-round proposals. Already reasoned decisions stayed unchanged (`map.map` callbacks, time arguments as `Int` milliseconds, no arithmetic functions on fixed-width types, etc.).

Round four (2026-10-22): reconciled a second external review similarly. Revisited spellings identified by both reviews (`value.str`, `hash`'s `_hex` inputs), renamed/changed them, and held R-L0-29 (abort negative positions) pending Dojo measurement. Also corrected list-generation errors: empty migration destinations in removal columns, truncated notes, operator-desugaring-target rows.

Round five (2026-10-22): mechanically checked naming across every listed function, choosing one parameter name per role (R-L0-30). Reconciled third/fourth external reviews; grouped types into protocols like `TimeAmount` (R-L0-31: `HttpMessage`, `Integer`, `FloatingPoint`, `Sized`); aligned out-of-range/narrowing conversions toward “do not silently return another value” (R-L0-29 hold→accept, R-L0-32/33, `map.update`, one NaN value). Renumbered duplicate `string.slice` proposal as R-string-15. Rejected/held proposals and reasons appear in [target-surface.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/target-surface.md)'s final table.

Round six (2026-10-22): fifth/sixth external reviews focused on inconsistencies among rules, function tables, notes, and verdicts. Rewrote old rule wording (unmarked conversions wrap, etc.) to match R-L0-32; split later-overturned ×/held proposals into a separate table with arrows to now-effective proposals. Integer wrapping became `_wrapping` cells (R-L0-34; `int.wrap` cannot handle the upper half of `UInt64`); specified rounding by destination (R-L0-35), one NaN per type width (R-float-10), and `http.start` accepting a built request (R-http-14). For rejections based solely on type errors, hold `map.map` and measure in Dojo (R-L0-36). Checks when assembling the list prevent recurrence (#3997 for a CI gate).

Round seven (2026-10-22): reorganized standard types into a Swift-inspired protocol hierarchy (R-L0-37, [protocol-view.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/protocol-view.md)). Added 164 functions to fill requirement holes (R-sized-10/11, R-bigint-07, R-bool-03, R-list-20, R-string-16, R-deque-03/04); renamed `Repr`'s method to `to_string` (R-L0-38). Hold whether `Bool` is ordered (R-bool-02) and `string.chars`→`to_list` pending Dojo.

Round eight (2026-10-22): found the trap where `6 ^ 3` silently exponentiates to 216; removed `^` exponentiation, retaining only `**` (R-L0-39; Rust/Go/Python/JS/Swift use `^` for XOR). Measure bit-operation spelling (`band`, `bit_and`, operators) in Dojo (R-int-10). Added an entity count to [target-surface.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/target-surface.md), counting protocol functions once (about 700 names to learn).

Round nine (2026-10-22): cleaned remaining surface roughness. Numeric conversions became 4 destination-side generic functions `from`, `from_checked`, `from_saturating`, `from_wrapping` (R-L0-40, matching Swift's 4 initializers; 347→44 functions). Bit operations became operators `&`, `|`, `^`, `~`, `<<`, `>>` (R-L0-41; remove `>>` composition). Closed gaps with `bit_width`→`bit_length` (R-int-11), N-bit operations using type width (R-int-12), `map` as pair `Container` (R-map-09), `regex.compile` (R-regex-11), `string.to_list` (R-string-17). Redesigned total: 1,100 functions, 690 names to learn.

Round ten (2026-10-22): wrote 30 formerly `list`-only algorithms (`enumerate`, `zip`, `sort`, `chunk`, etc.) once as `Sequence`/`Ordered` defaults, usable with identical names/shapes on `deque`, `set`, `string`, `bytes`, `map` (R-L0-42; like Swift `Sequence` extensions). Removed `min`/`max`/`clamp` from `Ord` (collision with `duration.min`), supplied `Text` requirements on `bytes` (R-bytes-27), renamed substring-counting `string.count` to `count_matches` (R-string-18; collision with `Container.count`). Each generation checks that protocol requirement parameter names agree across all types.

Round eleven (2026-10-22): compared `Bool` ordering across 9 languages; following the 7 ordered ones (Rust, Python, JS, Gleam, Elixir, OCaml, Kotlin), added `Bool` to `Ord` and `bool.compare` (R-bool-02 hold→accept). Only Go and Swift lack ordering. Remaining holds are measurement-dependent items such as R-map-04.

Round twelve (2026-10-22): established “never repurpose removed symbols” (R-L0-43). Canceled round-nine bit operators (R-L0-41): `^` only loses exponentiation alias and errors; `>>` remains composition; bit operations remain functions (`band`, etc.) required by `Integer` (R-int-10). Mechanically checked the whole surface (requirement shapes, rewrite verbs, Bool names, type-parameter names); renamed `bytes.new(len)` to `bytes.zeros(n)`, making `bytes.new()` consistently empty bytes (R-bytes-28).

## Reading order

1. [L0: Rules common to all modules](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/L0-conventions.md) — naming, placement, in-place mutation, failure representation, conversion direction, compatibility. All lower-layer decisions derive from here.
2. [L1: Category (module) list](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/L1-categories.md) — categories added/not added, division of responsibilities.
3. L2/L3: per-module pages — role comparison tables (L2), verdict tables for every function (L3).
4. [Redesigned standard library](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/target-surface.md) — public functions after applying all ○ proposals, by module with signatures and migration destinations for removed functions.
5. [Protocol hierarchy](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/protocol-view.md) — Swift-inspired standard protocols, per-type conformances/holes, hierarchy decisions (R-L0-37).
6. Evidence: [facts/naming-conventions.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/facts/naming-conventions.md) (20 naming practices × 9 languages), [facts/categories.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/roadmap/stdlib-redesign/facts/categories.md) (about 100 categories × 9 languages).

Four decision axes: (a) excesses/gaps versus other languages; (b) works on both native (Rust) and wasm (WASI); (c) how easily LLMs write correctly; (d) change category and compatibility.

Compatibility (R-L0-14): rename/removal gets `@deprecated(since=15, use=…)` in epoch 15 and removal in epoch 16. `almide fix` mechanically rewrites what it can and hints when shapes change.
