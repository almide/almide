## 主張

> Almideで書いたプログラムは、どのような入力を受けても、メモリを破壊したり、攻撃者から与えられたコードを実行したり、
> マニフェストが許可するファイルと能力の範囲外へ誘導されたりすることがない。
> 信頼できない入力で失敗することはあっても、文書化した時間・メモリ上限の範囲内で、
> 定義済みのエラーまたは定義済みのabortになるだけである。

この主張を無条件で述べられるのは、下のすべての表のすべての行が**解決済み（closed）**になったときだけです。
その分類が構造上不可能か、ある仕組みが防止しており、その仕組みが働かなくなるとCIのゲートが失敗する必要があります。
それまでは本ページを参照として、分類ごとに主張します。
その状態でも信頼の対象として残るもの（Rocqカーネル、rustc / LLVM / wasmtime、ハードウェア、
`@extern`の背後のコード）は[proofs/TRUSTED_BASE.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/proofs/TRUSTED_BASE.md)と
[docs/contracts/proven-vs-trusted.md](https://github.com/almide/almide/blob/35297a612fb29e3f78f6587aba253aa91d51f466/docs/contracts/proven-vs-trusted.md)に列挙しています。
