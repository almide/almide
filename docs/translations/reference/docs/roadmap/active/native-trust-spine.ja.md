> 原文注記：7月14～16日の ladder は段階実装と部分集合の測定記録で、現行対応一覧、普遍的安全、資格化ではない。出荷済みチェック付き slab と未チェック親 rung、旧 recipe が併存し、record access の旧案 FieldGetScalar に対して出荷 slab は ListGetScalar を使う。rung6 の18/18は render できた18/249内で、org全体は0/61であり corpus 全対応ではない。scalar capture/signature は heap や Float closure 対応を意味しない。旧 fallback と検証 opt-out は末尾の現在拒否／structural-only注記に更新されており、回避を許可しない。shim 基盤と renderer 対応は範囲付き信頼義務として残り、均衡 checker は任意出力の正しさではない。binary・差分 corpus・proof・benchmark を再実行していない。


> 目標：`almide build --target rust` を wasm と同じ v1 Perceus MIR に流し、ownership に自然な Rust に render する。`Dup` → `.clone()`、`Drop` は Rust の scope 終端 drop に委ねて消去し、runtime 境界は閉じた native shim 基盤へ写す。`verify_ownership`（Lean と対応する checker）が、render が消去する同じ op の Perceus 均衡を証明する — Drop 消去 render 定理を build ごとに検査する。出荷の型は wasm と同じ opt-in→ladder→default。

<a id="architecture-findings-2026-07-14-rung-1"></a>

## アーキテクチャ所見（2026-07-14、rung1）

- user function は target 中立 MIR op（`IntBinOp`/`CallFn`/制御フロー/`Alloc`/`Dup`/`Drop`）へ lowering される。wasm 固有性は (a) prim/linear-memory ベースの self-host runtime fn、(b) heap handle repr に集中する。
- したがって native は user fn を直接 render し、runtime 境界名（`int.to_string`、`print_str`、`__chk_div` など）を閉じた native shim 基盤へ対応づける。v0 `runtime/rs` と同じ規律で、inline 再実装しない。
- prim ベース self-host 本体を native render する案は明示的に却下。Rust 内に linear-memory emulator を出すことになり、正しくても非慣用的で遅い。

## Ladder

- [x] **Rung1**（出荷済み、`--target rust` 上の `--verified` opt-in）：i64 scalar、String literal＋`int.to_string`、`println`、完全な scalar 制御フロー（値としての if、loop）、scalar user fn、C-001/C-002 abort shim。
  gate は `tests/native_v1_differential_test.rs`。corpus の v1 対 v0（stdout/stderr/exit）を byte 比較し、wall case は `Err` を assert。他の全箇所は正直な wall（最初の観測 wall は `__str_concat`）。
- [x] **Rung2**（出荷済み）：dynamic String op を shim 化（`__str_concat`、`string.eq`、`string.len` は codepoint 数）。user fn の String parameter/return は MIR call-mode signature に従い borrowed `&str` / owned `String`。String 値 if-join は最初の arm yield 時に decl を patch。pipeline には精密 wall：heap `Repr::Ptr` parameter/result を string として render するのは宣言 `Ty` がそう述べるときだけで、{Int, Bool, String, Unit-ret} 以外の signature は lowering 前に wall。
- [x] **Rung3**（出荷済み）：String 基盤を現時点で到達する全境界表面へ拡張：`string.contains` / `starts_with` / `ends_with` / `to_upper` / `to_lower` / `trim` / `repeat` / `cmp`。各 shim は v0 oracle とまったく同じ式なので C-016/C-019/C-020 規律を継承する。加えて `almide run --verified` の native 配線（`compile_to_binary_with`）。
- [x] **Rung4 — SCALAR LIST、共有 MIR op 経由で出荷済み（2026-07-15、ceangal/module-var 作業系列が予定どおり構築）**：target 中立 op3個 `Op::ListLit { dst, elems }` / `ListGetScalar { dst, list, idx }` / `ListSetScalar { list, idx, val }` が、inline `Alloc{DynList}`＋`Handle`/`ElemAddr`/`Load|Store` prim 列を3 producer（scalar literal builder、`lower_scalar_index_access`、mutable-global 経路を含む IndexAssign store）で1対1置換。render_wasm は各 op を従前と厳密同一 WAT へ展開し挙動不変。RATCHET0＋KERNEL が全 corpus を再検証、cert stream は不変：ListLit は alloc-class `i`、get/set は中立 borrow なので Coq 語彙は変わらない。native は宣言型から pipeline が作る SIG-KIND 表で `Vec<i64>`/`&[i64]` に型付け（heap `Repr::Ptr` だけでは String と List を区別できない）。bounds shim は `$elem_addr_chk` と byte 同一 abort（"Error: index out of bounds"、exit1）。差分 corpus は list_param / list_index_math / list_set。範囲は `List[Int]`/`List[Bool]` signature、Float list は rung5 の f64 規約に従う。`list.len` は self-host CallFn のまま（既に target 中立、op化するかは4bが決める）。
- [ ] Rung4 残り（記録として元設計注記を保存）：v1 lower は list literal を `Alloc{DynList}`＋inline `Prim` store として実体化し、実体化 list への直接 `xs[i]` prim load を受け入れる。list 世界は設計上 prim 基盤より下なので、boundary-name mapping では native に届かない。native renderer で prim idiom を pattern-match する案は却下（op 忠実性でなく推測）。経路は target 中立 list op（例 `Op::ListLit`/`ListGet`/`ListLen`/`ListSet`）を導入し、render_wasm は現在の prim 列へ厳密同一 lowering（既存 gate で byte 一致を保護）、native は `Vec` op へ写す。ceangal/module-var 系列が現在編集する同じ `lower/binds*` brick に触れるので、並行別作業ではなく同系列と共同で行う。
- [ ] Rung5：record/variant（native struct/enum）、closure。
  **Records slab 出荷済み（2026-07-15 遅い時間）**：scalar-record literal は `Op::ListLit` 経由（宣言順 slot、default はゼロ埋め。`try_lower_scalar_record_construct` は `materialized_aggregates` を維持）。scalar field 読みは静的 slot index 付き `Op::ListGetScalar`（`lower_scalar_field_access`、tuple 経路も含む。pre-Handle block resolver は `resolve_aggregate_container_block` に分離）。pipeline は `try_render_rust_source` へ record/variant layout を渡し、全 scalar の `Named` record を `NativeSigKind::ListI64` として受け入れる。native は record block を `Vec<i64>`/`&[i64]` に render。mask 駆動 `DropListStr` record drop は scope 終端へ消去（全 scalar ⇒ empty mask）。3方向 byte 一致、差分行 record_field / record_out_of_order / record_return / record_float_field、classify wall-list も byte 一致。
  **Variants slab 出荷済み（2026-07-15 夜）**：flat-variant ctor は `Op::ListLit` で構築（slot0 tag＋field＋型幅へのゼロ埋め。heap-field ctor は prim 経路を維持。tracking も厳密に prim と一致：needs_rec→variant_drop_handles、materialized_aggregates）。match 読み：slot0 tag と全 scalar payload は subject block 上 `Op::ListGetScalar`（value-match non-unwrap 経路、unit-match、bind_variant_arm）。heap payload bind は h ベース LoadHandle を維持。native は DEAD-PURE-HANDLE 除去を追加：scalar-only match は渡された `Prim{Handle}` を未使用にし、Handle は pure なので未使用なら no-op render、使用された場合は引き続き正直に wall。3方向 byte 一致（variant_match / variant_nullary / variant_multi_payload）、classify wall-list も一致。最初の gate REJECT（kernel checker）は `loop_carried_slots` の ListLit-feeder gap。certificate.rs はそこでも ListLit を alloc-class として扱うようになった（record 再代入の `idd`＋`i` 分割）。
  **Closures slab 出荷済み（2026-07-16 夜）**：scalar-capture env block は `Op::ListLit`（[fnidx, drop-header=0, captures…]、lift_lambda fast path）で構築。heap/closure capture は prim Dup/Consume 経路を維持。lambda prologue の scalar-capture load と call-site fnidx（slot0）は `Op::ListGetScalar` 経由。native render：`Op::FuncRef` は lambda の名前順 index（`let vN: i64 = K`）、`Op::CallIndirect` は生成 `__almd_ci_<arity>(idx, env, args…)` dispatch 表（arity ごとに1つ、def/call が同じ BTreeMap 順序から index 空間を導くので構成上一致。i64-return lambda のみ arm を持ち、heap-return CallIndirect は dispatch 前に wall）。Vec の `DropVariant("closure")` は scope 終端へ消去（drop header0なので再帰 free なし）。signature 受入：`(Int|Bool…) -> Int|Bool` Fn 型→ListI64（env block は `Vec<i64>`）。lifted lambda は MirParam repr から [ListI64, I64…] parameter kind を登録（heap parameter は dispatch arm が型付けできないためプログラムを wall）。3方向 byte 一致（closure_capture / closure_two_envs / closure_multi_arg）。次の境界は heap-capture env block（prim 経路）、heap-param/-ret lambda（typed dispatch 表）、Float capture。
  **Rung6 計測＋default 切替（2026-07-16）**：v1 native renderer が default（`--no-verified` は両経路 opt-out、診断は `ALMIDE_VERIFIED_DEBUG`）。根拠は12差分行の3方向 byte 一致（差分 v0 oracle は `--no-verified` 固定。切替後の素の `almide run` は v1-first）、加えて spec/wasm_cross native sweep は **18/249 fixture が render、18/18 byte 一致**。sweep は実乖離1つを発見：`rt_chk_mod` が "modulo by zero" を出したが v0/wasm C-002 oracle は "division by zero"、切替前に修正。ORG native 列は **0/61 org source file が render**（yaml/sha1/toml/svg/rsa/base64/bigint/aes/ceangal/almai/homullus/porta）。scalar core＋rung5 の4 slab という subset はまだ org 級コードに届かない。probe の初期 blocker は `Bytes` parameter（sha1/base64/aes）、multi-module＋top-let（ceangal/porta/homullus）、Map/String 多用 stdlib。全箇所 honest wall→v0 なので、verified subset 外は切替による挙動変更ゼロ。次の測定道具は関数単位 native classifier（wasm classify_corpus 相当）で、org 列を program 全有無でなく fn 単位 coverage にする。
  **元 variant recipe 注記（保存）**：ctor block は同じ DynList（slot0=tag、slots1+=payload。`try_lower_variant_ctor` の Alloc+stores→先頭 tag const 付き ListLit）。match 分解は tag Load(slot0)＋Eq dispatch＋payload load（binds_p4:451/538 の分解箇所→ListGetScalar）、signature 受入は scalar-payload variant→ListI64、drop は native 上 `DropVariant` 消去 arm（scalar payload ⇒ block free）。
  **Record/variant 偵察（2026-07-15、layout を渡した実 lower 経路の probe_native --mir）**：scalar record は list と同じ DynList block（12-byte header＋8-byte slot、`Init::DynList`）へ lowering。field 読みは raw `Handle + Add(12 + 8*slot) + Load` prim 列、rung4 が list で解いた prim 基盤以下の class。したがって record slab は懸念より小さい。scalar-record literal は `Op::ListLit` をそのまま再利用でき（同 block、同 cert `i`）、field 読みは新 op1つ `Op::FieldGetScalar { rec, slot }`（静的 offset、bounds checkなし、wasm は今の prim 列と byte 同一、native `rec[slot]`）だけが必要。prim 列は複数 lower 箇所（binds.rs:672、calls_p2.rs:1270、binds_p4.rs:451/538、defunc_tuple_fold.rs×2）から出る。classify wall-list byte gate に対して1箇所ずつ op 化する。variant ctor は合成関数への `CallFn "<Ctor>"`（assembler 側）で、本体は prim store。同じ op 化で解放し、その後 match 分解の tag-dispatch lowering を監査する。注意：最初の probe は layout なし `lower_function_all` を使い record を lowering gap と誤読した。常に `lower_function_all_with_globals` から dump する（修正後 `debug_dump_mir` はそうする）。
  **Float slab 出荷済み（2026-07-15）**：`NTy::F64`/`NativeSigKind::F64`。float literal は bits 型 `i64` local のまま、各 float-op 境界で変換（`f64::from_bits`、bit exact）。FloatBin Add/Sub/Mul/Div、FloatUn Neg/Abs/Sqrt/Floor/Ceil、FloatCmp はすべて IEEE hardware 上 cross-target 一致。Min/Max/CopySign は wall（Rust/wasm NaN semantics の差。native render しない self-host 本体からしか到達しない）。`float.to_string` は v0 oracle と厳密同一の式に shim。差分行 float_print / float_arith / float_branch / float_fn_param と、3方向 probe（v0-native==v1-native==wasm）。rung 開発 tool として `debug_dump_mir`＋examples/probe_native.rs を追加。
  **元設計注記（記録用に保存）**：MIR は Float を f64 の bits を入れた i64 local として保持（`PrimKind::FloatUn/FloatBin` が op ごとに再解釈、render_wasm_p2 831-851）。native の「本当の f64」に必要なのは (1) `NTy::F64`＋`NativeSigKind::F64`（sig 表は `Repr` で区別できない宣言 Ty を既に区別）、(2) internal local 型付け：FloatBin/FloatUn または Float-kind param/call-result が生成したときだけ F64（`Str`/`Vec` local と同じ op 駆動推論）、(3) `FBits`/`FFromBits` prim を `f64::to_bits`/`from_bits` にする（consumer が対応する reinterpret なら no-op）、(4) shim：`float.to_string` → v0 と同じ `almide_rt_float_to_string`（Dragon4、byte 一致）。literal の `prim.ffrombits(<const>)` は厳密 f64 定数へ fold。差分行は float literal print、算術 chain、compare/branch、fn param/return、`float.to_string` round-trip。gate は corpus を増やし、`out_of_subset_walls_honestly` で現在 assert される `float` 行だけ wall を縮める。
- [x] Rung6（2026-07-16）：org byte-verify native 列を正直に測定 — 0/61ファイル（Bytes param、multi-module＋top-let、Map/String stdlib が最初の wall。次は per-fn native classifier）。

<a id="intended-invariants-and-their-evidence-boundary"></a>

## 意図する不変条件と証拠の境界

- subset 外拒否は意図した受入境界であり、受け入れた全プログラムの render 正しさの証明ではない。ownership check と差分 test は宣言された性質／fixture を覆い、任意出力の正しさは覆わない。
- 上記 v0 fallback と `--no-verified` は歴史的 rung 記録。現在の `--no-verified` は拒否され（`src/main.rs`）、Wasm 経路は structural-only（`src/wasm_route.rs`）。旧 option は検証回避の手順ではない。
- `verify_ownership` は render 前に全 lowered fn で走る。
- 差分 gate corpus は増加のみで、rung は corpus 行と共に出荷する。
- shim 基盤は閉じた map（`render_native.rs::shim`）。追加は trusted-floor 変更なので同じ PR に差分行が必要。
