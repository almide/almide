# E049 — `let ... in <expr>` is OCaml/Haskell syntax

Almide has no `in` keyword. Bindings chain by newline inside a block, and the
block's trailing expression is its value — so the `in` that OCaml, Haskell and
F# put between a binding and its body has nothing to separate here.

```almide
fn sum_digits(n: Int) -> Int =
  let abs_n = int.abs(n)
  in if abs_n == 0 then 0            // ← E049: `let ... in <expr>` is OCaml/Haskell syntax
     else (abs_n % 10) + sum_digits(abs_n / 10)
```

## Fix

Delete the `in`. What follows it is already the newline-chained continuation:

```almide
fn sum_digits(n: Int) -> Int =
  let abs_n = int.abs(n)
  if abs_n == 0 then 0
  else (abs_n % 10) + sum_digits(abs_n / 10)
```

Several bindings chain the same way — one per line, no separator:

```almide
fn area(w: Int, h: Int) -> Int = {
  let width = int.abs(w)
  let height = int.abs(h)
  width * height
}
```

## Diagnostic shape

```
error[E049]: `let ... in <expr>` is OCaml/Haskell syntax
  in let ... in
  here: in if abs_n == 0 then 0
  hint: In Almide, multiple lets chain by newlines inside a block — no `in` keyword.
  try: delete the highlighted text (machine-applicable — `almide fix` applies it)
```

The fix-it is **machine-applicable** and anchored to the `in` keyword plus the
blanks after it, so `almide fix <file>` deletes every one of them mechanically
and touches nothing else. The deletion is a pure re-spelling: the program it
produces is the program the `in` form denoted.
