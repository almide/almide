# E082 — the wasm leg cannot lower the program on --target wasm

`--target wasm` has one engine: the structural leg (`crates/almide-wasm`).
E082 means it **declined** the program on the route taken — the stock-WASI
build (`almide build`) or the embedded host (`almide run`). The reason is
printed on the error line and again on the machine-readable `wall:` line,
with the function it came from on the `-->` line (#2807). On the build
route, for example:

- a shape the emitter does not lower (`list-push-nonvar` — a mut op through a
  deeper field path such as `o.inner.xs`);
- an emitted host op the p1 `to_wasi` shim has no stock-WASI service for
  (`host op N has no stock-WASI service`; the fs ops are served there since
  #2742);
- a declared `@export(wasm, "sym")` whose body does not lower, or two exports
  claiming one name.

Until #2752 a program the structural leg declined was handed to a second
renderer (the incumbent v1 leg), and E082 meant that BOTH had refused
(#1922). That fallback is gone: there is no second leg, so a decline is the
whole verdict, never a silent change of renderer. The code keeps its number
(a program that was E082 before is E082 now; one that the fallback used to
serve is now E082 too).

```text
error[E082]: the wasm target cannot lower this program: list-push-nonvar
  --> in main (app.almd:5)
  note: this is the stock-WASI BUILD route; `almide run --target wasm` (the embedded host serves every op) may still run it
  note: `almide check --target wasm` reports this verdict at check time; the native target (`--target rust`) is unaffected
wall: list-push-nonvar
```

`almide check --target wasm` runs the same route without
building and reports E081 / E082 at check time — measured by the build
path itself, never a declared table, so it cannot drift from what
`build` does. On the build route the note names the embedded host as the
route that may still run the program (its shim serves every op; the
shape wall is the remaining ingredient). The same program always builds
with `--target rust`.

## Fix-it verdict

**not-fixable** — the fix is a platform decision (run through the
embedded host, run natively, or restructure the walled shape), not a
rewrite an unattended fixer may apply. (`mechanical` = an unattended
fixer may apply the rewrite; `conditional` = a suggested fix needs
review; `not-fixable` = no automatic rewrite exists. #1486's
applicability doctrine.)
