# E082 — both wasm legs refuse the program on --target wasm

`--target wasm` tries two verified engines: the structural leg (the
default) and the incumbent v1 leg. E082 means **both refused** the program
on the route taken — the stock-WASI build (`almide build`) or the embedded
host (`almide run`). The two reasons are printed above the code, one per
leg, because they are usually different; on the build route, for example:

- the structural leg lowered the program but an emitted host op has no
  stock-WASI service (`host op N has no stock-WASI service`) — the p1
  `to_wasi` shim carries the env/args/stdio/random/clock/sleep surface,
  not fs (#1921's op audit);
- the incumbent leg walled on the program's SHAPE (`fan.map consumed by
  \`!\` with a propagating callback`, and kin — the MIR-lowering subset).

Neither reason alone refuses the build: a plain `fs.read_text` program takes
the incumbent's WASI rendering, and a `!`-consumed `fan.map` without host
ops takes the structural leg. The conjunction is what E082 names (#1922).

```text
wall: main is outside the MIR-lowering subset: fan.map consumed by `!` with a propagating (!) callback body is not lowered by the incumbent leg (the structural leg serves it)
wall (structural leg, the default): host op 1 has no stock-WASI service (the embedded host — `almide run --target wasm` — serves it)
error[E082]: both wasm legs refused this program — …
  note: this is the stock-WASI BUILD route; `almide run --target wasm` (the embedded host serves every op) may still run it. …
```

`almide check --target wasm` runs the same routing decision without
building and reports E081 / E082 at check time — measured by the build
path itself, never a declared table, so it cannot drift from what
`build` does. On the build route the note names the embedded host as the
route that may still run the program (its shim serves every op; the
shape wall is the remaining ingredient). The same program always builds
with `--target rust`.

## Fix-it verdict

**not-fixable** — the fix is a platform decision (run through the
embedded host, run natively, or restructure the walled shape), not a
rewrite an unattended fixer may apply. (`mechanical` = an unattended
fixer may apply the rewrite; `conditional` = a suggested fix needs
review; `not-fixable` = no automatic rewrite exists. #1486's
applicability doctrine.)
