# E114 — a generic fn reaches itself at a growing type

A generic fn is compiled once for each type it is called at. A fn that calls
itself — directly, or through other generic fns — with a type built from its
own type parameter needs a new instance for every level of the recursion,
and there is no last one (#4287):

```almide
fn depth[T: Hash](x: T, n: Int) -> Int =
  if n <= 0 then 0 else 1 + depth((x, x), n - 1)   // ← E114
```

```
error[E114]: `depth` calls itself at a growing type: its `T` is `(T, T)` at this call
  hint: A generic fn is compiled once for each type it is called at, so a recursion whose type grows with every call needs an instance for every level and never ends. Recurse at the type `depth` was called with: collect the values in a `List[T]`, or count the levels in an `Int`.
```

The same code covers a cycle through several fns (`wrap[T]` calls
`unwrap([x])`, `unwrap[U]` calls `wrap(y)`): the message names the fns the
cycle runs through.

Recursion at the same type passes, as does a cycle that only renames or swaps
type parameters (`f[A, B]` calling `f(b, a)`): those need finitely many
instances.

## Fix

Recurse at the type the fn was called with:

```almide
fn depth[T: Hash](xs: List[T], n: Int) -> Int =
  if n <= 0 then 0 else 1 + depth(xs + xs, n - 1)
```

## Why

Before this check the program passed `almide check`, monomorphization made a
single instance and kept the self-call in it at the wrong type, and the first
error was the backend's: E082 on `--target wasm`, rustc's E0308 natively. The
rule is the expanding-cycle check: a cycle of generic calls with a type
parameter that grows on some edge is refused, a cycle whose parameters are
passed on unchanged is not.

Fixtures: `tests/diagnostics/e114-self-recursion-at-growing-type`,
`e114-mutual-recursion-at-growing-type`.

## Fix-it verdict

**not-fixable**: what the recursion should carry instead is a decision about
the program. (`mechanical` = an unattended fixer may apply the rewrite;
`conditional` = a suggested fix needs review; `not-fixable` = no automatic
rewrite exists. #1486's applicability doctrine.)
