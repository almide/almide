# E045 — tuple index on a non-tuple, or out of range

`.k` positional access is defined only on tuple values, and only for indices
below the tuple's arity. Both misuses previously passed `almide check`
("No errors found") with the expression left `Unknown`-typed, then died at
build behind the ConcretizeTypes banner — which told the user their own type
error was a compiler bug and to file an upstream report (#1266). The checker
now rejects both up front, naming what it saw.

```almide
let n = 5
let a = n.0        // ← E045: tuple index .0 on non-tuple type Int

let t = (1, 2)
let b = t.5        // ← E045: tuple index .5 is out of range for (Int, Int)
                   //         (valid: .0 through .1)
```

An object whose type is still an open inference variable (a lambda parameter
awaiting its call site) is NOT rejected here — the index is deferred and
resolved once the union-find binds the tuple type, so chains like
`xs |> list.map((p) => p.1)` keep working.

## Fix

Index a tuple, within its arity — or destructure instead of indexing:

```almide
let t = (1, 2)
let b = t.1

let (x, y) = t
```
