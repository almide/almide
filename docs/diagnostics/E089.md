# E089 — the value has no defined string form

A `${…}` segment renders through one of two routes: `Display` (the numbers,
`Bool`, `String`) or the Almide-literal repr (`List`, `Map`, `Set`, `Option`,
`Result`, tuples, records, variants). A type with neither has no text to
produce — and never produced any: such a segment used to pass `almide check`
and then fail the native build with a rustc `E0277` ("doesn't implement
`std::fmt::Display`"), while both wasm legs refused the shape. E089 is that
failure, moved to check time where it names the fix.

The types with no string form:

| Type | Why | Interpolate instead |
|---|---|---|
| `Bytes` | octets, not text | `${bytes.to_list(b)}`, `${bytes.to_string_lossy(b)}`, `${int.to_string(bytes.len(b))}` |
| `Unit` | carries nothing | drop the segment; a `println` / other Unit-returning call has no text |
| `Matrix` | numeric block | `${matrix.to_lists(m)}`, `${matrix.rows(m)}x${matrix.cols(m)}` |
| a raw pointer | an address is not stable text | the `Bytes` it came from, or the length |
| a function value | code, not data | call it: `${f(x)}` |

An opaque newtype (`mod type Blob = Bytes`) has its TARGET's string form —
it renders the value it wraps, at every position — so a newtype over one of
the rows above is the same gap, and the message names the wrapper.

A container, tuple, record or variant that HOLDS a function value or a raw
pointer has none either — the repr would have to render the held value. The
message names the field or case that holds it. `Bytes`, `Unit` and `Matrix`
inside a container DO render (`[[1, 2]]`, `some(())`, `[matrix.from_lists([[0]])]`):
those three are gaps at the top level only.

```almide
effect fn main() -> Unit = {
  let u = ()
  println("u=${u}")            // ← E089: a Unit value has no defined string form
}
```

## Through a generic

A generic body is checked once, with its parameters rigid, so the segment's
type there is `T` — fine for `show(1)`, impossible for `show(bytes)`. The
segment becomes a requirement on the function, and each CALL is judged
against it once its type arguments are known:

```almide
fn show[T](v: T) -> String = "v=${v}"

effect fn main() -> Unit = {
  println(show(1))                          // fine
  println(show(bytes.from_list([1, 2])))    // ← E089, reported at this call
}
```

The message names both ends — the segment inside the generic and the call
that instantiated it — and the calls in between when the requirement travelled
through several (`wrap` calling `show`). The diagnostic is anchored on
whichever end is in the file being checked.

## Fix

Interpolate what you mean: the octets, the rows, the length, the result of
calling the function. When the value really is the thing to show and the
type is yours, give it a printable form — a record or variant renders
structurally, so a wrapper record with data fields interpolates.

## Fix-it verdict

**not-fixable** — the error reports a semantic/design problem no automatic rewrite can decide. (`mechanical` = an unattended fixer may apply the
rewrite; `conditional` = a suggested fix needs review; `not-fixable` = no
automatic rewrite exists. #1486's applicability doctrine.)
