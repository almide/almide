# E008 — a concurrently-run body reaches a `var`

A body that may run at the same time as other invocations of itself reads
or writes a `var` declared outside it. Concurrent bodies are:

- every arm of a `fan { … }` block, and of the `fan.settle`, `fan.race`,
  `fan.bounded` and `fan.timeout` block forms;
- every fn-valued argument of `fan.map`, `fan.settle`, `fan.any`,
  `fan.any_map` and `fan.race`;
- the handlers given to `http.serve`, `http.route`, `http.mount` and
  `http.wrap` (handler and middleware);
- a parameter of your own fn that is passed on to one of the above
  (`fn serve_on(port: Int, h: HttpHandler) = http.serve(port, h)` makes `h`
  a handler slot of `serve_on`, and the check moves to its callers).

"Reaches" follows what the body can run: the fns it calls, the closures it
reads from a `let` (local or top-level, including closures stored in records
and lists), and closures a factory returns. A `var` declared inside the body,
or inside a fn the body calls, is per invocation and fine. A lambda passed
straight to a stdlib callback such as `list.map` runs inside the body that
contains it, so it may use that body's `var`s.

## Common cases

```almide
effect fn broken() -> Int = {
  var count = 0
  fan {
    count = count + 1         // E008: the arm reaches `count`
    count = count + 2
  }
  count
}
```

```almide
import http

var hits = 0

effect fn bump() -> Int = {
  hits = hits + 1
  hits
}

// E008: the handler reaches `hits` through `bump`
let app = http.router([http.route("GET /", (req) => http.response(200, "n=${bump()!}"))])

effect fn main() -> Unit = http.serve(8080, app!)!
```

## Diagnostic

```
error[E008]: cannot capture mutable variable 'count' inside fan block
  hint: Use a `let` binding instead of `var` for values shared across fan expressions
```

```
error[E008]: this fan.map callback can reach `total`, a `var` — fan bodies run concurrently
  in the callback passed to fan.map
  hint: return each element's contribution and combine the results after the fan, e.g. `fan.map(xs, f)! |> list.sum`, or bind a `let` copy of the value before the fan
```

```
error[E008]: this handler can reach `hits`, a `var` — handlers run concurrently
  in the handler passed to http.route (reached through fn `bump` at line 5)
  hint: a handler cannot share mutable state between requests. For a value fixed before serving, use a top-level `let` instead of `var`, or bind a `let` copy before the handler
```

The context names the site and, when the `var` is reached through other fns,
the path to it. When the `var` is never assigned anywhere, the hint says so
first: declaring it `let` is the whole fix.

## Fix

- Compute each branch or element independently, then aggregate the results
  after the fan:
  ```almide
  effect fn fixed() -> Int = {
    let (a, b) = fan {
      compute_a()
      compute_b()
    }
    a + b
  }
  ```
- For a value the body only reads, bind a `let` copy before the site
  (`let scale = scale0`); a `let` taken outside the body is a snapshot.
- A value fixed before serving is a top-level `let`, not a `var`. A `let`
  copy in main does not help a served handler: the app passed to
  `http.serve` may read no local of main (E095).

## Why

Concurrent writes to the same `var` produce undefined-order updates, and a
read races with them. Almide rejects the pattern at the checker rather than
emitting racy code, so the substrate a fan or a server runs on can change
without changing what the program means. `let` bindings are always safe to
read from a concurrent body; only `var` is restricted. This rule is dialect
epoch 6 (`proofs/dialect-epochs.toml`); before it, only a `fan { … }` arm
capturing a `var` directly was E008.

## Fix-it verdict

**conditional** — when the reached `var` is never assigned, declaring it `let` is the fix; otherwise the state has to move out of the concurrent body, which needs review. (`mechanical` = an unattended fixer may apply the
rewrite; `conditional` = a suggested fix needs review; `not-fixable` = no
automatic rewrite exists. #1486's applicability doctrine.)
