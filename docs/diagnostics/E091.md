# E091 — `var` does not destructure

`var` binds exactly one name (GRAMMAR.md: `var_stmt = "var" IDENT …`). The
patterns `let` accepts — a tuple `(x, y)`, a record shorthand `{ a, b }` — are
not available after `var`.

```almide
effect fn main() -> Unit = {
  let at = (1, 2)
  var (x, y) = at      // ← E091: `var` does not destructure
  x = x + 1
  println("${x} ${y}")
}
```

Before E091 this read "Expected identifier … check the token just BEFORE this
position", which points at a syntax slip that is not there, and every name in
the pattern then failed again as E003 at its first use. E091 names the rule
once. The parser recovers by binding each name as a `var` of its component, so
the names in the pattern raise no further errors.

## Fix

Bind each name with its own `var`:

```almide
var x = at.0
var y = at.1
```

If none of the names is reassigned, `let` destructures:

```almide
let (x, y) = at
```

When the value is a call, name it once and project from the name, so the call
runs once. A projection after a tuple index is parenthesized, because `p.1.0`
lexes `.1.0` as a float literal:

```almide
let p = decode_run(at)
var x = p.0
var last = (p.1).0
```

## Diagnostic shape

```
error[E091]: `var` does not destructure
  in var pattern
  here: var (x, y) = at
  hint: var does not destructure; bind each name (`var x = at.0`), or use `let (x, y) = at` if they need not change
  try:
      var x = at.0
        var y = at.1
```

When the statement is on one line and the value is a plain name, the
one-`var`-per-name rewrite is span-exact. The `var` → `let` rewrite is attached
as an alternative. Both are suggestions, and `almide fix` applies neither one
unattended.

## Fix-it verdict

**conditional**: both rewrites are exact, but choosing one is the author's
decision. One `var` per name keeps every name reassignable. `let` makes them
all immutable and is correct only when nothing reassigns them. (`mechanical` =
an unattended fixer may apply the rewrite; `conditional` = a suggested fix
needs review; `not-fixable` = no automatic rewrite exists. #1486's
applicability doctrine.)
