# E120 — a `??` whose grouping changed at dialect 16

Since dialect 16 every binary operator follows one widely used precedence
order (#4531). `??` is an infix level below `|>`, the ranges and the
arithmetic, and above the comparisons, `and` and `or`. Before, it bound
tighter than every binary operator: it took the postfix chain right before it
as its value and one prefix expression after it as its fallback.

The same text can therefore mean two things:

| text | before dialect 16 | since dialect 16 |
| --- | --- | --- |
| `x ?? 0 - 1` | `(x ?? 0) - 1` | `x ?? (0 - 1)` |
| `map.get(m, k) ?? 0 + 1` | `(map.get(m, k) ?? 0) + 1` | `map.get(m, k) ?? (0 + 1)` |
| `s + b ?? 0` | `s + (b ?? 0)` | `(s + b) ?? 0` |
| `-x ?? 0` | `-(x ?? 0)` | `(-x) ?? 0` |
| `xs \|> f ?? d \|> g` | `((xs \|> f) ?? d) \|> g` | `(xs \|> f) ?? (d \|> g)` |

Both readings usually type-check, so a file written for the old grouping
would change meaning without a word. In a file that is not stamped
`@dialect(16)` (or later), each such `??` is refused:

```almide
fn bump(mut m: Map[String, Int], k: String) -> Unit = {
  m[k] = map.get(m, k) ?? 0 + 1   // ← E120
}
```

```
error[E120]: this `??` groups differently since dialect 16: the same text meant something else before
  hint: Since dialect 16 `??` binds looser than `+ - * / % ^ >>`, the ranges and `|>`, ...
```

`??` next to a comparison, `and` or `or`, after a pipe (`xs |> f(a) ?? d`), or
with a single-expression value and fallback (`f(x) ?? -1`) reads the same in
both dialects and is never refused.

## Fix

Write the parentheses for the reading you mean:

```almide
fn bump(mut m: Map[String, Int], k: String) -> Unit = {
  m[k] = (map.get(m, k) ?? 0) + 1
}
```

`almide fix` adds the parentheses that keep the reading the file was written
for. It reads the file with the pre-16 grammar, prints it with the
parentheses, and keeps the result only if the current grammar reads it back
as the same program.

A file stamped `@dialect(16)` was verified against the new grammar
(`almide check --stamp` writes the stamp only after the file checks clean),
so it takes the new reading without this check.

## Fix-it verdict

**conditional** — `almide fix` adds the parentheses that keep the pre-16
reading, and keeps them only if the current grammar reads the result as the
same program. That is the right repair for a file written before dialect 16;
for one written for the new grammar the other reading may be the one meant,
so the diagnostic itself carries no machine-applicable repair.
(`mechanical` = an unattended fixer may apply the rewrite; `conditional` = a
suggested fix needs review; `not-fixable` = no automatic rewrite exists.
#1486's applicability doctrine.)
