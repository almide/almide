# E047 — invalid escape in a string literal

A `\` inside a string literal starts an escape. Almide defines exactly these:

| escape | in | means |
|---|---|---|
| `\n` `\t` `\r` | `"…"` `'…'` `"""…"""` | newline, tab, carriage return |
| `\\` | all | one literal backslash |
| `\"` | `"…"` `"""…"""` | a double quote |
| `\'` | `'…'` | a single quote |
| `\$` | `"…"` `"""…"""` | a literal `$` (suppresses a `${…}` hole) |
| `\xNN` | all | a codepoint in `0x00..0xFF`, exactly two hex digits |
| `\u{…}` | all | any Unicode scalar value, one to six hex digits |

Anything else is E047. A raw string (`r"…"`, `r"""…"""`) has no escape layer at
all — `r"\q"` IS backslash-q, and never reports E047.

```almide
let a = "bad:\q"          // ← E047: unknown escape sequence `\q`
let b = "bad:\u{110000}"  // ← E047: `\u{110000}` is not a Unicode scalar value
```

Both used to pass `almide check` silently, evaluating to their own spelling —
`"bad:\q"` was the six characters `b a d : \ q`, and `"\u{110000}"` was its
ten-character source text. That is the same silent reinterpretation E024
forbids for integer literals: a literal whose value is not what it says is a
bug the compiler must name, not carry.

## Fix

**Unknown escape** — escape the backslash, or use the escape you meant:

```almide
let path = "C:\\Users"    // a literal backslash is \\
let tab  = "col1\tcol2"   // \t, not \T
```

Regex patterns are ordinary strings, so a regex class is written with a
doubled backslash — or with a raw string, which needs none:

```almide
regex.find("\\d+", s)     // the regex \d+
regex.find(r"\d+", s)     // same, no doubling
```

**Out-of-range codepoint** — Unicode scalar values run `U+0000..U+D7FF` and
`U+E000..U+10FFFF`. The surrogate range `D800..DFFF` is a UTF-16 encoding
artifact and denotes no character; nothing exists above `U+10FFFF`:

```almide
let ok  = "\u{10FFFF}"    // the highest codepoint there is
let nul = "\u{0}"         // NUL — `\0` is not an Almide escape
```
