# E121 — an import name that is both a local module and a dependency

`import pkg` and `import pkg.sub` resolve their first segment `pkg` by one
decision (#4865, C-458). When `pkg` names both a module of the project — a
`pkg.almd` file or a `pkg/` directory beside the importing file — and an entry
of `[dependencies]` in `almide.toml`, the import is refused: the compiler does
not pick one, since `import pkg.sub` used to take the local directory while
`import pkg` took the dependency.

```
error[E121]: `import pkg` names both the local module src/pkg and the dependency `pkg` in almide.toml
  hint: rename one of them — the local module, or the `[dependencies]` key — so the name means one package
```

## Fix

Rename the local module (`src/pkg/` → `src/pkg_local/`) and import it by its
new name, or rename the dependency's `[dependencies]` key. A path dependency
whose directory IS the local one is a single package and is not refused.

## Fix-it verdict

**not-fixable**: which of the two names to keep — the local module or the
`[dependencies]` key — and what to call the other is the writer's choice, and
either rename touches files the diagnostic does not own. The diagnostic names
both places; it does not rewrite the code. (`mechanical` = an unattended
rewrite; `conditional` = a suggested fix needs review; `not-fixable` = no
automatic rewrite exists. #1486's applicability doctrine.)

Tested by `tests/import_dependency_ambiguity_test.rs` and the
`tests/diagnostics/e121-*` families.
