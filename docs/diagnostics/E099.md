# E099 — `testing.assert_aborts` outside a direct call in a test block

`testing.assert_aborts(expected, f)` is a test assertion that runs `f` in a
child process or a fresh instance (ADR-0029). The call site is what names the
closure the child runs, and the test harness is what reports the verdict, so
the call must be written directly in a `test` block — nested in an `if`, a
`match`, a `for` or a lambda there is fine. Three shapes are refused:

- a call in a `fn` (a helper the test calls included), in `main`, or in a
  top-level `let`. A program has no harness to report to, and a program that
  wants to abort just aborts:

  ```almide
  import testing

  fn check_aborts() -> Unit = testing.assert_aborts("boom", () => panic("boom"))   // ← E099
  ```

- a first-class use, which hides the call site:

  ```almide
  import testing

  test "a panic aborts" {
    let check = testing.assert_aborts                          // ← E099
    check("boom", () => panic("boom"))
  }
  ```

- a call inside another `assert_aborts` closure, which already runs in a
  child and would need a grandchild.

## Diagnostic

```
error[E099]: testing.assert_aborts is called outside a test block
  in a call of testing.assert_aborts
  hint: assert_aborts runs only in a test: move the call into a `test "…" { }` block. A program that wants to abort just aborts.
```

## Fix

Call it directly in the test, once per abort:

```almide check
import testing

test "a panic aborts" {
  testing.assert_aborts("boom", () => panic("boom"))
  testing.assert_aborts("index out of bounds", () => [1][3])
}
```

## Fix-it verdict

**conditional** — the call belongs in a test block, but which test, and
whether a helper's call should become one call per test site, is the
writer's choice. (`mechanical` = an unattended rewrite; `conditional` = a
suggested fix needs review; `not-fixable` = no automatic rewrite exists.
#1486's applicability doctrine.)
