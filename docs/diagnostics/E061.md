# E061 — top-level `let` bound to a function value

A module-level `let` whose initializer is a lambda is rejected: the binding
has no home in the compiled output (a closure cannot live in a module
constant) and is not callable from anywhere.

```
error[E061]: top-level 'let double' cannot be bound to a function value
```

```almide
let double = (x: Int) => x * 2      // ← E061

fn main() -> Unit = println(int.to_string(double(4)))
```

## The fix

Declare it as a function — same body, same call sites:

```almide
fn double(x: Int) -> Int = x * 2

fn main() -> Unit = println(int.to_string(double(4)))
```

A `let`-bound lambda inside a fn or test body is fine — it is a local value
there, capturable and passable like any other:

```almide
fn apply_twice() -> Int = {
  let double = (x: Int) => x * 2
  double(double(3))
}
```

## Why an error and not a lowering

Before this diagnostic the program was accepted and then failed in every
spelling: the native build placed the closure in a non-`Sync` static (rustc
E0277) and a call to the binding resolved nothing (E002). A check-time error
with the `fn` rewrite is the honest surface (#1540).

## Fix-it verdict

**conditional** — the `fn` rewrite is mechanical for an annotated lambda
(`let f = (x: Int) => …` → `fn f(x: Int) -> … = …`), but an UNANNOTATED
param's type only exists in the inference the rejected binding no longer
gets, so the rewrite needs the author to spell the signature. A suggested
fix with the inferred types is worth review, not unattended application.
