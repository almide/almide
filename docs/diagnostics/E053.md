# E053 — unknown attribute

An attribute name the compiler does not read. The attribute parses, and then
nothing happens.

```almide
@deprecatd(since = 3, use = "shout")   // ← E053: one transposed letter
fn yell(s: String) -> String = shout(s)
```

Before this warning existed, that line compiled clean and told nobody
anything: every caller of `yell` went unwarned while the author believed the
deprecation was live. The same held for any invented attribute — `@inline`,
`@cache`, `@unsafe` — all accepted, all inert.

## The vocabulary

The names the compiler reads live in one list,
`KNOWN_ATTRS` in `crates/almide-frontend/src/attr_vocab.rs`:

`@extern` `@export` `@intrinsic` `@wasm_intrinsic` `@inline_rust`
`@bounded` `@mutating` `@consume` `@borrow_ref` `@pure` `@schedule`
`@location` `@derived` `@main` `@deprecated` `@dialect` `@rewrite`

A near miss gets a suggestion; a name far from all of them gets the whole
list instead, because a wrong suggestion reads as authoritative.

## Declared but unread

A second list, `DECLARED_BUT_UNREAD`, records attributes the grammar accepts
that **no code reads yet**. They do not warn — the corpus already contains
them — but they are written down rather than quietly folded into the known
set, because "accepted and inert" is precisely the state this diagnostic
exists to make impossible to hold by accident.

It is currently empty. `@rewrite` sat here from the first corpus run until
almide#1450 corrected the record: the attribute is read by two BUILD-TIME
generators (the egg fusion rules and the codegen desugar fallback, both over
`stdlib/matrix.almd`), which an AST-consumer grep cannot see.

## Why a warning and not an error

Rejecting outright would break any file carrying an attribute from an older
tool. The language now has the machinery to do it properly instead: promote
E053 to an error at a future dialect epoch, with
[`proofs/dialect-epochs.toml`](../../proofs/dialect-epochs.toml) recording the
break and [E052](./E052.md) telling each caller what to write. That is the
path this warning is a first step on, not a permanent resting place.

## Malformed arguments on a known attribute

A KNOWN attribute whose arguments the compiler cannot read carries the same
code but is an **error**, not a warning (#1518): `@deprecated(since = 2)` with
neither `use =` nor `note =` used to be silently dropped, so the deprecation
never registered while the author believed callers were being told something.
An unreadable deprecation is worse than none — the compat argument above does
not apply, because the author is asking for behavior, not carrying a stale
name.

```almide
@deprecated(since = 2)                       // ← E053 (error): no use=, no note=
@deprecated(since = 2, use = "new_api")      // registers
@deprecated(since = 2, note = "unsound")     // registers
```
