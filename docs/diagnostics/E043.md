# E043 — the try_* spellings, public and internal

The `list.try_*` family (`try_map` / `try_filter` / `try_flat_map` /
`try_filter_map` / `try_fold` / `try_find` / `try_each`) was a monomorphic
workaround for the missing fallibility polymorphism. ADR-0006 dissolves it:
the CORE combinator is fallibility-polymorphic — a callback whose body ends
in `!` (or a named fn declared `-> T!`) instantiates the fallible form,
first-err short-circuit included. The family shipped one deprecation window
(v0.55.0) and is GONE since v0.56.0; this error carries the rewrite.

## The mechanical rewrite

```almide
list.try_map(xs, f)      →  list.map(xs, (x) => f(x)!)!
list.try_filter(xs, p)   →  list.filter(xs, (x) => p(x)!)!
list.try_fold(xs, z, f)  →  list.fold(xs, z, (a, x) => f(a, x)!)!
// find / each / flat_map / filter_map are the same shape
```

## The internal carriers are not the escape hatch

Removing the public names left their bodies behind as `list.__fallible_map` … —
the form the checker instantiates FOR you when a callback propagates. Those
were reachable from source for one release: `list.__fallible_map(xs, f)` compiled,
ran, and warned about nothing. That did not remove the second spelling, it
RENAMED it, which is worse for a writer than the deprecated name was — two
working spellings where only one is documented, and nothing says which is
blessed. Since then, naming a carrier in source is the same E043.

The carrier still exists and still runs; it is simply no longer something
source may write.

The same rule covers the fs streaming walkers (#1144, contract C-274), which
grew the fallible form later: `fs.__fallible_fold_lines` and
`fs.__fallible_for_each_line` are desugar targets, not spellings. They never
had a public `try_` name — the closed door is the only door they have ever
had.

```almide
fs.fold_lines(path, z, (a, l) => f(a, l)!)!   // ✓ the blessed spelling
fs.for_each_line(path, (l) => f(l)!)!         // ✓
fs.__fallible_fold_lines(path, z, f)          // ✗ E043
```

The two PARTITIONED cells (`fs.fold_lines_range` / `fs.fold_lines_chunked`)
have no fallible form at all — a partitioned walk has no defined first err —
so there is no carrier for them to hide either.

```
  try: fs.fold_lines(path, z, (a, l) => f(a, l)!)!
```

## Why

`try` is a loan-word whose lenders disagree (Rust `try_fold` = short-circuit;
Swift/Zig `try` = propagation = almide's `!`), and a per-strategy twin
multiplies the surface by strategy × combinator. One name per combinator,
with the callback's `!` carrying the strategy, is the Swift SE-0413 model.

The same argument is why the carriers are closed: the cost of `try_*` was
never the word, it was that a writer had to CHOOSE. A `__` prefix does not
remove the choice, it only hides one arm of it — and a model that has read
`stdlib/list.almd` will emit the hidden arm.
