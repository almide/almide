# E043 — list.try_* is deprecated (warning)

The `list.try_*` family (`try_map` / `try_filter` / `try_flat_map` /
`try_filter_map` / `try_fold` / `try_find` / `try_each`) was a monomorphic
workaround for the missing fallibility polymorphism. ADR-0006 dissolves it:
the CORE combinator is fallibility-polymorphic — a callback whose body ends
in `!` (or a named fn declared `-> T!`) instantiates the fallible form,
first-err short-circuit included. The family is removed in the next minor
(#1108).

## The mechanical rewrite

```almide
list.try_map(xs, f)      →  list.map(xs, (x) => f(x)!)!
list.try_filter(xs, p)   →  list.filter(xs, (x) => p(x)!)!
list.try_fold(xs, z, f)  →  list.fold(xs, z, (a, x) => f(a, x)!)!
// find / each / flat_map / filter_map are the same shape
```

## Diagnostic

```
warning[E043]: list.try_map is deprecated — the core HOF is fallibility-polymorphic (ADR-0006)
  try: list.map(xs, (x) => f(x)!)!
```

## Why

`try` is a loan-word whose lenders disagree (Rust `try_fold` = short-circuit;
Swift/Zig `try` = propagation = almide's `!`), and a per-strategy twin
multiplies the surface by strategy × combinator. One name per combinator,
with the callback's `!` carrying the strategy, is the Swift SE-0413 model.
