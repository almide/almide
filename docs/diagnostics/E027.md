# E027 — fan.timeout was removed

`fan.timeout(ms, thunk)` was removed in 0.29.0 (contract C-006). A wall-clock
timeout has no portable cross-target meaning: native could enforce it with a
real thread and `recv_timeout`, but wasm has no clock, scheduler, or threads,
so the thunk always ran to completion and the timeout never elapsed. It was
also the sole stdlib surface whose result was not a function of the program
and its inputs — whether the deadline fired depended on machine load, even
between two native runs. Both properties contradict the language's core
promise: byte-identical observable output across targets.

```almide
effect fn main() -> Unit = {
  let r: Result[Int, String] = fan.timeout(5000, () => slow())   // ← E027
}
```

## Fix

Enforce deadlines at the host boundary that invokes the program:

```bash
timeout 5 ./app          # POSIX
wasmtime run app.wasm    # + host-side deadline of your choice
```

Inside Almide, run the work directly — every fan combinator is deterministic
by list order and stays inside the equivalence guarantee:

```almide
effect fn main() -> Unit = {
  let r: Result[Int, String] = fan.any([() => slow()])
}
```

## E027 now covers two removals

`fan.timeout` (0.29.0) and `fan.race` (0.42.0). They were removed for the same reason stated
two different ways: a wall-clock deadline and a wall-clock race both make the RESULT a
function of machine timing, and Almide's model is deterministic data-parallelism — `fan` may
execute in parallel, but observable behaviour is defined to be sequential evaluation in list
order (see [the concurrency stance](../roadmap/active/concurrency-stance.md)).

`fan.race` had a second problem the tombstone message names: it never raced. The desugar
replaced `fan.race([t0, t1, …])` with t0's body and never evaluated the rest, so it was
exactly `thunks[0]()`.

Migrations:

| Removed | If you meant | Use |
|---|---|---|
| `fan.timeout(...)` | a deadline | the host boundary that invokes the program (`timeout 5 ./app`) |
| `fan.race(ts)` | thunk[0]'s result | `ts[0]()` — call it directly |
| `fan.race(ts)` | the first candidate that SUCCEEDS | `fan.any(ts)` |
