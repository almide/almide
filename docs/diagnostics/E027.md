# E027 — fan combinator tombstones: retired spellings that name their replacement

E027 is the fan-surface migration code. Every retired spelling answers it with
the replacement in the hint.

## `fan.race` → `fan.min(clock)`, `fan.any` → `??` / `list.find_map` (dialect epoch 14)

In every other ecosystem `race` means "the first to finish" (JS `Promise.race`,
Haskell `race`, `select`) and `any` means "no order guarantee" (`Promise.any`,
`findAny`, Rayon `find_any`). Almide's two forms selected neither way, so
dialect epoch 14 retired both names (ADR-0028, accepted 2026-10-18):

| Was | Now | Selects |
|---|---|---|
| `fan.race { a(), b() }`, `fan.race(budget) { … }`, `fan.race(xs, f)`, `fan.race(budget, xs, f)` | `fan.min(compute.ms(5)) { a(), b() }` / `fan.min(compute.ms(5), xs, f)` — the clock argument is REQUIRED | the Ok that spent the least deterministic compute within the budget; ties go to source order |
| `fan.any { a(), b() }` | `a() ?? b() ?? fallback` | the first Ok in source order; the right side of `??` runs only when the left side failed, so later candidates never run |
| `fan.any(xs, f)` | `list.find_map(xs, (x) => f(x)?) ?? fallback` | the first Ok in list order; `?` turns an element's Err into `none`, so that element is skipped |
| `fan.first_ok` (the interim epoch-14 draft name) | the same two spellings | — |

`fan.any` was not renamed but removed: trying candidates in order is
sequential by definition, and no peer puts it in the concurrency library (Rust
`Iterator::find_map`, OCaml `List.find_map`, Elixir `Enum.find_value` are all
list functions). The clock argument of `fan.min` says what "least" is measured
on; without it `fan.min { 3, 5 }` would read as the smallest value, so the
clockless forms are parse errors, not E027.

```almide
effect fn main() -> Unit = {
  let w = fan.race { solve_fast(), solve_slow() } ?? -1   // ← E027: write fan.min(compute.ms(5)) { … }
  let f = fan.any { fetch_a(), fetch_b() } ?? -1           // ← E027: write fetch_a() ?? fetch_b() ?? -1
}
```

The real-time selection — `fan.min(duration.ms(n)) { … }`, the first arm to
finish, arms may do I/O, the losers cancelled at their next charge site or I/O
boundary and awaited — is decided (ADR-0028) and lands in a follow-up
(#3788); until then it is a type error, not E027.

## Older removals

`fan.timeout(ms, thunk)` was removed
outright, and the thunk-list forms of `fan.race` / `fan.any` / `fan.settle`
were replaced by deterministic block heads — calling any of the old shapes
answers E027 with the per-fn migration hint ("changed signature: the
thunk-list form was removed; ... is now a block head").

`fan.timeout` itself went away in 0.29.0 (contract C-006). A wall-clock
timeout has no portable cross-target meaning: native could enforce it with a
real thread and `recv_timeout`, but wasm has no clock, scheduler, or threads,
so the thunk always ran to completion and the timeout never elapsed. It was
also the sole stdlib surface whose result was not a function of the program
and its inputs — whether the deadline fired depended on machine load, even
between two native runs. Both properties contradict the language's core
promise: byte-identical observable output across targets.

```almide
effect fn main() -> Unit = {
  let r: Result[Int, String] = fan.timeout(5000, () => slow())   // ← E027
}
```

## Fix

Enforce deadlines at the host boundary that invokes the program:

```bash
timeout 5 ./app          # POSIX
wasmtime run app.wasm    # + host-side deadline of your choice
```

Inside Almide, run the work directly, or bound it with the deterministic
`fan.bounded(compute.ms(n)) { … }`, or the oracle-tier
`fan.timeout(duration.ms(n)) { … }` (the block head that replaced the call):

```almide
effect fn main() -> Unit = {
  let r: Result[Int, String] = fan.bounded(compute.ms(5)) { slow() }
}
```

## E027 now covers three retirements

`fan.timeout` (0.29.0), `fan.race(thunks)` (0.42.0), and the epoch-14 pair
above. The first two were removed for the same reason stated two different
ways: a wall-clock deadline and a wall-clock race both make the RESULT a
function of machine timing, and Almide's model is deterministic
data-parallelism — `fan` may execute in parallel, but observable behaviour is
defined to be sequential evaluation in list order (see
[the concurrency stance](../roadmap/active/concurrency-stance.md)). The
oracle tier (`fan.timeout(duration…)`, and `fan.min(duration…)` to come) is
where timing is admitted as a recorded host input, never as a silent one.

`fan.race(thunks)` had a second problem the tombstone message names: it never
raced. The desugar replaced `fan.race([t0, t1, …])` with t0's body and never
evaluated the rest, so it was exactly `thunks[0]()`.

Migrations:

| Removed | If you meant | Use |
|---|---|---|
| `fan.timeout(...)` | a deadline | the host boundary that invokes the program (`timeout 5 ./app`), or `fan.timeout(duration.ms(n)) { … }` |
| `fan.race(ts)` | thunk[0]'s result | `ts[0]()` — call it directly |
| `fan.race(ts)` / `fan.any { … }` | the first candidate that SUCCEEDS | `a() ?? b() ?? fallback` |
| `fan.race { … }` | the least deterministic compute | `fan.min(compute.ms(n)) { … }` |
