# E037 — a comparison between two different types

`==`, `!=`, `<`, `<=`, `>` or `>=` was applied to operands of two
different types. A comparison relates two values of ONE type and nothing
converts a side implicitly: an `Int` and a `String` (`1 == "1"`), an
`Int` and a `Float` (`1 == 1.0`), a list and an element, tuples of two
arities, two record types, two type parameters (`a: A == b: B`), a type
parameter and a concrete type, a `Result` on exactly one side, or the
same container with different type parameters (`Option[Int]` vs
`Option[String]`). A sized width meets a canonical one only through a
literal (`x8 == 1`); a canonical VALUE needs `<type>.from(x)`.

The check runs after inference, on the resolved operand types, so it
holds through generics: inside a generic body a type parameter agrees
only with itself, and a call that would bind one parameter to two types
is refused at the call.

Before this code existed the same-container shapes passed `check` and
died as rustc E0308 behind the "codegen produced invalid Rust" wall.

## Common cases

```almide
helper() == ok(0)          // E037: Result on one side only
a == b                     // E037 when a: Option[Int], b: Option[String]
1 == "1"                   // E037: Int with String
n == 1.0                   // E037: Int with Float — `float.from(n) == 1.0`
fn same[A, B](a: A, b: B) -> Bool = a == b   // E037: A with B
```

## Diagnostic

```
error[E037]: operator '==' compares Option[Int] with Option[String]
  hint: == requires both operands to have the same type
```

(The post-inference check's hint: "A comparison relates two values of
the same type, and nothing converts one side implicitly — …".)

## Fix

- Unwrap the Result side first (`!` in an effect fn, `?? fallback`, or
  `match` on ok/err), or compare two Results of the same type.
- For mismatched parameters, convert one side or compare the payloads
  after unwrapping.

## Why

`==` is deep structural equality over ONE type. A comparison that can
never be true (or that rustc will reject) surfacing at check time keeps
the what-you-read-is-what-runs contract.
