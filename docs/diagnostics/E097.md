# E097 — `pub` before a `type`, `protocol` or `test`

A top-level declaration in Almide is public unless it says otherwise: `mod`
narrows it to the project and `local` to the file. `pub` is accepted only as
an explicit spelling of that default, before a `fn` or a top-level `let` /
`var`. A `type` and a `protocol` are public without it, and a `test` block has
no visibility at all, so `pub` there is E097.

```almide
pub type Point = { x: Int, y: Int }   // ← E097: `pub` does not apply to `type`
```

This is the declaration a Rust or TypeScript writer reaches for first to
export a type. Before E097 the parser stopped at the `type` keyword with
"Expected Fn (got Type 'type')", which names a token but not the change.

## Fix

Delete `pub`. Importers see the type as before:

```almide
type Point = { x: Int, y: Int }
```

To make a type less visible than the default, use the modifiers that apply to
it:

```almide
mod type Pair = { a: Int, b: Int }    // this project only
local type Tag = { name: String }     // this file only
```

The same rule applies to `pub protocol Shape { … }` (delete `pub`) and to
`pub test "…" { … }` (delete `pub`).

## Diagnostic shape

```
error[E097]: `pub` does not apply to `type` — remove `pub`
  in pub type
  here: pub type Point = { x: Int, y: Int }
  hint: A `type` is public by default — importers see it without a modifier. Remove `pub`; to narrow it, write `mod type` (this project) or `local type` (this file).
  try: delete the highlighted text (machine-applicable — `almide fix` applies it)
```

The fix-it is anchored to the `pub` keyword plus the blanks after it, taken
from the lexer's token positions, so `almide fix <file>` deletes exactly that.
The parser then reads the declaration as if `pub` were absent, so the rest of
the file is still checked and E097 is the only error the keyword produces.

## Fix-it verdict

**mechanical** — `pub type T = …` and `type T = …` declare the same public
type, and a `pub protocol` / `pub test` means the same without the keyword.
(`mechanical` = an unattended fixer may apply the rewrite; `conditional` = a
suggested fix needs review; `not-fixable` = no automatic rewrite exists.
#1486's applicability doctrine.)
