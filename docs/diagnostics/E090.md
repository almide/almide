# E090 — the `@extern(c)` signature has no C representation

`@extern(c, "lib", "fn")` binds a C function. Only values with a C form can
cross that boundary. The table is `almide_lang::types::extern_abi`, and the
checker and the Rust renderer both read it:

| Almide | C side | Note |
|---|---|---|
| `Int` | `int64_t` (`i64`) | its full width (dialect epoch 15, #4447; it was a C `int`, narrowed with `as`) |
| `Int8`..`Int64`, `UInt8`..`UInt64` | `i8`..`i64`, `u8`..`u64` | same width |
| `Float` / `Float64`, `Float32` | `double`, `float` | |
| `Bool` | `int` | `1` / `0` out, `!= 0` back |
| `Handle` | `*mut u8` | an opaque foreign token (`FILE*`, `sqlite3*`), only passed back to an `@extern` fn |
| `Region` (parameter) | `uint8_t *buf, size_t len` | TWO C arguments: the base and the length the runtime holds, never one the caller typed ([ADR-0031](../adr/0031-raw-pointers-carry-provenance.md) D3) |
| `Region` (return) | `uint8_t *` | only with `@region(len = …, release = "…")` on the declaration (D2); a read-only Region of `len` bytes, freed by `release` once the last copy drops (D6) |
| `String` (parameter only) | `*const u8` | a NUL-terminated copy of the text up to its first NUL, valid for the call |
| `Unit` (return only) | `void` | |

Anything else has no C form, and neither has a `mut` parameter (C cannot
write the new value back into the caller's `var`). That includes lists,
`Bytes`, maps, sets, records, variants, `Option`, `Result`, tuples, fn values,
and a `String` return, which has no owner to free it. Such a declaration used
to pass `almide check`. The native build then failed at rustc on a wrapper that
spelled the type as its debug text. E090 reports that failure at check time.

```almide
@extern(c, "c", "sum_all")
fn sum_all(xs: List[Int]) -> Int = _   // ← E090: parameter 'xs' has type List[Int]
```

```
error[E090]: @extern(c) fn 'sum_all': parameter 'xs' has type List[Int], which has no C representation
  hint: an @extern(c) parameter is one of Int, Int8..Int64, UInt8..UInt64, Float, Float32, Float64, Bool, String, Handle, Region;
        bind it through an `@extern(rust, "crate::host", "f")` fn in `native/*.rs` instead, …
```

A return outside the table names the return list:

```
  hint: an @extern(c) return is one of Int, Int8..Int64, UInt8..UInt64, Float, Float32, Float64, Bool, Handle, Unit, and Region with `@region(len = …, release = "…")`; …
```

### A `Region` return needs its length

A foreign pointer the program reads through is a `Region`, and the
declaration is the one place its length can be stated. Without
`@region(len = …, release = "…")` the return is E090:

```almide
import ffi

@extern(c, "z", "zbuf_new")
fn zbuf_new(n: Int) -> Region = _   // ← E090: a Region return needs its length
```

```
error[E090]: @extern(c) fn 'zbuf_new': a Region return needs the length the foreign function returns
  hint: state it on the declaration: `@region(len = n, release = "free_fn")`, with `n` a parameter or an integer, and `free_fn` the C function that frees the buffer — or return `Handle` and read it through accessor functions (ADR-0031 D2)
```

`len` names a parameter of an integer type or is a non-negative integer
literal; `release` is the C function's name as a string. A malformed clause
(`len` naming no parameter, a missing `release`, an unknown argument, or
`@region` on a fn that does not return `Region`) is E090 too.

### `@export(c)`

An `@export(c, "sym")` fn reads the same table the other way round: the C
caller passes the parameters and receives the return (#4447, #4448). An
`effect fn`'s return is its declared ok type; its err has no C form and
exits the process 1 with the message on stderr (C-452). Two rows have no
reverse. A `String` parameter is refused, because a C caller's `const char*`
carries no length and no owner; take a `Region` parameter instead, which
crosses as `(const uint8_t*, size_t)`. A `Region` return is refused, because
the caller would have no function to free it; take a caller-provided buffer
named by `@region(out = p)` instead. A `mut` parameter is refused too.

```almide
@export(c, "greet")
fn greet(name: String) -> Int = string.len(name)   // ← E090: parameter 'name' has type String
```

```
error[E090]: @export(c) fn 'greet': parameter 'name' has type String, which has no C representation
  hint: an @export(c) parameter is one of Int, Int8..Int64, UInt8..UInt64, Float, Float32, Float64, Bool, Handle, Region;
        a C caller's `const char*` has no length and no owner: take the bytes as a `Region` parameter …
```

Such an export used to compile into an `extern "C"` fn taking a Rust
`String`, which is undefined behaviour for a C caller. An effect fn
returning `String` or `Unit` used to fail at rustc.

## Fix

Pass scalars, `Handle`s and `Region`s, or bind through Rust. A foreign buffer
the program reads is declared with its length:

```almide
import ffi

@extern(c, "z", "zbuf_new")
@region(len = n, release = "zbuf_free")
fn zbuf_new(n: Int) -> Region = _

@extern(c, "z", "zfill")
fn zfill(buf: Region, byte: Int) -> Unit = _   // C: void zfill(uint8_t *buf, size_t len, int64_t byte)
```

An opaque foreign object is a `Handle`, passed back to the library's own
functions:

```almide
@extern(c, "sqlite3", "sqlite3_close")
fn db_close(db: Handle) -> Int = _
```

An `@extern(rust)` fn takes Almide values as plain Rust types (`&[i64]`,
`&[u8]`, `&str`, `&Record`, …; the table is in
[module-system.md §11.1](../specs/module-system.md)). Its `native/*.rs` body
can convert them and call the C function itself.

```almide
@extern(rust, "crate::host", "sum_all")
fn sum_all(xs: List[Int]) -> Int = _   // native/host.rs: pub fn sum_all(xs: &[i64]) -> i64
```

## Fix-it verdict

**not-fixable**: the fix is a new `@extern(rust)` shim and a host function
in `native/*.rs`, a different C prototype, or the length of a foreign buffer,
which only the binding author knows. The declaration alone does not determine
any of them. The compiler names the offending type and the table; it does not
rewrite the signature.

The check applies to the attr the native build binds, which is the first
`@extern` naming `rust` / `rs` / `c`.
