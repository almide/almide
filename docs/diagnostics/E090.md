# E090 — the `@extern(c)` signature has no C representation

`@extern(c, "lib", "fn")` binds a C function. Only values with a C form can
cross that boundary. The table is `almide_lang::types::extern_abi`, and the
checker and the Rust renderer both read it:

| Almide | C side | Note |
|---|---|---|
| `Int` | `int` (`i32`) | narrowed with `as` both ways |
| `Int8`..`Int64`, `UInt8`..`UInt64` | `i8`..`i64`, `u8`..`u64` | same width |
| `Float` / `Float64`, `Float32` | `double`, `float` | |
| `Bool` | `int` | `1` / `0` out, `!= 0` back |
| `RawPtr` | `*mut u8` | |
| `String` (parameter only) | `*const u8` | a NUL-terminated copy of the text up to its first NUL, valid for the call |
| `Unit` (return only) | `void` | |

Anything else has no C form, and neither has a `mut` parameter (C cannot
write the new value back into the caller's `var`). That includes lists,
`Bytes`, maps, sets, records, variants, `Option`, `Result`, tuples, fn values,
and a `String` return, which has no owner to free it. Such a declaration used
to pass `almide check`. The native build then failed at rustc on a wrapper that
spelled the type as its debug text. E090 reports that failure at check time.

```almide
@extern(c, "c", "sum_all")
fn sum_all(xs: List[Int]) -> Int = _   // ← E090: parameter 'xs' has type List[Int]
```

```
error[E090]: @extern(c) fn 'sum_all': parameter 'xs' has type List[Int], which has no C representation
  hint: an @extern(c) parameter is one of Int, Int8..Int64, UInt8..UInt64, Float, Float32, Float64, Bool, String, RawPtr;
        bind it through an `@extern(rust, "crate::host", "f")` fn in `native/*.rs` instead, …
```

## Fix

Pass scalars, or bind through Rust. An `@extern(rust)` fn takes Almide values
as plain Rust types (`&[i64]`, `&[u8]`, `&str`, `&Record`, …; the table is in
[module-system.md §11.1](../specs/module-system.md)). Its `native/*.rs` body
can convert them and call the C function itself.

```almide
@extern(rust, "crate::host", "sum_all")
fn sum_all(xs: List[Int]) -> Int = _   // native/host.rs: pub fn sum_all(xs: &[i64]) -> i64
```

The check applies to the attr the native build binds, which is the first
`@extern` naming `rust` / `rs` / `c`.
