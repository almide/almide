# E020 — Conflicting type declarations

The checker found conflicting declarations for the same type identity in
one module. Different packages can own distinct same-named types; the
canonicalizer qualifies their identities, and a local type can shadow an
imported bare name without redefining that imported type.

## Common cases

```almide
type Config = { name: String }
type Config = { host: String, port: Int }   // E020: 'Config' declared more than once

fn main() -> Unit = println("ok")
```

## Fix

Remove the duplicate declaration, or rename one of the types within the
module when they are intended to be distinct.

```almide
type AppConfig = { name: String }
type DepConfig = { host: String, port: Int }

fn main() -> Unit = println("ok")
```

## Fix-it verdict

**not-fixable** — the error reports a semantic/design problem no automatic rewrite can decide. (`mechanical` = an unattended fixer may apply the
rewrite; `conditional` = a suggested fix needs review; `not-fixable` = no
automatic rewrite exists. #1486's applicability doctrine.)
