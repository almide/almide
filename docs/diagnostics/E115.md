# E115 — HTML is served only from SafeHtml

`http.set_header` and `http.with_headers` write header fields into a response
whose body is a plain `String`. A `Content-Type` that names an HTML media type
(`text/html`, `application/xhtml+xml`; each comma-separated entry is read up to
its `;`, trimmed, in any case) would make the browser parse that String as a
page, so attacker text in it runs as script (row 11e). When the field is
written as literals the call is refused here; a value computed at run time is
refused when the call runs, with an abort.

```almide
import http

fn page(name: String) -> HttpResponse =
  http.with_headers(200, "<h1>${name}</h1>", [("Content-Type", "text/html")])   // ← E115
```

```
error[E115]: `http.with_headers` serves `Content-Type: text/html`, an HTML media type, with a String body; HTML is served only from SafeHtml
  hint: build the page as SafeHtml with the html builders (html.escape for text, html.attr / html.url_attr for attributes, html.script_json for data in <script>) and answer with http.html(status, page); trusted markup goes through html.raw(s)
```

## Fix

```almide
import html
import http

fn page(name: String) -> HttpResponse =
  http.html(200, html.concat(html.raw("<h1>"), html.concat(html.escape(name), html.raw("</h1>"))))
```

## Why

`http.html(status, page)` takes only `SafeHtml`, which a `String` reaches only
through a context builder or the named opt-out `html.raw`. A header write
that turns a String body into HTML would be a second, unmarked way in. The
guarded writers declare it (`@content_type_guard` in `stdlib/http.almd`,
naming the media-type list both this check and the run-time refusal read),
so the rule follows the declarations rather than a list of function names.

## Fix-it verdict

**not-fixable**: which parts of the page are text, attributes, URLs or
script, and which markup is trusted, is a decision about the page; no
rewrite of the String can make it. (`mechanical` = an unattended fixer may
apply the rewrite; `conditional` = a suggested fix needs review;
`not-fixable` = no automatic rewrite exists. #1486's applicability doctrine.)
