# E060 — import hygiene (warning)

An import that does nothing: a module imported and never used, or the same
module imported twice under two names.

```
warning[E060]: unused import 'regex'
warning[E060]: module 'regex' is already imported as 'regex'
```

```almide
import regex                 // ← E060: nothing below mentions regex
import json
import json as j             // ← E060: json already has a name in this file

fn main() -> Unit = println(j.stringify(json.parse("1")!))
```

Neither is an error — the program means what it says — but both are residue
that misleads the next reader: an unused import claims a dependency the file
does not have, and a duplicate import gives one module two names, so two call
sites that mean the same thing read as if they did not.

The fix: remove the unused line; keep ONE name per module. A deliberately
unused import (kept for a doc example, say) can be suppressed with an
underscore prefix: `import _regex`.

## What counts as a use

The verdict is spelled from the file, not from what the checker happened to
resolve. An import's name is USED when it appears as the head of any
qualified spelling — a call (`h.open()`), a constructor (`m.Box { .. }`,
`c.Red`), a type position (`-> g.Point`, a parameter, a `let x: g.Point`, a
generic argument, a protocol method signature), a pattern (`m.Some(x)`), or a
test `where` override path — or when a protocol the imported module declares
is named BARE in a bound or a conformance list (`fn go[S: Store]`,
`type Mem: Store`). Protocols resolve unqualified across modules, so the bare
spelling names no alias; the declaring module is matched instead.

The same holds for a type a stdlib module OWNS (`bytes`'s `Endian`, `fs`'s
`FileStat`, `process`'s `ProcessStatus`, `url`'s `Url`, …): spelling the
type bare — `fn f(e: Endian)`, `let xs: List[Endian]`, `FileStat { .. }` —
or one of its constructors (`LittleEndian`) uses that module's import, with
or without a `bytes.*` call beside it (#1853). The type alone pulls the
module's declaration into the program, so the import is not unused. A type
the file declares itself is its own (`type Endian = ..` shadows the
stdlib's, #1837): its bare spellings use no import, and an `import bytes`
beside it still warns.

Self-module imports (`import self.ports`, `import self.helper as h`) are
judged by the same rule (#1783). Before 0.62 they were exempt, so an
unreferenced one checked clean.

A file the parser had to recover (any parse error) gets no unused-import
verdict: recovery drops the text that may have been the use, and the parse
error is already the diagnosis.

## Fix-it verdict

**mechanical** — deleting the UNUSED import line is a pure re-spelling an
unattended fixer applies (`almide fix`). The DUPLICATE half stays display-only:
deleting a duplicate can strand references to its alias, which needs a
reference rewrite, not a line deletion. (`mechanical` = an unattended fixer
may apply the rewrite; `conditional` = a suggested fix needs review;
`not-fixable` = no automatic rewrite exists. #1486's applicability doctrine.)
