# E118 — only the standard library's types conform to a sealed protocol

`Body` (ADR-0032) is sealed: a body's type is the Content-Type a browser
obeys, so a user type declaring `Body` could serve any String as
`text/html`. Only the stdlib's types conform — String, Bytes, `Value`,
`html.SafeHtml`, `svg.SafeSvg` and `http.TypedBody`. The rule is read off the
protocol's `sealed` flag, not its name.

```almide
type Page: Body = { text: String }   // ← E118
```

```
error[E118]: type `Page` declares `Body`, which only the standard library's types conform to
```

## Fix

Convert at the response: `http.response(200, page.text)`, an `html.*` or
`svg.*` body, or `http.typed("text/csv", bytes)` for another media type.

## Fix-it verdict

**not-fixable**: which body a user type becomes is a decision about the
program. (`mechanical` = an unattended fixer may apply the rewrite;
`conditional` = a suggested fix needs review; `not-fixable` = no automatic
rewrite exists. #1486's applicability doctrine.)
