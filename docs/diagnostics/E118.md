# E118 — a media type's owner is not granted, not unique, or not a literal

A `Body` type states the Content-Type its response is served with
(ADR-0032). A type may own media types with `@media_owns(...)`, so that
`http.typed` cannot label bytes as one of them. Owning a type a browser runs
script in — the patterns `stdlib/html.almd` declares `@script_capable`:
HTML, XHTML, SVG, XML — is the authority to put script in front of a user,
so it is checked (D7):

- a dependency that owns a script-capable type builds only when the root
  `almide.toml` grants that package that type, by its source:

  ```toml
  [trust]
  media = { "almide/svg" = ["image/svg+xml"] }
  ```

- a grant for a type the package does not declare, or for a package that is
  not a dependency, is refused;
- two owners — the stdlib's, a dependency's, the application's — whose
  patterns can name one media type are refused, so a type has one owner;
- a `Body` type's media fn is a string literal, and a script-capable one is
  covered by that fn's own `@media_owns`, so a type serves only what it was
  granted.

The application's own types need no grant (the developer wrote them); they
are listed by `almide deps` with every other owner.

```almide
type Chart: Body = { markup: String }

fn Chart.__self_media_type(self) -> String = "image/svg+xml"   // ← E118
```

```
error[E118]: `Chart.__self_media_type` serves `image/svg+xml`, which runs script in a browser, without owning it
```

```
error[E118]: dependency `svg` (almide/svg) owns `image/svg+xml`, which runs script in a browser, and ./almide.toml does not grant it
```

## Fix

Declare what the type serves with `@media_owns(...)` on its media fn, write
the media type as a literal, and grant a dependency that owns a
script-capable type in `[trust] media` — only if you trust it to build that
type safely. HTML is `html.*`'s; build pages with its builders.

## Fix-it verdict

**not-fixable**: granting a package the right to serve script is a decision
about trust. (`mechanical` = an unattended fixer may apply the rewrite;
`conditional` = a suggested fix needs review; `not-fixable` = no automatic
rewrite exists. #1486's applicability doctrine.)
