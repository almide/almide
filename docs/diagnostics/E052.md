# E052 — calling a deprecated function

A call names a function marked `@deprecated`. The warning names the
replacement and says how much work the edit is; when the edit is a pure
rename, `almide fix` performs it.

```almide
@deprecated(since = 3, use = "shout")
fn yell(s: String) -> String = shout(s)

fn shout(s: String) -> String = s + "!"

effect fn main() -> Unit = println(yell("hi"))
//                                 ^^^^ E052: `yell` is deprecated since dialect 3
//                                 hint: Use `shout` — same signature — the name is the whole edit.
```

## The attribute

```almide
@deprecated(since = N, use = "replacement")   // renamed or superseded
@deprecated(since = N, note = "why")          // removed with no successor
@deprecated(since = N, use = "...", note = "...")
```

- **`since`** is the DIALECT EPOCH (`proofs/dialect-epochs.toml`), not a
  release. It is the same currency a file's `@dialect(N)` stamp records, so a
  stale file and the reason it is stale are denominated the same way.
- **`use`** names the replacement, fully qualified for another module
  (`string.trim_start`).
- **`note`** is free text. Required when there is no `use`: a deprecation
  with neither tells a caller nothing it can act on, and the compiler rejects
  it at the declaration.

A malformed `@deprecated` is an error at the *declaration*, not a silent
no-op — the failure mode worth preventing is an author who believes callers
are being warned when they are not.

## How the edit is classified

The compiler **derives** the classification by comparing the two signatures
rather than trusting a hand-written marker, so a replacement whose type drifts
later re-classifies itself on the next compile:

| the two signatures | hint says | `almide fix` |
|---|---|---|
| identical (parameter *names* may differ) | "same signature — the name is the whole edit" | **applies it** |
| differ in any parameter type, return type, or effect-ness | "the signature differs — check the arguments" | shows `try:`, does not apply |
| replacement not visible from here | "the replacement is not visible from here" | shows `try:`, does not apply |

Only the first row is machine-applicable. Auto-applying a rewrite across a
signature change would hand `almide fix` a miscompile, so it is deliberately
withheld and the reader does that edit.

## Why this exists

Almide's users are largely code generators, and a model writes whatever
dialect it learned. A diagnostic that only says "no such function" costs a
whole retry to guess the fix from; one that names the replacement is a repair
instruction applicable in a single edit — and when the edit is mechanical, in
no edits at all. That difference is the metric the language is optimized for.
