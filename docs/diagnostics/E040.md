# E040 — retired json.*/value.* alias

The dynamic `Value` surface had two module names for one concept (#1075).
The survivor split gives each module one sentence of identity:

- **`value.*` is the data model** — constructors (`value.null`, `value.int`,
  `value.str`, `value.object`, `value.array`, …) and accessors
  (`value.as_int`, `value.field`, `value.keys`, …).
- **`json.*` is the format over it** — `json.parse`, `json.stringify`,
  `json.stringify_pretty` (plus the json-branded path API and typed-key
  conveniences, which have no second name).

Every fn that was reachable under both names warns with E040 for one
release, then the alias drops. `value.get` is retired inside its own module
too: `value.field` is the same operation, and `get` means Option everywhere
else (`map.get` / `list.get`), which made a Result-returning `value.get` a
false friend.

## Common cases

```almide
fn main() -> Unit = {
  let v = json.object([("a", json.from_int(1))])   // ← E040 ×2
  let n = json.as_int(json.get(v, "a") ?? json.null())  // ← E040 ×3
  let x = value.get(v, "a")                        // ← E040
  println("${n ?? 0}")
}
```

## Diagnostic shape

```
warning[E040]: json.as_int is retired — constructors and accessors live on value.*; json keeps the format (parse / stringify)
  in call to json.as_int()
  hint: value.as_int returns a Result — append `?` for the Option this call produced: value.as_int(...)?
  try:
      value.as_int(json.get(v, "a") ?? json.null())?
```

## Fix

Run `almide fix <file>` — the whole family migrates mechanically, including
nested calls. The rewrites:

| retired | survivor |
|---|---|
| `json.null()` / `json.object(..)` / `json.array(..)` / `json.keys(..)` | `value.null()` / `value.object(..)` / `value.array(..)` / `value.keys(..)` |
| `json.from_string` / `from_int` / `from_bool` / `from_float` | `value.str` / `value.int` / `value.bool` / `value.float` |
| `json.as_string(v)` … `json.as_array(v)` (returned `Option`) | `value.as_string(v)?` … `value.as_array(v)?` (`?` is the Result→Option conversion, so the expression's type is unchanged) |
| `json.get(v, k)` (returned `Option`) | `value.field(v, k)?` |
| `value.get(v, k)` | `value.field(v, k)` |

UFCS spellings (`v.get(k)`) are warned but not auto-rewritten — rename the
method to `.field(k)`.

## Why

Two names for one operation is pure vocabulary cost: a writer must learn
both, gets no signal from seeing either, and mixes them within one file.
Every diff that touches the dynamic surface carried a which-namespace
judgment call that reviewers could not ground in anything. On the wasm leg,
`value.get` also lacked `value.field`'s Object-tag guard — retiring it
removes a latent cross-target divergence.
