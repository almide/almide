# E104 — a skipped record field has no default

`@skip` and `@skip_decode` keep a field out of a derived `T.decode`: input can
never set it (#4108). The decoder still has to build the record, so the field
needs a default to take.

```almide
type User: Codec = { name: String, @skip_decode is_admin: Bool }   // ← E104
```

```
error[E104]: field 'is_admin' is `@skip_decode` but has no default
  hint: A skipped field is never read from input, so `T.decode` needs a value for it. Give it one: `@skip_decode is_admin: <Type> = <default>`.
```

## Fix

```almide
type User: Codec = { name: String, @skip_decode is_admin: Bool = false }
```

## Why

serde (`#[serde(skip)]` needs `Default`), kotlinx (`@Transient` needs an
initializer) and Swift (a property left out of `CodingKeys` needs an initial
value) all refuse the same declaration: a field the decoder may not read
needs a value from somewhere, and the only place left is the declaration.

The check runs on every record field, Codec or not: the attribute only means
something to the Codec derive, but a skip with nothing to fall back to is
wrong wherever it is written. Fixture: `tests/diagnostics/e104-skip-without-default`.

## Fix-it verdict

**not-fixable**: the right default depends on the field. (`mechanical` = an
unattended fixer may apply the rewrite; `conditional` = a suggested fix needs
review; `not-fixable` = no automatic rewrite exists. #1486's applicability
doctrine.)
