# E101 — source that reads differently from what compiles

E101 refuses source text a reader sees differently from the compiler: a raw
hidden character anywhere in a `.almd` file (#4092, #4266), and an identifier
a reader cannot tell from another (#4266).

## Hidden characters

The set is C-418's escape table (`ALMIDE_RT_ERRTEXT_ESCAPED` in
`crates/almide-base/src/err_text.rs`) minus TAB, LF and CR: the characters a
runtime error text must escape are exactly the ones a source file must not
hold raw.

- the bidirectional controls (below), which reorder a displayed line;
- U+2028 LINE SEPARATOR and U+2029 PARAGRAPH SEPARATOR, which an editor or a
  web view shows as a line break the lexer does not see;
- every other General Category Cf character — U+200B..U+200D, U+2060..U+2064,
  a mid-file U+FEFF, U+00AD, … — invisible on screen;
- the Tags block U+E0000..U+E007F: invisible ASCII a model reading the source
  reads as text (ASCII smuggling);
- raw C0 and C1 controls other than TAB, LF and CR.

A leading byte-order mark is stripped before the scan. The nine
bidirectional controls:

| codepoint | name |
|---|---|
| U+202A | LEFT-TO-RIGHT EMBEDDING |
| U+202B | RIGHT-TO-LEFT EMBEDDING |
| U+202C | POP DIRECTIONAL FORMATTING |
| U+202D | LEFT-TO-RIGHT OVERRIDE |
| U+202E | RIGHT-TO-LEFT OVERRIDE |
| U+2066 | LEFT-TO-RIGHT ISOLATE |
| U+2067 | RIGHT-TO-LEFT ISOLATE |
| U+2068 | FIRST STRONG ISOLATE |
| U+2069 | POP DIRECTIONAL ISOLATE |

The rule is the same in a comment, a string literal, a heredoc and a raw
string, and on every target: it is a front-end error.

A line comment holding `U+202E } U+2066 if admin then U+2069 {` (the
characters themselves, not their names) is displayed by an editor or a code
review page as code with its order reversed, while the compiler reads a
comment. This page cannot show the raw character — that is the point.

```
error[E101]: raw hidden character U+202E RIGHT-TO-LEFT OVERRIDE at line 5, column 6
  hint: this character makes the source display differently from how it compiles (Trojan Source), or hides text from a reader that a model still reads. Remove it from a comment; inside a string literal, write the escape `\u{202E}` if the character is intended
```

## Fix

- In a comment: delete the character.
- In a string literal or heredoc that really needs it: write the escape. The
  escape is ASCII in the source, so the text a reviewer reads is the text the
  compiler reads, and it still decodes to the character:

```almide
let s = "user\u{202E} txt.exe"   // the escape, not the raw character
```

A raw string (`r"…"`) has no escape layer; build the value from an ordinary
literal instead. An emoji ZWJ sequence spells its joiners as escapes:
`"👨\u{200D}👩\u{200D}👧"`.

## Homoglyph identifiers

Two rules from UTS #39, judged only for identifiers holding a non-ASCII
character (rustc's `mixed_script_confusables` and `confusable_idents` draw
the same line, as warnings):

- **Mixed scripts.** A non-ASCII identifier must be at most UTS #39
  *Moderately Restrictive*: one script; Latin with Han, Hiragana, Katakana,
  Hangul or Bopomofo; or Latin with one other script except Cyrillic and
  Greek — and every character General Security Profile `Allowed`.
  `аdmin` with a Cyrillic `а` (U+0430) is Latin + Cyrillic: refused.
- **Confusables.** Two different spellings in one file with the same UTS #39
  skeleton, at least one non-ASCII, are refused at the later one: an
  all-Cyrillic `асе` beside `ace`. An interpolation hole's identifiers count.

```
error[E101]: identifier `аdmin` mixes scripts a reader cannot tell apart at line 4, column 4
  hint: its non-ASCII characters are `а` U+0430 (Cyrillic). An identifier must be written in one script, …
```

Fix: write the letter from the name's own script, or rename one of the two.
`привет`, `名前`, `user名` and `π` are all fine.

## Why

Trojan Source (CVE-2021-42574): with one of these characters in the source,
the code a reviewer reads is not the code the compiler reads. rustc denies
the bidi controls by default in comments and literals
(`text_direction_codepoint_in_comment`, `text_direction_codepoint_in_literal`).
Homoglyph identifiers are CVE-2021-42694: a second function that reads as the
first lets a change call different code from what the diff shows.

## Fix-it verdict

**not-fixable**: in a comment the character should be deleted, in a literal
it may be intended and should become an escape; the diagnostic does not choose.
