# E101 — raw bidirectional control character in the source

A raw Unicode bidirectional control character anywhere in a `.almd` file is
E101 (#4092). There are nine:

| codepoint | name |
|---|---|
| U+202A | LEFT-TO-RIGHT EMBEDDING |
| U+202B | RIGHT-TO-LEFT EMBEDDING |
| U+202C | POP DIRECTIONAL FORMATTING |
| U+202D | LEFT-TO-RIGHT OVERRIDE |
| U+202E | RIGHT-TO-LEFT OVERRIDE |
| U+2066 | LEFT-TO-RIGHT ISOLATE |
| U+2067 | RIGHT-TO-LEFT ISOLATE |
| U+2068 | FIRST STRONG ISOLATE |
| U+2069 | POP DIRECTIONAL ISOLATE |

The rule is the same in a comment, a string literal, a heredoc and a raw
string, and on every target: it is a front-end error.

A line comment holding `U+202E } U+2066 if admin then U+2069 {` (the
characters themselves, not their names) is displayed by an editor or a code
review page as code with its order reversed, while the compiler reads a
comment. This page cannot show the raw character — that is the point.

```
error[E101]: raw bidirectional control character U+202E RIGHT-TO-LEFT OVERRIDE at line 5, column 6
  hint: this character makes the source display differently from how it compiles (Trojan Source). Remove it from a comment; inside a string literal, write the escape `\u{202E}` if the character is intended
```

## Fix

- In a comment: delete the character.
- In a string literal or heredoc that really needs it: write the escape. The
  escape is ASCII in the source, so the text a reviewer reads is the text the
  compiler reads, and it still decodes to the character:

```almide
let s = "user\u{202E} txt.exe"   // the escape, not the raw character
```

A raw string (`r"…"`) has no escape layer; build the value from an ordinary
literal instead.

## Why

Trojan Source (CVE-2021-42574): with one of these characters in the source,
the code a reviewer reads is not the code the compiler reads. rustc denies
them by default in comments and literals (`text_direction_codepoint_in_comment`,
`text_direction_codepoint_in_literal`). Identifiers are ASCII-only already, so
comments and literals are the only places they could hide.

## Fix-it verdict

**not-fixable**: in a comment the character should be deleted, in a literal
it may be intended and should become an escape; the diagnostic does not choose.

Fixture: `tests/diagnostics/e101-bidi-control/` (comment, string literal and
heredoc cases); near-miss: `tests/diagnostics/silent/bidi-control-written-as-escape.almd`.
