# E116 — a response's Content-Type is written from its body's type

A response's `Content-Type` is its body's type (ADR-0032, row 11e): a String
is `text/plain; charset=utf-8`, `html.*` builds `text/html`, a granted
package's safe type its own type, a `Value` `application/json`, and any other media type is
`http.typed("text/csv", bytes)`. Writing the header by name would relabel the
body — a String served as `text/html` runs attacker text as script — so
`http.set_header` on a response and `http.with_headers` refuse it. With the
name written as a literal the call is refused here; a computed name aborts
when the call runs. A request is not a response body and may carry any
Content-Type.

```almide
import http

fn report(rows: String) -> HttpResponse =
  http.with_headers(200, rows, [("Content-Type", "text/csv")])   // ← E116
```

```
error[E116]: `http.with_headers` writes `Content-Type` by name, and a response's `Content-Type` is written from its body's type
```

## Fix

```almide
import http

fn report(rows: String) -> HttpResponse =
  http.with_headers(200, http.typed("text/csv", bytes.from_string(rows)), [])
```

`almide fix` makes this rewrite when the call is on one line, the body is a
String and the type is one `http.typed` accepts (`set_header(r, "Content-Type",
t)` with `r` a name becomes `http.with_body(r, http.typed(t,
http.body_bytes(r)))`).

## Why

Which header the body owns is declared once, on the writers
(`@header_write(…, owned = "__http_response_body_headers")` in
`stdlib/http.almd`), and both this check and the run-time refusal read it.

## Fix-it verdict

**mechanical** for the one-line literal shapes above (an unattended fixer may
apply the rewrite); otherwise the diagnostic carries no fix. (`mechanical` = an
unattended fixer may apply the rewrite; `conditional` = a suggested fix needs
review; `not-fixable` = no automatic rewrite exists. #1486's applicability
doctrine.)
