# E081 — the function is not available on the selected wasm target

The selected wasm route cannot serve the named function or emitted host
operation. Availability is per leg: stock preview1, direct components and
the embedded host do not expose identical services. The current matrix is
`proofs/target-availability.toml`; CI checks declared walls against the
renderer. Read the reason for the selected route rather than assuming that
no wasm execution path exists.

For example, a stock-preview1 HTTP-client wall does not mean the embedded
host or the WASI 0.3 HTTP component route is absent. Component builds also
validate the operations served by the selected shim.

Where a portable alternative exists, the diagnostic names it (`try:` line
— e.g. `testing.assert_gt` → `assert(a > b)`); the availability matrix
row carries it. Every row also names its closure `class` — how the
unavailability ends: `pending-self-host` (a self-host body closes it),
`pending-port` (a host port closes it, the row's `issue` says which) or
`native-only-forever` (the fn cannot exist on the wasm target as
specified; the row's `justification` says why). `host-capability` rows
name a private import required by a stock artifact: subprocess support uses
`almide:process/spawn` on the embedded host (ADR-0025), not a universal wasm
prohibition. The two pending counts are shrink-only
ratchets in CI.

Direct `--component` builds also check emitted host operations against
the selected p2 or p3 shim before writing the output file. These failures
name the operation and the component version. For example, direct p2 and
p3 currently lack argv imports, so a call through `args.option` reports
`env.args`, `args.option`, and host op 29. Plain preview1
builds serve argv and are not refused by this component-specific check.
`almide check --target wasm` checks the stock build route; it does not
select a component profile.

Native or embedded execution may provide the required host operation.

## Fix-it verdict

**not-fixable** — the fix is a platform decision (run natively, use the
named alternative, or wait for the port), not a rewrite an unattended
fixer may apply. (`mechanical` = an unattended fixer may apply the
rewrite; `conditional` = a suggested fix needs review; `not-fixable` = no
automatic rewrite exists. #1486's applicability doctrine.)
