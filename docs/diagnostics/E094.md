# E094 — type aliases form a cycle

A type alias is another name for its body: `type Coord = Pos` means whatever
`Pos` means. An alias that leads back to itself — directly, through other
aliases, or through a type argument — has no body to stand for, so it names
no type. This used to pass `almide check` silently (`type Tree = List[Tree]`)
or leave the alias an opaque name that every use then refused with an
unrelated error; E094 reports the cycle at the first alias declared in it.

```almide
type Coord = Pos

type Pos = Coord                  // ← E094: type aliases form a cycle: Coord → Pos → Coord
```

A cycle through a type argument is a cycle too:

```almide
type Tree = List[Tree]            // ← E094: type alias 'Tree' refers to itself (Tree → Tree)
```

Declaration order is not a cycle: an alias may name a type declared further
down (`type First = Pair2` above `type Pair2 = (Int, Int)`).

## Fix

Give one of the aliases a body that does not lead back, or make the
recursive type nominal — a record or variant may refer to itself:

```almide
type Tree = { kids: List[Tree] }

fn size(t: Tree) -> Int = list.len(t.kids)
```

## Fix-it verdict

**not-fixable** — whether the cycle wants a record, a variant or a different
body is the writer's intent; the message names the aliases in the cycle.
