# E062 — shebang without `-S` (warning)

`#!/usr/bin/env almide run` runs on macOS and dies on Linux.

Darwin's kernel splits the shebang line on whitespace before calling `env`.
Linux's `binfmt_script` does not: `env` receives the rest of the line as ONE
argument and looks for a program literally named `almide run`.

```
$ /usr/bin/env "almide run" --version
env: almide run: No such file or directory
```

`env -S` (coreutils 8.30, 2018) exists for exactly this split. The failure
never reproduces on the machine the script was written on, and the wrong
spelling is the one a writer reaches for — every shebang they have seen is
one word (`#!/usr/bin/env python3`), so the second word gets appended and `-S`
is never learned. Five scripts in a row were written without it before this
warning existed (#2159).

```almide
#!/usr/bin/env almide run        // ← E062: this shebang does not run on Linux

fn main() -> Unit = println("hi")
```

## Fix

Insert `-S` right after `env`:

```almide
#!/usr/bin/env -S almide run

fn main() -> Unit = println("hi")
```

The `try:` line under the warning is that exact rewrite.

## When it does not fire

The decision is made from the text of line 1 alone — no PATH lookup, no host
probe:

- the interpreter is not `env` (`#!/usr/local/bin/almide run` — the kernel
  hands `run` to almide directly on both platforms)
- `-S` / `--split-string` is present, including inside a flag cluster (`-iS`)
- only one program word follows `env` (`#!/usr/bin/env almide`), with flags and
  `NAME=value` assignments not counted

Under `--deny-warnings` it is an error like every other warning.

## Fix-it verdict

**mechanical** — inserting `-S` after `env` is a pure re-spelling of the same
command line: same interpreter, same program, same arguments, now split the
same way on both kernels. `almide fix` applies it unattended (the emitter is
`with_machine_fix`, replacing the whole of line 1). (`mechanical` = an
unattended fixer may apply the rewrite; `conditional` = a suggested fix needs
review; `not-fixable` = no automatic rewrite exists. #1486's applicability
doctrine.)
