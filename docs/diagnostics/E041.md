# E041 — implicit propagation was removed

Inside an effect fn, a fallible call's err used to return through the
enclosing failure channel WITHOUT a marker in five positions (statement,
un-annotated binding, condition, value-pattern match subject, interpolated
call). ADR-0008 retired this: propagation is spelled `!`, uniformly, in
every position. After the 0.54 deprecation window (where this code was a
warning), the implicit form is GONE — the value stays a `Result`, and a
position that would have auto-unwrapped it is this error.

## Common cases

```almide
effect fn main() -> Unit = {
  let r = int.parse(s)        // E041 — write: int.parse(s)!
  if flag() then ...          // E041 — write: flag()!
  println("${get()}")         // E041 — write: "${get()!}"
}
```

A discarded statement-position Result is the sibling error
[E042](E042.md) (must-use).

## Diagnostic

```
error[E041]: implicit propagation of this binding's value was removed — this value is a Result (ADR-0008)
  try: !          ← a mechanical insertion at the expression's end
```

## Fix

Append `!` to propagate, or consume the Result as a value: `?? fallback`,
`?` (to Option), or `match r { ok(v) => …, err(e) => … }`. The error
carries a machine-applicable insertion for the binding / statement /
condition / match forms; interpolated calls are spelled by hand
(`"${get()!}"`).

## Why

The implicit form was position-dependent (five positions took it, five
did not) and annotation-sensitive — the same expression changed runtime
behavior with a type annotation or a pattern shape. One explicit marker
in every position is the Rust/Swift/Zig model (ADR-0008's survey: no
language ships position-dependent implicit propagation).

## Fix-it verdict

**conditional** — append `!` vs handle explicitly is a choice the doctrine leaves open. (`mechanical` = an unattended fixer may apply the
rewrite; `conditional` = a suggested fix needs review; `not-fixable` = no
automatic rewrite exists. #1486's applicability doctrine.)
