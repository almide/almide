# E096 — a fn with a `mut` parameter used as a function value

A fn that declares a `mut` parameter can be called, but not turned into a
function value. A bare reference to it that is not a call is refused: a
`let`, an argument to another fn, a record field, a list element, a return
value, and the same for a module-qualified fn (`counter.bump`, `list.push`).

A `mut` parameter writes back to the caller's `var` (C-226). That promise is
part of the fn's signature, and a function type has no place for it: a value
of `bump` is a `(St) -> Unit`, and a call through it passes `s` as an
ordinary argument. Before this error, such a call lost the write on wasm and
failed to build natively.

```almide
type St = { count: Int }

fn bump(mut s: St) -> Unit = {
  s.count = s.count + 1
}

effect fn main() -> Unit = {
  var s = St { count: 0 }
  let f = bump          // ← E096
  f(s)
  println(int.to_string(s.count))
}
```

## Diagnostic

```
error[E096]: fn 'bump' has a `mut` parameter 's' and cannot be used as a function value
  in bump used as a value
  hint: A `mut` parameter writes back to the caller's `var`, and a function value cannot carry that. Call it directly (`bump(s)` with `var s`), or pass a lambda that names the `var` (`() => bump(s)`). If 'bump' only changes its own copy, drop `mut` from 's' and rebind it with `var` inside the body
```

The error points at the reference. The call and the lambda in the hint use
the fn's own parameter names: for `list.push` it reads
`list.push(xs, x)` with `var xs`, and `(x) => list.push(xs, x)`. A stdlib fn
does not get the last sentence, because its `mut` cannot be dropped.

When the reference is an argument filling a fn-typed parameter
(`list.map(groups, grow)`), there is no caller `var` to name: each call gets
an element. The hint then suggests a lambda of that parameter's arity, over
names the lambda binds itself, that copies each `mut` argument into a local
`var`:

```
error[E096]: fn 'grow' has a `mut` parameter 'xs' and cannot be used as a function value
  hint: A `mut` parameter writes back to the caller's `var`, and a function value cannot carry that. Pass a lambda that copies into a local `var`: `(item) => { var copy = item; grow(copy); copy }`. If 'grow' only changes its own copy, drop `mut` from 'xs' and return the new value
```

The lambda ends in the copy when the fn returns `Unit` and the parameter
expects a value back (`list.map`'s `(A) -> B`), so the new value is the
result; otherwise it ends in the call. For a stdlib fn in a two-argument
slot, `list.fold(xs, init, list.push)` suggests
`(a1, a2) => { var copy = a1; list.push(copy, a2); copy }`.

## Fix

- Call the fn directly where the write must land: `bump(s)` with `var s`.
- As a callback argument, pass the lambda from the hint: it copies the
  element into a local `var`, calls the fn on it and returns the copy:
  ```almide
  let grown = list.map(groups, (item) => { var copy = item; grow(copy); copy })
  ```
- Where a function value is needed, pass a lambda that names the `var` the
  write should reach. The lambda captures `s`, so the write lands in it:
  ```almide
  let tick = () => bump(s)
  tick()
  ```
- If the fn changes the parameter only as its own scratch copy and the caller
  never needs the write, the parameter does not need `mut`. Drop it, rebind
  inside the body and return the new value:
  ```almide
  fn next(x: Int) -> Int = {
    var y = x
    y = y + 1
    y
  }
  ```
  `next` is then an ordinary `(Int) -> Int` value (`xs |> list.map(next)`).

## Why

Languages that pass by reference and also allow function values put the mode
in the function type: Swift writes `(inout Int) -> Void` and Rust
`fn(&mut i32)`. Almide's function types have no such mode, so the value
would have to forget the write. Koka's local `var`s take the other route: they
cannot be passed to other functions at all. Almide refuses only the
conversion, so the direct call and a lambda that names the `var` keep their
meaning.
