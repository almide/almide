# E042 — this statement discards a Result (must-use)

A statement-position expression whose type is `Result` throws the value —
and with it, the error — away. With implicit propagation removed
(ADR-0008, [E041](E041.md)), a silently dropped Result would be the one
place a failure could vanish without a trace, so it is a check error in
EVERY fn kind (effect, fallible, pure, test).

## Common cases

```almide
effect fn main() -> Unit = {
  cleanup(tmp)            // E042 — the err is silently dropped
  fs.write(p, s)          // E042
}
```

## Diagnostic

```
error[E042]: this statement discards a Result — the error would be silently dropped
  try: !          ← a mechanical insertion at the call's end
```

## Fix

Two spellings, by intent:

```almide
cleanup(tmp)!             // propagate the err
let _ = cleanup(tmp)      // discard ON PURPOSE (the explicit-discard spelling)
```

Matching on ok/err also consumes it. `let _ =` is the same
intentional-discard lineage as `map_err`'s `(_)` (ADR-0004 D3).

## Why

Rust ships `#[must_use]` on Result as a warning and its ecosystem lints
it to deny; Swift requires `try` before every throwing call. An
error-by-default is the stricter cousin ADR-0008 D2 chose: silently
losing an error is the silent-loss class, and a warning that scrolls by
is how it ships.
