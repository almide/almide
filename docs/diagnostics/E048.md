# E048 — variant pattern from the wrong family (Option vs Result)

`some(..)` / `none` destructure an **Option**. `ok(..)` / `err(..)` destructure
a **Result**. The two families are separate types in Almide, and a pattern from
one never matches a subject of the other.

```almide
fn first_plus_one(xs: List[Int]) -> Int = match list.get(xs, 0) {
  ok(a) => a + 1,   // ← E048: `list.get` returns `Int?`, an Option
  _ => 0,
}
```

The classic source is a wrong guess about a producer's return type — `list.get`,
`map.get` and `string.find` all return `T?` (an Option), while `int.parse`,
`fs.read_text` and `json.parse` return a Result. Reading the producer's
signature is the reliable way to pick the arm spelling.

## Why this is an error and not a silent bind

Until #1341 the checker only rejected a constructor pattern aimed at a plain
scalar. A cross-family pattern fell through, binding its payload as
`Ty::Unknown`, which survived every later pass and detonated in codegen:

```
error: [COMPILER BUG] internal type resolution failed before codegen
    [fn f:3:12] unresolved Var ty=Unknown var_id=1 name=a stored_ty=Unknown
  hint: please report this at https://github.com/almide/almide/issues
```

on native, and an "outside the executable subset" wall on wasm. Both blamed the
compiler for a plain type error in the program, and neither named the one-word
fix — the #1266 misattribution class. E048 is that same rejection, moved to the
only place that sees both the pattern and the subject's type.

## Diagnostic shape

```
error[E048]: pattern `ok(..)` destructures a Result, but the subject is `Option[Int]`
  in match pattern
  hint: Option and Result are separate types: an Option is matched with `some(..)`
        / `none`, a Result with `ok(..)` / `err(..)`. Write `some(..)` here.
  try:
      some(..)
```

The `try:` snippet is always the **same arm position** in the subject's family:
success arm ↔ success arm, failure arm ↔ failure arm. The one asymmetric pair is
`err(e)` ↔ `none`: an Option's failure arm carries no error value, so the binder
goes away (and, in the other direction, `none` ↔ `err(..)` gains one).

## Fix

Use the spelling for the family the subject actually is.

```almide
fn first_plus_one(xs: List[Int]) -> Int = match list.get(xs, 0) {
  some(a) => a + 1,
  _ => 0,
}
```

If you meant the value to be a Result, convert at the producer instead of at the
pattern — for example `list.get(xs, 0) ?? 0` for a fallback, or a `some`/`none`
match whose arms build the `ok(..)` / `err(..)` you want.
