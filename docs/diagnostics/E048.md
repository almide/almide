# E048 — variant pattern the subject's type does not have

A constructor pattern must name a case the **subject** actually has. E048 covers
the three ways it can fail to:

| pattern | subject | |
|---|---|---|
| `ok(..)` / `err(..)` | an `Option` | wrong family |
| `some(..)` / `none` | a `Result` | wrong family |
| `some`/`none`/`ok`/`err` | a user variant | builtin carrier over a user ADT |
| a user ctor `C(..)` | a variant without `C`, or an Option / Result | foreign case |
| a user newtype's `Value(..)` / record's `Value { .. }` | the STDLIB's `Value` (`FileStat`, …) | stdlib type vs. its user shadow |

`some(..)` / `none` destructure an **Option**. `ok(..)` / `err(..)` destructure
a **Result**. The two families are separate types in Almide, and a pattern from
one never matches a subject of the other — nor does either match a user variant,
whose cases are its own.

```almide
fn first_plus_one(xs: List[Int]) -> Int = match list.get(xs, 0) {
  ok(a) => a + 1,   // ← E048: `list.get` returns `Int?`, an Option
  _ => 0,
}
```

The classic source is a wrong guess about a producer's return type — `list.get`,
`map.get` and `string.find` all return `T?` (an Option), while `int.parse`,
`fs.read_text` and `json.parse` return a Result. Reading the producer's
signature is the reliable way to pick the arm spelling.

## Why this is an error and not a silent bind

Until #1341 the checker only rejected a constructor pattern aimed at a plain
scalar. A cross-family pattern fell through, binding its payload as
`Ty::Unknown`, which survived every later pass and detonated in codegen:

```
error: [COMPILER BUG] internal type resolution failed before codegen
    [fn f:3:12] unresolved Var ty=Unknown var_id=1 name=a stored_ty=Unknown
  hint: please report this at https://github.com/almide/almide/issues
```

on native, and an "outside the executable subset" wall on wasm. Both blamed the
compiler for a plain type error in the program, and neither named the one-word
fix — the #1266 misattribution class. E048 is that same rejection, moved to the
only place that sees both the pattern and the subject's type.

The **foreign-case** cell was worse still: a user ctor from another variant
(`match shape { Red(r) => .. }`) bound its payload Unknown and reached codegen,
which emitted **invalid Rust** on native (`codegen produced invalid Rust — this
is an Almide bug`) and walled on wasm.

Only structurally-known subjects are claimed. A type still under inference, or a
`Named` type that is an opaque alias (whose `SafeHtml(s)` destructure IS legal),
stays silent — error recovery is unaffected.

One more cell is a **stdlib type against its user shadow** (#1828, #1835). A
program that declares its own `Value` — a record, or an opaque newtype `mod type
Value = String` — owns it as `self.Value` (`m.Value` in module `m`), while
`json.parse` still returns the STDLIB's `Value`. Aiming the user type's pattern
at the json value is E048, with the E013 hint naming both types:

```
error[E048]: pattern `Value(..)` is not a case of `Value`
  in match pattern
  hint: `Value` is the `value` module's type and has no constructor to destructure.
        Here `Value` is the `value` module's type, not your `type Value` (which is
        `self.Value`): a same-name declaration never rebinds a stdlib type, so read
        this value through `value.*` — or rename your type to keep the two apart.
```

Before this cell existed the pattern bound its payload `Ty::Unknown` and reached
codegen: rustc E0308 on native, and the structural wasm leg read the json value's
payload as the user's `String`.

## Diagnostic shape

```
error[E048]: pattern `ok(..)` destructures a Result, but the subject is `Option[Int]`
  in match pattern
  hint: Option and Result are separate types: an Option is matched with `some(..)`
        / `none`, a Result with `ok(..)` / `err(..)`. Write `some(..)` here.
  try:
      some(..)
```

The `try:` snippet is always the **same arm position** in the subject's family:
success arm ↔ success arm, failure arm ↔ failure arm. The one asymmetric pair is
`err(e)` ↔ `none`: an Option's failure arm carries no error value, so the binder
goes away (and, in the other direction, `none` ↔ `err(..)` gains one).

## Fix

Use the spelling for the family the subject actually is.

```almide
fn first_plus_one(xs: List[Int]) -> Int = match list.get(xs, 0) {
  some(a) => a + 1,
  _ => 0,
}
```

If you meant the value to be a Result, convert at the producer instead of at the
pattern — for example `list.get(xs, 0) ?? 0` for a fallback, or a `some`/`none`
match whose arms build the `ok(..)` / `err(..)` you want.

For a user variant, match its own cases — the hint lists them:

```
error[E048]: pattern `Red(..)` is not a case of `Shape`
  hint: the subject's cases are: Circle / Square.
```

## Fix-it verdict

**conditional** — which constructor family was meant is intent. (`mechanical` = an unattended fixer may apply the
rewrite; `conditional` = a suggested fix needs review; `not-fixable` = no
automatic rewrite exists. #1486's applicability doctrine.)
