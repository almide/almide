# E057 — fn has no body

A function DECLARATION with no `= body`:

```
error[E057]: fn 'f' has no body
  hint: Write the body after '=': `fn f(...) -> T = expr` (or `= { ... }`).
        Only @extern / @intrinsic declarations may omit it
```

## What it means

The parser keeps the bodyless form because two declaration families need it
legitimately — `@extern` bindings and `@intrinsic` runtime declarations (and
the stdlib's `= _` placeholder parses as a body). A PLAIN fn that omits `=`
used to slip through the checker's body-matching arm entirely: check passed,
an unused declaration even ran, and the first CALL died at the native build
with a missing-function error (the acceptance-parity class — check must
reject everything the build cannot honor).

## What to do

- Write the body: `fn f() -> Int = 42`, or a block: `= { ... }`.
- If the fn is genuinely implemented outside Almide, declare it as such:
  `@extern(...)`. `@intrinsic` is reserved for stdlib implementations,
  not a user escape hatch (see [E085](E085.md)). A user body `= _` is a
  typed hole, not a foreign implementation: it aborts if reached on native
  and is not supported by the structural Wasm emitter.

## Where it fires

At the declaration, during check — before anything can call it.
