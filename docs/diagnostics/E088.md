# E088 — a recursive call retains the current scoped activation

The first `scoped` fragment admits ordinary workers and **direct tail-recursive**
workers. E088 rejects the two recursion shapes that keep the caller's
activation alive across the call: a single self-call with work left after it,
and mutual recursion between scoped workers.

```
error[E088]: recursive call retains the current scoped activation
  = addition remains after the recursive call
  = required by the `scoped` declaration of `count`
  hint: carry the count in an accumulator and return the recursive call
```

The note names what remains after the call — `addition`, `a constructor`,
`a binding` — so the accumulator rewrite is visible from the message.

```almide check-fail=E088
type Chain = Nil | Cons(Int, Chain)

scoped fn total(c: Chain) -> Int =
  match c {
    Nil => 0,
    Cons(h, t) => h + total(t),
  }

effect fn main() -> Unit = println(int.to_string(scoped { total(Cons(1, Cons(2, Nil))) }))
```

## The fix

Carry the pending work in an accumulator so the recursive call is the arm's
result.

```almide check
type Chain = Nil | Cons(Int, Chain)

scoped fn total(c: Chain, acc: Int) -> Int =
  match c {
    Nil => acc,
    Cons(h, t) => total(t, acc + h),
  }

effect fn main() -> Unit = println(int.to_string(scoped { total(Cons(1, Cons(2, Nil)), 0) }))
```

Mutual recursion (`even_steps` calling `odd_steps` calling `even_steps`) is
refused for the same reason and is fixed by folding the pair into one
directly-recursive worker.

**Not refused**: a worker whose arm makes two or more self-calls — a tree walk
such as `1 + count(l) + count(r)`. That shape has no accumulator rewrite, so
it is admitted as an ordinary worker; the rule targets the single non-tail
call that an accumulator would fix.

## Fix-it verdict

**conditional** — the accumulator parameter and its seed are the author's
choice; the diagnostic names what remains after the call and the shape to
write.
