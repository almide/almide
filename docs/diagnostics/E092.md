# E092 — a `@pure` fn is not pure

`@pure` promises the empty effect set: the fn, and everything it calls, has no
effect category, writes no output and declares no abort. The attribute used to
be accepted and ignored, so a fn marked `@pure` could print, abort or call into
the host while its author believed otherwise (#3250). It is now checked.

A `@pure` fn is E092 when:

- it is an `effect fn`;
- it is an `@extern` fn — a foreign body cannot be checked;
- anything it reaches calls `println`, `eprintln`, `panic`, `assert`,
  `assert_eq` or `assert_ne` (the writes and aborts ADR-0022 admits in a plain
  `fn` — admitted there, not here);
- anything it reaches calls a stdlib function that carries an effect category
  (`io.write`, `process.pid`, `args.flag`, … — the table is
  `STDLIB_MODULE_EFFECTS` in `crates/almide-ir/src/effect.rs`);
- anything it reaches calls an `@extern` fn.

```almide
fn checked(n: Int) -> Int = {
  assert(n >= 0)
  n
}

@pure
fn double(n: Int) -> Int = checked(n) * 2   // ← E092
```

```
error[E092]: `@pure` fn `double` reaches `assert` via `checked`, and `assert` aborts the program when it fails
  --> main.almd:7:28
```

The error is located at the call in the `@pure` fn that leads to the impure
call, and names the path. When the impure call lives in a module inferred after
the `@pure` fn's file, the error is reported at the first call of the path in
that module, and names the `@pure` fn with its file and line.

## What does not count

- A call through a fn-typed parameter or local. `@pure fn apply(f: (Int) -> Int,
  x: Int) -> Int = f(x)` is pure; the function passed in is judged where it is
  written (ADR-0026 D1).
- A language-defined trap: division by zero, an index out of bounds. These can
  still end the run, but they are not declared aborts (ADR-0027 §4).

## Fix

Move the impure call to a caller that is not `@pure`, or remove `@pure`. An
assertion that guards an input can usually become a total expression
(`if n >= 0 then n else 0`) or a `Result` the caller handles.

ADR-0027 (draft) proposes a `pure fn` modifier with exactly this meaning and
retiring the attribute in its favour.
