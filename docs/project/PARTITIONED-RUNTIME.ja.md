# パーティション型ランタイムの要件 (#568)

[English](./PARTITIONED-RUNTIME.md) | [日本語](./PARTITIONED-RUNTIME.ja.md) | [简体中文](./PARTITIONED-RUNTIME.zh-CN.md)

Critical プロファイルの Almide wasm 成果物を実行するために、パーティション型ホスト（ARINC 653 型の時間・空間分割、またはコンポーネントごとにメモリと CPU の予算を設定する環境）が提供すべきものと、成果物自体が保証するものを説明します。以下の具体的な成果物チェックは、`tests/static_memory_test.rs` の PID 参照アプリケーションを検証するものであり、すべての Critical プロファイルのプログラムや Wasm コンポーネント経路を検証するものではありません。デプロイする成果物ごとに、許可されたケイパビリティと実際のインポートを確認する必要があります。各行にゲートを示します。

## 成果物が保証すること（空間）

| 性質 | 仕組み | ゲート |
|---|---|---|
| 固定ヒープ予算 | `almide build --heap-cap <bytes>` は bump frontier の上限をモジュールに埋め込む。超過時は決定的な地点で定義済みの中断（`Error: out of memory`、終了コード 1）が発生し、黙って拡張することはない | `tests/static_memory_test.rs::fixed_heap_budget_suffices_and_is_enforced` |
| 定常状態の割り当て規律 | `almide check --profile critical`（#567）は回数指定ループ内の割り当て、実行時長のヒープコンストラクター、クロージャー、再帰、`while` を拒否する。critical-clean なプログラムのループ本体が割り当てるのは、最大でも有界な一時オブジェクト（宣言された print ケイパビリティのためのスカラーから文字列への変換） | `tests/static_memory_test.rs::reference_app_is_critical_clean` |
| 割り当てのないカーネル算術 | 制御則の関数から出力される Rust に、ヒープ関連のトークンが含まれない（Vec/Box/String/format!/clone/RcCow がない） | `tests/static_memory_test.rs::kernel_fns_emit_allocation_free_rust`（Float カーネルについては `tests/wcet_kernel_test.rs` も参照） |
| 単一の非共有リニアメモリ、スレッドインポートなし | 参照コア成果物は非共有メモリを1つ持ち、名前またはモジュールに `thread` を含むインポートがない。このテストは普遍的な5操作のインポート集合を要求するものではない | `tests/static_memory_test.rs::artifact_is_partition_shaped` |
| 有界スタック | `--profile critical` では呼び出しグラフが DAG になる（再帰は E073 で拒否）。そのためスタックの深さは静的な呼び出しグラフの深さで制限され、さらに wasm 自身のスタックにもホスト側の制限がかかる | プロファイルゲート（`tests/critical_profile_test.rs`） |

## ホストが提供すべきもの

1. **実際の成果物のインポートを実装するホスト**：ビルドしたモジュール／コンポーネントと、許可されたケイパビリティを調べてください。別のプログラムではファイルシステム、ネットワーク、プライベートなプロセス操作が必要な場合があり、すべてが参照用の5操作のインターフェースに変換されるわけではありません。パッケージングでコアまたはコンポーネントの経路を選択します（`src/cli/build_wasm.rs`）。serve 形式の HTTP ビルドは WASI 0.3 ハンドラーコンポーネントを使用します。
2. **メモリ分割**：リニアメモリは初期ページ数を宣言します。パーティションごとのメモリ割り当て枠を強制するホストは、追加で wasmtime の `StoreLimits` 上限を設定できます。成果物自身の `--heap-cap` 予算の方が厳しい制限なら、その中断が先に発生するため、失敗は定義済みのものに保たれます。
3. **時間分割**：ホストはプリエンプションとホスト呼び出しのタイムアウト方針を提供し、検証しなければなりません。決定的な計算メーター（C-320）は、モデル化された計上した計算コストを協調的に制限します。ブロックするホスト呼び出しを中断するものではなく、それ自体でハードウェアのタイムクォンタムを証明するものでもありません。
4. **並行実行の方針**：選択した経路とホストサービスを検証してください。参照成果物のスレッドインポートなしのチェックは、すべてのホストサービスや他のすべての Almide 成果物がシングルスレッドである証明ではありません。

## 適格性確認の境界

このクラスの成果物に対する、適格性確認済み／最小限の実行環境（どのホストを、どのように適格性確認するか）は #865 の範囲であり、この文書の範囲ではありません。本文はその契約の成果物側を扱います。参照成果物の性質はゲートで検証されますが、デプロイ時には、その環境のインポート、リソース予算、ホストの保証を確立する必要があります。
