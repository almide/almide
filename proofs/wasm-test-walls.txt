# WASM TEST-LANE WALL REGISTER — spec files whose tests do NOT run on wasm
# because a renderer declined them.
#
# This is the OTHER way a spec file can fail to reach the wasm leg, and until
# #2121 nothing watched it. `tests/wasm_skip_ledger_test.rs` gates the declared
# `// wasm:skip` markers and is blind to walls by construction: a wall carries
# no marker, so it never appeared in any ledger, and `almide test spec/
# --target wasm` — a CI gate — reported green while five files' tests had not
# run there.
#
# A row here is NOT the same claim as a `// wasm:skip`. That marker says wasm
# CANNOT run the file (an OS API, an `@extern` binding, a caught panic) and its
# ledger refuses subset debt outright (#812, "fix the wall rather than parking
# it here"). A row here says a LEG has not lowered the shape yet, and names the
# issue that removes it.
#
# SHRINK-ONLY, both directions (scripts/check-wasm-test-walls.sh):
#   - a wall with no row FAILS — a new one cannot join silently
#   - a row whose file no longer walls FAILS — delete the row
#
# Format: <repo-relative path><TAB><why, and what retires it>
#
# Every row below is ONE cause: the test lane renders through the incumbent
# brick alone, while `build`/`run`/`check --target wasm` render through the
# two-leg router whose default is the structural leg. `almide build --target
# wasm` reports `structural leg, verified` for every one of these four files.
# #2179 gives the lane that route and empties this register.
